# 성과·비용·다음 실행의 계약

버전: gtm_observed_utm_v1 · 적용일: 2026-09-16 · 상태: 실제 제품 집계 API 연결 확인. [AGENTS.md](AGENTS.md)를 먼저 읽는다. 분석의 첫 대상은 콘텐츠이며 크리에이터·협업·캠페인·포맷·집행별로 같은 원본을 묶는다.


## 현재 API의 정확한 범위

`performance`는 기본 최근 30일(최대 93일)의 관측 결과를 반환한다. start_at 이상 end_at 미만이며 일별 표시는 Asia/Seoul이다. 제품 전체(product_overall)는 모든 획득 채널의 지표이고 콘텐츠 귀속 합계와 같지 않다. plan_id 필터도 제품 전체 숫자를 바꾸지 않는다.

- landing_visitors: 기존 new_visit/new_session 이벤트의 고유 local_id. 사람 수·총 방문 횟수와 다르다.
- signups: logs의 career_signup_completed 최초 시각. 로그가 없으면 talent_users.created_at으로 보완하고 fallback 수를 표시한다.
- signup_cohort_completed_7d: 기간 내 가입자 중 가입 시각 이상, 가입+7일 미만에 실제 onboarding_completed 이벤트가 있는 사용자. 아직 7일이 안 지난 가입자는 미성숙이다.
- onboarding_completion_events: 가입 기간과 무관하게 조회 기간 내 최초 완료 이벤트가 발생한 사용자. 위 가입 cohort 완료와 다른 지표다.
- identity: 가입 시 서버의 contact_queue.payload.landingLocalId를 우선한다. 없으면 같은 브라우저 ID에 이메일 하나가 확인된 login_email을 보완 사용하고 legacy_identity_signups를 표시한다. 내부/확인된 QA 계정을 제외하며 사용자 ID·이메일·브라우저 ID는 API가 반환하지 않는다.
- 콘텐츠 귀속: 가입 이전 7일 이내에 기록된 마지막 명시적 UTM. 다른 채널의 더 늦은 UTM이 있으면 이전 GTM에 귀속하지 않는다. 발급 링크 ID/source/campaign이 모두 일치해야 한다. 공용 링크는 shared_attribution에만 한 번 기록한다.
- actions: 실제 message_sent 활동, research_result 기록, published_at의 수다. 초안은 발송이 아니다. 이 수를 서로 나눠 협업 cohort 회신율/합의율로 쓰지 않는다.

현재 제품이 같은 UTM 재방문을 생략할 수 있고 source-only 방문과 연결되지 않은 기기가 있어 **정확한 전체 last-non-direct를 보장하지 않는다**. 제품 계측 보완 전 빈칸을 추측해서 채우지 않는다. 기존 비-GTM 링크를 새 콘텐츠 실적으로 임의 이관하지 않는다.

현재 콘텐츠 비용은 누적 배분 비용이다. CPA는 게시 시점이 조회 기간 안에 있고 비용/통화가 확인된 경우만 잠정 표시한다. 조회 기간 전환과 생애 비용을 맞춘 최종 수익성 지표가 아니다. D14 가입+D7 완료의 고정 게시 cohort, 연락 cohort 퍼널과 실험 비교는 아래 계약에 따라 별도 분석하며 현재 API에 자동 구현됐다고 주장하지 않는다.

## 성과는 같은 행에서 읽는다

콘텐츠 목록의 기본 성과 칼럼은 발생 비용, 유입, 신규 가입, 목표 완료, 목표당 비용, 관측 기간, 미측정/관측 중 여부다. 세부 플랫폼 지표와 당시 조건은 펼쳐 읽는다. 여러 플랫폼 게시를 묶어 보여줘도 고유 관객이라고 합산하지 않고, 플랫폼마다 다른 지표 정의를 유지한다.

시작 목표로 ‘신규 가입 후 7일 내 온보딩 완료’를 제안한다. 목표와 귀속 정의는 집행 계획의 버전으로 고정한다. 단순 조회수·가입자 수·활성 사용자 수를 같은 성공으로 취급하지 않는다. 실제 매출/공헌이익이 없으면 CPA를 쓰며 수익 ROI를 꾸며내지 않는다.

## UTM과 제품 연결

기본 발급안은 source=플랫폼, medium=실제 획득 채널, campaign=캠페인의 불변 UUID(하이픈 제외), content=gtm_contents.tracking_links 안의 고정 링크 ID다. 링크 항목 → 콘텐츠 → 협업/집행/캠페인/포맷으로 바로 찾아간다. 링크 이름을 바꾸거나 삭제해 과거 성과의 대상을 옮기지 않는다.

본문·스토리 등의 링크는 위치별 항목으로 발급한다. 여러 콘텐츠가 공용 프로필 링크를 공유하면 게시별 확정 성과로 나누지 않고 해당 공용 범위 또는 미배분 성과로 표시한다. 제품 사용자를 마케팅 원장에 복제하지 않고 기존 제품의 방문·인증 연결·가입·완료 이벤트를 제한 조회한다.

링크 항목에 귀속 범위와 대상 ID를 고정한다. content 범위일 때만 특정 콘텐츠 전환으로 집계한다. 공용 account/plan 범위는 그 범위의 결과로 한 번만 계산하며, 링크를 처음 등록한 콘텐츠에 전부 붙이거나 관련 콘텐츠 모두에 복제하지 않는다. 전체 집행 결과에는 콘텐츠에 배분하지 못한 기여도 별도로 표시한다.

기존 계측의 시각·중복·로그인 연결을 구현 전에 코드로 확인한다. 부족한 부분은 제품 공통 계측을 보완한다. 단순 UTM 문자열만으로 콘텐츠별 정확한 귀속이 완성됐다고 가정하지 않는다. 기존 로그의 문자열 길이·파라미터 우선순위도 구현 시 다시 확인하며 신규 링크는 충돌 없는 표준 UTM을 사용한다.

## 비교 기준

장기 목표는 가입 직전 7일 이내 마지막 non-direct 방문이다. 현재 구현은 아래에 명시한 관측된 명시적 UTM 모델이며 두 정의를 혼동하지 않는다. 가입보다 미래의 방문은 제외하고, 다른 획득 채널도 함께 비교한다. 신규 가입과 그 가입 후 7일 내 완료를 같은 획득에 귀속한다. 사용자×지표×귀속 버전당 한 번만 계산한다. 직접 재방문으로 기존 유효 접촉을 지우지 않는다.

인증으로 확인되지 않은 다른 기기·브라우저 사용자를 추측해 합치지 않는다. 지역·학생 여부도 확인 가능한 원본만 사용하고 미확인을 별도로 표시한다. 이 귀속은 관측 배분이며 인과적인 순증 사용자 수를 뜻하지 않는다.

게시 후 14일 내 가입한 사람의 7일 완료까지 비교하려면 최대 게시 후 21일과 데이터 도착 여유가 필요하다. 관측이 진행 중이면 잠정 결과로 표시한다. 뒤늦게 받은 12일 누적 조회수를 7일 값으로 기록하지 않는다. 누적값을 날짜별로 더하지 않는다. 완료 시각이 없는 과거 플래그를 7일 완료로 채우지 않는다.

미측정·권한 없음·오류·실제 0은 다르다. 전환 0일 때 CPA를 0원으로 보이지 않는다. 과거 집계 정정은 새 버전으로 남기고 당시 채택 리뷰의 근거는 유지한다. 외부 자료의 보존 기한은 역사 보존보다 우선한다.

## 집계 단위와 분모

| 비교할 것 | 같은 기준으로 계산할 단위 |
| --- | --- |
| 연락→회신→합의 | 첫 실제 제안 발송이 있었던 협업 cohort. 초안은 제외하고 follow-up 메시지는 새 협업 수로 세지 않음 |
| 회신율 | 같은 발송 cohort 중 실제 상대 회신이 확인된 협업 / 실제 제안 발송 협업. 자동응답·반송·아직 관측 중인 건은 별도 표시 |
| 합의율·게시 이행률 | 연락→합의 또는 회신→합의 중 분모를 명시. 게시 이행은 기한이 도래한 약속 산출물 기준으로 측정 |
| 콘텐츠·제작물·제작자 수 | 게시 행 수, content_group_id 수, creator_id 수를 구분. 두 플랫폼에 같은 영상을 올렸다고 독립 제작 두 건으로 보지 않음 |
| 가입·완료와 CPA | 같은 목표·귀속 버전·기간·대상 조건의 고유 사용자와 해당 비용. 콘텐츠 CPA의 단순 평균 대신 합산 비용/중복 제거한 완료 수 사용 |

국가·관객·단가·포맷·제품 랜딩이 다른 실행은 차이를 함께 보여준다. 이전 주에 보낸 메시지에 이번 주 답장이 왔다고 서로 다른 주의 건수를 나눠 회신율을 만들지 않는다. 중간에 취소·실패한 협업도 최초 cohort와 발생 비용에서 지우지 않는다. 아직 충분히 기다리지 않은 cohort는 잠정 결과다.

지표 정의에는 최소한 단위, 포함 대상, 기준 시각, 관측 창, 분자/분모, 귀속·비용 버전, 제외/결측 처리, 통화·시간대를 둔다. 예를 들어 7일 완료 창은 가입 시각 이상 가입+7일 미만으로 고정한다. 조회 기간과 실제 데이터 cutoff를 함께 표시한다.

## 비용과 예산

gtm_costs 한 항목 안에서 예상액, 확정 약정액, 발생 비용, 실제 지급·환불을 구분한다. 팀 시간은 실제/자가 보고/추정 근거와 시간 단가를 가진다. 비용의 원통화·기준 통화·환율 기준을 함께 보존한다.

Agent·API 사용량은 실행 로그/청구 근거에서 모으고 팀원 작업 시간은 해당 협업·조사·집행에서 짧게 입력하거나 구분된 추정으로 남긴다. 메시지 왕복 수와 협상 경과 시간은 활동에서 계산한다. 회신을 기다린 시간을 팀원이 계속 일한 시간으로 계산하지 않는다. 같은 도구 청구를 사용량별 비용과 월 청구 비용에 중복 반영하지 않는다.

- 현금 지출 = 실제 지급 - 환불.
- 전체 총비용 = 발생 외부 비용 + 노동 비용. 실패한 발굴/협의·공통 비용도 포함한다. 집행별 비용은 실제 배분으로 계산하며 아직 집행을 정할 수 없는 공통 비용은 전체에서 별도 표시한다.
- CPA = 같은 범위의 발생 비용 / 해당 목표의 귀속 완료 수. 외부비용 기준과 팀 시간 포함 기준을 구분한다.
- 가용 현금 = 한도 - 현금 비용별 max(현재 약정액, 발생 외부 비용, 순지급액)의 집행 배분 합 - 아직 비용으로 전환되지 않은 예약 - 별도 보유 예비비. 모든 항은 같은 기준 통화로 계산한다.

약정 30만 원에 선금 15만 원을 지급해도 예산 사용은 45만 원이 아니다. 승인 예약을 비용으로 전환할 때 예약을 동시에 해제한다. 노동 한도는 현금과 구분한다.

취소·감액으로 실제 의무가 줄면 근거와 함께 현재 약정/발생액을 정정하고 과거 합의 버전은 보존한다. 환불이 들어왔다는 사실만으로 비용 발생이나 계약 의무가 자동으로 사라진다고 보지 않는다. 취소 후 환불 대기인 돈도 가용 예산에 조기에 되돌리지 않는다. 집행 한도 축소가 기존 약정·예약보다 작으면 새 지출을 막고 부족액을 표시하며 기존 의무를 삭제하지 않는다.

팀 시간·도구 청구 등 비용이 미수집이거나 배분이 미완성이면 알려진 비용과 누락 범위를 보여주고 CPA를 잠정으로 표시한다. 비용 미확인을 0으로 넣지 않는다. 다른 통화의 원금액을 그대로 합치거나 근거 없는 환율을 적용하지 않는다.

플랫폼별 원가는 costs의 배분 내역에서 읽고 합계가 원장과 일치해야 한다. 합의한 단가 비중 또는 설명 가능한 기준을 사용한다. 전환이 잘 나온 콘텐츠에 사후적으로 비용을 적게 붙여 성과를 꾸미지 않는다. 배분 변경은 새 버전과 관련 예산 검사를 거친다. 두 번 게시했다고 원 제작비를 두 번 발생시키지 않는다. 다음 실행의 추가 지출과 과거 제작 원가는 따로 제시한다.

## Scale / Retry와 다음 행동

| 구분 | 예시 | 기록 위치 |
| --- | --- | --- |
| 업무 진행 | 제작 중, 게시 완료 | 협업·콘텐츠의 실제 상태 |
| 측정 상태 | D7 관측 중, 통계 미수집 | 시각·수집 기록에서 계산 |
| 채택 방향 | Scale / Retry / Hold / Stop | 해당 원장에 연결한 채택 리뷰 활동 |
| 다음 행동 | CTA 변경 후 1건 제안 | 해당 원장의 action_items 항목·담당·기한 |

방향은 변경 가능한 팀의 어휘다. 고정 CPA/CTR 수식으로 의미를 판정하지 않는다. 특정 크리에이터의 영구 등급으로 만들지 않는다. 팀이 채택한 실제 결정만 이력으로 남기고 현재 검토 중인 제안은 제안으로 표시한다.

리뷰에는 적용 대상·조건, 당시 결과·기간·비용·cutoff, 방향, 이유 한 개의 본문, 채택자·시각을 둔다. 원장 하나의 판단은 그 상세에서 바로 찾는다. 여러 콘텐츠의 조합에 대한 판단은 집행 리뷰에 대상 목록과 필터를 남기고 관련 상세에서도 링크한다. 방향값은 발송·지출 권한이 아니다.

다음 콘텐츠에 이전 콘텐츠와 리뷰 참조, 새로 바꾼 조건을 남긴다. 이후 새로운 단가·결과가 들어오면 ‘검토 이후 새 자료’가 있음을 알린다. 기존 결론을 유지할지는 Agent/팀원이 근거를 읽고 판단한다.

## 일간·주간 사용과 2차 최적화

오늘 할 일은 협업·콘텐츠·집행의 미완료 action_items와 실제 기한/미지급/수집 실패를 모은 보기다. 한 건의 대표 다음 행동 뒤에 남은 업무도 포함하며 동일 항목은 부모와 하위 화면에 보여도 한 번만 센다. 성과 표는 같은 원장을 캠페인·포맷·타깃·채널로 묶은 보기다. 오늘 할 일/포맷 성과를 별도 수기 원장으로 만들지 않는다.

매일 기한·답변·게시·지급·수집 실패를 확인한다. 매주 같은 기간의 성과·비용·표본 수·결측을 보고 반복/변경/중단과 다음 행동을 정한다. 크리에이터 상세에서 관련 협업과 콘텐츠까지 바로 내려갈 수 있어야 한다.

2차에서는 계획 시점의 입력·예측을 고정하고 이후 실제와 비교한다. 응답·합의·게시·제품 전환의 단계별 범위를 추정하고 단가·팀 시간·겹치는 관객·실행 가능 수량을 함께 고려한다. 적은 데이터로 성공 확률을 확정하지 않는다. 인과 실험의 배정·기간·조건은 실제 실험을 시작할 때 기록한다. 단순 평균 성과를 대규모 집행에 그대로 외삽하지 않는다.
