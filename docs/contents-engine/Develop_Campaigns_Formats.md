# Develop_Campaigns_Formats.md

버전: 1.1 · 적용일: 2026-09-17 · 상태: active (범위는 Connections 기준) · 관리: 아래 관리 역할

[AGENTS.md](AGENTS.md)를 먼저 읽는다. 이 문서는 해당 작업의 입력 파악부터 분석·실행·저장·결과 확인까지 소유한다. 외부 발송·게시·송금·플랫폼 API 연결은 문서만으로 생기지 않는다.

## 업무 계약

- **호출 상황:** ‘어떤 주제로 풀면 좋을까’, ‘잘된 영상 방식을 다른 사람에게도 맡기게 정리해’, ‘뉴스레터용 포맷도 만들어’. 기존 가이드 수정도 포함한다.
- **입력·근거:** 제품의 실제 가치·타깃 문제, 기존 캠페인·포맷, 원본 콘텐츠·결과·채택 리뷰. 성공 사례가 없으면 검증 전 가설임을 표시한다.
- **소유하는 방법:** 전달할 가치와 표현 방식 구분 → 기존 기준 재사용 여부 확인 → 메시지·hook·표현 흐름·필수 근거·CTA·참고 예시 정리 → 어떤 상황에 쓸지 설명 → 재사용할 버전 발행.
- **저장:** gtm_campaigns/formats와 연결된 가이드 버전, 참고한 콘텐츠·리뷰. 과거 실행의 버전은 그대로 둔다.
- **완료:** Outreach_Creators.md가 제안 방향을 잡고 Prepare_Content.md이 제작자별 브리프를 만들 수 있는 자료다. 이름표나 ‘바이럴하게’ 같은 지시만으로 끝내지 않는다.
- **예외·경계:** 단일 콘텐츠의 대본 수정마다 새 포맷을 만들지 않는다. 크리에이터별 말투는 가이드의 영구 규칙으로 고정하지 않는다. 반복 가능한 제작 방식과 적용 범위가 생길 때 라이브러리에 반영한다.
- **관리:** 콘텐츠/GTM 담당이 근거 콘텐츠와 새 성과를 보며 갱신한다.

## 현재 도구로 끝까지 수행하기

[Connections.md](Connections.md)의 Supabase plugin 및 `gtm_workspace` 호출 계약을 사용한다. 칼럼은 [data-model.md](data-model.md), 제품 사실은 [Business_Context.md](Business_Context.md), 계산은 [measurement.md](measurement.md)가 원본이다.

1. `list gtm_campaigns`, `list gtm_formats`, `list gtm_outreach_templates`와 관련 콘텐츠·발송·회신 결과를 읽어 기존 기준을 재사용할지 판단한다.
2. 캠페인에는 대상·상황·전달 가치·주장 근거·CTA를 적는다. Format Bank에는 hook, 순서 있는 제작 흐름, 반드시 보여줄 제품 순간, 캡션 출발점, 예시, 반복/중단 기준, 적합한 제작자와 콜드 아웃리치 각도를 적는다. 영상·글·뉴스레터를 같은 구조로 수용하므로 고정 Shot 개수에 맞추지 않는다.
3. 반복해서 쓸 첫 연락 기준이 생기면 `gtm_outreach_templates`에 캠페인·채널·언어·대상·제목/본문 시작점·전달 가치·요청 산출물·제안 조건·후속 문구·링크·버전을 저장한다. 사람 이름만 바꾸는 완성 문구가 아니라 상대의 실제 콘텐츠 근거로 개인화할 출발점이어야 한다.
4. 편집 가능한 가이드와 실제 사용 시점의 고정 버전을 구분한다. `save`로 Format Bank와 Outreach Templates의 구조화된 칼럼과 guide/version을 저장한다. 구체 콘텐츠는 `gtm_contents`, 정확한 메시지 원문은 `gtm_activities`에서 당시 format/template을 참조한다.
5. 기본 조회의 콘텐츠 사용 수·게시 수·발송 수·회신 스레드·응답률은 실제 기록에서 계산한다. 소량 데이터의 응답률이나 상관관계를 자동 품질 판정으로 쓰지 않는다.
6. 기존 게시 콘텐츠와 실제 발송 메시지의 실행 버전은 변경하지 않는다. 새 기준이 미게시 브리프나 미발송 초안에 영향을 주면 대상과 다음 행동을 남긴다.

## 중단·충돌·완료 확인

같은 쓰기를 재시도할 때 request_id와 본문을 유지한다. row_version 충돌은 최신 행을 읽고 실제 변경을 재판단한다. 애매한 외부 결과를 성공으로 기록하지 않는다. 외부 입력을 기다리면 기존 원장의 실제 할 일·담당·기한·재개 조건을 남긴다. 결과에는 사용한 문서 버전, 저장한 원장 ref/ID, 실제 완료 범위와 남은 사항을 포함한다.
