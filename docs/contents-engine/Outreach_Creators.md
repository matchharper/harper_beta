# Outreach_Creators.md

버전: 1.2 · 적용일: 2026-09-17 · 상태: active (범위는 Connections 기준) · 관리: 아래 관리 역할

[AGENTS.md](AGENTS.md)를 먼저 읽는다. 이 문서는 해당 작업의 입력 파악부터 분석·실행·저장·결과 확인까지 소유한다. 외부 발송·게시·송금·플랫폼 API 연결은 문서만으로 생기지 않는다.

## 업무 계약

- **호출 상황:** ‘오늘 연락할 사람과 메시지 만들어’, ‘이 안으로 보내’, ‘지난번 잘된 사람에게 새 협업을 제안해’. 새로운 거래를 시작하는 첫 제안이 범위다.
- **입력·근거:** 현재 집행 목표·조건·남은 예산·팀 대응량, 후보의 활동 지역·플랫폼·규모·최근 활동·관객 근거, 최신 연락/협업·중단 요청, 캠페인·포맷, 기존에 제시한 조건과 실제 과거 결과. 제품 설명은 Business_Context를 읽는다.
- **소유하는 방법:** 기존 목록에서 후보 비교 → 의사결정에 필요한 정보만 갱신 → 오늘 연락할 대상과 이유 선정 → 상대의 실제 콘텐츠를 근거로 메시지 작성 → 제안 조건·후속 대응량 확인 → 저장·제시 → 요청과 권한이 포함하면 발송 및 결과 확인.
- **제안의 구체성:** 각 대상에 어떤 캠페인·포맷 또는 제작 방향을 제안할지, 무엇을 요청할지, 제시 가능한 보수/조건이나 먼저 물어볼 견적 범위가 있어야 한다. 모든 대상에게 이름만 바꾼 문장을 만드는 것으로 완료하지 않는다. 동시에 진행 중인 연락과 겹치지 않는지도 확인한다.
- **집행 미정:** 조사·메시지 초안은 알려진 조건으로 진행하고 모르는 조건을 표시한다. 집행이 여러 개면 최근 집행을 임의로 적용하지 않는다. 비용 약정·제작 착수 전 필요한 집행과 허용 범위를 확인하며, 초안을 만들기 위해 임의 예산이나 무의미한 집행을 생성하지 않는다.
- **저장:** collaborations의 제안 준비 기록과 대상별 메시지 초안/실제 발송 활동. 동일 요청 재실행 시 준비된 초안과 발송 이력을 재사용한다. 선정하지 않은 중요한 대안과 이유는 최종 제안 안에 짧게 남긴다.
- **완료:** 각 대상에 연락 경로·선정 이유·정확한 메시지·제안 범위가 있고, 준비/발송/실패가 구분된다. ‘메시지 만들어’의 완료는 검토 가능한 초안이며 발송으로 해석하지 않는다.
- **예외·경계:** 회신이 이미 왔다면 Manage_Collaborations.md에서 기존 대화를 이어간다. 견적을 모르면 가격 확정 의뢰처럼 쓰지 않는다. 이전 거래의 무응답 follow-up은 Manage_Collaborations.md, 새 거래 제안은 Outreach_Creators.md다. 최신 중단·중복·예산 검사는 실제 발송 직전에 한다.
- **관리:** Outreach 담당이 회신·합의·반송·팀 시간·메시지 품질을 함께 보고 개선한다.

## 현재 도구로 끝까지 수행하기

[Connections.md](Connections.md)의 gtm_api 호출 형식을 사용한다. 칼럼은 [data-model.md](data-model.md), 제품 사실은 [Business_Context.md](Business_Context.md), 계산은 [measurement.md](measurement.md)가 원본이다.

1. 집행 목표·남은 예산·팀 대응량을 읽고 `list gtm_creators`에서 후보를 비교한다. 기본 조회의 활동 지역, 플랫폼 계정, 팔로워, 최근 365일 게시 수, 최근 게시일, 주제/관객 근거, 연락 상태, 마지막 연락, 열린 협업/다음 업무, 최신 Scale/Retry 방향, 자료 최신성을 사용한다. 팔로워 순으로만 고르지 않는다.
2. `do_not_contact`, `outreach_status`, `last_contact_at`, `current_collaboration_*`를 먼저 확인해 중복 제안과 중단 대상은 제외한다. `data_status`가 incomplete/stale이면 이번 선정에 영향을 주는 `refresh_fields`만 Research_Creators.md 절차로 갱신한다. 과거 협업의 실제 비용·콘텐츠·제품 전환과 당시 조건을 읽고 이번 조건과 비교한다.
3. 각 후보에 대해 선정 근거, 반대 근거/불확실성, 제안할 캠페인·포맷 또는 제작 방향, 연락 채널, 제시 조건 또는 먼저 물을 견적, 예상 후속 대응량을 정한다. `list gtm_outreach_templates`에서 캠페인·채널·대상·제안 조건이 맞는 기존 기준을 확인하되 응답률만으로 템플릿을 자동 선택하지 않는다. 자료가 부족한 후보는 오늘 발송 대상과 추가 조사 대상으로 구분한다. 임시 적합성 점수를 크리에이터 속성으로 저장하지 않는다.
4. 한 크리에이터의 한 제안 건을 `gtm_collaborations`에 생성/재사용한다. 선택한 템플릿은 출발점으로만 쓰고 상대의 실제 콘텐츠를 근거로 첫 문장과 제안 방향을 개인화한다. 최초 제안의 정확한 본문·목적지·채널·조건·참조 캠페인/포맷을 `message_draft` 활동에 저장하며 `outreach_template_id`로 사용한 기준을 연결한다. payload에는 recipient, channel, draft_version, document_version을 둔다. 추천 이유는 body에 간단히 남긴다.
5. 현재 전용 발송 연결은 미설정이다. 준비된 초안과 협업 ref를 반환한다. 이후 발송 도구가 연결되고 실제 발송 요청이 있으면 발송 직전 최신 회신·중단·열린 협업·동일 외부 메시지를 다시 확인하고 전송한 뒤 provider ID·시각·원문을 `message_sent` 활동에 남긴다. 불명확한 전송은 기존 결과를 확인한 뒤 같은 논리 요청으로 재시도한다.
6. 실제 기다릴 후속 업무는 협업의 `patch_item action_items`로 기록한다. 초안을 보냈다고 표시하지 않는다. 결과에는 후보별 크리에이터 ref, 계정/규모/최근 활동, 선정 이유, 제안 방향, 정확한 메시지, 조건, 연락 경로, 자료 기준일, 협업 ref, 준비/발송 여부와 다음 업무를 한 번에 보여준다.

## 중단·충돌·완료 확인

같은 쓰기를 재시도할 때 request_id와 본문을 유지한다. row_version 충돌은 최신 행을 읽고 실제 변경을 재판단한다. 애매한 외부 결과를 성공으로 기록하지 않는다. 외부 입력을 기다리면 기존 원장의 실제 할 일·담당·기한·재개 조건을 남긴다. 결과에는 사용한 문서 버전, 저장한 원장 ref/ID, 실제 완료 범위와 남은 사항을 포함한다.
