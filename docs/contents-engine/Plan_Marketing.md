# Plan_Marketing.md

버전: 1.3 · 적용일: 2026-09-18 · 상태: active (범위는 Connections 기준) · 관리: 아래 관리 역할

[AGENTS.md](AGENTS.md)를 먼저 읽는다. 이 문서는 해당 작업의 입력 파악부터 분석·실행·저장·결과 확인까지 소유한다. 외부 발송·게시·송금·플랫폼 API 연결은 문서만으로 생기지 않는다.

## 업무 계약

- **호출 상황:** ‘100만 원으로 학생 마케팅 준비해’, ‘미국에서 1만 명을 확보하려면 어떻게 해야 해’, ‘다음 달은 누구에게 얼마씩 맡길까’. 예산 고정과 목표 고정은 같은 계획 업무다.
- **입력·근거:** 무엇을 몇 명 얻으려는지, 기간·시장·예산·팀 시간·이미 약속한 비용. gtm_plans, 관련 후보·견적·과거 결과, 캠페인·포맷 가이드를 읽는다.
- **소유하는 방법:** 목표 정의 → 근거와 빈칸 확인 → 신규/재협업 후보 및 조합 비교 → 응답·합의·게시·전환 단계별 필요 수량과 비용 산정 → 일정·팀 대응량 검토 → 실행 가능한 선택지 제안. 시장 근거가 약하면 파일럿을 포함한다.
- **저장:** plans의 목표·한도와 계획 문서 버전. 계획 시점의 후보·조건·데이터 기준일·가정·예측 범위를 보존한다. 연락을 실행할 후보가 정해지면 Outreach_Creators.md에 같은 plan ID를 넘긴다.
- **완료:** 누구에게 어떤 캠페인·포맷·조건으로 접근할지, 필요한 연락/게시 수와 비용·기간·예상 결과 범위, 아직 확인할 정보가 결정 가능한 형태다. 목표 달성을 보장하는 숫자를 만들지 않는다.
- **예외·경계:** 후보가 부족하면 Research_Creators.md, 제작 방향이 없으면 Develop_Campaigns_Formats.md의 해당 작업을 필요한 만큼 수행한다. 원래 목표와 예산을 다시 해석하거나 새 집행을 중복 생성하지 않는다. ‘계획만’이면 외부 실행까지 진행하지 않는다.
- **계획 변경:** 이미 진행 중인 약정·지급·게시 예정과 남은 팀 용량을 반영한다. 예산을 줄이거나 타깃을 바꿀 때 기존 의무를 없어진 것으로 계산하지 않는다. 당시 채택 계획은 보존하고 새 버전의 변경 이유·영향 범위를 남긴다.
- **관리:** 집행 책임자가 당시 예측과 실제 결과를 비교해 개선한다. 전환 공식은 measurement.md가 소유한다.

## 현재 도구로 끝까지 수행하기

[Connections.md](Connections.md)의 gtm_api 호출 형식을 사용한다. 칼럼은 [data-model.md](data-model.md), 제품 사실은 [Business_Context.md](Business_Context.md), 계산은 [measurement.md](measurement.md)가 원본이다.

1. 관련 `gtm_plans`와 `performance`, `list gtm_creators`의 활동 지역·플랫폼·규모·최근 활동·연락 상태·자료 최신성, 후보별 비용·과거 채택 리뷰를 읽는다. ‘1만 명’이 방문인지 가입인지 완료인지가 계획 규모를 바꾸면 그 지표부터 확정한다.
2. 기존 근거로 응답→합의→게시→가입→완료의 범위를 계산한다. 충분한 과거 표본이 없으면 근거 없는 확률을 만들지 않고 파일럿 예산·추가 확인을 제시한다. 알려진 약정·순지급·예비비와 팀 시간을 반영한다.
3. 후보별 캠페인/포맷, 연락 수, 게시 수, 단가, 예상 결과 범위, 기간, 가정을 담은 계획 문서를 만들고 고정 버전을 보존한다. `save gtm_plans`의 brief·목표·통화·한도·기간·plan_document_ref·plan_version을 저장한다.
4. 실제 채택이 확인되면 `plan_adopted` 활동에 당시 문서 버전과 채택 근거를 남긴다. 예산 등록은 발송·송금 명령이 아니다. 이미 허용된 연락 준비는 같은 plan ID로 이어간다.
5. `get gtm_plans`에서 committed_cash/available_cash와 미확인 비용을 확인해 실행 가능성과 부족 조건을 보고한다.

## 가격 전략을 포함한 후보별 예상 비용

가격 전략이 정해진 outreach에서는 후보별 최근 측정 콘텐츠 최대 10개의 조회수 중앙값을 예상 조회수로 사용한다. 조회수 이력이 없으면 임의 숫자를 만들지 않고 예상 비용을 미확정으로 둔다. `base_plus_views` 전략의 예상 비용은 `기본 업로드 비용 + (예상 조회수 ÷ 조회수 단위 N × 단위당 금액 M)`이며 통화의 최소 단위로 반올림한다. `fixed` 전략은 조회수와 무관하게 고정 금액을 쓴다.

팀원이 다른 가격안을 지정하지 않으면 Pricing Strategies의 **현재 권장 실험안**을 제안의 출발점으로 삼는다. 추천 이유와 근거 한계를 계획에 함께 적고, 이미 사용한 조건을 수정하지 않는다. 새 결과가 기존 추천을 바꿀 만하면 새 버전을 비교해 권장안을 교체한다.

팀원에게 후보 순위를 보고할 때는 목표 사용자 적합성·콘텐츠 결·최근 활동·평소 반응·과거 협업 결과와 함께 예상 조회수·예상 비용·근거 표본을 나란히 보여준다. 예상 비용은 선택 판단의 한 요소이며, 비용이 낮다는 이유로 적합성과 품질 근거가 약한 후보를 위로 올리지 않는다. 채택한 전략과 예상값은 Outreach Review에 표시하고 실제 제안에 사용한 조건은 해당 버전의 스냅샷으로 고정한다.

## 중단·충돌·완료 확인

같은 쓰기를 재시도할 때 request_id와 본문을 유지한다. row_version 충돌은 최신 행을 읽고 실제 변경을 재판단한다. 애매한 외부 결과를 성공으로 기록하지 않는다. 외부 입력을 기다리면 기존 원장의 실제 할 일·담당·기한·재개 조건을 남긴다. 결과에는 사용한 문서 버전, 저장한 원장 ref/ID, 실제 완료 범위와 남은 사항을 포함한다.
