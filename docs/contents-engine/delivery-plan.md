# 구현 순서와 구조 확인

상태: 검토안, 미구현. [AGENTS.md](AGENTS.md)를 먼저 읽는다. 현재 승인된 작업은 설계 문서 수정이며 실제 DB·연동·배포는 수행하지 않았다.

## 1차 — 필요한 업무가 연결되어 실행되는 구조

1. 세 업무 화면(크리에이터·협업·콘텐츠)의 한 행과 기본 칼럼부터 확정한다. 캠페인·포맷은 기준 관리, 집행 계획은 목표·예산을 묶는다.
2. 여섯 원장과 네 보조 기록을 구현한다. 기존 계정·메시지·비용·작업·권한·변경 이력 기반을 먼저 확인하고 충족하는 부분을 재사용한다. 아래 실행 기반의 저장 위치·소유자·검증 방법을 확정한 뒤 해당 기능을 연결한다. 새 문서·원장을 무조건 추가하지 않는다.
3. Agent의 진입점을 AGENTS.md로 연결하고 [작업 문서 기획](Document_Plan.md)에 따라 Research_Creators, Outreach_Creators 등 독립 업무별 문서를 작성한다. 각 문서는 그 업무의 분석·실행·저장·확인을 끝까지 책임진다. 기본 조회 한 번으로 관련 요약·근거 위치를 함께 가져오게 하고, 화면 수정과 같은 변경 함수를 사용한다.
4. 후보 조사·갱신 → 메시지 준비·발송/회신 → 조건 합의 → 콘텐츠·UTM → 게시·성과 → 비용·회고를 순서대로 연결한다. 각 연결의 실제 자동화 가능 범위를 검증한다.
5. 당시 조건·문서 버전·메시지·비용·결과·채택 리뷰·다음 콘텐츠 연결을 남긴다. 이후 복원할 수 없는 기록이므로 2차로 미루지 않는다.
6. Sheets 편집과 Metabase 분석은 공통 조회 위에 필요한 만큼 붙인다. 팀원에게 모든 내부 원장을 노출하지 않는다.

1차 완료 기준은 같은 작업을 위해 여러 장부를 다시 입력하지 않는 것, Agent가 기록의 위치를 추측하지 않는 것, 실제 결과로 다음 협업을 제안할 수 있는 것이다. 모든 플랫폼의 API 접근이나 완전 자동 송금을 보장하는 의미는 아니다.

## 기능을 사용 가능으로 표시하기 전

업무 데이터의 논리 테이블은 10개다. 권한·중복 방지·재시도·변경 이력의 실제 저장은 기존 코드/DB를 조사한 뒤 재사용 위치와 부족한 항목을 정한다. 이 확인 없이 ‘테이블 10개만 만들면 운영 가능’이라고 보고하지 않는다. 확인 결과는 Connections.md와 data-model.md에 반영하며 별도 관리 메뉴를 늘리지 않는다.

| 확인할 것 | 사용 가능한 범위의 기준 |
| --- | --- |
| 데이터·문서 연결 | 실제 테이블/함수·문서 버전·읽기/쓰기 권한이 연결되고 기본 조회에서 근거를 찾을 수 있음 |
| 조사·성과 수집 | 해당 계정/지표의 접근 범위·비용·보존 조건을 확인하고 실제 수집·결측·재수집을 검증함 |
| 외부 발송·게시·지급 | 요청자의 실행 권한, 확정된 내용/금액, 대상, 중복 방지, 불명확한 응답 조회를 실제 도구에서 검증함 |
| 공통 변경 | 동시 수정·공유 브리프 변경·외부 메시지/지급 중복·예산 점유를 서버/DB가 보호함. 문서 지시만으로 보장하지 않음 |
| 지속 운영 | 회신/자료 대기 후 재개, 부분 성공, 인증 만료, 누락 수집의 담당·기한·복구 경로가 확인됨 |

작업 문서별로 ‘조회/준비 가능’과 ‘외부 실행 가능’을 구분해 AGENTS.md에 표시한다. 사용 가능한 조사·초안 기능부터 열고 검증 전인 실행 기능만 제한한다. 연결이 없는 플랫폼은 팀원의 발송/자료 제출 결과를 같은 원장에 기록하는 경로를 제공한다. 이를 완전 자동화라고 보고하지 않으며, 1차 종료 시 자동·팀원 처리·미지원 범위를 연결별로 명시한다.

## 2차 — 같은 자원에서 더 좋은 결과

반복 데이터로 목표별 후보·포맷·가격을 비교하고 예측 범위를 검증한다. 재협업·새 후보·새 포맷에 자원을 나누며 현금과 팀 시간을 함께 본다. Design_Experiments와 Improve_Engine을 추가해 비교 실험과 작업 방법 개선을 담당하게 하고, 기존 Plan_Marketing/Review_Performance를 고도화한다. 기본 회고·재시도 기록과 지침 정정은 1차부터 유지한다. 추가 데이터 구조는 실제 실행·조회 수요가 확인될 때만 만들며 기본 탐색 경로는 유지한다.

## 설명 가능한지 확인하는 사례

아래는 설계의 수동 점검 예시이며 실행된 테스트나 LLM 평가가 아니다. 새로운 상황별 도구·상태를 만들기 위한 목록으로 사용하지 않는다.

| 상황 | 기대하는 저장·조회 |
| --- | --- |
| 한 사람, 두 플랫폼, 한 번의 합의 | 크리에이터 1, 협업 1, 콘텐츠 2. 협업 비용은 한 번. 같은 영상은 묶어서 표시 |
| 한 계약에서 서로 다른 두 포맷 | 같은 협업의 콘텐츠별 포맷·브리프·성과를 비교 |
| 다음 달 단가/CTA를 바꿔 다시 맡김 | 새 협업·콘텐츠에서 이전 거래·콘텐츠·채택 리뷰 연결. 과거 조건 유지 |
| 외부 제작 영상을 Harper 계정에 재사용 | 콘텐츠에서 실제 게시 계정과 원본 소재·사용권 연결. 원 제작비 중복 없음 |
| 연락했지만 무응답/거절 | 협업과 대화·조사 비용은 남고 가짜 콘텐츠는 생성하지 않음 |
| 집행을 정하기 전에 협업 문의가 들어옴 | 최소 확인된 크리에이터·협업·대화로 시작. 운영 목록에 포함하고 약정 전 집행 연결 |
| 같은 매니저 주소가 여러 크리에이터에 있음 | 사람을 합치지 않고 목적지 중복·중단은 발송 기반에서 확인 |
| 링크 위치가 둘이거나 새 링크가 필요 | 같은 콘텐츠의 고정 ID를 가진 링크 항목들. 기존 귀속 유지 |
| 여러 콘텐츠가 프로필 링크 하나를 공유 | account/plan 귀속으로 한 번만 집계. 임의 콘텐츠에 몰거나 각 콘텐츠에 복제하지 않음 |
| 팀원이 메모만 수정 | 관객 자료 기준일은 그대로. 행 수정일을 관객 갱신일로 쓰지 않음 |
| D7 데이터가 없고 D12 값만 있음 | 누락과 실제 관측일 표시. 0/저성과/7일 값으로 만들지 않음 |
| 선금·잔금 또는 공통 도구비 | 비용 한 건의 지급/배분 내역으로 대사. 총액 중복 없음 |
| 환불이 들어왔지만 지급 의무가 남음 | 환불과 약정 감액을 구분. 근거 없이 남은 예산이 늘어나지 않음 |
| 집행 예산을 기존 약정보다 줄임 | 과거 약정 보존, 부족액 표시, 새 약정은 남은 허용 범위에서만 가능 |
| CTA 변경을 Retry로 채택 | 해당 콘텐츠에서 근거·방향·다음 행동 확인, 후속 콘텐츠로 연결 |
| 통계 제출과 지급 확인이 동시에 남음 | 같은 협업의 업무 두 항목과 각각 담당·기한. 하나를 끝내도 나머지는 유지 |
| 두 플랫폼의 공통 브리프를 수정 | 선택한 미게시 콘텐츠의 참조를 함께 갱신. 게시된 버전·이전 검수 사실 보존 |
| 같은 게시물을 나중에 유료 증폭 | 기존 콘텐츠에 배포 변경·비용 연결. 자연/유료 분리가 불가능하면 혼합 성과 표시 |
| 다른 Agent가 지난 조사에 이어 후보 추가 | 결과 ref로 기준·검색 진행 위치·후보·미확인 자료를 읽고 중복 조사 없이 이어감 |
| 수동 기록한 메시지를 자동 동기화가 다시 수집 | 연결+provider 메시지 ID로 실제 메시지 하나만 유지. 실제 발송과 초안도 구분 |

구현 검증은 ID·동시 변경·중복 발송·예산·귀속·당시 조건 보존을 중심으로 한다. LLM 평가를 실제로 만들거나 실행할 때는 상위 AGENTS.md의 평가 등록 규칙을 따른다. 지금 평가 데이터나 별도 평가 도구를 만들지 않는다.

## 이번에 제거한 복잡성

별도 시도 메뉴, 소재/게시/링크별 입력 화면, 중복 작성하는 다음 업무 원장, 모든 문서를 위한 artifacts 업무 메뉴를 제거했다. 작업 문서는 독립 업무별로 기획하며 국가·가격·기간 같은 조건마다 복제하지 않는다. 대화·시계열·비용 등 반복되는 실제 사실의 내부 저장은 유지한다. 내부 기록을 숨기기만 하는 대신 기본 조회 결과에 필요한 관계를 함께 제공한다.

## 2026-09-16 전체 문서 점검에서 보완한 점

7개 설계 문서 전체의 역할·저장 위치·완료 기준을 대조했다. 업무 테이블 10개, 작업 문서 계획 15개는 유지했다.

| 발견한 빈틈 | 반영한 개선 |
| --- | --- |
| 단일 ‘다음 행동’이 동시에 남은 일을 덮어씀 | 기존 원장 안에 작은 업무 목록, 목록의 대표 행동과 전체 할 일 보기를 구분 |
| 집행 미정 문의·독립 조사의 저장/인계 위치가 불명확 | 미분류 협업 허용, 조사 결과 ref와 검색 진행 위치 보존 |
| ‘최신 정보’의 의미와 갱신 실패 처리가 불명확 | 자료별 기준 시각·수집 시각·갱신 주기, 실패 후 기존 기준일 유지, Sheets 반영 상태 표시 |
| 묶음 콘텐츠의 브리프 수정·검수 범위가 불명확 | 공통 고정 참조·선택 행 동시 변경·실제 검수 버전 연결 |
| 공유 링크·코호트·혼합 배포가 성과를 왜곡할 수 있음 | 귀속 범위·분모·성숙 기간 명시, 같은 게시물 중복 방지 |
| 환불·예산 변경·공통 비용 누락이 가용액/CPA를 왜곡할 수 있음 | 실제 지급과 의무를 구분하고 미배분·결측·예산 부족 표시 |
| 문서를 넘나들 때 책임/완료가 흐려짐 | 원래 작업의 책임 유지, 부분 결과와 외부 대기 후 재개 명시 |
| 기획된 자동화를 실제 가능 기능으로 오해할 수 있음 | 기능별 연결 검증·사용 범위 표시, 실행 기반 확인을 활성화 조건에 포함 |

이 점검은 설계와 문서 연결의 검토다. 작업 문서 본문 작성, DB/API 구현, 실제 플랫폼 연결, 구현 테스트는 이후 작업이며 수행됐다고 간주하지 않는다.
