## 실행 기준

회사의 `contact_talent(action=send_to_agent)`는 기존 관계에서 후보자 에이전트에게 목적·사실·질문·요청·답장을 보내는 범용 도구다. 기존 즉시 enqueue 경로를 유지한다. 기본 company capability에서도 정확한 관계를 읽는 `read_agent_messages`와 이 연락 계약을 함께 제공한다. 후보자 메시지와 승인, 온보딩, 진행 중 작업의 재개도 일일 처리로 옮기지 않는다. 연락과 후보자 동의·프로세스 재개·Role 이동은 별개의 효과다. 기존 관계·공유 권한과 legacy 연락 계약은 유지한다.

일일 처리함에 들어가는 원본은 다음 다섯 가지다.

1. 후보자가 이미 수락한 internal 관계에서 회사가 프로세스를 종료했다. `notifyCandidateOnClosure=false`이면 추가하지 않는다.
2. 후보자가 이미 수락한 internal Role이 종료·삭제됐다. 최종 오퍼, 이미 종료된 프로세스, 테스트 Role은 제외한다. 단순히 추천만 받았던 모든 사람에게 연락하지 않는다.
3. company-side가 확정한 `candidate_first`/`both` 제안이다. 정확한 Role을 전달하며 Career가 일반 내부 공고 탐색을 시작하지 않는다. 현재 자격·차단·Role 상태를 다시 확인한다. 기존 전달 작업에 이미 배정된 선정은 중복 접수하지 않는다.
4. 실제 저장된 회사 후속 연락 날짜가 도래했다. 기존 일반 Career 예약도 같은 실행에 합친다. 단순 무응답 자체로 새 주기나 후속 날짜를 만들지는 않는다.
5. 후보자에게 오늘 남은 실제 미팅·면접 일정이 있다. 현재 시각 이후의 확정 일정과 시각 미정인 당일 일정이 대상이다. agent 실행 예약과 구분한다.

원본 사건이 없고 별도 예약도 없는 후보자는 실행하지 않는다. 동의한 외부 기회 탐색은 별도 기존 주기를 유지하며, stopped 또는 외부 추천 off에서는 자동 실행하지 않는다. 기본은 active 3일/passive 6일이고 이미 저장된 사용자 지정 주기를 초기화하지 않는다. 외부 탐색 설정에 의한 일시 중지와 명시적인 예약 중지를 구분해 후자를 자동 재개하지 않는다.

## 입력·완료·비용

`career_daily_sources`는 원본 사건 revision, 처리 가능 시각, 실행 소유권과 완료 영수증을 기록한다. 모델의 임시 계획이나 의미 판단을 별도 상태로 저장하지 않는다. UI의 `career_action_items`와는 다른 서버 내부 처리함이다.

Career에는 정확한 사건·Role/추천 참조, 현재 실제 일정, 예약 지침, 최근 발송 이력을 제공한다. 회사의 사적인 거절 사유를 후보자 안내 원문으로 취급하지 않는다. 대상 사건을 함께 판단하고 필요하면 메일 하나로 전달한다. 검토 결과 연락이 불필요하면 발송하지 않는다. 꼭 필요한 안내를 뒤로 미루면 구체적인 다음 예약을 남기도록 안내한다. 검토 완료와 실제 발송 완료는 별도로 기록한다.

메일 또는 별도 chat 연락의 `sourceIds`는 그 메시지에 실제 포함한 사건을 나타낸다. 다른 실행의 ID는 받지 않으며, 일일 사건이 있는 실행에서 누락하면 발송 전에 실행 계약 오류를 돌려준다. 실제 발송 영수증 이후에만 해당 종료 안내·회사 팔로업의 전달 기록을 남긴다. 포함하지 않은 팔로업까지 발송 완료로 바꾸지 않는다. 이메일은 Career 이력에도 저장되므로 같은 내용을 별도 chat으로 복제할 필요가 없음을 도구 계약에 명시했다.

정기/일일 실행 전에 모든 팔로우 회사의 공고를 자동 평가하는 준비 작업을 제거했다. 원본 Career agent가 현재 목적에 필요한 근거만 조회·평가하도록 한다. Worker의 일반 cache 준비와 원본 agent의 tool loop 때문에 **논리적 실행 한 번이 provider API 요청 한 번이라는 뜻은 아니다.** 기존 Worker 슬롯/동시성 설정은 변경하지 않았다.

## 추가 점검에서 고친 문제

- 종료 후 재개·재종료가 일어나면 이전 종료 안내 이력 때문에 새 사건이 막힐 수 있었다. 사건 revision을 기준으로 이전 대기를 취소하고, 발송 도중 재개됐으면 실제 영수증만 남기며 다시 종료시키지 않는다.
- 사건 소유권을 새 실행으로 넘긴 뒤 이전 실행이 계속 처리할 수 있었다. 발송 전 현재 run 소유권도 확인한다. 반대로 자기 실행이 방금 완료한 전달은 외부 취소로 오인하지 않아 불필요한 재실행을 막는다.
- talent-first의 `not_before`와 선정 수정, 공개 회사명 차단을 현재 판정에 반영했다. 동일 내용 갱신은 새 사건을 만들지 않는다.
- Worker가 취소된 회사 팔로업의 본문과 함께 사건 참조까지 지워 빈 모델 실행으로 이어질 수 있었다. 사건 참조를 보존해 원본 Career 호출 전에 현재 상태를 판정하도록 수정했다. 일반 cache 준비 전체를 제거한 것은 아니다.
- 사건 재조정으로 이어진 일일/예약 실행이 일반 대화 모델로 바뀔 수 있었다. 즉시 회사 연락이 아닌 예약 재조정은 기존 scheduled 모델을 유지한다.
- 과거 agent가 일반 프로필 답장을 자동 예약의 지침으로 복사한 경우를 확인했다. 사용자 메시지 참조만으로 자동 예약 제한의 예외가 되지 않게 이관 조건을 바로잡았다.
- 설정 때문에 중지된 예약을 명시적으로 다시 중지해도 설정 중지 표식이 남아 자동 재개될 수 있었다. 기존 RPC 입력으로 실제 실패를 재현한 후 예약 쓰기 함수 원본에서 표식을 제거하도록 수정했다. 새 웹의 보정 코드는 제거했다. 운영 함수 본문과 권한도 최종 정본에 일치한다.

DB 선반영 당시에는 source fence·Worker hydration·모델 선택의 코드 수정이 미배포였다. 위의 후속 웹·Worker 배포로 새 수집 경로까지 운영에 반영됐다. 당시 Notion 문서는 DB 선반영과 미배포 기능을 구분했고, 후속 배포 완료 후 현재 동작으로 다시 갱신했다.
