# Career UX writing 1부 적용 — 2026-11-04

기준 문서는 `harper-talent-dev-handoff.html`의 1부다. 배포 화면을 기준으로 작성된 제안이므로 현재 로컬 구현과 사용자 제외 지시를 우선했다. 제품 코드 배포·push는 하지 않았다. 번역은 기존 번역 계약에 따라 이번에 바꾼 94개 키의 한국어·영어 188행만 DB에 동기화했다. `View CV`는 이미 있는 `이력서 보기 / View resume` 키를 재사용했다.

## 반영

- 기회 목록·카드·상세·액션·직접 추가 화면의 용어를 `Harper 연결`, `직접 지원`, `기회`, `이번엔 넘길게요`, `연결 요청`으로 정리했다. 회사가 먼저 요청한 `intro_request`에만 `먼저 온 관심`을 사용한다.
- `Harper가 본 점`, `하는 일`, `원문 보기`, `이 회사의 다른 기회`, `회사 한눈에 보기`, `모의 면접 해보기`를 반영했다. 외부 채용 페이지 버튼에는 외부 이동 아이콘을 표시한다.
- `원하는 조건`, `이력서·링크`, `링크`, `문서`, `대표 이력서 바꾸기`, `다른 문서 추가`, `회사에 보이는 프로필`, `초대 보상` 등 실제 남아 있는 화면의 문구를 정리했다.
- 공유 방식과 일하는 방식의 하드코딩된 영어 옵션을 번역 경로로 옮겼다. 공유 옵션은 `Harper가 먼저 공유해요`, `내가 먼저 확인해요`, `잠시 멈춤`이다. 선택값·권한·저장 로직은 유지했다.
- 홈의 기회 수 과시 문장과 공유 옵션의 68% 홍보 문장을 제거했다. 인사는 첫 방문에도 맞는 `반가워요 / Welcome`으로 옮겼다.
- 일반 Career 텍스트 대화는 실제 번역 사전에서 현재 메뉴·상태·기회 유형 이름을 읽는다. 기존 `Profile > Resume/Links`, `Jobs tab` 안내를 수정했다. 전문적/친근한 대화 버전의 말투는 유지했다.
- 설정 context의 `exceptional_only` 설명은 실제 회사 측 publication의 `open_to_matches` 조건과 맞게, 먼저 소개 동의를 받는 설정으로 바로잡았다. 새로운 상태·검열·문구 치환·재시도 로직은 추가하지 않았다.

## 후속 적용: 조건·공유·자료 화면 정리

사용자가 승인한 추가 제안 네 가지와 후속 이름·브라우저 카드 요청을 로컬에 반영했다.

- 기존 근무 형태(full_time/fractional/advisor) 선택을 설정에서 원하는 조건으로 옮겼다. 제외할 회사도 원하는 조건에서만 편집하며, 두 설정의 저장 hook·원본 데이터는 그대로 사용한다. Brief 행에 복사하지 않는다.
- 설정의 프로필 설정을 공유 설정으로 바꾸고 공유 방식 편집만 남겼다. 홈·프로필에는 `CareerProfileSharingSummary`로 현재 상태와 해당 설정 바로가기를 표시한다. 모바일에서도 해당 설정 탭을 바로 연다.
- Gmail은 링크 목록에서 분리해 연결된 서비스에 표시한다. 기존 연결·해제·이메일·일정 기능은 유지했다.
- 이력서·링크 메뉴를 자료 / Resources로 바꿨다. 기존 `/career/documents` 주소와 문서 상세 동작은 유지했다.
- 채팅의 브라우저 열기는 문서 카드의 `PreviewUI`를 직접 재사용한다. 같은 모니터 아이콘·제목·보조 문구 구성으로 표시하며, 기존 브라우저 선택·종료 상태·도킹 동작을 유지한다. 공용 카드에 native disabled 전달만 추가했다.
- 실제 기본 prompt builder의 한·영 화면 정보도 새 메뉴와 설정 위치에 맞췄다. 기존 말투·상태·실행 계약은 유지한다.
- 번역은 후속 변경 4개 키의 한국어·영어 8행만 DB에 동기화하고 저장값을 다시 확인했다. 기회 목록 재분류 등 다른 제안은 적용하지 않았다. 배포·push하지 않았다.

프리뷰의 가짜 데이터로 근무 형태 선택·제외할 회사 추가, 공유 설정 이동, 자료의 링크·문서·연결된 서비스 구분을 확인했다. 브라우저 카드는 실제 공용 컴포넌트를 로컬 검증 화면에 렌더링해 문서 카드와 비교하고 뷰어 열기를 확인했다. 이 검증 화면은 확인 후 제거했으며 원격 브라우저 실행·사용자 설정 변경은 하지 않았다. 스크린샷과 실제 prompt builder 출력은 ignored `output/playwright/` 및 `output/career-ux-settings-prompt.txt`에 있다.

후속 검증: TypeScript 검사, 전체 Career 번역 검사(1,737개 키), 변경 파일 ESLint 오류 검사, 프롬프트/cache 8개 및 브라우저·Gmail 2개 기존 테스트가 통과했다. 프리뷰의 기존 동기 setState effect 경고 1건은 유지했다. 실제 Gmail OAuth나 운영 데이터 저장 E2E는 수행하지 않았다.


## 후속 적용: 기회·내 정보 메뉴 통합

후속 사용자 요청에 따라 앞서 보류했던 메뉴 구조 중 아래 항목을 적용했다.

- 사이드 메뉴의 새 기회·내 기회를 기회 / Opportunities로 합쳤다. 내부 `CareerOpportunityTabs`의 맨 왼쪽은 새 기회이며 진행중, 저장함이 이어진다. 종료/보관 및 별도 숨긴 포지션은 유지했다.
- 새 기회·진행중 숫자는 공용 `Badge variant="count" size="xs" radius="full"`을 사용한다. 기존 집계 값에 `bg-action`·흰색 글자를 적용하며, 빈 화면과 로딩 중에도 탭을 유지한다.
- 프로필 사이드 메뉴를 내 정보 / My info로 바꾸고 `TabBoxes variant="neutral"`로 프로필, 내 자료, 원하는 조건을 묶었다. 세 화면의 기존 주소와 문서 상세 진입은 유지했다.
- 데스크톱·모바일 모두 같은 메뉴 구조를 사용한다. 프롬프트의 현재 화면 정보와 한·영 번역도 갱신했다. 변경한 3개 키의 한국어·영어 6행만 번역 DB에 동기화하고 읽어서 대조했다.
- 개발 프리뷰의 현재 방식은 실제 기회 화면을 렌더링하도록 연결했다. 합성 데이터로 데스크톱·모바일 메뉴, 탭 전환, 숫자 배지, 한·영 화면을 확인했다. 운영 사용자 데이터 변경·지원·소개·배포는 수행하지 않았다.

검증: TypeScript 검사, 변경 파일 ESLint(오류 없음), Career 번역 검사 1,745개 키, 기회 목록·로딩 관련 기존 테스트 5개와 프롬프트/cache 기존 테스트 8개를 통과했다. 기존 `CareerHistoryPanel` effect 경고는 유지했다. UI 스크린샷은 ignored `output/playwright/career-navigation-*.png`, 실제 한·영 prompt builder 출력은 `output/career-navigation-prompt.txt`에 있다. 공유 개발 서버에서 프리뷰 최초 요청은 기존 Turbopack lucide 모듈 캐시 오류로 500을 반환했으며, 클라이언트 복구 후 실제 화면에서 상호작용을 검증했다.


## 후속 적용: 설정의 기회 수신·공유·언어 묶기

- 공유 설정 탭을 기회 설정으로 바꾸고 새 기회 받기, 직접 지원 기회도 받기, 프로필 공유 방식을 한 화면으로 모았다. 계정에서 수신 스위치를 제거했으며 기존 API, 저장값과 중지 확인 계약은 유지했다.
- 전체 수신 스위치는 Harper 연결 또는 직접 지원 추천 중 하나라도 켜져 있으면 켜짐으로 표시한다. 프로필 공유만 멈추고 직접 지원 추천은 받는 기존 조합을 잘못 꺼짐으로 표시하지 않는다. 끄기는 기존처럼 두 수신 경로를 함께 멈춘다. 공유 설정과 스위치는 같은 context를 읽어 서로의 변경이 보인다.
- 계정 탭에는 이름, 이메일, 언어 설정, 로그아웃, 회원 탈퇴를 둔다. 언어는 공통 Select와 기존 locale provider·settings API·실패 시 복구 동작을 재사용했다. 프로필 드롭다운의 언어 메뉴와 별도 모달은 제거했다.
- 설정 순서는 기회 설정, 계정, 초대하기(기존 노출 대상)다. 현재 settingsTab=profile 링크와 홈·프로필의 바로가기 주소는 유지한다. 프롬프트의 메뉴 안내도 수정했다.
- 한·영 변경 12개 키 24행만 번역 DB에 동기화하고 다시 읽어 일치 여부를 확인했다. 운영 수신 설정·언어 변경, 배포·push는 수행하지 않았다.
