# 요청할 때 생성·수정하는 Harper 이력서

## 제품 계약

웹 채팅의 `generate_resume`가 명시적인 생성·수정 요청을 실행한다. 대화하는 AI가
Profile·경력 메모·관련 Memory·기존 문서에서 사실을 찾아 내용을 작성하고, 도구는
인증·검증·PDF 생성·저장을 담당한다. 검토나 생성 제안만으로 파일을 만들지 않는다.
지원처가 없는 기본 이력서와 업로드 파일 없이 저장된 정보로 시작하는 흐름도 지원한다.

Profile·Memory는 평소의 사실 원본이고, 이력서 JSON은 요청 시 만든 문서별 편집 원본이다.
표현 변경을 Profile·Memory에 자동 반영하지 않는다. 없는 성과·기간·영문 이름을 만들거나
사적인 고민·추론된 선호를 이력서 사실로 쓰지 않는다. 중요한 충돌과 불완전한 추출만 확인한다.

## 도구 계약

- `action=create`: `document_name` 필수. `document_id`, `expected_revision`은 받지 않는다.
- `action=update`: `document_id`, `expected_revision` 필수. 이름은 변경 요청 때만 전달한다.
- `content`: 언어·기본 정보·경력·학력·프로젝트·대외활동·기술·추가 섹션의 전체 내용.
- `target_role`, `source_document_ids`, `source_refs`: 선택적 지원 역할 및 최소 원본 참조.
- 사용자 ID·파일 경로·공개 여부·폰트·레이아웃은 모델 입력으로 받지 않는다.
- 편집 전에 `read_document(format=structured)`로 현재 JSON과 revision을 읽는다.
- 기존 항목 ID는 유지하고 새 항목은 ID를 생략한다. 서버가 ID·스키마·템플릿 버전을 부여한다.
- Memory 출처는 도구가 반환한 사용자별 `ref`, Profile 출처는 `experience:id`,
  `education:id`, `extra:id`, `user:id`를 사용한다. 출처 원문을 PDF에 출력하지 않는다.

이름은 `{이름}_{이력서 또는 Resume}_{직무·회사 등 특징}`을 기본으로 한다.
사용자가 지정한 이름을 우선하며 별도 이름 확인을 요구하지 않는다. 서버가 파일명 문자를
정리하고 `.pdf`를 한 번만 붙인다. 이름 중복은 허용하며 식별자는 문서 UUID다.
예: `이덕행_이력서_PM.pdf`, `Deokhaeng_Lee_Resume_Openrouter.pdf`.

## PDF와 저장

고정 HTML/CSS를 Next.js Node 서버의 Chromium으로 PDF 출력한다. A4 세로·1열,
본문 10.5pt, 여백 16mm, Noto Sans KR 400/700을 사용한다. 폰트는 의존성에 고정해
서버에서 내장하며 외부 요청을 차단한다. 한 페이지를 우선해 간결하게 작성하되 필요한
내용이 많으면 자동으로 여러 페이지로 나눈다. 글자 축소나 사실 자동 삭제를 하지 않는다.
폰트 로드와 PDF 텍스트 추출을 검증하고 렌더링은 30초로 제한한다.

`talent_documents`의 `structured_content`에 JSON, `extracted_text`에 같은 JSON의
일반 텍스트, 기존 파일 필드에 PDF를 저장한다. `revision`으로 동시 수정을 검사한다.
생성 문서는 `kind=resume`, `origin_type=harper_generated_resume`이며 비공개·비대표다.

1. 서버 인증 및 참고·수정 대상의 소유권을 검사한다.
2. 생성은 사용자·요청 식별자·역할·언어에서 문서 UUID를 일정하게 계산한다.
   이미 존재하는 문서면 해당 결과를 반환한다. 같은 이름의 다른 요청은 다른 ID를 갖는다.
3. JSON에서 PDF와 일반 본문을 생성·검증하고 매 시도마다 새로운 파일 경로에 업로드한다.
4. 생성은 기존 문서 PK로 중복 INSERT를 막는다. 수정은 소유권·revision·삭제 여부를
   WHERE 조건으로 검사하여 JSON·본문·파일 정보를 한 UPDATE로 저장한다.
5. 기존 origin_id에는 마지막 저장 요청 식별자를 기록해 수정 응답 유실 재시도를 처리한다.
6. 저장에 성공하면 이전 파일을 제거한다. 저장 거절이 확정되면 이번 업로드를 제거한다.
   DB 응답이 불확실할 때는 파일을 함부로 지우지 않고 같은 요청의 재시도로 저장 결과를 확인한다.

별도 작업·정리 테이블, 실행권·만료 관리, 정리 cron은 사용하지 않는다. 작업 추적용
새 컬럼도 추가하지 않는다. structured_content와 revision은 편집 원본과 동시 수정
검사를 위해 유지한다. 진행 중 중복 요청이 PDF를 각각 렌더링할 수 있지만 문서는
한 개만 저장된다. 프로세스 강제 종료·응답 유실·파일 삭제 실패로 미참조 파일이 남을 수
있으며 이 버전은 자동 정리 완료를 보장하지 않는다. 이미 삭제한 문서는 재시도로 복구하지 않는다.

업로드 원본에서 처음 생성할 때는 새 문서를 만든다. 일반 수정은 같은 행·링크를 유지하며,
다른 용도의 별도 문서를 요청한 경우에만 새 문서를 추가한다. 별도 버전 테이블·편집기·
생성 이력서 Markdown 다운로드는 제공하지 않는다.

## 비공개와 기존 호환

생성 이력서는 자동 대표 선택·수동 대표/공개 변경·회사 조회/전달에서 제외한다.
사용자는 문서 상세의 PDF 미리보기와 다운로드를 이용해 직접 제출한다. 서명 URL은
문서 열기 시 인증·소유권 확인 후 발급하고 만료 전에 갱신한다.

기존 Storage 및 talent_documents 접근 정책은 사용자 요청에 따라 변경하지 않는다.
별도 내부 작업 테이블은 두지 않는다. 기존 Storage의 광범위한
접근 허용 정책은 여전히 미해결이며, 이번 기능의 앱 권한 검사와 별도로 다뤄야 한다.

## 검증과 운영

- `src/lib/resumes/resume.test.ts`: 생성/수정 스키마, 이름, ID, HTML 및 링크 안전성,
  실제 Chromium 한국어·장문 PDF 검사 (`RESUME_PDF_TEST=1`).
- `src/lib/resumes/storage.test.ts`: PGlite PostgreSQL에서 마이그레이션 및 중복 요청,
  응답 유실 재시도, 같은 이름의 별도 문서, 동시 수정, 삭제, 실패 보존 검사.
- 기존 문서·도구 노출·스트리밍 도구 연결 테스트를 함께 실행한다.
- `scripts/testGeneratedResumeLive.ts`: `HARPER_RESUME_LIVE_TEST=1`에서만 실행하는 독립
  테스트 계정. `--seed`, 기본 생성, `--update --stream`, `--review`,
  `--security-tests`, `--cleanup` 순서로 확인한다.
  테스트 계정은 추천·회사 공유를 끄고, 이메일을 발송하지 않는다.
- 로컬 macOS 테스트는 `RESUME_CHROMIUM_EXECUTABLE_PATH`로 headless Chromium을 지정할 수 있다.
- 실제 배포에서는 번들 포함·Chromium 실행·폰트·메모리·시간 제한을 검증해야 한다.
  개발 환경에서의 성공을 배포 환경 검증 완료로 취급하지 않는다.
- 생성 성공/실패·소요 시간·페이지 수·열기/다운로드·추가 수정은 구조화 로그로 기록한다.
  생성 도구 입력·본문·파일명·출처 원문은 분석 로그에 기록하지 않는다.

## 구현 검증 기록 — 2026-09-28

- 실제 Supabase에 추가 마이그레이션을 적용했다. 기존 문서 RLS와 Storage 정책은
  변경하지 않았다. 이후 단순화 마이그레이션으로 작업·정리 테이블과 관련 함수 4개를 제거했다.
- 격리된 가상 계정에서 로그인 → 과거 Memory를 반영한 생성 → 같은 ID/이름으로
  수정 → 문서 상세 PDF 표시 → 다운로드를 확인했다. 웹 스트리밍 수정도 확인했다.
- 검토만 요청한 턴에서는 문서 수와 revision이 바뀌지 않았다. 공개·대표 지정은
  400, 다른 계정의 조회·수정은 404, 미인증 조회는 401로 거부됐다.
- 관련 자동 테스트 38개 통과. 한국어 1페이지, 영어·긴 URL 1페이지,
  한영 혼합 장문 6페이지를 실제 렌더링하고 PDF 본문 추출과 시각 검사를 진행했다.
- 프로덕션 빌드 성공. 빌드 추적 결과에서 Chromium, Noto Sans KR, PDF worker와
  canvas 네이티브 모듈 포함을 확인했다. 변경 코드 ESLint와 번역 검증도 통과했다.
- 단독 `tsc --noEmit`에는 이번 변경과 무관한 기존
  `src/lib/growthTalentGtmReport.test.ts:283`의 table.rows 타입 오류 5건이 남아 있다.
- 앱 배포는 하지 않았다. 실제 Vercel Linux 환경의 Chromium 실행·메모리·시간 제한과
  PDF 파일 정리 실패에 대한 운영 확인은 배포 시 추가 확인해야 한다.
- 기존 Storage의 광범위한 접근 정책은 이 변경으로 해결되지 않는다.

## 2026-09-28 단순화

사용자 요청에 따라 talent_resume_jobs와 talent_resume_cleanup 및 관련 RPC를 삭제했다.
revision 증가 트리거만 유지한다. 생성 요청의 중복은 기존 문서 ID와 PK로,
수정은 기존 origin_id 및 revision으로 처리한다. 기존 적용 마이그레이션 파일명도
실제 DB 기록 번호와 일치시켰으며, 삭제는 후속 마이그레이션으로 기록했다.

단순화 후 관련 자동 테스트 11개와 ESLint를 통과했다. 실제 Supabase와 Chromium으로
생성 → 같은 요청 재시도 → 같은 문서 수정 → 수정 요청 재시도를 확인했다.
추가된 작업·정리 테이블 및 RPC는 실제 DB에서 존재하지 않음을 재확인했다.

## Summary 제거 및 입력 보정

고정 템플릿 v3는 이름·연락처 → 학력 → 경력 → 프로젝트 → 대외활동·기술·기타 순서로
표시하며 학력 정보가 없으면 생략한다. 소개/Summary를
출력하지 않는다. 새 도구 스키마에서 summary를 제외하고, 기존 JSON을 수정할 때에도
제거한다. 기존 저장 PDF는 자동으로 바꾸지 않고 다음 생성·수정 때 적용한다.
모델이 모르는 기간·연락처 등 선택 필드에 빈 문자열이나 null을 보내면 생략한다.
이름·항목 제목 등 필수 필드의 빈 값은 계속 검증 오류로 처리한다.
