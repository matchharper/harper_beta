### 질문·답장 E2E

승인된 revision 3의 제목과 본문은 DB에 정확히 저장됐다. 그러나 실제 Gmail 메일 `1a0253678d8ba432`은 현재 배포된 worker가 예전 템플릿을 다시 생성해 제목과 본문이 달라졌다. 이 문제는 “초안을 먼저 보여주고 승인한 문구 그대로 보낸다”는 제품 약속을 위반하므로 단순 문체 문제가 아니라 배포 전 필수 재검증 항목이다.

`khj605123@gmail.com`에서 메일 `1a0253796f4e5437`로 같은 스레드에 실제 답장했다. 답장은 회사 전달 queue `c8b026b2-7728-4711-8981-59a9b2386279`에서 한 번 발송됐고, 원래 Slack 질문 스레드와 해당 역할의 웹 대화 양쪽에서 확인했다.

### 연결 거절 E2E

- 사전 안내: 소개 이메일 미발송, 후보자에게 종료 결정 표시, 내부 사유 비공개, 임시 보류가 아님, 전달·확인된 안내 회수 불가를 설명했다.
- 실제 결과: `내부:프로세스중단`, `introRequested: false`, 소개 이메일 ID·수신자 없음.
- Gmail에서 거절 fixture 역할 제목을 검색한 결과 0건이었다.
- 같은 결정을 다시 실행하지 말라는 후속 질문에는 상태만 조회했고 새 결정이나 메일을 만들지 않았다.
- 첫 승인 후 확인이 한 번 더 반복되는 불필요한 마찰을 발견해, 구체적인 거절 의사가 나오면 최초 응답부터 서버가 추적하는 비변경형 확인 단계를 사용하도록 프롬프트를 보강했다.

### 수정한 주요 문제

1. 소개 메일의 시스템 라벨·장문·테스트 메타데이터를 제거하고, 현재 재직 또는 대표 경력 한 줄만 쓰도록 변경했다.
2. 소개 메일 출력 검사에 정확한 인사·회사 사람 재호명·정확한 마무리·문단 구조·한영 혼용 차단을 추가했다.
3. 일반 Slack 스레드에서 가장 최근 역할 링크가 잘못 붙을 수 있던 문제를 `preferredRoleId`로 고쳤다.
4. 질문 초안 수정 응답이 짧은 토큰 제한으로 잘리던 문제를 수정했다.
5. 승인한 질문 문구를 worker가 다시 생성하던 문제를 로컬 worker에서 제거했다. 시스템 footer는 전송 시에만 별도로 붙인다.
6. 후보자 답변이 Slack에만 저장되고 웹 역할 대화에는 누락되던 문제를 요청 ID 기반 멱등 미러 저장으로 고쳤다.
7. Slack 알림·모달의 `Email intro`, `Direct contact`, `Recipients`, `후보자 연결을 거절했어요` 같은 기계적인 표현을 `소개 이메일`, `직접 연락`, `회사 수신자`, `<이름>님과의 연결을 거절했어요`로 바꿨다.
8. 웹 후보자 상세의 조사 오류인 `김호진와 연결`을 `김호진님과 연결`로 고쳤다.
