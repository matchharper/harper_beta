## 경계

이 기능은 **같은 실제 계정의 데이터를 덮어쓴다**. 별도 테스트 계정 복제나
발송 차단 모드가 아니다. 다른 탭·기기의 작업도 종료한 뒤 사용한다.
현재 창에서 진행 중인 채팅·통화에는 버튼이 비활성화된다.
DB에 실행 중·대기 중인 추천/지원/통화 작업이 있으면 서버도 복원을 거절한다.
복원 이후에는 원래 앱과 Worker가 정상적으로 다시 데이터를 갱신할 수 있다.
다른 기기의 이미 진행 중인 일반 대화까지 강제로 취소하는 기능은 아니다.

이미 전송한 이메일, 회사/외부 사이트 제출, 캘린더, OAuth 연결, 공유 공고 원문,
회사 전체 상태, 인증·결제, 감사 로그는 과거로 돌릴 수 없다.
발송·연락·일정 원장에 기준 이후 변경이 있거나 새로운 외부 지원 실행 근거가 있으면
중복 실행 방지를 위해 복원을 중단한다. 외부 원장이 새 계정 행을 참조하는 경우에도
전체 transaction을 취소한다. 이 경우 원장 삭제로 우회하지 않는다.
실제 발송까지 반복 실험하려면 별도의 격리 환경이 필요하다.
시간과 외부 공고를 동결하지 않으므로 같은 입력이 같은 모델 출력을 보장하지 않는다.

## 보관과 실행

개인 데이터 원본은 Git에서 제외된 `.local/career-reset/baseline.json`에 보관한다.
디렉터리는 소유자 전용이며 원본은 읽기 전용이다. 버전 관리에는 계정 ID, 기준 표시와
SHA-256만 남긴다. 내용이 바뀌거나 파일이 없으면 새로 저장하지 않고 실패한다.
Next의 output tracing에서도 이 private 폴더를 제외한다.
현재 캡처는 이후 컬럼 변경에 자동 적응하지 않는다. 구조가 달라지면 명시적 호환 검토가 필요하다.

API는 로컬 개발에서만 열리며 Supabase가 직접 검증한 Daniel 세션만 허용한다.
일반 개발용 JWT decode fallback은 사용하지 않는다. 요청에서 대상 계정이나 SQL을 받지 않는다.
기존 Dev SQL DB 연결을 재사용하며 schema migration/운영 배포는 필요하지 않다.

복원은 관련 테이블의 쓰기 잠금을 잡고 실행/전달 경계를 검사한다. 잠금을 오래 기다리면
실패한다. 행을 transaction-local 임시 테이블에 저장한 뒤 해당 tuple만 교체한다.
세션 내 trigger 실행을 일시 중지해 자동 알림·timestamp 변경·cascade를 재실행하지 않는다.
현재 DB의 FK 그래프에서 영향받는 연결을 확인하고, 기준과 복원 결과의 모든 값을 비교한 후
커밋한다. 서버 내부 명령은 묶어서 실행해 전체 테이블 잠금 시간을 줄인다.
다른 계정·회사 행을 cascade로 지우지 않으며, 실패 시 모든 DB 변경이 롤백된다.
