# 후보자 조건 확인 질문 계획 — 통합 계획으로 대체

문서 기준: 2026-10-07. 이 문서의 이전 설계는 후속 논의를 반영한 [Talent × Role 매칭 통합 구현 계획](unified-talent-role-matching-implementation-plan-ko.md)으로 대체했다. 구현 기준은 통합 계획 하나를 사용한다. 현재 배포된 동작을 설명하는 문서가 아니다.

질문·답변의 상세 설계는 통합 계획의 12–14절, 저장과 공개 범위는 20–21절, prompt/tool 계약은 25절에 있다.

| 이전 제안에서 바뀐 점 | 최종 설계 |
| --- | --- |
| 답변 LLM이 저장 후 재검토 tool을 따로 선택 | 기존 `write_talent_context`의 실제 Brief 변경을 서버가 확인하여 matching refresh 등록 |
| 역할별 예외 사실을 별도 progress/fact로 저장 | 기존 Brief에 명시된 역할 예외를 자유 형식으로 저장 |
| Fit 불확실성을 폭넓게 수집 | 2차에서만, 답을 알면 강한 추천 후보가 되는 드문 실질 조건을 `missingInfo`로 남김 |
| 질문별 상태와 반복 가능 횟수를 관리 | 실제 메시지·Brief·연락 이력으로 판단. 같은 입력의 반복 실행과 발송은 fingerprint/idempotency로 방지 |
| 과거 질문을 매 대화의 상세 context에 포함 | 최근 실제 연락 index 최대 5개와 일반 reader의 검색·원문 조회 |

실제 질문은 후보자 전달 단계에서 만들고, role rerank가 질문 task를 만들지 않는다. 답변은 추천 수락이나 회사 공유 동의가 아니다. 우선 검토·동의·회사 공유 흐름도 반드시 통합 계획을 함께 따른다.
