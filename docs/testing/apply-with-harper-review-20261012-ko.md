# Apply with Harper 전체 흐름 재점검

2026-10-12 로컬 작업 트리 기준. 배포하지 않았다. 실제 후보자·회사에 지원하거나 연락하지 않았으며, UI와 저장·제출 테스트에는 synthetic fixture를 사용했다.

이 문서의 초기 검증 이후 실제 로그인된 로컬 브라우저의 준비 시작·최초 제안 표시도 추가 확인했다. 실제 계정의 최종 저장·외부 회사 접수까지 완료한 것은 아니다. 후속 범위와 남은 한계는 [Haiku 기록의 후속 로컬 검증](../evaluation/application-suggestions/reports/2026-10-12-haiku.md#후속-로컬-검증과-문서-제목-변경)을 참고한다.

## 발견한 문제와 수정

| 구간 | 문제 | 수정 |
| --- | --- | --- |
| 시작 버튼 | 시작 권한을 이미 지원 모드의 도구 목록으로 검사해 정상 요청도 403으로 거절할 수 있었다 | 일반 채팅의 시작 권한을 먼저 검사하고, 서버가 직접 준비를 실행. 온보딩·채널·호출자 도구 제한 유지 |
| 준비 실패 | 준비가 실패한 뒤 활성 모드에 남아 정상 대화로 복구하기 어려웠다 | 실패 진행 기록을 보존하면서 모드를 종료. 새 준비 요청 가능. 동시에 종료된 상태나 새 실행은 덮어쓰지 않음 |
| 이력서 저장 후 후속 응답 | 추가 자료나 질문 답변만 바뀌어도 이미 반영한 이력서 수정을 다시 요구할 수 있었다 | 실제 승인된 이력서 변경 내용의 fingerprint를 저장. 자료만 변경하면 기존 이력서 재사용, 적용 철회·수정 시 실제 문서 반영 필요 |
| 도구 책임 | 일반 이력서 수정 도구와 구형 제안 수정 도구가 새 준비 흐름에도 함께 노출됐다 | 제안은 `manage_application_suggestions`, 저장은 `ready_for_role`로 일원화. 생명주기 도구는 사실 정정·종료·전환만 제공. 구형 세션 호환은 별도 유지 |
| 작성 지침 | 일반 수정 도구를 제외하면 공통 이력서 작성 지침도 빠질 수 있었다 | 실제 저장 도구에 맞게 공통 작성 지침 재사용. 변경이 없으면 action=reuse, 변경 시 평평한 create/copy/update 명령으로 계약 명확화 |
| 중복 도구 요청 | 저장된 canonical 상태 대신 저장 전 생성한 임시 제안 ID를 반환할 수 있었다 | 도구 응답을 실제 저장된 상태에서 생성 |
| 답변 기록 | 접힌 기록의 움직임과 편집된 답변 표시가 부족했다 | Chevron 회전, hover/focus opacity, 200ms 펼침·접힘, 본문 명도와 왼쪽 구분선. 승인한 실제 inline 편집 내용을 표시 |

## 검증

- 관련 자동 테스트 180개 중 기본 실행 176개 통과, 실제 브라우저가 필요한 4개는 별도 opt-in 실행에서 모두 통과. 별도 실행은 공통 구조 검증 1개를 포함해 5/5 통과했다.
- 시작 권한, 실제 4단계 준비 orchestration, 중복 시작, 제안 0개, 준비 실패 복구를 연결해 검증했다. 저장소는 소유권·revision 조건을 검사하는 fake admin이며 실제 인증된 HTTP 요청이나 production DB 테스트는 아니다.
- 실제 resume service로 원본 보존, 비공개 사본 저장, 현재 revision/fingerprint, 후속 자료 변경 시 재사용, 적용 철회 후 같은 사본 수정, 타 사용자 문서 차단을 검증했다.
- 실제 로컬 Chrome과 synthetic 지원 양식에서 PDF 첨부, 승인된 GET/POST 제출의 1회 실행, 승인 없는 제출 차단, 읽기 전용 조사, 대기 후 입력값 유지가 통과했다. 실제 ATS 제출 성공률을 의미하지 않는다.
- 1440×1000 및 1280×800 데스크톱에서 시작 카드·4단계 진행·제안 composer·답변 기록을 확인했다. inline 수정 → 적용 → 질문 답변 → 마지막 응답 제출 → 기록 펼치기로 수정 내용 보존을 확인했다.
- 숫자·방향키의 입력 중 차단, 선택 후 짧은 표시, Enter/Space로 기록 열기·닫기, 빠른 토글, reduced motion을 확인했다. 390×844에서도 가로 넘침이 없었다. 브라우저 page error 없음.
- 전체 타입 검사 및 변경 범위 ESLint 통과.

## 모델 재평가

등록된 `application-suggestions`의 frozen `conversations-v1` 3건을 그대로 재실행했다. 최종 run은 `conversation-2026-10-12T10-09-07-078Z`; 원문·호출·설정·hash는 ignored `runs/`에 보관한다.

- 직접 수정 지시: 추가 확인 없이 수정 사본 생성, 기존 학력 보존, 문서 링크와 지원 제안.
- 새 경험 답변: 회사 소속을 추정하지 않고 답변에 근거한 새 문구를 한 번 제안.
- 세 번째 라운드 건너뛰기: 네 번째 라운드 없이 기존 이력서로 준비 완료. 이번 최종 run에서는 잘못된 빈 resume 명령 재시도도 없었다.

3/3 행동 기준을 원문으로 확인했다. 대화 평가의 저장은 in-memory executor이며 실제 파일 저장 검증과 구분한다. 작은 합성 평가로 모든 대화 품질을 보장할 수는 없다. 준비 완료 응답에는 여전히 원본 보존이나 제출 전 상태를 반복 설명하는 경향이 조금 남아 있다.

## 남은 검증 범위

실제 로그인된 사용자에서 인증·DB·Agents API·외부 ATS까지 이어지는 production 전체 실행은 수행하지 않았다. 외부 지원 사이트의 로그인/CAPTCHA/조건부 항목과 실제 접수 결과는 현장 조건에 따라 달라진다. 배포 및 Notion 동기화는 수행하지 않았다.


## 추가 Haiku 5.5 검증

사용자의 로컬 점검 요청에 따라 모든 평가 모델 호출을 Haiku 5.5로 고정하고 실제 로컬 Chrome을 다시 조작했다. [상세 기록](../evaluation/application-suggestions/reports/2026-10-12-haiku.md)에 중간 실패, 수정한 계약, frozen dataset과 최종 run을 남겼다.

주요 추가 수정은 지원 대행 불가 공통 지침 제거, 버튼 결정의 같은 continuation 내 보호, 승인된 실제 편집 내용과 과거 제안의 context 분리, 적용/제출 의미 구분, ready 도구의 평평한 JSON 및 명시적 reuse 동작이다. 최종 전체 흐름 8사례·11턴은 도구 오류 없이 통과했고, 첫 제안 3건과 후속 대화 3건도 의미 기준을 통과했다. 관련 자동 테스트 61개, 타입 검사, 변경 범위 린트도 통과했다. 검증용 모델 고정이며 제품 기본 모델을 영구 변경하거나 배포한 것은 아니다.
