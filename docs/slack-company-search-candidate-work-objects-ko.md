# Slack 검색 결과의 후보자 카드

문서 기준: 2026-10-08. 로컬 구현 기준이며 배포 또는 Slack 앱 설정 적용을 뜻하지 않는다.

## 팀원이 사용하는 흐름

1. 역할에 대한 검색이 끝나면 Harper의 후보자 설명과 함께 후보자별 Slack Work Object 카드가 표시된다.
2. 카드를 누르면 Slack의 오른쪽 상세 패널에서 Documents, TL;DR, 위치, 경력, 학력, 기타 경험과 Harper Note를 확인한다. 맨 위 Documents의 `자세히 보기`는 같은 후보자의 Harper 웹 상세 화면으로 이동한다.
3. 검토 대기 상태에서는 `Intro 요청` 또는 `Pass`를 선택할 수 있다. 상세 패널은 현재 팀원의 권한을 확인한 뒤 결정 버튼을 표시한다.
4. `Intro 요청`에서는 후보자에게 전할 회사의 관심 이유와, 후보자가 수락했을 때 소개 이메일을 받을 팀원을 선택하고 제출한다. 기존 웹의 Intro 요청과 같은 처리 경로를 사용한다. 요청을 제출했다는 사실과 후보자에게 제안이 실제 전달되었다는 사실은 구분해 표시한다.
5. `Pass`는 확인 후 해당 제안을 제외한다. 후보자에게 연락하거나 알림을 보내지 않는다.

이미 요청 중이거나 종료된 제안에는 결정 버튼을 표시하지 않는다. 상세 패널을 열 때마다 현재 권한과 제안 상태를 다시 확인한다. 종료된 제안에서는 상태만 표시한다.

## 카드와 상세 화면 구성

메시지 밖의 작은 카드에는 이름과 최근 경력의 직함·회사만 표시한다. Intro 요청과 Pass 버튼, 프로필 요약, Role, 상태는 상세 패널에 표시한다. 최근 경력은 시작일이 가장 최근인 이력을 사용하고, 직함이나 회사가 없으면 `Candidates in Harper`로 표시한다.

상세 패널의 첫 항목은 `Documents`이며 `자세히 보기` 링크를 항상 표시한다. 이 링크는 카드의 `/org/role` 주소와 같고 Workspace·Role·후보자·제안 정보를 유지한다. 웹의 기존 문서 조회 권한이 허용되는 경우에만 공개된 LinkedIn·등록 링크·이력서·문서 링크를 함께 표시한다. 파일은 `/org/resume`에서 기존 문서 조회 API로 현재 로그인과 공개 권한을 다시 확인한 뒤 연다. Slack에 Storage 경로나 임시 다운로드 주소를 저장하지 않는다. 현재 Company-first의 연결 전 상세 조회는 등록 링크와 이력서를 제외하므로 이 단계에서는 `자세히 보기`만 표시한다.

작은 카드의 아이콘은 `public/images/squareface.png`의 Harper 얼굴 이미지로 고정한다. Slack에서 접근할 수 있는 공개 주소 `https://matchharper.com/images/squareface.png`를 사용한다. 오른쪽 상세 패널의 각 경력은 회사명, 굵은 직책, 기울임 기간을 줄바꿈한 하나의 마크다운 항목에 표시한다. 회사명과 직책·기간을 별도 항목으로 나누지 않아 같은 경력 안에서 간격이 벌어지지 않는다. Slack은 한 필드에 아이콘과 마크다운을 함께 지원하지 않으므로 합친 경력 항목에는 회사 로고를 표시하지 않는다. 상세 패널 상단은 Harper 표시를 유지한다.

`Harper Note`는 해당 제안에 저장된 `selection_reason`을 표시한다. `TL;DR`은 Role별 기준 평가와 함께 생성한 `introduction`이며, 해당 제안의 `presentation.summary`에서 읽는다. 후보자가 작성한 프로필 bio는 TL;DR에 사용하지 않는다. 저장된 소개가 없으면 TL;DR 항목은 숨긴다. 현재 Worker의 신규 제안 저장 경로는 introduction을 selection_reason에도 넣으므로 두 항목의 내용이 같을 수 있다. 두 항목은 각각 최대 600자까지 표시한다.

상세 본문은 경력별로 하나의 마크다운 항목을 사용한다. 경력, 학력과 기타 경험은 줄바꿈과 강조로 구조를 나눈다. 각 경력에 별도 `Details`·`상세` 항목이나 긴 업무 설명은 표시하지 않는다. 경력은 최근 6개까지만 표시하며 나머지는 `외 N개 경력, 총 X.X년` 또는 `N more experiences, total X.X years`로 안내한다. 총 경력은 생략된 이력까지 포함한 전체 재직 기간을 합쳐 계산하며, 동시에 재직한 기간은 한 번만 더하고 경력 사이의 공백은 제외한다. 퇴사일이 없는 이력은 조회일 기준 오늘까지 계산하고 미래 날짜는 포함하지 않는다. 연수는 실제 날짜 차이를 소수점 한 자리로 반올림한 근삿값이다. 날짜가 누락되거나 잘못된 이력이 있으면 총 기간을 추정하지 않고 미확인으로 표시한다. 소개와 추천 이유는 최대 600자, 학력·기타 경험 설명은 항목당 최대 360자 뒤에 `…`를 붙여 미리보기 길이를 줄인다. 원본 프로필은 수정하지 않으며 전체 내용은 Documents의 `자세히 보기`에서 확인한다.

Slack 기본 카드가 이름 아래 문구를 `직함 in 회사명` 형태로 조합한다. 이 구분자를 `at`으로 바꿀 수는 없다. 카드·상세 항목과 버튼은 `src/lib/org/slackCandidateWorkObject.ts`, 상세 프로필의 항목·순서는 `src/lib/org/slackCandidateWorkObject.server.ts`에서 바꾼다. 이름·탭·두 열 배치 같은 기본 틀은 Slack이 정한다. 자유로운 상세 본문을 만들려면 Slack의 별도 [Work Object embed](https://docs.slack.dev/messaging/work-objects-embeds/)를 구현해야 한다. 외부 Workspace에 배포하는 앱의 embed는 Slack의 파일럿 초대가 필요하다.

열려 있던 상세 패널에서 항목 구성이 바뀌면 Slack의 데이터 동기화 이후에도 이전 라벨이나 본문이 남을 수 있다. 이 경우 패널을 닫고 같은 카드를 다시 열면 최신 구성을 확인할 수 있다.

## Intro 크레딧과 실패 처리

Slack interactivity API에서 웹과 같은 Intro 서버 함수를 호출한다. 과금이 시작된 Workspace는 Role에 배정된 슬롯 또는 Free 크레딧을 성공한 Intro 요청당 1회 사용한다. 같은 요청의 재시도는 중복 차감하지 않는다. 무제한 슬롯과 기존 과금 미시작 Workspace는 크레딧을 차감하지 않는다. Pass는 차감하지 않는다.

크레딧이 부족하면 요청 상태 변경과 발송 작업 생성까지 함께 취소된다. Slack 모달에는 웹과 같은 크레딧 부족 안내와 Harper 문의 링크를 표시하고, 작성한 내용과 선택한 팀원을 유지한다. 모달의 처리 코드는 `src/lib/org/slackCandidateInteractivity.ts`에 있다.

## 공개 범위

- Slack 계정의 이메일과 Harper Workspace 가입 정보를 확인한다. 다른 Workspace의 설치나 연결되지 않은 채널로 조회할 수 없다.
- 프로필은 웹의 기존 후보자 상세 조회를 사용하며, 현재 공개 허용 여부와 역할·제안의 유효성을 확인한다.
- 연락처, 이력서 파일, 내부 메모, 후보자 비공개 추천 맥락은 Work Object에 넣지 않는다.
- Intro 요청과 Pass는 현재 결정 권한을 다시 확인하고 기존 명령의 중복 처리·공개 허용 검사를 적용한다. Viewer에게 결정 권한을 부여하지 않는다.

## 전송 형식과 복구

Slack은 한 메시지의 본문 뒤에 Work Object를 붙이므로 후보자별로 메시지를 나누어 보낸다. 새 수동 검색 결과는 기존 회사 측 LLM이 `후보자 식별자 + 설명`으로 나눈 메시지를 작성한다. 인사·후속 질문은 별도 메시지로 작성하므로 마지막 후보자의 카드도 설명 바로 다음에 놓인다. 서버는 식별자·누락·중복만 확인하며 설명을 키워드로 판정하거나 다시 쓰지 않는다. 웹에서는 같은 메시지들을 이어 붙여 기존처럼 한 번의 답변으로 표시한다.

정기 검색 결과는 Worker의 기존 후보자별 작성 결과를 전송 블록의 식별자로 보존한다. 후보자 설명과 마무리 질문을 구분하는 데 추가 LLM 호출이 필요하지 않다.

배포 전 만들어진 기존 메시지에는 이 메시지 경계가 없다. 이때만 서버가 제공한 후보자 링크와 문단 경계를 사용한다. 링크가 없거나 여러 후보자가 같은 문단에 있으면 원문 전체를 먼저 보낸 뒤 후보자별 카드를 이어서 보낸다. 기존 메시지의 이 경우에는 카드가 설명 바로 아래에 놓인다는 보장은 없다.

채널과 후보자별 전송 기록을 확인해 부분 실패 시 완료된 메시지는 다시 보내지 않는다. 정기 검색 결과는 기존 Slack 메시지 기록의 전송 식별자를 사용하고, 수동 검색의 결과 알림은 기존 실행 결과의 알림 기록을 사용한다. 새로운 테이블은 필요하지 않다.

새 카드 권한을 아직 승인하지 않은 Workspace에는 기존 후보자 설명과 프로필 링크를 한 메시지로 보낸다. 정기 검색의 기존 전송 블록도 그대로 사용한다. 카드에 필요한 링크 권한과 프로필 조회 시 팀원을 확인할 계정 조회 권한이 모두 있는지 실제 Slack 토큰으로 확인하며, 권한 확인이 실패해도 일반 메시지 전송을 진행한다. Slack 앱 관리 화면에서 재설치한 경우에도 현재 승인된 권한을 반영한다.

Slack이 카드 메타데이터나 추가 권한을 명시적으로 거부하면 같은 설명·링크·메시지 식별자로 카드 없이 다시 전송한다. 네트워크 응답 유실, 토큰 해지, 채널 삭제 같은 일반 전송 실패를 카드 오류로 처리하지 않는다. 부분 전송 중 권한이 바뀌면 이미 보낸 메시지는 유지하고 남은 메시지만 이어 보낸다. 기존 텍스트 방식으로 완료한 결과를 재설치 후 카드로 다시 보내지 않는다.

## Slack 앱 설정과 검증

배포 시 `slack/harper-manifest.yaml`의 다음 설정도 Slack 앱에 적용해야 한다. 로컬 Socket Mode 앱에는 `slack/harper-local-manifest.yaml`을 사용한다.

- Work Object Previews 활성화, `slack#/entities/item` 지원
- `matchharper.com` 도메인 등록 및 `links:read`, `links:write` 권한
- `entity_details_requested`, `link_shared` 이벤트 구독
- 기존 Interactivity 요청 경로 유지

추가 권한 적용에는 Slack 앱 재설치 또는 권한 재승인이 필요할 수 있다. 설정 적용만으로 서버 코드가 배포되지는 않는다. 기존 일반 링크의 자동 미리보기 차단은 유지하고 명시적으로 전달한 Work Object만 표시한다.

실제 Slack에서 확인할 때는 전용 테스트 계정과 격리된 역할을 사용한다. 운영 DB에 테스트 역할을 만들 필요가 있다면 먼저 `docs/test-internal-role-isolation-ko.md`를 따른다. 일반 후보자의 Intro 요청을 검증용으로 제출하지 않는다.

로컬 자동 검증:

```sh
node --import tsx --test src/lib/org/slackCandidateWorkObject.test.ts src/lib/org/slackCandidateWorkObject.server.test.ts src/lib/org/slackApiRequest.test.ts src/lib/org/slackMemberAccessPolicy.test.ts
```

실제 Slack 검증 항목은 후보자별 카드 위치, 오른쪽 패널 내용, Viewer의 읽기 전용 동작, 가입하지 않은 계정의 접근 제한, Intro 입력과 상태 갱신, Pass 이후 버튼 제거다. 자동 테스트는 격리된 DB·Slack 어댑터를 사용하며 실제 Slack 화면이나 실제 후보자 연락을 확인하는 테스트가 아니다.

참고: [Slack Work Objects 구현 문서](https://docs.slack.dev/messaging/work-objects-implementation/).
