# Career · Floating Sky

2026-11-05 · 구현 브랜치 `codex/career-floating-sky-20261105` · 로컬 구현, 미배포.

## 기준과 목적

`harper-design-handoff-1104.html`의 `glass bgD`가 시각 기준이다. 큰 배경 하나 위에 대화, 작은 유리 표면, 정보 패널을 배치한다. 열린 Hark의 상단 탐색·여백·하단 입력창을 보조 참조로 사용한다. 사용자 데이터와 실행 동작은 기존 Career를 사용한다. 예시 회사·날짜·성과·예약을 제품의 실제 데이터처럼 만들지 않는다.

## 원본 수치

배경은 아래 네 레이어를 순서까지 그대로 사용한다. 스크롤하는 패널마다 배경을 새로 시작하지 않는다.

```css
radial-gradient(760px 520px at 10% 6%, rgba(255,255,255,1), transparent 62%),
radial-gradient(820px 600px at 94% 98%, rgba(216,222,232,.9), transparent 66%),
radial-gradient(560px 440px at 55% 52%, rgba(255,255,255,.5), transparent 70%),
linear-gradient(180deg, #F5F6F8, #E9ECF0)
```

| 역할 | 값 |
| --- | --- |
| 기본 글라스 | `linear-gradient(180deg, white 52%, white 34%)` — 각 값은 색의 alpha |
| 작업 표면 | `linear-gradient(180deg, white 44%, white 26%)` |
| Blur / saturation | `blur(40px) saturate(1.6)` |
| 기본 radius | 카드·작업·동적 UI 18px, composer 16px, 상단 세그먼트 12px, 선택 탭 8px |
| Shadow | `0 1px 0 rgba(255,255,255,.75) inset, 0 -1px 0 rgba(255,255,255,.25) inset, 0 0 0 .5px rgba(255,255,255,.35), 0 18px 40px -22px rgba(30,25,20,.22), 0 1px 2px rgba(30,25,20,.03)` |
| 본문 / 보조 / 희미한 정보 | `#1D1D1F` / `#6E6E73` / `#AEAEB2` |
| 구분선 | black 6%; 표 내부 black 7% |
| 선택 탭 | white, `0 1px 3px rgba(0,0,0,.08)` |
| 팔로업 | padding 18px, 간격 12px, 제목 22px / 1.3 / 300 / -0.3px |
| 팔로업 설명 / 행동 | 14px / 1.5, 행동 weight 500 |
| 집계 숫자 | 34px / 1.1 / 300 / -1px |

색상과 표면은 `src/styles/career-floating-sky.css`에 한 번 정의한다. Career route가 마운트된 동안 루트 토큰을 바꿔 body portal의 설정·메뉴·모달도 같은 외관을 받는다. 다른 제품의 공용 기본값은 변경하지 않는다. 메뉴·모달은 배경 위에서 읽을 수 있도록 더 높은 white alpha를 사용한다. 이는 참조에 없는 겹침 상태의 확장이다.

글꼴은 원본과 같은 Apple/system 우선순위를 사용한다. 본문 `#1D1D1F`, 설명 `#6E6E73`, 날짜·보조 라벨 `#AEAEB2`를 구분하며, 입력 placeholder는 `#8B8B93`이다. 모달·메뉴·팝오버는 glass 아래에 white 64%를 더해 뒤의 글자가 겹치지 않게 한다. 지원 검토·입력 폼·문서 결과물에는 작업 표면의 44% → 26%를 적용했다.

## 레이아웃

- 데스크톱: 높이 64px의 상단 바. 왼쪽 Harper/Home, 가운데 채팅·기회, 오른쪽 설정·프로필. 기존 설정 모달과 프로필 메뉴를 재사용한다.
- 대화 본문과 composer는 최대 560px. 팔로업과 기회 목록은 같은 `--career-panel-width` 420px이며 768–1023px에서는 360px이다. 외곽 28–40px와 충분한 열 간격을 두고 작은 노트북에서는 가용 너비에 맞춰 줄인다.
- 오른쪽 바닥은 투명하다. 패널의 큰 흰 사각형·왼쪽 고정 탐색은 없앤다. 기회를 선택해도 대화 인스턴스와 draft는 유지한다.
- 모바일: 최상단 홈·채팅·기회. 홈은 팔로업과 현황, 채팅은 타임라인, 기회는 동일한 기회 목록. composer는 한 인스턴스를 계속 유지하며 홈에서 focus/타이핑은 탭을 바꾸지 않는다. 제출이 실행되면 채팅으로 전환한다. safe area와 키보드 높이를 고려한다.
- 내 정보·자료·원하는 조건·관심 회사의 기존 deep link는 유지한다. 프로필 메뉴 및 채팅 동적 UI에서 접근한다.

## 유지하는 제품 계약

기회는 기존 `CareerHistoryPanel`, `OpportunityCard`, 목록·행 펼치기, TabBoxes, 저장/지원/보류/거절/되돌리기/상태 수정 경로를 쓴다. 회사명 외에 role title과 위치·근무 방식·고용 형태를 유지한다. 지원 준비·실제 제출·회신·면접을 같은 것으로 취급하지 않는다. 새 UI가 표시되는 것만으로 mutation을 실행하지 않는다.

복사·삭제·시간·thinking·working·중단·첨부·@기회·지원 검토·브라우저 작업은 유지한다. 기본 composer의 빈 입력 상태는 보내기 버튼이며 진행 중인 통화, 통화 시작 링크와 처리할 항목의 통화 진입은 유지한다. 마크다운 원문·복사 내용은 변경하지 않고 표의 시각적 컨테이너만 글라스로 바꾼다. 모바일 홈에서는 일반 대화 제안 버튼을 감춰 입력창을 작게 유지하고, 채팅에서 다시 보여 준다.

팔로업은 `CareerActionItem`의 저장된 제목·설명·행동을 표시한다. 임의의 “오늘 오후 다시 연락”은 만들지 않는다. 지원 현황은 기존 정확한 집계인 저장함·지원함·진행중을 사용한다. 0개·조회 중·오류·재시도 상태도 같은 구조를 사용한다.

## 채팅에서 꺼내는 UI

기존 `career_ui` 참조의 매칭·기회·원하는 조건을 유지한다. 내 일정·예약된 작업·할 일·관심 회사·자료 등은 기존 독립 reader/component를 재사용할 수 있는 항목부터 확장한다. 모델은 UI 종류와 실제 조회 범위를 지정하고 렌더러가 최신 사실을 조회한다. 표시를 위한 별도 persistence나 품질 판별 로직은 추가하지 않는다. 웹 전용 guide의 실제 로딩 경로를 확인하고 이메일/통화의 표시 참조 제외 계약을 유지한다.

## 온보딩과 세부 상태

가입 단계·필수 정보·동의·제출 계약은 보존한다. 같은 sky 배경 위에 480px의 좁은 form을 바로 배치하며 메인 영역은 글라스로 감싸지 않는다. 메인 폼의 배경·테두리·그림자·blur는 없고 개별 입력/선택 카드의 표면만 유지한다. 차분한 진행 표시와 검은 주행동을 적용한다. 모달은 `TalentCareerModal`, 메뉴는 기존 Radix primitive를 유지해 focus·Escape·키보드·바깥 클릭을 보존한다. hover는 짧은 색/그림자 변화, focus는 보이는 ring, reduced-motion에서는 이동 애니메이션을 줄인다.

아바타는 로그인 사용자의 기존 이미지 또는 이름 이니셜이며 프로필/계정 메뉴 진입점이다. 별도 생성 캐릭터나 인물 모델 기능은 추가하지 않는다.

## 전달 산출물과 확인

팀원에게 보낼 하나의 HTML에 실제 구현 컴포넌트의 렌더링을 포함한다. 설정·프로필 메뉴·기회 확장·거절·첨부·빈 상태·오류·동적 UI·온보딩과 참조에서 조정한 내용을 설명한다. “아침 브리핑”은 기능이 없어 일반 대화 날짜로, 고정 공유 제외 목록은 실제 전송 내용/권한 확인으로 설명한다. 승인/취소·거절 선택은 기존 계약을 따른다. 외부 회사 공개 프로필은 별도 제품 경로라 이번 Career 디자인 적용 범위에 포함하지 않는다.

검증은 변경 경로의 TypeScript/정적 검사, 기회/동적 UI의 관련 테스트, 데스크톱·모바일 실제 브라우저 렌더링과 탐색·입력·모달 상호작용에 집중한다. 운영 발송·지원·가입 데이터는 만들지 않고 예시 preview와 읽기 전용 상태를 사용한다. 배포하지 않는다.

### 전달 파일과 재생성

`docs/design/career-floating-sky-handoff.html`을 브라우저에서 열면 된다. 로컬 개발 서버의 `/career/preview/design-system`은 같은 전달서를 보여 주고 최신 공통 스타일로 단일 HTML을 내려받는다. `/career/preview`는 실제 컴포넌트의 상호작용을 확인하는 개발 전용 fixture다.

큰 화면 스냅샷을 갱신하려면 `TSX_TSCONFIG_PATH=scripts/tsconfig.json pnpm exec tsx scripts/renderCareerDesignScreens.tsx`를 실행하고, `node scripts/assembleCareerDesignHandoff.mjs docs/design/career-floating-sky-handoff.html`로 합친다. 이 renderer는 모든 fetch를 격리하고 예시 provider만 사용한다. 이어 전달서 페이지를 새로고침해 HTML 다운로드를 실행하면 최신 CSS·로컬 폰트·이미지까지 묶인다. 내려받은 파일을 전달 HTML 경로에 저장한다. 제품의 상호작용 검증은 스냅샷 생성과 별도로 수행한다.


### 세부 디자인 재점검 · 2026-11-05

- 팔로업의 `compose_reply`는 Hark의 분리된 맥락 카드 배치를 참고해 입력창 위 12px 간격에 놓았다. `send_message` 등 기존 행동 종류의 실행 계약은 유지했다. 선택/닫기는 입력 중인 초안을 지우지 않으며, 닫기 후 입력창으로 focus가 돌아온다. 이력서 업로드와 회사·역할·질문 펼치기도 같은 표면에서 제공한다.
- 일반 질문·지원 준비와 통화 질문은 기존 답변 폼을 입력창 위에 둔다. 통화 질문이 열려도 일반 composer를 재마운트하지 않는다. 답변 저장·건너뛰기·수정·재시도는 기존 구현을 쓴다.
- `CareerAnimatedRegion`에서 기회 상세와 답변 카드의 열림/닫힘을 하나의 spring(stiffness 360, damping 38)으로 공유한다. 닫히는 내용은 즉시 inert/aria-hidden이 된다. Career의 MotionConfig는 사용자 모션 감소 설정을 따르고 CSS의 반복·전환 애니메이션도 줄인다.
- 기초 토큰은 ink/secondary/soft, radius 8/12/16/18/20/24/pill, blur/saturation, 표면 alpha, hover/pressed/selected, focus, 너비와 여백으로 묶었다. 공용 surface/card/modal/menu/composer 토큰이 이를 참조한다. 상태 전환은 180ms, 눌림은 120ms, 진입은 240ms와 공통 easing을 쓴다. 인라인 height 전환만 위의 공용 spring을 사용한다.
- hover 시 표면이 밝아지고 클릭 시 1px 눌림, 키보드 focus는 보이는 파란 외곽선을 사용한다. touch에서 hover를 새로 강요하지 않는다. 타임라인 하단은 실제 composer 높이에 맞춰 페이드하여 글라스 뒤 글자가 겹치지 않게 한다.
- 작은 기회 카드의 빠른 액션을 우측 하단으로 옮겼다. role title·회사·근무 정보의 읽기 너비를 확보하고 desktop hover/focus에서 표시한다. 터치 화면에서는 바로 사용할 수 있다. 회사 카드 안에 버튼을 중첩하던 구조는 기존 ClickablePanel로 바꿨다.
- 자료 카드, 업로드, 문서·통화 기록, 관심 회사, 브라우저 작업, 지원 준비·검토·시뮬레이션·검색 상태에 남은 예전 표면을 정리했다. 온보딩 선택 카드와 완료 말풍선도 같은 토큰을 사용한다. 브랜드 Face 그림은 기존 자산을 유지한다.
- 자료 업로드의 native file input은 sr-only로 두어 Tab 접근을 제공한다. 온보딩 선택은 aria-pressed로 알리고 중첩된 checkbox 버튼을 비대화형 체크 표시로 바꿨다. 서브 탭의 선택 표면도 흰색으로 통일했다.
