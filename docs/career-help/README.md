# Career Help System — RAG Corpus

## Purpose

This directory contains the mdx corpus for Harper's in-app help system. Content is organized by UI surface and feature, indexed for semantic search (RAG), and served to users within the Career workspace via an in-app help panel.

## Format & Structure

Each mdx file follows this structure:

```mdx
---
title: "<Korean title for the doc>"
ui_target: "<dotted slug, e.g., right-panel.match-button>"
category: "right-panel" | "chat" | "general"
---

## <H2 heading per concept; chunking happens at H2>

<Korean explanation paragraph(s).>

<Optionally a short usage hint.>
```

**Frontmatter fields:**
- `title` — Korean title describing the UI element or feature
- `ui_target` — Dot-separated slug identifying the component/feature (e.g., `chat.voice-input`, `right-panel.settings-button`)
- `category` — One of: `right-panel`, `chat`, `general`

**Content guidelines:**
- Each file: 100–400 words per H2 section (RAG chunk size)
- One file = one UI element or feature concept
- All content in Korean (consistent with product UI)
- Heading hierarchy: H2 sections only (chunking points)
- No speculation — describe what the UI does based on actual component code
- All drafts include a final comment line: `<!-- Draft: auto-generated. Pending human review per Stage 4.2 quality gate. -->`

## Indexing Pipeline

To index all help documents for RAG:

```bash
pnpm index:help -- --all
```

Indexed documents are stored in the vector database and served to the in-app help retrieval system.

## Quality Gate (PR Process)

Before merging help docs to production:

1. **Draft phase** — Files created with auto-generated content and `<!-- Draft: ... -->` marker
2. **Human review** — Assigned reviewer verifies:
   - Accuracy against actual component behavior
   - Korean terminology consistency with UI/product
   - Tone and clarity for non-technical users
   - Completeness (no gaps or speculation)
3. **Merge** — Remove draft markers after approval
4. **Index** — Run `pnpm index:help -- --all` to rebuild RAG vectors

See `.github/pull_request_template.md` for PR checklist fields related to help content.
