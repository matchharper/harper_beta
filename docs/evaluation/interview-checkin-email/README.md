# 인터뷰 전후 이메일 작성 미리보기

2026-10-23 사용자 요청: 인터뷰 시작 **2시간 전**, 예정 종료 **15분 후**에 각 수신자의 원본 Harper LLM이 연락한다. 분량을 제한하거나 고정 양식을 강제하지 않는다. 현재는 작성 프롬프트를 검증하는 미리보기이며 자동 스케줄러 구현·운영 활성화·배포를 뜻하지 않는다.

현재 품질 판정: 사용자에게 발송한 v4 회사 사후 본문은 지난 약속을 앞으로 있을 일정처럼 설명해 실패했다. 아래 과거 assistant 검토를 품질 승인으로 해석하지 않는다. 공통 지침의 충돌·중복과 기준 시각 전달을 수정했고, 최종 v6의 `gpt-6-luna` 8건을 직접 검토했다. [수정 근거·실행 결과·한계](reports/2026-10-23-prompt-reset.md)를 따른다. 추가 발송·운영 배포는 없다.

후속 v6는 같은 8개 상황의 목적을 업무 지시만 남기도록 줄이고, 다음 일정 선택 요청을 받을 사람이 후보자임을 명시한 입력 버전이다. v4/v5의 본문·실패·gold는 보존한다. 공통 작성 지침은 한 원본에서 담당하고, 미관측 여부를 나타내는 내부 boolean 대신 약속 시각과 실제 받은 소감·요청을 입력한다. Canonical runner의 버전 인자에 `v6`를 사용하며 모델·reasoning·안전 경계는 아래와 같다.

- 목적/평가 단위: 수신자 한 명의 인터뷰 전후 이메일 한 통. 정보의 정확성, 가벼운 맥락 연결, 유용한 선택적 다음 도움을 확인한다.
- 동결 입력과 gold: `cases-v1.json`/`gold-v1.json`/`manifest-v1.json`과 후속 v2–v6. 공개 fixture는 모두 합성·비식별 예시다. 변경할 때 새 dataset version을 만든다. v5는 영어 사후, 자정 경과 사후, 이미 소감·연락 보류 의사를 받은 사후 3건이며 첫 실행 전에 gold를 고정했다. v6는 기존 5건과 이 3건의 목적·기능 설명을 정리한 8건이다.
- 입력 계약: 확인된 일정, 수신자에게 공개 가능한 상대 정보, 최근 대화, 현재 시각, 가능한 후속 도움과 실제 수행 사실. 예정 종료 시각 경과는 참석·인터뷰 완료의 증거가 아니다. 프롬프트에 완성된 이메일이나 필수 성공 문장을 넣지 않는다.
- Canonical runner: `scripts/previewInterviewCheckinEmails.ts`. 실제 Career prompt builder + email adapter + talent completion과 회사 공통 email prompt builder + company completion을 사용한다. 이 미리보기는 주어진 합성 사실로 작성만 수행하며 DB·도구 실행은 차단한다. 운영에서의 기존 turn/일반 도구 연결은 별도 구현 대상이다.
- 실행: `TSX_TSCONFIG_PATH=scripts/tsconfig.json node --import tsx scripts/previewInterviewCheckinEmails.ts <fresh-run-id> [v1|v2|v3|v4|v5|v6]`. `--case <id>`로 한 사례만 선택할 수 있다. 사용자 제공 참고 사례는 `--context-file <task/private/file.json>`로만 전달하며 입력 hash와 실제 입력을 ignored run에 보존한다.
- 모델 설정: 기본은 일반 talent-side `resolveCareerTextChatModel(null)`과 `resolveOrgAgentModel(undefined)`의 모델·reasoning이다. 명시적 `--model gpt-6-luna`는 이번 사용자 요청의 모델 실험을 지원한다. 최대 출력 16,384 tokens, timeout 180초, 실제 모델/usage와 조립된 prompt·source hashes는 run에 보존한다. 기존 원본 LLM의 prompt와 completion helper를 사용하며 별도 문체 원본을 만들지 않는다.
- 지표/gate: 제목·본문 구조 검증 외에는 해당 run의 이메일 전체를 직접 읽는다. 사실 날조·참석/합격/발송 단정·비공개 정보 공유·무단 다음 인터뷰 실행 0건. 상대 맥락을 자연스럽게 활용하고 연락 목적에 맞는 내용을 제공하는지 판단한다. 질문이나 다음 제안은 선택이며 특정 단어·문장 수·길이로 품질을 점수화하지 않는다.
- Provenance/privacy: 사용자의 2026-10-23 요청으로 합성 회사·후보자·인터뷰를 작성했다. 실제 후보자/회사 데이터와 운영 DB는 읽거나 수정하지 않는다. 모델 원문·전송 영수증·수신 주소는 ignored `runs/`에만 0700/0600으로 보존한다.
- 발송: runner는 생성만 수행한다. 검토한 저장본만 사용자가 지정한 주소에 기존 Harper sender/renderer를 통해 별도 전송한다. 제목에 테스트·수신자 관점·시점을 표시한다. 실제 인터뷰 초대/캘린더 생성/회사 메시지/추천 생성은 하지 않는다.
- 한계: 소규모 작성 품질 미리보기이며 자동 시각 실행, 일정 변경 경쟁, 권한 조회, 이메일 답장 연결, production end-to-end 검증이 아니다. 테스트 메일은 합성 이메일임을 명시하고 운영 reply alias를 만들지 않는다. 무응답 추가 독촉이나 인터뷰 종료 추정도 구현하지 않는다.

## 입력·실행 후속 기록

- v1은 불필요한 공유 안내와 장문을 보였다. v2는 같은 합성 인터뷰의 목적과 가능한 도움 사실을 간결하게 바꿨고 기존 의미 gold는 유지했다.
- 최초 v2의 후보자 사전 메일이 회사 담당자를 수신자로 혼동했다. 해당 결과는 발송하지 않았다. 수신자를 명시하고 인터뷰 사실을 회사 요청 필드와 분리했다. 공통 이메일 지침은 유지하되 진행 중인 지원서가 없는 연락에 지원서 작성 예시를 넣지 않았다.
- `v2-context`까지는 이메일 답장 전용 Haiku 설정이었다. 사용자가 요구한 일반 talent-side 중심에 맞춰 `v2-talent-default`는 일반 Career 기본 모델을 사용한다. company-side는 공통 기본 모델이다. 각 run은 원본과 설정을 보존하며 출력 후처리는 하지 않는다.

## 2026-10-23 검토·사용자 테스트 발송

- 최종 run: `preview-20261023-v2-talent-default`. 후보자 2통은 일반 Career 기본 `claude-sonnet-5-5`, 회사 담당자 2통은 company-side 기본 `gpt-6.1-sol`로 실제 생성했다.
- 4통 원문을 직접 검토했다. 상대 정보·대화 주제 보존, 예정 시각과 실제 참석 구분, 후속 일정 요청은 제안으로 유지, 미실행 발송·회사 결정 주장 없음. 후보자 사후 메일은 더 간결하게 다듬을 여지가 있으므로 사용자 수신 후 피드백을 받는다. 독립적인 human gold 검증이나 출시 gate 통과를 뜻하지 않는다.
- 사용자가 명시한 한 주소에 최종 작성본 4통을 기존 Harper 발신자와 이메일 renderer/Resend 경로로 전송했다. 테스트 표시는 메일 제목과 본문 밖 안내에 추가했고 LLM 본문은 직접 수정하지 않았다. 원문·payload·provider ID와 수신 주소는 ignored run 안에만 있다.
- 자동 scheduler, DB·제품 코드, 운영 설정, 배포, 실제 인터뷰/후속 일정, reply alias는 변경하지 않았다. 본문은 작성 예시이며 테스트 회신이 합성 인터뷰에 연결되지는 않는다.

## 사용자 정정: 리마인드 중심 v3

- 사용자는 v2의 내용·템플릿 느낌을 거절했다. 앞선 assistant 검토는 사용자 품질 승인이 아니다. 리마인드 이유와 일정이 먼저 이해되고, 상대의 관련 배경·미팅 링크·자연스러운 끝인사가 있는 짧은 연락을 선호했다.
- v3 입력/gold/manifest는 첫 실행 전에 새로 동결했다. 기존 합성 인터뷰를 유지하면서 목적을 질문 코칭에서 약속 리마인드로 수정했다. 공개 fixture 링크는 reserved example.com이며 실제 사용자 제공 Meet 링크와 인물 사실은 private reference에만 둔다.
- 회사 공통 outbound 이메일 지침에서 이유 중심 제목과 자유로운 인사·끝인사를 사용한다. 후보자 이메일 adapter에 일반 outbound mode를 추가해 답장용 서명 금지와 무관한 지원서 작성 예시를 분리했다. 기존 reply mode는 유지하며, 본문에 정형 인사·서명을 코드로 붙이지 않는다.
- `preview-20261023-v3`의 합성 4통을 읽었다. 회사 연락은 리마인드 맥락·링크·끝인사를 제공했다. 후보자 메일은 여전히 장문·추가 제안이 있어 사용자 요구 수준으로 완료했다고 판단하지 않는다. 해당 4통은 추가 발송하지 않았다.
- 사용자 참고 사실만 넣은 영어 회사 사전 샘플은 별도 실행했다. 첫 reference 입력에 임의 45분 종료 시각이 들어간 것을 발견해 발송하지 않고, 종료 시각을 제거한 private v2로 재실행했다. 실제 일정 조회나 변경은 없다. 최종 본문·발송 근거는 `preview-20261023-v3-reference-no-end`에 보존한다.
- 기존 이메일/회사 프롬프트 관련 검사 13개 통과. 자동 스케줄러·운영 DB·배포는 수행하지 않았다. 회사 사전 메일 한 통의 검토·발송은 전체 네 종류의 문체 품질 완료나 실제 예약 실행 검증이 아니다.

- v3 회사 사전 reference 수정본 한 통을 사용자가 지정한 기존 테스트 주소에 실제 발송했다. 사용자 제공 사실과 URL을 바탕으로 한 예시임을 표시했고, 작성된 본문은 그대로 사용했다. 전송 영수증은 해당 ignored run에 보존한다.

## 사용자 정정: 길이 제한 없음 · Luna 5통

2026-10-23 사용자가 텍스트 길이는 문제가 아니라고 명시했다. 위 v3에서 길이 때문에 미완료로 판정한 것은 assistant의 잘못된 해석이며 철회한다. v4는 길이를 평가 기준으로 삼지 않고 맥락·사실·자연스러운 자유 형식을 확인한다. 기존 frozen v1–v3는 이력으로 보존한다.

`previewInterviewCheckinEmails.ts <run> v4 --model gpt-6-luna --context-file <task/private/luna-five-v1.json>`으로 5통을 생성한다. 후보자 전후·회사 전후 한국어 4통과 사용자 참고 사실의 영어 회사 사전 1통이다. 기존 원본 LLM별 prompt와 실행 helper를 재사용하고 모델만 이번 요청대로 지정한다. 모델이 다른 값으로 바뀌면 중단하며 실제 모델·reasoning·원문을 manifest에 기록한다. 후보자 Luna는 기존 xhigh, 회사 Luna는 기존 medium 설정이다. 운영 기본 모델·예약 발송은 변경하지 않는다.

- `preview-20261023-v4-luna-five`에서 5통 모두 실제 `gpt-6-luna`로 생성했다. 전부 읽어 제공된 사실·수신자·참여 링크와 미실행 후속 행동의 구분을 확인했다. 분량을 이유로 수정하거나 다시 생성하지 않았다.
- 사용자가 지정한 기존 테스트 주소로 원문 5통을 전송했고, provider의 `delivered` 상태를 각각 확인했다. 제목에 1/5–5/5, 모델명, 수신자 관점과 시점을 표시했다. 원문·실제 입력·전송 영수증은 ignored run에만 보존한다. 사용자 문체 승인이나 자동 예약 기능의 운영 검증을 뜻하지 않는다.
