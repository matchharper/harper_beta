## 변경과 판단

지원 준비의 원본 대화 LLM이 사용자의 질문 답변을 근거로 이력서 사본과 실제 지원 항목을 같은 턴에 저장하도록 지침을 정리했다. 같은 사실을 새 문구로 작성했다는 이유만으로 다시 승인을 받지 않는다. 사용자가 직접 고친 문구·거절한 수정은 보존하고, 별도 제안만 요청한 범위도 지킨다. 민감 정보·법적 자격을 추론하거나 동의를 대신 선택하지 않는다. 외부 제출 승인은 기존 엔진이 계속 담당한다.

첫 제안, 후속 대화, 저장 결과, 제출 결과에 공통 사용자 문체 지침을 적용했다. 정상적인 접속·로그인 불필요·CAPTCHA 미관측 등의 내부 관측을 보고하지 않고, 준비한 결과와 실제 필요한 다음 행동을 설명한다. 도구 호출 뒤 공통으로 주입되던 즉시 답변 지침도 아직 맡긴 작업이 남아 있으면 계속 실행하도록 수정했다. 운영용 후처리 검열·별도 LLM·숨은 재시도는 추가하지 않았다.

답변 payload에 기존 application의 참조 ID만 저장하고, 메시지 변환과 새로고침에서 보존한다. 지원서는 해당 답변 아래에 직접 렌더링한다. 이전 저장본은 해당 이력서의 정확한 문서 링크가 있는 답변에 연결하며, 공고 상세 재열기는 기존 모달을 유지한다. 배경은 neutral-50, 체크박스·라디오에는 공통 UI를 사용한다. 수정 후 제출 확인을 누르면 먼저 최신 revision으로 저장하며, 제출 확인 중에는 첨부 파일을 흐린 선택창 대신 읽을 수 있는 파일 링크로 표시한다.

## 건너뛰기와 위임 작성 수정, 다른 공고 확인 — 2026-10-29 오전 후속

건너뛴 응답은 저장되어 있었지만 `finishApplicationAnswer`가 skip을 action의 완료된 선택으로 반영하지 않아 pending으로 남았다. skip을 skipped로 끝내고, 이미 제출한 batch에서 자동 후속 호출이 선택을 다시 열지 않도록 했다. 기존 pending+skip 데이터는 세션 reader에서 호환 해석하며 DB backfill은 하지 않는다. 원본 LLM에는 건너뛴 제안의 범위도 남겨, 추가하지 않기로 한 경력 사실이 다른 지원 문서에 이동하지 않도록 했다.

일반 지원 자료는 기존 `write_document`로 저장하고 기존 application review에 문서 ID·제목을 연결한다. `ready_for_role`는 첨부 소유권을 이력서 생성 전에 확인해 잘못된 문서 ID가 불필요한 사본을 남기지 않도록 한다. 재사용 호출의 사용하지 않는 부가 metadata 때문에 폼 저장이 거부되던 검사는 제거했다. 실제 content/changes를 reuse로 보내 조용히 버리게 되는 충돌만 계속 거부한다. 기존 이력서 작성 정책의 '수정 내용을 설명하라'는 지침은 지원 준비에서는 공통 전달 지침을 따르게 했다. 폼 필드가 없는 카드와 실제 편집 가능한 폼의 사실 projection도 구분했다. 출력 검열·고정 성공 문장·별도 심사 모델은 추가하지 않았다.

실제 사용자 Chrome에서 기존 반복 공고를 제외하고 현대카드 Agentic AI, Neon Postgres에 저장된 Databricks AI FDE, 멘타트 FDE를 차례로 새로 시작했다. 사용자에게 사실 답변을 지어 넣지 않았고, 현대카드의 원문 기반 RAG 설명 한 건만 적용했다. 나머지 확인되지 않은 경력·날짜·경험은 건너뛰었다. 정확한 record ID·시각과 스크린샷은 ignored `runs/live-browser-2026-10-29-diverse/`에 보관한다.

- 멘타트: Wanted 원문 외에 회사/ATS 직접 공고를 선택하지 못해 초기 조사 중단. 이 역시 로그인 장벽을 관측한 결과가 아니며, 필드 0개를 '추가 요건 없음'으로 해석하지 않는다. 로컬에서 3개 skip 선택 후 저장 오류가 났고 재시도도 최종 저장으로 이어지지 않았다. DB에는 12:10:36 KST에 이미 status=ended, endReason=user로 종료된 기록이 있었으며 응답은 비어 있고 최종 문서도 없다. 누가 어느 화면에서 종료했는지는 확인하지 못했으므로 skip 로직의 새 실패로 확정하지 않는다. 종료된 지원을 임의로 재개하지 않았고 이 사례는 준비 완료 전 중단으로 기록한다.

Frozen delegated-v1/v2의 실제 Haiku 실행에서는 일반 프로젝트 문서 작성·저장·첨부, 폼 답변 작성, 포트폴리오 원본만 별도 요청, 건너뛴 새 경력 제외를 검사했다. 실패 run(재사용 부가정보 거부, 잘못된 첨부 ID와 구조 경로, 장황한 안내)은 보존했다. 12:05 시작 v2 4개는 tool error 없이 저장까지 완료했고 12:08 로그인 사례도 재실행했다. 실제 provider 요청의 read/write/ready 결과가 텍스트 projection임을 확인했다. 그러나 최신 답변도 문서 내용을 불필요하게 요약하는 경향이 남아 **정성 품질 전체 통과로 판정하지 않는다**. 네 사례는 독립 holdout이나 실제 ATS 제출 검증이 아니다.

핵심 단위 검사 28개 통과, 마지막 변경의 15개 재검사 통과, 변경 파일 lint와 diff 검사 통과. 웹·Worker 배포, schema/migration 변경, 회사 제출은 하지 않았다. 실제 브라우저에서는 private 지원 준비와 문서만 저장했다.

종료된 활동의 waiting 질문 batch를 그대로 화면에 넘겨 '답변을 기다리고 있어요'가 남는 표시 문제도 확인했다. `applicationQuestionMessages`의 UI projection에서 종료된 활동의 미완료 질문을 기존 cancelled 상태로 표시한다. durable batch와 답변은 변경하지 않아 나중의 명시적 resume 가능성은 보존한다. 이는 실제 종료 사실을 보여주는 변경이며 답변 실패 원인을 추측하는 LLM 필터가 아니다.

종료 표시 수정 후 실제 Chrome을 새로고침해 멘타트 질문이 기존 취소된 질문 표시로 바뀌고 답변 대기 문구가 사라지는 것을 확인했다. 세 공고 목록과 결과 화면을 private result.png에 보관했다.
