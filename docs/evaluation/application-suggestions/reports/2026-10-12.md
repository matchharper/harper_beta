# Apply with Harper v6 로컬 검증

배포 전 작업 트리 기준. 실제 회사 지원·회사 연락·production 후보자 데이터 접근 없이 synthetic fixture로 검증했다.

후속 전체 재점검에서 시작 버튼의 권한 검사 오류를 발견해 수정했다. 아래 최초 검증은 실제 시작 요청 전체를 검증했다는 뜻이 아니다. 최신 수정·180개 테스트의 실행 범위·추가 모델 평가·데스크톱 검증은 [후속 재점검 기록](../../../testing/apply-with-harper-review-20261012-ko.md)을 따른다.

## 모델 출력 검토

| 평가 | 최종 run | 결과 |
| --- | --- | --- |
| 첫 suggestions 3건 | `2026-10-12T09-41-43-244Z` | 3/3 구조 및 의미 기준 충족. 기존 이력서의 확인된 사실만 개선, 실제 필수 연락처 질문, 실제 요청된 추가 답변 작성, 미확인 경험 질문으로 분리 |
| 후속 대화 3건 | `conversation-2026-10-12T09-50-18-996Z` | 3/3 최종 행동 기준 충족. 직접 수정은 재확인 없이 copy, 새 경험은 하나의 새 문구 제안, 세 번째 round skip은 기존 이력서로 종료 |

첫 batch는 runtime GPT_6_LUNA_MODEL, 후속 대화는 runtime 기본 Career 모델 `claude-sonnet-5-5`를 사용했다. 원문·호출·설정·hash는 각 ignored `runs/<run>/`에 보관한다. 수동 의미 검토이며 키워드 판정이나 시나리오별 runtime 분기를 추가하지 않았다. 평가 fixture/gold는 최초 버전 그대로 유지했다.

후속 대화 마지막 case에서 첫 호출은 빈 resume 객체를 보내 구조 검증에 실패했고, 모델이 resume 속성을 생략한 호출로 수정해 완료했다. 최종 성공 3/3은 모든 첫 tool call이 성공했다는 뜻이 아니다. 3건만으로 실제 사용 전체의 품질이나 반복 상한 준수를 보장하지 않는다.

이전 run에서 발견해 일반 prompt/tool 계약으로 수정한 문제: UI 언어 불일치, 의미 없는 동의어 교체, 알려준 경험을 확인되지 않은 회사에 귀속, 새로운 문구를 검토 없이 반영, 후속 단계에서 불필요한 추가 개선 시작, ready 명령의 metadata 위치. 이전 결과도 덮어쓰지 않고 runs에 유지한다.

## 실행 및 UI 확인

- 선택한 이력서 start card, 서버 직접 준비 시작, 실제 4단계 progress, v6 suggestion batch 연결을 코드 경로로 확인.
- 자동 테스트: suggestion 구조/결정, 원문과 편집 응답 snapshot, 선택 답변 batch의 원자적 저장·중복 방지·새로고침, 도구 노출/중단·예산, 원본 보존과 비공개 이력서 저장·revision·fingerprint, 브라우저 제출 승인 경계를 검증.
- 실제 PDF를 synthetic 로컬 지원 양식에 첨부하고 승인된 제출을 완료하는 기존 resumeAttachment integration test 통과.
- 실제 Chrome 1280×900 및 390×844에서 Composer·Start·진행 UI 확인. 숫자 1/2, 위아래+Enter, 즉시 좌우 이동, 180ms 선택 표시, inline 편집, 입력 중 단축키 차단, 선택 해제, 마지막 응답/skip의 전체 제출 확인. 모바일 가로 넘침과 page error 없음.
- 변경 범위 lint 및 최종 전체 타입 검사 통과. 전체 번역 검사는 이번 변경 밖의 CareerPriorityReviewDevControls/TalentCareerModal에 있는 미등록 키 22건으로 실패하며, 새 구현 파일의 미등록 키는 없다. 이 작업의 새 번역 10개는 ko/en 20행만 scoped sync했다.

## 확인 범위와 제한

DB 저장 테스트는 소유권 조건을 검사하는 fake admin으로 실제 resume service를 실행했다. 대화 평가의 ready 저장은 in-memory executor이므로 실제 문서 저장 검증과 구분한다. 지원서 조사와 실제 ATS 제출은 기존 Agents API 실행 경로를 재사용하지만 이번 검증에서 실제 회사에 지원하지 않았다. 로그인/CAPTCHA/지원하지 않는 필수 항목은 수동 완료 링크가 필요할 수 있다. 배포 및 Notion 동기화는 수행하지 않았다.
