# 범용 이력서 편집 기준 검토 · 2026-10-14

이력서 생성 → 최초 제안 → 후속 제안/승인 → 저장 경로를 확인하고, 공통 편집 기준을 작게 보강했다. 특정 직군이나 도구에 대한 runtime 분기는 추가하지 않았다. 이번 변경은 로컬·미배포이며 운영 계정 수정, 회사 연락, 지원 제출이 없다.

## 변경

- 독자의 관점에서 핵심 책임과 후보자의 강한 근거를 먼저 고른다. 필수 자격의 충족과 이력서에서 강조할 비중을 구분한다.
- 기여·판단·결과를 직무에 맞게 전달하고, 정량 성과를 일률적으로 요구하지 않는다. 수치의 집계 대상·단위·기간·귀속과 실제 직함·자격을 지킨다. 관련 사실이라는 이유만으로 모든 메모를 삽입하지 않는다.
- 원문 대비 명료성과 정보 가치의 순이익을 판단한다. 이미 좋은 문장, 유용한 경력, 원래 언어를 보존하며, 불필요한 수식어나 비보유 자격 설명은 개선으로 보지 않는다.
- 같은 원문의 관련 수정은 하나의 제안으로 묶고 각 제안을 독립적으로 승인/거절할 수 있게 한다. 승인된 문구는 임의로 고치지 않는다.
- 신규 생성에 확인된 연락처·전문 링크를 포함하며, 기존의 일률적인 한 페이지 우선 지침을 경력·실제 제출 요건에 맞는 분량으로 바꾼다. 기존 schema/renderer는 변경하지 않는다.
- 후속 대화의 기존 완료 지침을 앞쪽으로 이동했다. 사실 답변 → 공유 사실 저장 → 새 문구의 실제 검토 batch → 승인된 문구 저장 계약을 유지한다.

공통 책임 원본: `src/lib/career/prompts/resumePolicy.ts`의 `RESUME_EDITORIAL_CONTRACT`. 최초 writer와 후속 preparation prompt가 import하며, 일반 생성 tool policy도 같은 계약을 사용한다. preparation의 tool policy에 같은 긴 계약을 중복 주입하지 않는다. 정성 판단은 LLM prompt에서 수행하며 키워드 판정·후처리·별도 평가 LLM·새 상태/테이블을 추가하지 않았다.

연구 근거는 [17개 공식 자료를 교차검토한 문서](../../../research/resume-writing-evidence-and-application-prompt-review-ko.md)에 보관한다.

## 동일 입력 비교

Frozen synthetic `editorial-v1` 7사례. Sonnet 5.5, temperature 0.2, 실제 writer/tool/output 계약, read-only fixture. baseline은 `runs/2026-10-14T03-43-15-561Z`이며 마지막 run은 아래에 기록한다. 입력/gold는 baseline 전에 동결했고 수정하지 않았다. 여러 보강 run은 같은 gold에 대조했다. 한 사례/직군의 비맹검 수동 검토로 평균 개선율이나 실제 선발 효과를 추정하지 않는다.

최종 run: `runs/2026-10-14T03-51-19-838Z`. 구조 7/7 통과. 전체 원문을 frozen gold와 직접 대조했으며, 아래의 경고 때문에 모든 정성 release gate를 무조건 통과했다고 판정하지 않는다.

| 직군/사례 | 수정/질문: baseline → 최종 | 원문 검토 |
| --- | --- | --- |
| engineering | 2/2 → 1/2 | 마이그레이션·복구 시간·롤백·코칭을 한 제안으로 통합. 실제 직함과 숫자 보존. 기존 일반적인 서비스 구축·유지 문구가 빠지는 편집의 이득은 별도 판단 여지. |
| design | 2/2 → 1/2 | 인터뷰·프로토타입·출시 협업·접근성의 질적 근거를 반영. 숫자 성과를 만들지 않음. 이미 충분한 근거가 있는데 모션 우대 질문은 가치가 낮을 수 있음. |
| product | 2/1 → 2/2 | 21%→28%를 롤아웃 기간 변화로 정확히 보존. 범위 협상도 반영. 인과관계 미확인 설명을 이력서에 직접 붙이는 것은 정확해도 문장 품질 측면에서 약함. |
| legal-corporate | 2/3 → 3/2 | 실제 한국 자격 유지, 기밀 공개 없음. 자회사·플레이북·에스컬레이션 근거 반영. 원문보다 넓은 Identified라는 행위가 추가되어 엄격한 근거 기준에서는 주의가 필요. |
| founder | 2/2 → 1/3 | 고객 검증·출시·유료 고객·공동창업자·확장 보류를 한 제안으로 통합, 기존 운영 경력 보존. prioritizing resources over further growth는 사실에 대한 해석이 추가된 표현이므로 원문보다 강한 주장인지 점검 필요. |
| sales | 1/2 → 2/2 | 최종은 14건 수주 지원과 $920k ARR book을 구분하고 공동 기여 보존. 중간 run의 14건 합계 ARR로 잘못 묶던 표현은 해소. quota·enterprise·CRM 보유를 만들지 않음. |
| already-strong | 0/1 → 0/1 | 수정 0개 유지. 중요한 미확인 필수 자격에만 질문 1개. 제안 수를 채우기 위한 재작성 없음. |

최종은 같은 원문에 대한 중첩/다른 수정안 의존이 없었고, 실제 직함·자격의 변형과 private 사유 공개도 없었다. 수정 수가 감소한 사례는 연관 근거를 통합한 결과이며 개수를 품질 점수로 해석하지 않는다. baseline도 이미 여러 유용한 제안을 했으므로 모든 직군에서 이전보다 낫다는 결론은 아니다.

남은 정성 한계: 우대 조건을 이유로 낮은 가치의 질문을 하는 경향, 사실에 맞지만 불필요한 한계 설명, 원문보다 넓어진 행위·판단 표현. 이번 변경은 범용 기준과 저장 동작을 보강했지만 이러한 판단 오류를 완전히 해결하지는 않았다.

## 중간 실패와 보강 근거

모든 중간 run을 ignored `runs/`에 보존했다. 출력의 구조 통과만으로 의미 품질을 통과로 처리하지 않았다.

- 첫 보강에서 법무 자격에 비보유 미국 자격을 추가하는 제안이 나왔다. 편집상 제약과 실제 이력서 내용의 구분을 공통 계약에 명시했다.
- 한 엔지니어 제안이 다른 수정안이 만든 문구를 originalText로 삼았고, founder의 두 제안이 같은 원문을 서로 다르게 대체했다. 수정 제안은 선택적으로 승인되므로 독립적인 원문 기준과 하나의 원문에 대한 통합 제안을 명확히 했다.
- sales에서 포트폴리오(book) 전체 ARR을 14건 수주의 합계로 묶는 문제가 반복됐다. 수치의 원래 집계 대상과 이를 정의하는 명사·한정어를 보존하고, 명시적으로 연결되지 않은 숫자는 따로 쓰도록 보강했다. 최종 run에서는 ARR book과 수주 지원의 구분을 유지했다. 한 번의 성공으로 모든 수치 귀속 문제가 해결됐다고 해석하지 않는다.
- 후속 Haiku 두 실행은 말로만 문구를 제안하고 실제 검토 batch를 만들지 않아 scripted 승인을 계속할 수 없었다. `journey-2026-10-14T03-44-34-616Z`, `journey-2026-10-14T03-45-56-650Z`는 실패로 보존했다. 기존 완료 지침을 앞으로 옮긴 뒤 `journey-2026-10-14T03-46-57-675Z`, `journey-2026-10-14T03-49-53-259Z`에서 사실 저장 → review → 승인 → 실제 문서 저장이 완료됐다.

## 저장과 회귀

- 기존 `memory-v2`를 실제 Haiku 5.5/production 도구와 격리 adapter로 실행했다. 최신 확인 run은 `journey-2026-10-14T03-49-53-259Z`: 개인 프로젝트 사실을 Memory에 저장, 영어 원문에 별도 프로젝트 제안, 승인 후 사본 저장, 원래 회사 경력·학력·연락처 보존. 다음 역할의 초기 writer가 이전 대화 없이 저장된 사실을 제안으로 재사용했다. 추가 질문과 최종 안내는 다소 장황하여 완전한 문장 품질 보장은 아니다.
- 업로드 원본/승인 문구 저장은 `journey-2026-10-14T03-46-15-260Z`에서 실제 `ready_for_role`과 resume service로 확인했다. 승인 문구만 바뀐 사본을 생성하고 원본·학력·연락처를 보존했다. 마지막 수치 지침 변경 전 실행이며 renderer·실제 DB를 검증한 것은 아니다.
- 기존 초기 `v1` 3사례는 `2026-10-14T03-49-53-935Z`에서 구조 통과 3/3. 필수 LinkedIn 질문, 실제 관측된 지원 동기만 초안, 알려진 이메일 재질문 없음, 미확인 ML 경험과 민감 정보 구분을 원문으로 확인했다. 최신 수치 지침 변경 전 실행이다.
- 관련 단위 검사 16/16, 변경 파일 lint 통과. 단위 검사는 승인·원본 보존·native 저장 명령과 구조 상한을 검증하며 정성 품질의 자동 보장은 아니다. 처음 실행은 API 환경 누락, 다음은 server-only alias 누락으로 실행 설정이 실패했고, 저장된 `.env.local`과 기존 `scripts/tsconfig.json`을 사용한 정상 실행 결과로 구분했다.
- 전체 TypeScript 검사는 다른 파일의 가입 상태 타입 및 nullable 값 오류로 실패했다. 이번 4개 변경 파일에 대한 오류는 없었다. 무관한 오류를 수정하지 않았다.

## 해석 범위

합성 사례의 입력 사실과 reviewer rubric은 assistant 작성이며 독립 human gold가 아니다. 실제 회사 공고, 데이터 조회의 recall, 폼 조사·ATS 접수 성공률, PDF 시각 품질은 이번 범용 편집 benchmark로 판단하지 않는다. 직군별 예시는 평가 coverage이며 runtime 분기나 필수 섹션 규칙이 아니다. 최대 수정 7개/질문 3개/전체 10개는 상한으로 유지한다. 4~5개를 채우는 것을 성공 기준으로 삼지 않는다.
