# Career 프롬프트·화면 후속 점검

2026-11-14. 기존 Career 구현 위에서 수행한 로컬 개선이다. 배포·운영 DB 변경·실제 지원·발송은 수행하지 않았다.

## 발견과 수정

1. **저장한 결과를 다시 여는 연결이 빠져 있었다.** 텍스트 채팅 지침은 기존 Role의 `[posting]` 카드만 설명했고, 일반 기회·비교 도구는 화면 주소를 반환하지 않았다. 첫 비교 실행은 별도 홈 할 일을 만들어 다시 질문하는 우회로를 만들었다. 도구가 정확한 workspace path를 반환하도록 하고, 원본 화면 지침을 실제 상대 경로를 연결하는 계약으로 수정했다. 일반 기회 ID를 Role ID로 해석하지 않는다.
2. **검토용 지원 초안의 언어를 대화 언어와 혼동했다.** 영어 채용 원문을 읽고도 한국어 지원 문안을 만들었다. 기존 언어 문단을 수신자·용도 기준으로 명확히 고쳤다. 채팅에서 검토하는 외부용 초안도 동일한 기준을 사용하며, 사용자에게 하는 설명은 대화 언어를 유지한다. 별도 언어 판별기나 재작성 호출은 추가하지 않았다.
3. **모델이 정한 섹션 제목이 사라졌다.** view 도구 스키마에는 title이 있었지만 narrative 저장 파서가 버렸다. 제목을 보존하고 실제 화면에 표시하도록 맞췄다. view 반환값도 섹션·원문·근거·선택·실행 요청을 읽을 수 있는 전용 텍스트로 제공한다.
4. **근거가 익명 번호로 보였다.** 현재 접근 가능한 원문의 제목과 도메인을 표시하고 정확한 버전으로 이동한다. 상세 원문과 같은 소유자별 Query 캐시를 사용한다. `format=resource` 읽기는 기회 등의 전용 화면 DTO와 근거 DTO를 구별하며 기존 서버 접근 검증을 그대로 거친다.
5. **모바일에서 비교 내용이 잘렸다.** collection의 회사명이 한 글자씩 꺾이고 본문 Markdown 표의 마지막 열도 잘렸다. collection과 본문 표 모두 모바일에서 항목과 열 제목을 함께 읽는 세로 배치를 사용한다. 데스크톱은 표를 유지하고 원문 값·링크·하나의 table DOM을 보존한다. 공용 RichText의 선택적 `responsiveTables`를 사용하며 다른 화면의 기본 렌더링은 유지한다.
6. **저장함의 링크와 읽기 흐름을 정리했다.** 제목의 상세 이동과 추천 이유 펼치기를 분리해 본문 링크가 바깥 링크 안에 중첩되지 않게 했다. 근거·진행 상태·다음 행동의 구획, 빈 목록, 조회 실패 후 재시도도 보완했다. 일반 기회·비교 본문의 내부 링크는 실제 라우터로 연결한다.
7. **저장 성공 후 재조회를 기다렸다.** 서버가 확정한 변경을 상세 캐시에 반영하고 목록·근거 재조회는 뒤에서 진행한다. 격리 브라우저에서 읽기에 2.5초 지연을 넣었을 때 저장된 상태와 버튼 활성화를 약 50ms에 관측했다. 운영 응답 시간 측정치는 아니다.

## 원본 모델 실행

`cases-v11.json`, `gold-v11.json`, `manifest-v11.json`을 첫 실행 전에 고정했다. 공개 회사 근거는 v10의 가상 자료이고 모든 입력은 가상 시뮬레이션임을 명시한다. 실제 제품의 모델 설정·capability 선택·프롬프트·도구 스키마·실행 루프를 사용했다. 검색 원문과 저장은 격리 fixture다.

| 입력 | 수정 전 관측 | 수정 후 관측 |
| --- | --- | --- |
| 투자 뉴스보다 개발을 계속하며 기술 책임을 넓힐 기회 찾기 | 조건에 맞는 구체적인 기회를 남겼지만 직접 열기 안내 없음 | 근거·제약을 유지하면서 저장된 기회의 정확한 링크 제공 |
| 두 회사를 비교하고 다시 볼 화면 남기기 | 비교를 저장한 뒤 홈 할 일을 추가해 다시 질문하도록 함 | 비교 화면으로 직접 연결. 추가 홈 할 일 없음 |
| 이번 탐색만 싱가포르 이전 허용, 출장 상한 유지 | 기존 검색 조건을 변경하지 않고 출장·필수 경험 불일치 설명 | 같은 범위를 유지하며 회사 전체와 현재 역할의 판단을 구분 |
| 전체 이력서·발송 없이 소개와 장애 대응 사례 작성 | 확인된 사실만 사용했지만 지원 문안도 한국어 | 영어 지원 문안과 한국어 설명. 미제공 성과 수치 없이 결과 보완 질문 |

각 입력을 수정 전후 한 번씩, **총 8회** 실행했다. 최종 답변뿐 아니라 중간 메시지, 실제 provider 입력, 도구 결과, 저장된 기회·비교·개인정보 수정·외부 실행 기록을 검토했다. 수정 후 네 실행에서 새 언어 계약이 실제 모델 입력에 포함되고, 저장 결과의 경로가 후속 입력으로 전달됨을 확인했다. 네 실행 모두 Brief/Memory 변경과 외부 실행 시도가 없었다.

실행 경로:

- `runs/2026-11-13T17-21-14-706Z-usability-baseline`
- `runs/2026-11-13T17-24-04-867Z-usability-refined`

비교 전 fixture의 view 반환은 JSON이었으므로 개선 실행에서는 실제 제품의 `formatCareerView`를 공유하도록 수정했다. 따라서 변화는 프롬프트 한 문장만의 효과로 분리해 주장하지 않는다. 새 source manifest에는 방법 handbook과 opportunity formatter도 포함한다. 별도 심사 LLM, 정성적 키워드 검사, 숨은 답변 재시도는 없다.

## 화면과 코드 검증

- 실제 모델이 저장한 비교 definition을 격리 브라우저 transport에 넣어 제품 ViewDetail로 렌더링했다. 데스크톱 1440px, 모바일 360px에서 원문·제목·표·근거 영역을 확인했다. 본문 표 너비는 수정 전 320px 영역에 344px, 수정 후 320px 안에 320px였다.
- 390px/360px 모바일에서 500개 전체 선택, 첫 항목 제외, 추가 페이지 선택 유지, 화면 이동 후 유지, 실제 위임 요청에 제외 ID 전달을 확인했다. 409 재시도의 request ID 유지와 새 revision 확인 후 재선택도 확인했다.
- 키보드 저장/해제, 숨김/복원, 정확한 원문 이동, 추천 이유 펼치기, 대화로 행동 인계, 빈 목록, 삭제/오류와 새로고침, 영어 정적 문구를 확인했다. 페이지 가로 넘침과 중첩 링크는 발견되지 않았다.
- 프롬프트·capability·도구 노출 테스트 **27개**, RichText·대화 렌더링/이동 테스트 **25개** 통과. 후자는 새로운 일반 기회/비교 링크 이동, 모바일 표의 원문·열 제목·링크 보존을 포함한다.
- Node 렌더 검사 최초 실행은 CSS module loader 부재로 실패했다. 기존 렌더 스크립트와 같은 격리 CSS 처리로 재실행했다. 기존 선택 버튼 색상 클래스와 과거 form 메시지 자체를 최신 폼으로 취급하던 테스트 두 개도 실패했고, 변경 전 RichText로 재현했다. 버튼은 선택/비활성 의미를 검증하고 폼은 현재 소유 대화의 최신 revision을 읽도록 fixture와 기대를 고쳐 25개 전체가 통과했다. 제품의 폼·선택 동작은 변경하지 않았다.
- 브라우저 프리뷰가 URL의 종류·ID·revision을 무시하던 부분도 실제 라우트와 맞췄다. 초기 검사에서 이 문제와 Next route announcer가 포함된 중복 locator로 중단한 시도가 있었으며, 수정 후 해당 동작을 다시 검사했다.
- TypeScript, 변경 파일 ESLint, `git diff --check` 통과. 관련 번역 키 **34개**의 한국어 원문 일치와 영어 존재 확인. 앞선 기록의 전역 번역 누락은 이번 확인 범위가 아니며 운영 번역 DB sync는 수행하지 않았다.

스크린샷·QA 목록·원본 실행 자료는 owner-only `runs/`에 보존한다. 이는 실제 사용자 계정/운영 DB를 연결한 전체 E2E, 실시간 시장 검색 품질, 실제 채용 성과 또는 범용 agent 대비 우월성 검증이 아니다. 해당 운영 적용 전 검증은 [구현 현황](../../../career-agent-implementation-progress-ko.md)의 남은 항목을 따른다.
