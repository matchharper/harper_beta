# FDE 지원을 처음 준비하는 ML 엔지니어

서울에서 검색 랭킹을 평가하고 추론 파이프라인을 배포한 사람이다. FDE 경력과 연결한 Gmail은 없다. 회사에 자료를 보내기 전에 내용을 보고 싶다고 했다.

| 사용자가 한 일 | 운영 화면에서 확인한 결과 |
| --- | --- |
| Cognition Korea 공고에서 ‘Harper와 지원하기’를 눌렀다. | Harper가 ML 배포 경험과 부족한 고객 협업 경험을 짚었다. 이름·이메일·LinkedIn·이력서·선택형 경험 질문이 있는 검토 폼을 만들었다. 고객과 일한 경험은 직접 물었다. 준비할 일을 고르는 목록과 Gmail 연결 제안은 없었다. |
| 다른 테스트에서 “그때 주고받은 메일에 남아 있을 것 같아요”라고 했다. | 운영 채팅에 Gmail 연결 카드가 나왔다. 메일의 필요한 부분만 복사해도 된다고 안내했다. 첫 지원 화면에는 이 카드가 없었다. |
| 고객 개발팀과 검색 지연을 재현하고 중복 계산을 고쳤다고 답했다. | 같은 비공개 이력서의 버전이 1에서 2로 바뀌었다. 실제로 받은 한 페이지 PDF에 누구와 문제를 재현했는지, 무엇을 고쳤는지, 고객 트래픽의 p95가 410ms에서 260ms로 줄었다는 사실이 들어갔다. |
| Wonderful FDE에 어떻게 소개할지 먼저 보여 달라고 했다. | Harper가 회사 소개문을 썼다. 고객 업무 분석과 AI 에이전트 구현을 지원자의 경험에 연결하고, 고객 대응 경력과 연차를 물었다. 운영에서는 채팅으로 검토했다. |
| 팀 연락처를 알려주고 “그분께 보낼 메일 써줘요”라고 했다. | 운영 메일 폼에 실제 수신자, 제목, 본문, 수정·발송 요청 버튼이 나왔다. 이 주소는 사용자가 줬다. Cognition과 Wonderful에서 연락처가 확인되지 않았을 때는 담당자 메일을 제안하지 않았다. |

## 제출과 회신

팀이 운영하는 테스트 채용 폼에서는 서로 다른 두 계정으로 Harper의 제출 버튼을 승인했다. 두 번 모두 Harper의 브라우저에 ‘Failed to fetch’가 표시됐다. 첫 실행에서는 접수처 로그에도 POST가 없었다. 중복 제출을 막기 위해 같은 지원 건을 다시 보내지 않았다. 세 번째 테스트에서는 ML 엔지니어가 36,294바이트 PDF를 첨부하고 운영 화면의 ‘확인하고 제출하기’를 눌렀다. 팀 접수처가 발급한 번호 `9bb4d89f-2887-4033-834e-ad94a1031142`가 실제 Harper 채팅에 표시됐다. 이 세 건은 웹 변경을 배포하기 전 결과다.

브라우저가 첨부 칸에서 실제 파일을 읽어 원본의 바이트 수와 SHA-256을 대조하도록 실행 계약을 고쳤다. 별도 지원 건으로 같은 운영 접수처에서 영어·한국어 파일명을 각각 사용했다. 원격 브라우저가 32,471바이트를 읽었고 각각 접수 번호를 받았다. 첫 번호는 `20f23b0e-6517-42fa-af40-e7240e98b0c4`, 두 번째는 `bccb56b6-bd50-4f84-bfd4-23eba60fc1f0`이다. 브라우저에서 직접 실행한 결과이며 이전 두 건의 오류 원인은 확정하지 못했다.

담당자 회신을 원래 지원 대화로 돌려주는 함수가 운영 DB에 빠져 있어 두 마이그레이션을 적용했다. 운영 DB 테스트에서 이미 읽은 메일과 다른 스레드의 메일은 무시했고, 같은 회신을 두 번 전달해도 원래 대화에 실행 한 건만 생겼다. 테스트를 롤백했고 실제 메일은 보내지 않았다. Gmail에 새로 도착한 합격·탈락 메일은 정기 조사가 읽어야 한다. 해당 계정의 실제 Google 권한과 받은편지함에서 시작하는 알림은 확인하지 못했다.

## 변경한 코드로 확인한 결과

- [Cognition 지원 버튼 문구](../cases-v26.json)와 새 지원 안내로 같은 모델을 두 번 실행했다. 한 번은 이력서·지원서·면접 준비를 체크박스로, 한 번은 적합성 검토를 더해 다중 선택으로 제안했다. Gmail을 연결하라는 제안은 두 번 모두 없었다.
- [Wonderful 소개와 메일 초안](../cases-v25.json)에서는 소개문과 공유할 프로필, 또는 수신자·제목·본문을 폼으로 검토했다. 실제 회사에는 전송하지 않았다. [메일에서 개인 경험을 찾고 다음 지원에 재사용한 실행](2026-11-16-private-application-evidence.md)은 테스트 사서함을 사용했다.
- 테스트 접수 화면의 개인정보 동의가 미리 선택된 경우를 발견했다. 새 동의 입력은 초안에 모델이 참을 넣어도 사용자에게 빈 체크박스로 보인다. 일반 체크박스는 기존 답을 표시할 수 있다.

운영 화면 기록은 전용 계정의 `fde-cognition-click-v1/35`, `fde-choices-on-screen-v1/35`, `fde-wonderful-review-v1/35`, `fde-contact-review-v1/25`, `fde-receiver-v2/24`, `fde-ml-ats-v1/24`에 있다. 운영 DB 함수와 버튼의 한·영 번역을 반영했다. 웹 변경은 배포 전이다.
