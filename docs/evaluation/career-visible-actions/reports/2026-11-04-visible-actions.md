# Visible actions 개발 검증

고정된 v1 합성 사례 4건을 실제 제품 provider/tool loop로 실행하고, 전체 모델 입력·도구 인자와 결과·최종 문장을 직접 읽었다. 일반 대화와 위임 결과는 `gpt-6.1-sol`, 재방문은 `claude-haiku-5-5`이며 각 사례는 1회다. 정상 실행은 `2026-11-04T13-55-54.752Z`다.

| 사례 | 관측 결과 | gold 판단 |
| --- | --- | --- |
| casual_offer | 면접 연습을 대화로 안내하고 목록 도구를 호출하지 않음 | 충족 |
| return_ready_reviews | 준비된 지원서 3건을 검토하는 `send_message` 항목 1개 생성. 이미 제출했다고 주장하거나 클릭만으로 제출하지 않음 | 충족 |
| async_missing_reply | 입사 가능일 답변을 위한 `compose_reply` 항목 생성. 정확한 work/form 참조와 미제출 상태 유지 | 충족 |
| return_resolved | 취소된 작업의 기존 항목을 읽은 revision으로 삭제하고 재방문 메시지는 생략 | 충족 |

첫 실행 `2026-11-04T13-54-40.586Z`에서는 도구 생성이 기대한 `toolCallId`를 제품 실행기가 전달하지 않아 실패했다. 제품에서 이미 사용하는 `resumeRequestId`/`userMessageId`와 내용 hash의 조합을 생성 멱등성 키로 사용하도록 수정했다. 실패 산출물을 보존하고 같은 고정 입력으로 다시 실행했다. 두 번째 실행에서 네 사례의 목적을 충족했다. 데이터나 gold를 결과에 맞춰 바꾸지 않았다.

별도의 로컬 검증에서 실제 SQL migration을 PGlite에 적용하여 소유권·RLS·revision 충돌·동일 생성 재실행·삭제 후 재생성 방지·11개 저장 허용을 확인했다. 실행 도구 결과와 삭제 이후에도 유지되는 선택 카드의 메시지 맥락, capability turn의 소유자별 목록 조회와 도구 실행 후 다음 모델 입력 갱신도 검사했다. 관련 단위 테스트 24개와 타입 검사가 통과했다. Playwright의 합성 preview에서 데스크톱/모바일 카드 표시, 클릭 메시지 전송, 입력창에 항목 연결, 사용자 답변 후 선택 해제, 빈 목록을 확인했다.

이 평가는 `manage_action_items` 하나만 노출한 개발용 표본이다. 여러 일반 도구와의 경쟁, selector, 실제 사용자 재방문 빈도나 장기 목록 품질, 운영 DB, 외부 지원·발송까지 검증한 결과가 아니다. 운영 성공률이나 회귀 전반을 보장하지 않는다. 배포와 운영 DB migration은 실행하지 않았다. 원본 provider 교환과 소스 snapshot은 ignored `runs/`에만 보존한다.
