# 첫 온보딩 통화 추천 준비율 — pilot-v1

2026-09-28, 데이터 기준 **2026-09-28 10:17:29 KST**. Codex의 직접 의미 검토이며 독립적인 사람 검토는 아직 없다.

## 판단

**현재 둘 중 선택한다면 Realtime을 우선한다.** 첫 통화에서 추천에 필요한 정보와 저장 정확성이 확인된 비율이 Realtime에서 높았다. 종료 기록이나 발화 수만으로 GPT Live가 더 낫다고 판단할 근거는 부족하다. 다만 이 결과는 작은 표본과 기록 누락을 가진 잠정 audit으로, 통계적으로 확정된 승자 또는 모델 자체의 보편적 우열을 뜻하지 않는다.

## 무엇을 계산했는가

첫 온보딩에서 통화를 선택한 사용자 가운데, 첫 통화와 당시 기존 프로필로 역할·탐색 의사·지역·보상·중요한 조건을 추천할 만큼 파악했고, 중요한 정보가 정확하게 저장된 사용자 비율이다. 명시적 미정·무관도 유효하다. 정해진 질문 수나 턴 수, 완료 플래그로 판정하지 않았다.

첫 통화는 첫 연결 시도 session 기준이다. 재시도나 채팅에서 나중에 얻은 정보는 첫 통화의 성과에 더하지 않았다. 과거 저장 내용은 변경 이력으로 복원했다. 모델명을 숨긴 사례 자료에서 50명 모두 판정한 뒤 A/B 배정을 결합했다. 이전 그룹별 발화 집계를 알고 있었으므로 완전한 blind는 아니다.

## 주 분석: 24시간 관찰 기회가 확보된 40명

| 판정 | A · Realtime | B · GPT Live |
|---|---:|---:|
| 통화를 선택한 전체 사용자 | 18명 | 22명 |
| 추천 준비·저장 정확성 확인 | **9명 / 50.0%** | **5명 / 22.7%** |
| 정보 충분성 부족 | 0명 | 8명 |
| 정보는 충분하나 중요한 저장 문제 | 0명 | 1명 |
| 첫 통화 기록 부족으로 판정 불가 | 9명 | 8명 |

**확인된 성공 비율 차이: Realtime +27.3%p.** 이는 판정 불가를 실패라고 확정한 수치가 아니라, 전체 분모 중 성공을 확인할 수 있었던 비율이다. 표본 안에서 실제 성공률은 누락 사례에 따라 Realtime **50.0–100.0%**, GPT Live **22.7–59.1%** 사이일 수 있다. 두 범위가 겹치므로 누락을 해결하지 않고 확정 승리라 할 수 없다.

참고로 ‘성공을 확인했는가’만 이항 변수로 계산한 Realtime−Live 차이의 Wilson/Newcombe 95% 구간은 **−2.2%p~+51.7%p**로 0을 포함한다. 이 구간은 실제 성공 여부의 기록 누락이나 정성 평가 오차를 해결하지 않는다.

연결 시도 자체가 없는 2명도 Live의 전체 분모에 남겼다. 실제 attempt가 있었던 사용자로만 제한하면 Realtime **9/18=50.0%**, Live **5/20=25.0%**다. 이 조건부 지표는 시작 실패를 제외하므로 주 지표로 삼지 않았다.

## 차이를 만든 관측

Live의 부족 판정 8명에서는 다음 역할과 중요한 이동 조건을 충분히 확인하기 전에 대화가 끝나거나 중단됐다. 8턴 이상이어도 이에 해당하는 사례가 있었다. 그중에는 사용자가 다음 질문을 기다리거나 계속 진행해 달라고 하는데 마무리하는 대화도 있었다. 관측된 기록에 대한 판단이며, 음성 원본이 없어 누락된 발화까지 단정하지 않는다.

저장 문제 1명은 사용자가 보상 범위를 중요한 거절 조건으로 표현했지만, 저장에는 단순 목표 범위와 ‘특정 거절 조건 없음’이 함께 남은 경우다. 단순한 종료·체크리스트 완료로는 잡히지 않는 차이다.

반면 Realtime의 확인 가능한 9명에서는 역할과 조건을 구체적으로 정리한 뒤 저장한 근거가 있었다. 다만 개별 보상이나 지역 기준을 얼마나 구체적으로 알아야 ‘추천 가능’이라고 볼지에는 평가자의 판단이 들어간다.

## 판정 기준의 민감도

경계선 사례 5명(Realtime 3명, Live 2명)을 모두 성공에서 제외하는 보수적인 재집계에서도 Realtime **6/18=33.3%**, Live **3/22=13.6%**로 관측 방향은 같다. 이 사례 ID는 모델 결합 전에 gold에 기록했다. 그러나 이는 독립 평가자를 대신하지 않으며, 기록 누락까지 해소하는 분석도 아니다.

## 보조 결과

| 지표 | Realtime | GPT Live |
|---|---:|---:|
| 24시간 내 운영상 온보딩 완료 event | 15/18 · 83.3% | 14/22 · 63.6% |
| 24시간 미경과 표본까지 포함한 성공 확인 비율 | 11/24 · 45.8% | 5/26 · 19.2% |

운영상 완료는 채팅 전환이나 재통화 후 완료도 포함하며, 정보 품질을 보증하지 않는다. 24시간 미경과 10명은 주 분석에서 제외했다. 전체 통화 선택자는 50명이며, 앞선 발화 수 분석의 실제 연결 시도자는 47명이었다. 첫 통화만 보는지 재통화까지 보는지, 관찰 시간이 충분한지도 달라지므로 서로 같은 비율처럼 비교하면 안 된다.

## 데이터 품질과 한계

- 실제 attempt 모델이 있는 47명에서 기존 배정 함수와 불일치 0명. 첫 session의 완료 기록 24개는 모두 onboarding이다.
- 40명 중 17명은 첫 통화 사용자 발화 기록이 없어 판정 불가다. 그중 일부는 이후 채팅이나 재통화를 했지만 첫 통화 성공에 포함하지 않았다. 기록 부재를 실제 무발화 또는 기술 실패로 단정하지 않았다.
- 완료 이벤트의 userTurns와 저장된 사용자 메시지 수가 11건에서 달랐다. 따라서 텍스트 기록이 원음 전체를 재현한다고 가정하지 않았다. 발화 수 임계값을 품질 지표로 쓰기 어려운 이유이기도 하다.
- 종료 이벤트가 없는 session의 저장 구간에는 이후 채팅 내용이 포함될 수 있다. 그런 경우 첫 통화 원문에 없는 저장 내용으로 성공 판정을 만들지 않았으며, 이번 ready 16건은 모두 첫 session의 종료 기록이 있었다.
- 기존 문서/프로필은 통화 이전 버전임을 확인할 수 있는 경우만 사용했다. 현재 프로필을 과거 정보로 소급하지 않았다.
- 원음, 음성 지연, 끊김, 총비용을 동일한 기준으로 측정한 자료가 없어 이 audit으로 비교하지 않았다. 비용·지연이 0이라는 뜻이 아니다.
- 당시 실제 운영 경로의 결과다. 프롬프트·provider·일시별 변경을 통제한 동일 입력 재실행 benchmark가 아니다.

## 의사결정에 쓰는 범위

이 자료는 **Realtime을 우선 선택할 잠정 근거**로 사용한다. 전면 전환을 자동 승인하는 release gate로 사용하지 않는다. 확정 비교를 위해서는 첫 session에 연결된 원문·저장 이력을 양쪽에서 빠짐없이 남기고, 같은 고정 기준을 독립적으로 재검토한 뒤 주 지표와 기술 실패·지연·비용을 함께 비교해야 한다. 이번 작업에서는 배포나 실험 비율 변경을 하지 않았다.
