# Career Voice 최종 확인 선택화·완료 후 종료

2026-10-25 로컬 구현. 배포·운영 DB 변경 없음.

## 변경한 동작

- 필수 정보는 탐색 의사, 다음 역할, 지역, 보상, 업무 언어다. 다섯 주제가 확인되면 별도 최종 확인, 요약 승인, 통화 종료 동의 없이 마무리할 수 있다. 과거 최종 확인 key는 읽기 호환만 유지한다.
- 짧은 답도 직전 질문의 맥락에서 완전한 답인지 판단한다. 발화 길이만으로 기다리거나 다시 묻지 않는다. 저장된 진행은 최신 답변보다 늦을 수 있다.
- A/B 모두 기존 end_call에 complete_onboarding 명령을 전달한다. 정상 완료와 사용자 중도 종료를 구분한다. 새로운 도구·테이블·대화 상태 머신은 추가하지 않았다.
- 정상 종료는 마지막 전사와 저장 요청을 기다린다. 기존 온보딩 추출기가 통화 전체를 반영하고 필수 coverage를 확인한 뒤, 실제 완료·첫 추천 요청 처리가 성공해야 연결을 닫는다. 필수 답변이 남으면 갱신된 맥락으로 이어간다. 저장 오류는 완료로 취급하지 않는다.
- 사용자의 중도 종료는 즉시 통화를 끊는다. 미완료 온보딩을 완료했다고 선언하지 않는다. 사용자가 직접 선택하는 기존 수동 완료 경로는 유지한다.
- 오래된 완료 마커만으로 음성 저장 경로에서 필수 답변 누락을 건너뛰지 않는다. 이미 완료된 대화에 뒤늦게 도착한 저장 요청이 대화 단계를 다시 chat으로 바꾸지 않는다.
- 재연결 시 진행률 75%만으로 ‘마지막 확인’을 시키던 별도 시작 지침도 제거했다.

## 검증

합성 `live-prompt-v2`의 발화·문맥·실제 도구 인자를 Codex가 직접 검토했다. 점수나 키워드로 정성 판정을 대체하지 않았다.

| 사례 | A Realtime | B Live | 확인한 행동 |
| --- | --- | --- | --- |
| 마지막 필수 답변, 저장 snapshot 지연 | 통과 | 통과 | 추가 확인 없이 complete_onboarding=true |
| 짧은 ‘네’가 마지막 답변 | 통과 | 통과 | 짧은 답을 수용하고 complete_onboarding=true |
| 미완료 상태에서 사용자 중단 | 통과 | 통과 | complete_onboarding=false |
| 필수 정보 누락 | 통과 | 통과 | 종료하지 않고 보상 질문 |
| 진행 갱신 뒤 재개 | 통과 | 통과 | 이미 답한 보상을 반복하지 않고 업무 언어 질문 |

B의 첫 유효 실행에서는 마무리 말만 하고 종료 도구를 호출하지 않는 2건을 발견했다. 마지막 필수 답변을 받은 같은 차례에 백엔드로 완료·종료를 요청하는 책임을 명확히 하고 재실행했다. 최초 실패 출력은 보존했다. 별도의 연결 중단·DNS 오류 실행도 보존하며 통과로 세지 않는다.

코드 검사 41개 통과. 실제 route와 hook 콜백을 격리된 의존성으로 실행해 전사 지연, 저장 지연, 완료 지연, 필수 항목 누락, 추출 실패, 완료 실패, 중도 종료, 이미 완료된 요청의 재처리를 확인했다. 전체 통화 추출이 앞쪽 답변과 마지막 단독 사용자 답변을 보존하는지도 확인했다.

변경한 실행 경로의 ESLint 통과. 전체 TypeScript 검사는 작업 범위 밖의 기존 오류 3건으로 미통과했다: `OpportunitySwipeRow.test.tsx`, `jobTitleSimilarityServer.test.ts`, `slackCandidateWorkObject.server.ts`. 이번 수정 파일의 타입 오류는 보고되지 않았다.

## 한계와 재현

- A는 합성 텍스트 입력에 대한 실제 Realtime 음성 응답, B는 합성 음성 입력이다. 모델 간 음성 인식·속도·비용 비교가 아니다.
- 운영 DB transaction, 브라우저 WebRTC, 실제 마이크·스피커와 네트워크 조건의 전체 제품 E2E는 실행하지 않았다. 격리된 hook 검사는 React 렌더링을 검증하지 않는다.
- 이 결과는 변경 경로의 제한된 검증이며 운영 완료율 개선을 증명하지 않는다.
- 고정 입력·기대 행동은 `live-prompt-cases-v2.json`, 재현 정보와 실행별 결과는 `completion-manifest-v2.json` 및 ignored `runs/`에 보관한다. 이전 dataset과 실패 run은 덮어쓰지 않았다. 원문 출력은 이 보고서에 복사하지 않았다.
