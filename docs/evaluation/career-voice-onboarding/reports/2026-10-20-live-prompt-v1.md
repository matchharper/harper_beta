# Live 온보딩 prompt / 진행 context 수정 검증

2026-10-20. 로컬 구현이며 미배포. [동결 입력과 기대값](../live-prompt-cases-v1.json), [재현 manifest](../live-prompt-manifest-v1.json).

## 구현

Realtime과 Live가 같은 온보딩 목적·필수 질문·최종 확인 기준을 공유한다. Live의 말하는 모델에 초기 진행 상황을 제공하고, 답변 저장 뒤에는 기존 checklist에서 만든 최신 진행 요약을 `session.thinking.append`로 전달한다. 같은 저장 결과의 상세 맥락은 Responses backend instructions에도 반영한다. 별도 추출 모델·진행 상태·의미 판정 규칙을 추가하지 않았다.

Live backend는 공유 prompt를 바탕으로 다음 질문 하나에 필요한 사실과 실제 작업 결과를 전달한다. 말하는 모델은 그 내용을 자연스럽게 말한다. 마지막 동의가 아직 저장되지 않았어도 직전 대화의 의미를 반영해 같은 확인을 반복하지 않도록 했다. 통화 종료와 실제 온보딩 저장 완료는 구분하며, Live의 backend handoff에 완료 마커를 생성하지 않는다. 저장 완료는 기존 checklist extraction 경로가 담당한다. 일반 통화·모의면접의 backend prompt와 모델·A/B 배정은 유지한다.

## 실제 모델 점검

`gpt-live-1`, `gpt-6.1-sol` / `xhigh`, `cedar`. 합성 음성을 WebSocket으로 실제 시간에 맞춰 전달했다. 현재 prompt에 대한 사례별 최신 유효 실행 4개 모두 아래의 제한된 gate를 통과했다.

| 사례 | 직접 확인한 응답·동작 | 판정 |
| --- | --- | --- |
| 보상·업무 언어가 남았는데 완료 여부 질문 | 남은 확인이 있다고 설명하고 최소 연봉을 질문. 종료 호출 없음 | 통과 |
| 최종 확인에 동의했지만 저장 coverage에는 미반영 | 짧게 마무리하고 `end_call` 호출. 같은 확인 질문이나 저장·검색 성공 주장 없음 | 통과 |
| 기본 질문이 남은 상태에서 중단 요청 | “네, 지금 끊어드릴게요.”라고 답하고 `end_call` 호출. 추가 질문·완료 주장 없음 | 통과 |
| 보상 답변이 저장된 뒤 진행 상황 갱신 | 이미 답한 보상·지역·역할을 반복하지 않고 업무 언어를 질문. backend 갱신 및 frontend context 수신 확인 | 통과 |

첫 사례의 유효 실행은 `runs/live-prompt-2026-10-20T02-37-39.829Z`, 나머지 세 사례는 `runs/live-prompt-2026-10-20T02-47-46.083Z`에 보존했다. 전체 입력·이벤트·출력 음성은 ignored 경로에만 있다. 각 유효 실행에서 API error 없이 `session.closed`를 수신했다.

초기 점검에서는 짧은 실행 제한으로 응답이 잘려 판정하지 못했고, 다음 질문에 필요한 내용만 전달하도록 prompt를 보완했다. 중간 실행의 세 사례는 연결 종료 확인 또는 입출력 기록이 불충분해 통과로 세지 않고 재실행했다. 테스트 연결 준비 중 인증 설정 오류도 있었으며 모델 평가에 포함하지 않았다. 입력과 기대값은 변경하지 않았다.

## 코드 확인과 한계

- 관련 자동 검사 19개 통과. 여기에는 기존 모의면접·통화 목적 분리, 공통 prompt 재사용, 완료 마커 분리, 진행 갱신 이벤트가 포함된다. 필수 coverage의 64가지 조합은 모두 한 번의 context event에 들어가는 500토큰 이하임을 확인했다.
- 변경 파일 ESLint 및 TypeScript 검사 통과. 관련 없는 동시 작업 변경은 이 수정의 일부가 아니다.
- 온보딩 완료 판단을 새로 구현하지 않았다. 저장 API의 기존 `question_checklist_covered` → 완료 저장·초기 추천 경로를 유지한다.
- 실제 DB 추출·저장과 브라우저 WebRTC의 전체 통화는 이번 합성 smoke에 포함하지 않았다. 음질·소음·끼어들기·지연 분포·완료율·사용자당 비용 개선은 아직 검증하지 않았다. 이 결과는 실제 서비스 완료율 상승이나 전체 rollout 승인을 뜻하지 않는다.
