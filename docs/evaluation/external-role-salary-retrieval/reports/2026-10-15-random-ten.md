# 추가 무작위 사용자 10명 검색 검증

2026-10-15. **10명 모두 계획 생성·임베딩·최초 목록 조회에 성공했고 timeout은 없었다. 그러나 상위 공고의 직무 오탐과 URL 중복이 남아, 목록 품질까지 전부 통과했다고 판단하지 않는다.** 현재 로컬 코드와 운영 DB의 읽기 전용 실행 결과이며 배포·추천 저장·발송은 하지 않았다.

## 표본과 범위

- 기존 3명을 제외한 eligible 사용자 2,704명에서 새 무작위 seed로 10명을 추출했다. 모두 서로 다른 사용자이며, 결과를 보고 교체한 사례는 없다.
- eligible 범위는 온보딩 완료, 외부 추천 허용, stopped 아님, 삭제 아님, 경력·Brief·기존 Behavior 보유다. 모든 가입자를 대표하는 표본은 아니다.
- 입력·seed·해시는 `manifest-v8-random-ten.json`, 실행 전 기준은 `gold-v8-random-ten.json`에 고정했다. Profile·전체 Brief·같은 snapshot의 Behavior를 사용했다.
- 현재 Ops의 최초500개 목록과 같은 planner·단일 결합 embedding·list-only SQL을 실행했다. 연봉 추정 채우기, scoring, summary, reranking, 추천 저장·발송은 실행하지 않았다. 국가 기준과 가중치는 비교·변경하지 않았다.

API 단계는 실제 호출 당시 monotonic timer receipt다. 아래 평가 도구 오류와 복원 방법을 함께 기록한다. 각 사용자1회이므로 p95나 장기 안정성 근거는 없다.

DB·서버의 쿼리별 인프라 비용은 이 측정으로 산출하지 못했다. Planner는 저장소의2026-10 단가, embedding은 [공식 text-embedding-3-small 단가](https://developers.openai.com/api/docs/models/text-embedding-3-small)의100만 입력토큰당$0.02를 사용했다. ## 평가 코드 오류와 복구

제품의 목록 조회는 전원 성공했지만, 그 뒤 붙인 평가용 감사 SQL이 스키마 경로를 생략해 `relation company_roles does not exist` 오류를 냈다. 이는 `search_external_roles_v2`의 제한된 search_path 안에서 감사 SQL만 잘못 작성한 문제다. 따라서 최초 runner의 `completed=0`은 제품 검색10건 실패가 아니라 **후속 감사10건 실패**다. 원래 오류와 이미 생성된 계획·목록·API receipt를 보존했다.

평가 코드에서 두 테이블에 `public.`을 붙이고 `--audit-run`으로 기존 목록만 다시 검사해10/10 완료했다. 모델·embedding·검색을 재실행하지 않았고 추가 모델 비용은0이다. 감사 실패 전에 timing result 파일을 저장하지 못했으므로 검색 시간은 보존된 SQL/rows 파일 시각으로 복원했다. 이 방법의 작은 파일 I/O 오차를 감안해 본문은0.1초 단위로 표시했다. 제품 코드나 검색 정책은 이번 검증 중 변경하지 않았다.

## 재현 자료와 판단

- 입력: `private/users-v8-random-ten.json` (owner-only, gitignored)
- 최초 실행: `runs/users-2026-10-15T03-53-10-757Z`
- 감사 복구·집계·중복 증거: `runs/audit-2026-10-15T03-58-24-671Z`
- 정본 실행기: `scripts/evalExternalSalaryUserRetrieval.ts --random-ten`; 복구는 `--random-ten --audit-run=<최초 실행 경로>`
- 같은 입력의 재평가에서는 기존 fixture/gold를 바꾸지 않고 새 run을 만든다. 이번 오류/성공 결과를 이전3명 비교와 섞어 timeout 개선율이나 검색 속도 개선율로 계산하지 않는다.

실행 안정성·기본 데이터 경계는 이10명에서 통과했다. **좋은 후보를 넓게 모으는 초기 검색으로는 동작하지만, 목록 자체를 완성된 추천으로 보기에는 역할 의미·책임 수준·사용자 제외 조건·중복 처리의 개선이 필요하다.** 후속 scoring/reranking이 이 문제들을 얼마나 제거하는지는 이번 검사 범위 밖이다.
