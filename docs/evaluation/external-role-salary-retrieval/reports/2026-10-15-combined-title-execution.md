# 현지어 제목 결합 검색과 실행 비교

2026-10-15. 로컬 구현·읽기 전용 검증 결과이며 미배포다. 국가별 연봉 기준·가중치 비교는 하지 않았고, Role 연봉의 동기 추정 단계는 변경하지 않았다.

## 구현

- 선호 검색 국가의 언어와 영어로 직무명을 생성한다. 모든 제목을 `, `로 합친 텍스트 하나를 한 번 임베딩하고, 제목 사전을 한 번 ANN 검색한다. V2 web/Worker 공유 검색, Ops 사용자별 검색, `recommend_job_postings`의 기존/full-JD 경로에 연결했다.
- 검색 제목별 임베딩을 저장한 구 기본 계획은 새 버전에서 다시 생성한다. 공고 제목 사전 자체는 기존처럼 제목별 벡터를 유지한다.
- 한 번의 ANN에서 최대 5,000개 제목을 가져온다. 단일 1,000개로 줄인 실험은 후보 수가 500/12/46개로 감소하여 채택하지 않았다. 5,000개는 이전 최대 5회×1,000개 범위다. 결합 검색은 여러 별도 검색의 합집합과 동일하지 않다.
- 동일 제목 거리·동일 키워드 점수에는 같은 관련도 순위를 부여한다. UUID는 최종 표시 동점만 정리한다. 최초 후보 경계의 동일 거리도 함께 남겨 연봉 비교 전에 UUID 때문에 탈락하는 문제를 고쳤다.
- 제목 key를 묶어 인덱스로 후보를 읽고, 급여·키워드 계산 결과를 재사용한다. 최종 목록을 정한 뒤 넓은 공고·회사 정보를 붙인다. 가용성·차단·기추천·testOnly 필터와 국가 배분, 제목/키워드 80:20, 연봉 가중치 0.35는 유지한다.
- Ops에서 동일 사용자·동일 컨텍스트의 완료된 계획/임베딩만 최대 5분 재사용한다. 목록은 매번 다시 조회한다. 일반 추천의 연봉 추정 대기와 후속 scoring/reranking 입력은 그대로다.

## 고정 입력과 측정 범위

`manifest-v7-execution.json`과 `gold-v7-execution.json`에 등록했다. 이전 v6의 3개 사용자별 국가, 키워드, 스칼라 연봉 기준, 필터, 기존 SQL을 그대로 두고 v7 제목/단일 벡터만 교체했다. 원본 프로필과 회사/공고 데이터는 ignored owner-only private/runs에만 있다. 운영 DB 쓰기, 추천 생성, 메시지 발송은 없다.

계획 생성 점검은 고정된 3개 사용자 컨텍스트로 Luna low를 각각 한 번 호출했다. 한국 선호 사례는 영어·한국어 8개 제목, 일본 선호 사례는 영어·일본어 10개 제목, 호주 선호 사례는 영어 3개 제목을 반환했다. 각각 쉼표로 합친 입력 1개와 벡터 1개를 확인했다. 해당 실행은 `users-2026-10-15T03-22-00-213Z`다. 이때 새로 추정된 연봉이나 키워드로 실행 비교 조건을 바꾸지 않았다.

시간 비교는 기존→변경, 변경→기존의 순서로 사용자별 2회씩 실행했다. 아래는 **DB 연결·쿼리·결과 전송을 포함한 검색 구간 wall time**이다. 계획 생성, 임베딩 API, Role 연봉 추정, scoring/reranking 시간은 포함하지 않는다. 두 구현 모두 동일한 읽기 전용 bridge와 30초 SQL 제한을 사용했다. 캐시 온도와 동시 운영 부하는 고정하지 못했으므로 일반적인 p95 또는 전체 추천 완료 시간으로 해석하지 않는다.

## 준비된 추정치의 로컬 재생

`runs/execution-2026-10-15T03-27-54-076Z`에서 user-1만 검사했다. 연봉 적용 전 후보를 읽고, 기존 준비된 추정치 중 원본 해시가 일치하고 공개 급여가 없는 공고에만 로컬에서 붙였다. 새 추정 호출이나 운영 DB 저장은 하지 않았다. 공통 연봉 계산과 고정 가중치0.35를 적용했다.

관련도에 연봉을 반영하는 경로는 동작하지만, 이 재생에서 상위50의 연봉 효용은 낮아졌고 낮은 추정 연봉 공고도 늘었다. 검색 집합 자체와 예측 연결 비율이 달라 순수한 정렬만의 효과로 해석할 수 없다. 추정치는 정답 급여가 아니며, 이 결과로 추천 품질 개선을 선언하지 않는다. 동점 처리의 오류 수정은 별도 합성 SQL 테스트에서 확인했다: 같은 제목·키워드의1,302개 공고 중 이전 UUID 한도 밖의 적정 급여 공고도 비교 대상으로 남고 상위에 올랐다.

## 중간 실험과 검증

초기 v6는 제목 임베딩을 바꾸기 전 SQL 실행 구조만 비교했다. 최종 v6 ABBA 기록은 `execution-2026-10-15T03-18-19-537Z`이며 timeout은 없었다. 이후 현지어 결합 검색 요청을 포함한 결과는 위 v7을 정본으로 본다.

전체 FTS를 먼저 강제하는 중간 구현은 일부 사례에서 빨라졌지만 다른 사례에서30초 timeout이 증가해 폐기했다. `execution-2026-10-15T03-11-02-252Z`와 `execution-2026-10-15T03-13-52-925Z`에 실패 결과를 보존했다. 단일1,000개 제목 조회의 후보 감소는 `execution-2026-10-15T03-24-38-425Z`에 보존했다. 성공한 실행만 골라 최종 결과로 제시하지 않았다.

TypeScript 검사와 변경 경로 ESLint가 통과했다. PGlite/pgvector에서 기존 권한·가용성·국가 조건, 관련도 동점, 기존 추천 경로의 단일벡터 SQL 실행을 확인했다. 모의 embedding API에서 쉼표 결합 입력1개/벡터1개, SQL의 ANN CTE1개, 여러 벡터 입력 거부를 확인했다. 저장 계획 버전/벡터 개수와 Ops 컨텍스트 변경에 따른 캐시 무효화도 검사했다.

현재 확인한 결론은 요청한 단일 검색 계약과 SQL 동점 오류 수정이 완료됐다는 것이다. 전체 평균은 소폭 줄었지만 사용자별 속도·검색 범위·연봉 지표는 혼재한다. 미배포 상태이며 실서비스의 전체 추천 속도나 최종 추천 품질은 아직 검증하지 않았다.
