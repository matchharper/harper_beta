# 일정·메일 연속 실행 점검 — 2026-11-02

사용자가 가짜 데이터로 직접 실행하고 실제 출력을 확인해 달라고 요청했다. 앞선 v2는 독립 사례 6개였으므로 이번 v3에서는 같은 가짜 사용자의 일정·작업 예약·이전 발송 본문을 유지하며 네 번 연속 실행했다. 추가 두 사례는 회사/시간대 혼합과 Gmail 실패를 확인한다. 운영 데이터 쓰기·발송·배포는 하지 않았다.

## 실제 모델 실행

고정 입력/정답은 `cases-v3.json`, `gold-v3.json`, `manifest-v3.json`이며 첫 실행 전에 작성했다. 실제 `gpt-6.1-sol/high`로 **6개 실행 모두 통과**했다. 모델 입력·도구 호출·도구 결과·메일 원문·저장 행은 `runs/2026-11-02T09-10-01-319Z/`에 보존했다. 출력에 맞춘 정답 수정이나 성공 출력 선별은 없다. 모든 메일 본문을 직접 읽고 사실·실행 결과와 대조했다.

## 생성된 메일 → 렌더링 → 발송 원장

`replayCareerMeetingDelivery.ts`가 실제 생성된 리마인드 한 건을 읽어 제품 이메일 렌더러와 운영과 같은 outbox SQL을 실행했다. 별도의 격리 DB이며 네트워크 호출은 차단된다.

- 정상 경로: 다른 본문으로 중복 예약해도 최초 본문과 같은 delivery ID가 유지됐다. 로컬 전송 캡처 1회, 발송 이력 1행이었다. 완료 RPC를 두 번 호출하고 다시 claim해도 이력이나 발송이 추가되지 않았다.
- 발송 직전 일정 변경: 일정 버전 1→2 후 admission이 `false`, 원장이 `context_changed`가 됐다. 전송 캡처 0회, 발송 이력 0행이고 provider 시도 시각도 없었다.
- 실제 provider는 호출하지 않았다. `sent`는 이 검증 DB에서 가짜 provider 영수증을 받은 결과다. 실제 메일 수신 성공을 의미하지 않는다.

## 발견·수정한 문제

실제 생성된 한국어 본문에서 괄호 뒤에 조사가 붙는 강조 문법이 HTML/텍스트 메일에 별표 그대로 노출됐다. 기존 CommonMark parser의 CJK 강조 경계에서 재현되는 표시 문제였다. [플러그인 원본 문서](https://github.com/tats-u/markdown-cjk-friendly/blob/main/packages/remark-cjk-friendly/README.md)의 동작·호환성을 확인하고 `remark-cjk-friendly` 2.3.3을 고정해 공통 이메일 Markdown parser에 연결했다. 모델의 본문이나 prompt는 수정하지 않았다.

재현 테스트는 수정 전 실패했고 수정 후 통과했다. 괄호/조사 강조, 코드와 escaped 별표 원문 보존, 기존 링크·표·HTML 정제 검사를 포함한 렌더러 **9개**가 통과했다. 같은 모델 본문을 다시 렌더링해 실제 HTML에 강조 태그가 생기고 텍스트에서 불필요한 별표가 사라짐을 확인했으며 발송 SQL 재생 2개도 다시 통과했다. 수정 전후 결과는 run 폴더의 `before-cjk-*`, `reminder-email.html`, `reminder-email.txt`, `delivery-replay.json`에 보존했다. 공통 렌더러이므로 변경 범위는 Career와 회사 이메일 모두에 해당하며 배포하지 않았다.

## 검사 결과와 한계

- 일정 SQL·기본 context·메일 발송 경계·Gmail adapter·HTTP route·일정 UI 관련 **46개**, 렌더러 **9개**, 합계 **55개 통과**. 최초 실행에서 2개 파일은 import용 가짜 환경변수 누락으로 실행되지 않았다. 해당 두 파일에 가짜 설정을 제공해 재실행한 15개가 통과했다. 중복 실행은 합산하지 않았다.
- 최종 전체 TypeScript와 변경 렌더러/테스트 ESLint 통과.
- v3는 실제 모델·실제 일정/예약 SQL·source 완료 RPC를 사용한다. Gmail 응답, 메일 provider, Worker/queue의 실행 전달은 합성 경계다. 시간 경과에 따른 예약 실행 전달은 저장된 예약을 읽어 모사하며 실제 운영 scheduler를 실행하지 않는다.
- 앞선 요청에서 운영 DB 두 migration은 이미 적용했다. 이번 점검에서는 운영 DB 쓰기, 번역 DB 동기화, 실제 메일·Calendar 발송, 웹·Worker 배포를 하지 않았다. 새 UI·Gmail 기본 context와 이번 표시 수정은 배포 전 상태다.
