# 일정·메일·리마인드 재검증 — 2026-11-02

사용자의 재검증 요청에 따라 기존 테스트를 다시 실행하고, 실제 HTTP 경로·Gmail adapter·발송 직전 DB 경계·브라우저 상호작용·추가 모델 사례를 확인했다. 재검증 당시에는 운영 DB 적용·배포·실제 메일 발송을 하지 않았다. **후속 요청으로 운영 DB 변경 2개를 적용했으며 이 문서 마지막 적용 기록이 최신이다. 웹·Worker는 미배포다.**

## 재현하고 수정한 제품 문제

1. **발송 직전 일정 변경:** JavaScript의 일정 버전 검사 후 수신자·사용자 메시지를 조회하는 사이 일정이 바뀌면 기존 최종 DB admission은 발송을 허용했다. 실패하는 SQL 테스트로 재현했다. `20261102084400_career_meeting_delivery_admission.sql`에서 기존 `begin_career_agent_email_attempt`가 일정 행을 잠그고 소유자와 버전을 최종 확인한다. 변경됐으면 `context_changed`로 돌리고 provider 시도 시각을 만들지 않는다. 네트워크 발송이 허용된 뒤 이미 시작된 외부 요청을 취소하거나 회수하는 기능은 아니다.
2. **자정을 넘기는 일정 표시:** 시작일의 `23:30–00:30`만 보여 종료 날짜를 오해할 수 있었다. 종료일이 다르면 날짜를 함께 표시하도록 수정하고 테스트·모바일 화면에서 확인했다.

추가로 기존 `career.apply.start/title` 키에 서로 다른 한국어 원문이 연결된 충돌을 정리했다. 기존 화면의 ‘준비/이력서 점검’ 문구를 별도 키와 직접 작성한 영어에 연결하고, 화면의 버튼과 클릭 후 대화 문구를 일치시켰다. 번역 DB에는 쓰지 않았다.

## 자동 검사

- 웹/DB 관련 **101개**를 확인했다. 첫 통합 실행은 99개 통과, 기존 지원 카드 문구를 찾는 테스트 2개 실패였다. 테스트의 오래된 라벨을 현재 화면 문구에 맞춘 뒤 해당 파일의 3개가 모두 통과했다. 중복 실행은 합산하지 않았다.
- 범위: 일정 생성/수정/취소와 멱등성·소유권·버전 충돌, 회사 trigger 격리, 72시간 context, agent 예약 collector, provider 입력/재개, 메일 outbox/retry/cancel/admission, Gmail 검색/정확한 thread/권한/연결 해제, HTTP 인증·Role 필터·페이지·실패 상태, 일정 화면과 도구 가용성.
- Worker **30개 통과**: 공통 agent handoff 9개와 기존 check-in 검사 21개. 이전 5개 실패는 테스트가 여전히 75일/45일을 가정한 반면 현재 기존 코드는 90일/30일 상수를 사용하는 문제였다. 테스트 입력을 설정된 경계 전후로 수정했으며 Worker 정책·운영 코드는 바꾸지 않았다. 공통 agent 경로는 기존 schedule collector를 그대로 사용한다.
- 팔로우 도구의 `read` action을 빠뜨린 오래된 schema 기대값도 수정했다.
- 전체 TypeScript와 변경 production 파일 ESLint 통과. 일정 및 충돌 수정에 사용한 번역 키 8개의 원문·한영 사전을 별도 검증했다.

전체 Career 번역 검사는 **다른 기존 화면의 누락·원문 불일치 148건으로 여전히 실패**한다. 개발 화면의 `ui.*`, 기존 버튼 문구와 사전의 차이 등이 포함되며, 이번 일정 기능이 전역 번역 검사를 통과했다고 주장하지 않는다. 이 범위 전체를 자동 번역하거나 기존 사전을 일괄 덮어쓰지 않았다.

## 브라우저 → API → 로컬 SQL

무시되는 `output/playwright/appointments-server.ts`에서 실제 `UpcomingAppointments`, 실제 HTTP GET handler, 실제 SQL reader를 연결했다. 인증은 가상 토큰, DB는 PGlite다. 서버는 localhost의 별도 포트를 사용했으며 기존 개발 서버나 Worker를 건드리지 않았다.

- 31개 일정에서 최초 30개 → ‘일정 더 보기’ → 31개, 중복 행 없음.
- 정확한 미팅 URL 확인, ‘관련 포지션’ 클릭 후 해당 Role의 일정 1개 조회.
- DB 취소 후 새 조회에서 해당 일정이 사라짐.
- DB 오류 시 복구 버튼 표시, 복구 후 버튼 클릭으로 정상 목록 반환.
- 390px 모바일에서 가로 넘침 없음. 자정을 넘기는 일정의 종료 날짜 표시 확인.
- 화면: `output/playwright/appointments-retest-mobile.png`, `appointments-retest-desktop.png`, `appointments-retest-role-mobile.png`.

이 테스트의 DB adapter는 PostgREST join transport를 대체한다. 실제 Supabase 로그인/hosted PostgREST, Gmail OAuth, 메일 provider 수신 및 회사 Calendar 연동까지 검증한 운영 E2E는 아니다. 운영 전에는 두 신규 migration 적용과 배포가 별도로 필요하다.
