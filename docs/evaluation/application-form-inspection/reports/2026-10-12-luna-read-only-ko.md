이 기록은 초기 synthetic v1의 준비 문항 선택 계약을 검증한 이력이다. 이후 사용자의 실제 JD 테스트 요청으로 조회 결과를 전체 입력 목록으로 확장했다. 현재 결과와 실제 사이트 검증은 [실제 JD 조회 검증](2026-10-12-live-jds-ko.md)을 따른다.

## 변경 내용

- Ashby 공개 조회를 우선 사용한다. 성공하면 브라우저나 조회 LLM을 호출하지 않는다.
- 다른 공개 폼은 실제 지원과 같은 OpenAI-hosted 브라우저 실행기를 읽기 전용으로 사용한다. 조회 모델 기본값은 **GPT-6 Luna, reasoning low**다.
- 환경 준비부터 문항 확인까지 **180초**로 제한한다. 실패·시간 초과는 미확인으로 반환한다. 종료 후 사용량 확인과 자원 정리에는 별도의 짧은 제한을 둔다.
- 조회 모델에는 후보자 사실·이력서·파일·로그인 정보가 없다. 입력·선택·첨부·제출·승인은 서버에서도 차단한다. 공개 링크와 iframe 문항은 읽을 수 있다.
- 모델은 현재 화면의 문항 ref만 고른다. 필수 여부·글자 수 제한·첨부 형식·안내문은 실제 화면에서 읽은 값을 사용한다. 없는 제한은 추측하지 않는다.
- 대화 기본 모델, 이력서 작성 모델, 실제 지원 브라우저 모델은 유지한다. 조회만 별도 `APPLICATION_FORM_INSPECTION_MODEL` 설정을 사용한다.
- Agents API가 요구하는 시작 입력을 세션 생성 시 함께 전달하도록 조회와 실제 지원 경로를 수정했다. 실제 지원의 동일 작업 중복 전송은 막고 기존 질문/승인 응답은 유지한다.

## 회귀 검사와 한계

관련 테스트 **34개 통과**, TypeScript 검사 통과, 변경 production 파일 ESLint 오류 0. 실제 Chromium으로 폼 입력·첨부·승인·제출 거절, 외부 버튼의 쓰기 차단, iframe 원본 속성 조회와 공개 링크 이동을 확인했다. 기존 실제 지원의 승인 전 전송 차단·승인 request 불변성·중복 전송 방지·첨부 bytes·암호화·취소/시간 제한·cleanup 검사도 통과했다. Ashby 공개 조회는 mock 원본을 사용하는 회귀 검사로 확인했다.

`[llm-usage]` 비용 로그를 유지한다. 이 synthetic 실행에서 provider session usage는 null이어서 비용을 `usage_unavailable`/null로 남겼다. 0달러로 간주하지 않는다. Agents API 내부 호출별 비용과 hosted 환경 비용을 합친 최종 청구액을 증명한 검증은 아니다.

세 가지 고정 사례는 배관과 읽기 전용 경계를 확인하는 작은 회귀 세트다. 모든 채용 사이트의 문항 조회 성공률이나 실제 제출 성공을 보장하지 않는다. 로그인·CAPTCHA·답변에 따라 생기는 문항·원본에 없는 제한은 여전히 미확인으로 남긴다.
