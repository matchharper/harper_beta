## Prompt 수정 계획 — 적용하지 않음

1. 공통 A/B/C schema 뒤에 `pass` 또는 `recommend`를 덧붙이라고만 하지 않고, 각 stage prompt의 맨 마지막에 그 stage의 **완성된 최종 JSON schema**를 한 번만 제시한다. 1차의 모든 role에 boolean `pass`, 2차의 모든 role에 boolean `recommend`가 필수임을 schema 자체로 고정한다.
2. A 판단에서 역할 유형을 먼저 분류한다. technical leadership·Field CTO처럼 architecture, customer technical ownership, team/system delivery가 core인 역할은 모든 하위 기술을 최근 직접 구현했는지를 IC 역할과 같은 방식으로 요구하지 않도록 일반 원칙을 명확히 한다.
3. C에서 단순 정보 부재와 명시적 회사 threshold 미달을 분리한다. 회사가 최소 신호 수나 반드시 필요한 조합을 명시했고 입력 증거가 그 기준에 못 미치면 `ambiguous`로 자동 완화하지 않도록 한다.
4. A의 판단 순서를 `core function/domain → explicit hard requirement → 단일 후보 질문`으로 고정한다. core mismatch가 있으면 언어·비자 같은 두 번째 누락이 있어도 `hold`가 될 수 없다는 체크를 출력 직전에 둔다.
5. location convention과 현재 거주·현지 학교/회사 기록에 따른 일반 근무 가능성 판단을 최종 체크에 다시 연결해, 1차 ABC06처럼 이미 Tokyo에서 근무하는 후보에게 일반 work authorization을 묻는 false hold를 줄인다.
6. 수정 후 같은 frozen input으로 최소 3회 반복해 평균 label만 보지 않고 `pass`/`recommend` schema 완결성, ABC12 hard-negative, ABC13 false hold, ABC01·03 positive recall을 독립 gate로 본다.

이번 run에서는 위 prompt 변경을 적용하지 않았다.
