# Slack 답장 참여 판단 — Jev 전환 검증

문서 기준: 2026-10-15 (KST). 로컬 구현·provider 검증이며 운영 배포 완료를 뜻하지 않는다.

## 변경과 판단 계약

답장 여부를 GPT-6 Luna의 생성 문자열로 받던 경로를 OpenRouter `typesafe/jev-1.13`의 native Decisions API, 단일 Choice 질문으로 전환했다. 실제 응답 모델은 `typesafe/jev-1.13-20260917`이었다. latest 메시지의 수신자와 진행 중인 Harper 요청을 문맥으로 판단하며, 이전 Harper 참여만으로 다른 팀원에게 묻는 질문에 응답하지 않도록 했다.

일정 키워드 우회는 제거했다. 권한 검사·직접 멘션·Role 작성·진행 중 후보자 workflow의 기존 우회와 답장 본문을 작성하는 company-side LLM은 유지한다. 구조 검증은 `type=choice`와 유효한 선택지뿐이다. confidence/키워드에 따른 의미 재판정은 없다. 오류/5초 timeout은 응답 경로로 진행하며 다른 모델을 호출하지 않는다. caller 취소는 전파한다.

OpenRouter가 보고한 비용을 공통 로그의 `provider_reported`로 저장하고 없으면 단가 추정을 사용한다. provider 호출 시작부터 응답 JSON을 읽을 때까지의 `durationMs`를 별도 저장한다. 본문이나 회사 대화는 usage 로그에 넣지 않는다. 기존 aggregate/debug 소비자 계약을 유지하며 개별 호출 receipt에서 provider 비용 출처를 구분한다.

정본은 [`scripts/evalSlackReplyRouterLive.ts`](../../../../scripts/evalSlackReplyRouterLive.ts), 계약과 frozen hash는 [태스크 README](../README.md) 및 manifest v2다. raw request/response, exact source snapshots, source revision/dirty diff hash와 prompt fingerprints는 ignored `runs/<run-id>/`에 0700/0600으로 보존한다.
