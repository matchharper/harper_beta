# 외부 역할 연봉 추정·초기 검색 반영 결과

문서 기준: 2026-10-15. 코드 구현과 검증, DB 스키마 변경, 유료 추정 실행을 마쳤다. 웹·worker는 아직 배포하지 않았으며, 운영 salary 필드에 추정값을 저장한 건수는 **0개**다. 추정값을 LLM 입력에서 숨기는 새 reader가 배포된 뒤 준비된 결과를 저장한다.

GPT-6-Luna Decisions에 기본 `mapping`을 사용했다. 회사별로 인접하게 정렬하고 최대 10개씩, 동시 4회 요청했다. 실패/누락 역할만 별도 retry run으로 처리했으며 마지막 52건은 역할당 단독 요청했다. 따라서 전체 호출 평균은 대부분 10개를 포함하되 최종 단독 retry도 포함한다. 모델 실행 시간에는 DB capture·구현·수동 조사 시간이 포함되지 않는다. 비용 정보가 없는 53개 실패 요청은 무료라고 단정하지 않고 예비액을 남겼다.

추정 결과는 연간 세전 기본급의 하한·상한을 원으로 저장하도록 준비했다. 실제 급여를 덮어쓰지 않는다. 텍스트 급여가 이미 저장된 역할도 보존한다. 원문이 바뀌었거나 실제 급여가 새로 입력된 역할은 저장 시 건너뛴다. 공고 급여가 새로 수집되면 추정 표시를 해제하고, 숫자 없이 같은 공고가 재수집되면 추정값을 보존한다.

범위 폭 중앙값 49.3%는 대략 중앙값의 ±24.7%이며 아직 정밀한 오퍼 예측은 아니다. 검색에 쓰는 가장 그럴듯한 채용 band로 추정하도록 요청했으며 범위를 임의로 잘라 좁히지 않았다. 글로벌 시장은 한국·미국보다 앵커가 넓고 거칠어 정확도 미검증이다.

## 실제 검색 목록 비교

실제 company_roles **6,181개**의 4개 검색 pool을 읽기 전용으로 캡처했다. 목표 연봉 8천만/1.2억/2억/3억과 급여 비중 0/0.2/0.35/0.5/1, 총 **80개 조건**을 비교했다. 기본값은 **0.35**로 설정했다.

급여 min/max 구간 전체에서 목표를 만족하는 정도를 평균한다. 목표 이상 급여는 효용이 포화되어 아주 큰 상한으로 순위를 무한히 높일 수 없다. 급여가 없으면 기존 직무 순위를 그대로 유지한다. 하한만 있고 목표에 못 미치거나, 상한만 있고 목표를 넘으면 나머지 범위를 모르므로 중립이다. 하한만으로 목표를 넘는 경우는 충분, 상한조차 목표 미만이면 낮은 효용을 부여한다.

제목·키워드 순위에 연봉 배수 0.65–1.35를 곱한다. 급여만으로 제외하지 않으며 국가별 할당도 유지한다. 제목 후보 pool을 6배까지 확보한 뒤 급여를 반영한다.

### 공개 급여로 검증: 목표 2억 원, 목록 500개

| 검색 | 충분한 공개 급여: 기존→변경 | 크게 부족한 공개 급여: 기존→변경 | 급여 미상: 기존→변경 | 기존 목록 유지 |
|---|---:|---:|---:|---:|
| ML·연구 국내/미국 | 104→115 | 0→0 | 367→353 | 486/500 |
| ML·연구 미국 | 228→263 | 0→0 | 183→143 | 459/500 |
| 고객지원 미국 | 19→31 | 49→36 | 283→274 | 471/500 |
| 영업 미국 | 112→144 | 27→18 | 170→146 | 455/500 |

‘충분’은 공개 하한 ≥ 목표, ‘크게 부족’은 공개 상한 < 목표의 60%다. 부분 급여와 혼합 band는 별도 집계되므로 세 열의 합이 500은 아니다. 미상 급여 역할도 상당수 남으며 불합격으로 처리하지 않았다. 이 비교는 급여에 따른 순위 검증이고 실제 후보자 관심·지원·오퍼를 측정한 결과는 아니다.

### 준비된 추정값을 합친 추가 비교

같은 frozen input을 복제해 원문 hash가 일치하는 **1,152개 pool 행**에 준비된 예측값을 합쳤다. 원본 데이터·공개 급여 gold는 수정하지 않았다. 예측값은 정답이 아니다.

목표 2억 원의 고객지원 검색에서 상한이 크게 부족한 예측 역할은 18→14개, 공개 급여가 크게 부족한 역할은 49→36개로 줄었다. 여전히 급여를 모르는 역할은 235→227개 남았다. 미국 ML은 목표를 만족하는 공개 급여가 228→236개로 늘었고, 완전 미상도 40→31개 남았다.

국내/미국 혼합 검색에서는 국내 후보 pool 자체가 320개뿐이라 국가 할당을 채우면서 거의 모두 선택된다. 이 경우 연봉만으로 낮은 급여 역할을 충분히 교체할 수 없었다. 급여 ranking 효과는 후보 pool의 폭과 기존 국가 할당의 영향을 받는다. [전체 순위 평가](../../external-role-salary-retrieval/reports/2026-10-15.md)에 표와 한계를 남겼다.

## 추정기와 Ops 확인

이전 조사에서 고정한 한국·미국 50개를 새 production contract로 10개씩 실행했다. **50/50** 정상, **$0.0091991**, 성공 요청 평균 **1.34초**였다. 이전 공개 근거의 동일 역할 annual cash/base 6개에서 중앙값 절대 백분율 오차 중앙값은 **11.2%**였다. 명시적으로 기본급인 5개만 보면 **6.7%**다. 작은 공개 근거 표본이며 blind gold가 아니므로 전체 64,144개의 정확도로 해석하지 않는다.

`/ops/debugging/role-salary`는 최대 **20개**, 기본 `mapping`이며 실제 production 함수로 **20/20** 정상 반환을 확인했다. 비용 **$0.0031026**, 응답 **1.34초**다. 최초 연결 확인에서 요청/decoder contract 불일치로 0/20이 나왔고, 이를 수정한 뒤 재실행한 결과다. 두 호출과 50개 smoke 비용은 기존 $1 실험 ledger에 모두 기록했다.

## 구현·검증·남은 실행

opportunity quality의 prompt, score 생성, runtime reader와 UI를 제거했다. DB에는 `salary_is_predicted`를 추가하고 이전 quality column을 제거했다. Worker는 외부 목록에서 누락 급여를 채워 이후 검색에 재사용한다. 예측 numeric 급여와 표시 범위는 LLM 역할 입력에서 제거한다. 실제 공개 급여는 유지한다.

관련 웹 테스트 31개, 추가 SQL 계약 테스트, worker의 급여·검색 관련 테스트, TypeScript 및 변경 범위 lint가 통과했다. DB 계약 테스트에는 실제 공개 급여 보존, 원문 변경 무효화, 원화·월급 변환, 부분 범위 효용, 예측값 LLM 차단이 포함된다. 넓은 기존 worker 테스트에서는 이번 변경과 무관한 최종 안내 prompt 문구 assertion 1개가 실패했으며 해당 prompt는 수정하지 않았다.

남은 단계는 **웹과 6개 opportunity worker의 새 reader 배포 확인 → 준비된 결과 저장 → 실제 저장 개수 확인**이다. 배포는 현재 요청에서 승인되지 않았다. 운영 추정 급여는 아직 0개다. 저장은 기존 run receipt를 재사용하므로 전체 LLM을 다시 호출하지 않는다. 저장 시점의 실제 급여/원문 변경 때문에 준비 개수보다 실제 저장 개수가 적을 수 있다.
