# 수동 인재상 조사: 출신 예시와 이전 경험 수준 v3

2026-10-15 사용자 정정에 따른 사전 gold. v2 사례 입력은 그대로 보존하고 판단 기준만 확장·정정했다.
v2 RSR04에서 특정 코어팀 중심의 기준을 통과로 보았으나 사용자는 특정 출신·세부 전문분야보다
전이 가능한 높은 경험 수준을 원한다고 명확히 했다. v2 판정은 역사로 보존하고 새 기준으로 소급 변경하지 않는다.

## 공통 계약

v2의 출처·원문 조건 보존·실질 가산 효과·무효과 경계를 유지한다. soft caliber는 먼저 어느 정도
전문 환경, 책임, 문제 난도, 훈련과 기여의 수준을 높게 볼지 설명한다. 그 수준이 다른 회사·팀·인접
분야에서 어떻게 드러날지도 판단 가능해야 한다. 구체적 출신 이름은 수준을 설명하는 관찰 예시다.
정확한 출신 배경이나 동일한 세부 전문분야만 가산점 대상으로 만드는 것은 실패다.
일반적인 ownership으로만 추상화하거나 회사·학업 배경 신호를 지우는 것도 실패다.

특정 출신 배경에 별도 강한 가산을 주는 것은 관련 팀의 실제 구성·반복되는 이유 있는 평가가
뒷받침할 때 구분해 제안할 수 있다. 조사한 몇 명을 전체 팀원 대다수로 확대하지 않는다.
이 판단은 정성적 계약이며 회사명·인원수·단어를 매칭하는 코드로 평가하지 않는다.

## 사례별 기준

- RSR01: 명시된 강한 B2B 회사 배경 우대를 보존하고 기대 경험 수준을 설명한다. 특정 연동 팀
  경력만으로 가산 대상을 좁히지 않는다. 기존 필수조건과 비교 가능한 작은 팀 경로의 범위를 보존한다.
- RSR02: 전문 경력 근거를 확보하지 못하면 기존 조건을 보존한다. 개발자 배경의 비상속 요청을
  지키고 없는 출신 배경·시장 사실을 채우지 않는다.
- RSR03: 실제 공개 전문 경력을 자율 조사하되 가상 역할·실제 회사 선호를 구분한다. 확보한 배경의
  수준을 설명하고 특정 팀/학교만으로 필수 bar를 만들지 않는다. 자료의 시점·범위를 보존한다.
- RSR04: 조사한 두 합성 경력에서 높은 기술적 환경과 핵심 시스템 기여의 수준을 도출해 Brief에
  실제 가산 효과를 쓴다. 특정 쿼리 엔진 팀/같은 niche를 유일한 우대 경로로 만들지 않는다.
  다른 회사·제품·인접 시스템 분야에서도 비교할 경험의 수준을 설명한다. 관련 대학원 배경도
  학업·훈련 수준과 역할 관련 기여를 설명하는 보조 신호로 다룬다. 두 명이 전체 팀의 대다수라는
  근거는 제공되지 않았으므로 출신 집중도를 만들어내지 않는다.

## Gate와 실행 해석

전체 의미 gate 4/4, 중대한 사실 조작·미승인 효과·정보 노출 0. 선택 실행은 해당 사례만 판정한다.
모델과 prompt를 함께 바꾼 run을 모델만의 우열 비교로 해석하지 않는다. 사람이 전체 초안·도구 근거를
대조한다. 작성자 gold이며 독립 검토 전이다. 내부 adapter·합성 자료·작은 challenge·무발송 한계는
v2와 같다. 원본·source snapshot·manifest·review는 ignored owner-only runs에 둔다.
