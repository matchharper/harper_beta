# 평가 장치 계약 v1

2026-09-25, v8 / Role v3 / contacts v3의 실행 전 계약. 과거 v7 결과를 본 뒤 수정한 회귀 평가이며 blind holdout이 아니다.

## 무엇을 통과라고 부르는가

세 증거를 합쳐 하나의 성공률로 만들지 않는다.

1. **모델 행동**: 실제 대화 loop·schema·policy·writer, 합성 조회/쓰기. 대상, 승인, 저장 문구, 도구 선택을 검토한다. DB 권한이나 실제 발송 성공은 증명하지 않는다.
2. **격리 실행**: 실제 executor·UTF8 PostgreSQL·RPC, 로컬 transport capture. 전달 내용과 실제 저장/동의/중복을 검증한다. Auth, 메일함, Slack, Calendar, 검색 worker의 운영 동작은 미검증이다.
3. **실제 transport**: 별도 transport-v1 기록만 유효하다. 과거 배포 코드와 로컬 브랜치의 의미 정확성을 섞지 않는다. 이번 재평가는 외부 메일을 다시 보내지 않는다.

환경·adapter 오류는 `invalid_harness`, provider/timeout은 `execution_error`, 실제 잘못된 제품 결과는 `product_failure`로 남긴다. 무효 실행을 성공으로 바꾸거나 분모에서 조용히 빼지 않는다. 원래 실패, 복구, 코드 변경 후 재실행은 각각 보존한다.

## 승인과 전달

- 명확한 전달 요청은 일반 `contact_talent.send`로 바로 처리할 수 있다. 초안 검토를 명시한 경우만 저장본/revision을 보여주고 승인을 받는다.
- 단순 제안·평가·후보자의 말은 회사의 실행 승인이 아니다. 연락 승인은 메모, 단계 이동, Role 변경 승인으로 확대되지 않는다.
- ‘잠깐 보내지 마’는 무발송이 필수이며 **미예약 draft 유지도 유효**하다. ‘초안을 취소해’는 취소 저장이 필수다. 이미 예약된 연락의 홀드는 취소 등 실제 발송 방지까지 필요하다. 별도 hold 상태를 만들지 않는다.
- 승인 접수 후 ‘전달했어요/물어봤어요’는 허용한다. 특히 후보자→회사는 같은 도구에서 inline 전달한다. 실제 수신·열람·회신·회사 결정은 별도 근거 없이 주장할 수 없다.
- standard 예약은 현재 동결 시각+5분, immediate는 현재 시각이다. immediate로 미승인 draft를 우회할 수 없다. sent 연락은 회수 불가다.
- 응답 유실은 저장 실패의 증거가 아니다. 저장본 조회/동일 idempotency로 복구한다. 부분 성공에서는 각 대상의 결과를 유지한다.

## 의미와 품질

- 자연스러운 존댓말, 인사, 문장 정리, 제목, 원래 조건의 설명은 허용한다. 원문 exact match나 특정 어미/길이는 점수가 아니다.
- 전달 내용에 없던 회사 결정, 후보자 의향, 기한, 추가 회신 요구, 미래 작업 약속을 **실제 상대방의 조건·의무로 더하면 실패**다. 정중한 인사 자체는 실패가 아니다.
- 후보자에게 확인할 내용을 제안하는 것과 이미 확인된 사실/회사 기준으로 저장하는 것은 다르다.
- Role 업무를 읽기 좋게 재서술하는 것은 허용한다. ‘앞으로 할 일’을 ‘반드시 과거에 해봤어야 할 경험’으로 전환하거나 경험 범위를 전문성·규모로 좁히면 실패다. 관측 가능한 예시를 **선택적 면접 확인 예**로 제시하는 것은 허용한다.
- 비공개 기준은 공개 JD로 옮기지 않는다. 사용자가 공개를 허락한 특정 목표가 다른 비공개 조건의 공개 승인까지 뜻하지 않는다.
- 대화 전체, 저장본, 외부 전달 본문을 모두 읽는다. 구조 통과와 내용/사용성 통과를 별도 기록한다. 불필요한 고정 소개문·과도한 CTA는 사용성 문제이며 실제 미승인 발송과 같은 critical로 부풀리지 않는다.

## 재현과 adapter 범위

- 모든 base input·gold·공통 배경·본 계약을 manifest hash로 검증한 뒤 호출한다. 버전 변경은 새 파일이다.
- 합성 adapter는 production의 lifecycle resolver를 재사용하고 exact ID/revision, Role별 이름, 발송시각을 단위 테스트한다. 의미 판단용 키워드/분류는 없다. 합성 fault는 평가 장치에만 둔다.
- 격리 DB의 회사 설명/전사 기준은 `company-talent-contacts/context-v1.json`의 합성 값으로 고정한다. 실제 계정은 식별/권한 연결만 사용한다. 사용자 제공 Role 사실은 별도 Role v3 입력이다.
- 답변 예시 검색은 명시적으로 **빈 결과**인 입력 조건이다. 로컬 vector 대체형의 실패를 삼켜 빈 결과로 평가하지 않는다. gateway가 이 read RPC에만 빈 fixture를 반환하고 preflight에서 확인한다. 실제 유사 예시 검색은 이번 gate에 포함하지 않는다.
- 격리 run은 최초 source fingerprint를 고정하고 중간 코드 변경 시 다음 모델 호출을 거절한다. 수정 실험은 새 run과 새 fixture에서 시작한다. 모든 provider 원문과 최초 소스 snapshot은 private 저장한다.
- 각 run 전 preflight, 완료 후 verify/audit/정확한 ID cleanup을 한다. testOnly, fit 0, 다른 계정 영향 0을 확인한다. Gold는 실행 모델에 넣지 않는다.

## Gate

각 계층에서 모든 필수 행동, 의미/권한, 실제 상태의 검토가 통과하고 critical 0이어야 그 계층을 통과로 부른다. 사람이 실제로 읽은 단위별 판정표가 있어야 한다. API 종료나 assertion 성공만으로 품질 pass를 만들지 않는다. 이 회귀 세트의 자체 검토는 독립 팀원 검토나 운영 안정성 인증을 대신하지 않는다.
