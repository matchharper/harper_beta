# 조사 Brief의 경력 수준 보완 — 2026-10-16

로컬 구현 및 격리 실행 기록이다. 운영 저장·발송·후보 탐색·배포·채용 시작 자동 연결은 하지 않았다.

## 변경

- 공통 작성 원본 `hiringBriefAuthoringPrompt.ts`에서 전문·학업 환경의 수준, 개인의 성장·성과, 직무 직접 경험을 구분했다. 배경 자체의 가산이 특정 프로젝트 세부사항 확인에만 종속되지 않게 했다.
- 비교 수준을 설명하는 대표 배경은 Brief 안에도 남기고 다른 회사·분야의 동급 배경을 긍정적으로 설명한다. 미확인 선호를 해당 배경에 가산하지 않는 부정 정책으로 바꾸지 않도록, 새 제한의 회사 근거를 저장 전 검토하게 했다. 정성 validator·후처리·추가 모델은 없다.
- 회사 공통·다른 Role의 조건은 적용 범위와 강도를 확인한다. 조사 과제의 중복된 수준 지침은 공통 작성 계약에 위임했다.
- 작성 가이드에서 공통 matching의 전체 Brief 입력과 일부 Slack writer의 앞 2,000자 입력을 구분했다. Worker 코드는 바꾸지 않았다.
- 기존 runner는 frozen delivery 계약 버전을 선택하도록 확장했다. 이전 입력/gold는 그대로 보존하고 v4 입력과 delivery-v2 gold를 첫 호출 전 동결했다.

## 실제 모델 실행

동일한 v4 입력의 RSR04(합성), RSR05(실제 공개 회사의 가상 Role)만 선택했다. gpt-6.1-sol/medium, OpenAI Responses, completion 최대40,000토큰, fallback 없음. 실제 내부 데이터 대신 메모리 adapter, 실제 공개 웹 검색과 본문 조회를 사용했다.

최종 결과는 기존 자격 보존, 구체적인 배경 수준과 강한/보조 가산 효과, 다른 경력 경로와의 비교, 가상 요청과 회사 확정 선호의 구분을 충족했다. 자료에 포함된 전 팀원의 현재 재직을 주장하지 않았다. 미확인 선호는 열린 상태로 남겼고 근거 없는 출신별 가산 금지 정책은 없다. 내부 대화·검토 이유 미수집도 회사에 기록이 없다는 의미로 확대하지 않았다.

네트워크 기록은 모델 provider와 공개 Exa만 포함한다. 원문, 도구·source snapshot·hash·dirty fingerprint, 검토 기록과 추출한 Brief/Slack은 각 ignored `runs/`의 0700/0600에 보존했다. 출력 문장을 수작업으로 보정하지 않았다.

## 짧은 검증 및 남은 범위

- 변경 경로의 `roleSearchResearch.test.ts` 7개 통과. 모델 설정·무단 효과 차단·세션 캐시·대상 Brief/스레드 범위를 확인했다.
- 기존 조사 관련 범위의 임시 tsconfig로 TypeScript 검사 통과.
- 최종 RSR05 Brief는 2,070자다. 핵심 수준과 비교 효과는 앞 2,000자에 포함되며 뒤의 제공 범위 문구가 일부 잘릴 수 있다. Slack 답글은 1,684자로 상세형이다. 모든 소비 경로의 길이 문제를 해결했다는 뜻은 아니다.
- Live 웹은 실행마다 달라지는 관찰이다. 작은 선택2건의 작성자 검토로 전체5건 gate, 독립 평가, 실제 회사 선호, 실제 DB/Slack/Worker E2E 또는 후보 추천 성과를 입증하지 않는다.
