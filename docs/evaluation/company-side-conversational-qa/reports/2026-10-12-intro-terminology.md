# Intro 사용량 단위 변경 검증

문서 기준: 2026-10-12. 앱은 미배포다. 운영 서비스 답변 자료와 Stripe의 상품 설명 변경은 앱 배포와 별도로 수행했다.

## 변경 범위와 입력 보존

한국어에서도 사용량 단위를 Intro로 쓰며 영어는 1 Intro / 2 Intros로 표현한다. Intro 요청은 행동이고, 잔액은 사용 가능한 단위이며 완료된 소개나 채용 건수가 아니다. 표현 계약은 `src/lib/org/agent/uxWritingPrompt.ts`, 실제 서비스 정책의 명칭은 `serviceKnowledgePrompt.ts`에서 수정했다. 출력의 단어를 검사해 재작성하거나 폐기하는 런타임 코드는 추가하지 않았다.

기존 frozen v18의 cases·gold·manifest를 수정하지 않고 canonical `scripts/evalCompanyAgentCapabilities.ts`로 새 run을 만들었다. 모든 입력은 합성이다. DB·Slack·메일 호출은 차단하고 모델 provider만 호출했다. 현재 기본 `google/gemini-3.8-flash` / OpenRouter / medium / temperature 0.5 / progressive를 유지했다. 모델 요청·응답, 소스 snapshot, fingerprint와 실행 manifest는 ignored owner-only `runs/`에 있다. 독립 팀원 검토와 실제 대화 전달 E2E는 수행하지 않았다.

R3의 공개 정책·권한·실패 사실성은 구현자 원문 검토 기준 5/6대화다. 실패와 원문을 보존하며, R4·R5 일부 재실행을 최종 소스의 전체 v18 통과나 모든 향후 답변의 용어 보장으로 주장하지 않는다. R5 당시의 가격 2대화 용어 목표는 2/2였지만, R6·R7에서는 옛 명칭 부연이 다시 관측됐다. 회사 정보 조회의 결제 범위를 분명히 한 뒤에는 미확인 회사 계약 추정이 관측되지 않았다.

최종 R8의 6대화·8발화 원문과 도구 결과를 모두 읽었다. 이번 명칭 목표는 6/6이며, Intro 요청 실패와 연결 수락 실패는 각각 별도 notice 1개·외부 효과 0개, 허위 완료·원인 추정·잔액 노출이 없었다. 입력·gold·manifest는 그대로 보존했다. 한국어 가격 답변의 조건부 Slots/Billing 확인 경로 누락 때문에 전체 frozen v18 gate를 통과했다고 주장하지 않는다. 모델 답변의 긴 설명·반복·문체와 실제 운영 전달 E2E, 독립 팀원 검토도 별도 한계다.

## 전체 점검에서 보완한 내용

- 공개 요금제와 회사 소개의 Free FAQ는 회사 이메일로 즉시 가입할 수 있다고 안내했으나 실제 신규 직접 가입은 중단되어 있었다. 현재 지원되는 미팅 신청과 초대받은 팀원의 참여로 안내를 맞췄다.
- 회사 정보 조회는 채용·회사 정보만 제공하고 구독·계약·잔액은 제공하지 않는다. 정보가 없다는 이유로 Free를 추정하지 않도록 서비스 지식 원본에 조회 범위를 명시했다. 일반 표현 계약에서 과거 사용량 명칭을 Intro와 연결해 이해하도록 했으며 출력 검사·재작성 코드는 추가하지 않았다.
- 슬롯의 Role 변경 안내는 `Intro 잔액과 갱신일`로 다듬고, 결제 복구는 슬롯 이용과 Intro 제공으로 설명했다. 한국어 문서의 복수형 잔여 표기도 Intro로 맞췄다. 설계 문서의 실제 `credits` 테이블 이름은 보존했다.
- 미공개 회사 약관 검토본의 제4·6·7·9조에 남아 있던 Free 1 Role·5개·만료 시 Role 중지 규칙을 현재 로컬 정책인 Role 무제한·공용 10 Intro·슬롯별 50 Intro·만료 후 Role 유지로 맞췄다. 공개 약관과 기존 동의 버전은 변경하지 않았다. 설계 문서의 명시적으로 폐기된 과거 설계 기록은 현재 정책으로 바꾸어 기록하지 않는다.

## 표시·조회 경로 검증

- 기존 화면·문구·Documents·FAQ·Stripe 계약 테스트 47개 통과. 올바른 scripts tsconfig로 company-side LLM의 billing notice 테스트 3개도 통과했다. 첫 일반 tsconfig 실행에서 난 `server-only` 모듈 해석 오류는 검증 설정 문제로 기록한다.
- 기존 billing API 테스트의 합성 Workspace는 현재 Harper 전용 결제 허용 ID가 아니어서 5개 하위 사례가 403으로 차단됐다. 원본 테스트를 고치지 않고 임시 실행본의 합성 Workspace ID만 기존 허용 ID로 맞춘 검증은 5개 하위 사례와 상위 테스트가 모두 통과했다. 이 실행본은 즉시 삭제했으며 실제 DB 접근·계정 생성·결제를 하지 않았다.
- 수정한 29개 TS/TSX 파일의 구문 검사, 수정 런타임 파일의 ESLint, `git diff --check`를 통과했다. Intro 수량 표시 함수는 한국어·영어의 0·1·2·미확인 값 8개 조합을 확인했다. 고정 문구는 양쪽 언어의 잔액 부족 안내에 함께 적용된다.
- `/org`의 실행 가능한 문자열을 다시 읽어 남은 Credit 표기는 번역/FAQ key, 기존 URL 호환 값, 과거 `Shared credits` 응답을 새 표시로 읽는 비교 값, 모델이 과거 단위를 이해하기 위한 공통 표현 지침임을 확인했다. 실제 고정 표시 문구에는 옛 명칭이 없다. 내부 식별자·장부·제공량·차감·갱신·권한을 변경하지 않았다.
- 전체 점검 후 관련 테스트 50개와 Slack의 Intro 부족 안내 1개가 통과했다. Slack 검증은 해당 사례만 실행했고 다른 35개는 선택 범위 밖으로 건너뛰었다. 실행 파일 21개의 구문 검사와 ESLint도 통과했다.
- 실제 로컬 `/pricing` 화면에서 한국어·영어, 월간·연간 금액, Intro 표기와 Free FAQ의 초대 기반 접근을 확인했다. 데스크톱 1512px와 모바일 390px 모두 페이지의 가로 넘침이 없었고 모바일 화면에서도 표시가 잘리지 않았다. 이 화면 확인은 실구독 구매나 운영 `/org` 전체 E2E가 아니다.

## 외부 자료 변경 검증

운영 회사용 서비스 답변 자료 12행을 기존 ID로 수정하고 질문이 바뀐 6행의 embedding을 갱신했다. company 78행과 career 11행의 수, 다른 행의 원문, 태그·활성화·메모 보존을 저장 후 조회로 대조했다. 이 갱신은 모델 평가의 DB 접근과 별개이며, 평가에 운영 데이터를 주입하지 않았다.

Stripe Live와 Test의 기존 Harper Slot 상품 설명을 Intro로 바꾸고 각각 API 재조회로 확인했다. Live는 키의 권한을 넓히지 않고 사용자가 2단계 인증을 완료한 Dashboard에서 설명만 저장했다. 기존 상품명·수량 단위·상품/Price ID·월 $249·연 $2,388·통화·결제 주기는 유지했다. 실제 구독 구매나 청구는 하지 않았다.

전체 점검에서 서비스 답변 자료 89행을 저장 후 snapshot과 다시 대조했으며 company 78행·career 11행과 모든 내용이 같았다. 회사용 질문·답변에 옛 사용량 명칭은 없었다. Stripe Live·Test 설명과 월간·연간 가격도 원본과 다시 대조해 설명 이외의 변경이 없음을 확인했다.

원본·수정 계획·저장 후 자료는 ignored `.local/intro-terminology-20261012/private/`의 owner-only 파일로 보존한다. 앱 push·배포·Worker 재시작·DB migration·공개 약관 교체는 하지 않았다. Notion은 조회만 했고, 작업 지침에 따라 배포 후 관련 3개 페이지의 용어를 동기화한다.
