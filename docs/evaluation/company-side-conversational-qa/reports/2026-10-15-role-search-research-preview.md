# 수동 인재상 조사 미리보기 구현·검증

작성일: 2026-10-15. 로컬 구현 기준이며 배포하지 않았다.

## 결론

조사 전용 수동 실행과 결과 보존을 구현했다. 기존 회사 대화 LLM이 일반 조회 도구와 공개 웹 검색을 사용해 조사 근거, Hiring Brief 초안, 회사 설명 초안을 만든다. **채용 시작 run·제품 route·cron·queue에는 연결하지 않았다.** 실제 Brief 저장, 후보자 검색·연락, Slack 스레드 생성·발송도 없다.

최종 r3 실행은 3/3 완료했지만 의미 품질은 **1/3 통과, 2/3 미통과**다. 자율 검색과 초안 생성은 확인했다. 근거에서 도출한 탐색 제안을 회사의 확정 기준과 구별하고, 기존 자격 범위를 유지하는 품질은 부족하다. 자동 적용 가능한 상태라고 판단하지 않는다. 출력 원문을 수정해서 통과시키지 않았다.

## 구현과 실행 범위

- 실행 함수: `src/lib/org/agent/roleSearchResearch.server.ts`의 `runRoleSearchResearchPreview`.
- 기존 `runOrgAgentToolLoop`와 현재 회사 모델을 재사용한다. 한 작업 세션 안에서 필요에 따라 여러 completion과 도구 호출이 일어난다. 단일 모델 API 호출로 조사를 끝내는 구조가 아니다.
- 시작부터 `web_search`, `open_url`을 제공한다. 회사·역할·후보·대화·연락 기록은 기존 일반 read 도구로 조회할 수 있다. trusted allowlist를 공통 capability resolver와 실제 executor 경계 모두에 적용해 loader가 쓰기·발송 도구를 추가하지 못한다.
- 웹 검색 provider는 **Exa**다. Google 검색 API나 로그인한 LinkedIn 브라우저를 구현한 것은 아니다. 공개 LinkedIn URL을 발견·조회할 수 있으나 개별 페이지의 접근성과 최신성은 보장하지 않는다.
- 공개 검색·본문 cache는 세션 메모리에 둔다. 이번 CLI는 운영 DB client를 만들지 않고 입력 packet의 내부 자료만 읽는다. 실제 DB의 권한·조회 계약 검증은 이번 평가 범위 밖이다.
- 수동 runner: `scripts/runRoleSearchResearchPreview.ts`. 기본 평가 입력 외에 동일 구조의 `--input=<local-packet.json>`을 받을 수 있다. 미수집 후보·대화 기록은 없는 기록처럼 반환하지 않고 조회 한계를 드러낸다.
- 평가에서 외부 네트워크는 모델 completion과 Exa 공개 조회로 제한했다. DB·Slack·메일·queue transport는 허용하지 않았다. 합성 Role은 메모리 안에만 만들며 DB에 fixture를 삽입하지 않았다.

```sh
TSX_TSCONFIG_PATH=scripts/tsconfig.json node --import tsx scripts/runRoleSearchResearchPreview.ts --run=<새-ID> --case=RSR01,RSR02,RSR03
```

환경의 모델·Exa 자격증명이 필요하며, 실제 provider 호출 비용이 발생한다. 같은 run ID로 기존 결과를 덮어쓰지 않는다.

## 평가 계약과 실제 결과

입력·gold는 [research-preview-v1](../research-preview-v1.json), [gold](../research-preview-gold-v1.md), [frozen manifest](../research-preview-manifest-v1.json)로 첫 실행 전에 고정했다. 보완 과정에서도 입력과 gold를 바꾸지 않았다. 내부 자료와 공개 웹이 합성인 2건, 내부 역할은 가상이고 웹만 실제인 1건이다. 작성자 수동 검토이며 독립 팀원 검토는 아직 없다.

실제 모델은 OpenRouter의 `google/gemini-3.8-flash`, reasoning `medium`, temperature `0.5`다. 세션 제한은 240초, 공통 loop의 도구 예산은 30회·결과 80,000자다. 다른 모델 fallback 없이 실행했다.

| --- | --- | --- | --- | --- |
| `20261015-role-research-r3-1` / RSR01 | 92.2초 | 12 / 9 | 미통과 | 팀 소개와 개인 경력 근거를 읽고 동명이인을 구분했다. 명시된 강한 이전 회사 경험 가산점과 미확인/미충족 구분을 보존했다. 그러나 기존의 넓은 구현·배포 기준 설명에 기업 고객 환경·연동 범위를 추가하고, 우대 설명에서도 특정 통합·장애 해결 조합이 필요하다고 서술해 기준을 좁혔다. |

| `20261015-role-research-r3-3` / RSR03 | 69.8초 | 9 / 4 | 미통과 | 인물 이름·프로필 링크 없이 실제 공개 검색 3회와 URL 조회 3회를 수행했다. 팀 소개·경력·유관 채용 자료를 찾고 개발자 도입 경험으로 연결했다. 그러나 관찰된 팀 배경으로 만든 학교·회사 가산점을 가상 역할의 확정 우대처럼 표현했다. 다른 직무의 공개 공고와 가상 요청의 경계, 이미 내려간 공고의 과거 자료라는 표시도 부족했다. |

도구 수는 내부 read 실패를 포함한다. 완료 횟수는 모델 API 호출 횟수이며 별도 연구 모델·글쓰기 모델을 뜻하지 않는다. 3건의 50.9~92.2초는 작은 표본의 관측값이며 서비스 지연 보장이 아니다.

## 실제 자율 조사를 확인한 범위

실제 웹 사례에는 회사명·홈페이지·가상 역할만 주고 참고 인물 이름이나 URL을 주지 않았다. 모델이 회사·관련 직무를 검색하고 결과에서 팀원과 자료를 발견했다. r3에서는 공식 About 및 유관 채용 페이지를 열었다. `open_url` 3회는 같은 세션의 검색 본문 cache를 읽었으며, 각각 별도의 원본 HTTP 재조회가 있었던 것으로 세지 않는다. Exa 검색 3회는 실제 네트워크 성공을 확인했다.

앞선 r1에서는 LinkedIn/GitHub 등을 포함한 검색어를 스스로 만들고 검색 결과의 개인 홈페이지도 열었다. 따라서 제공된 링크를 단순 요약하는 경로에만 갇혀 있지는 않다. 다만 이 결과는 임의의 LinkedIn 프로필을 항상 전체 조회할 수 있다거나, 모든 팀원의 경력을 조사했다는 증거가 아니다.

공개 자료를 확보하는 것과 채용 기준을 올바르게 만드는 것은 별개의 평가다. 팀원의 배경에서 높은 경험 수준의 **탐색 가설**을 만드는 것은 유용하다. 그것을 회사가 이미 정한 자격·가산점으로 표현하는 것이 이번 미통과의 핵심이다. 회사가 명시한 높은 배경 선호를 지우는 방향으로 해결하지 않는다.

## 코드 경계 검증

- 변경 경로 관련 단위 검증 **25/25 통과**: `roleSearchResearch.test.ts`, `capabilities/capabilities.test.ts`, `capabilityLoop.test.ts`.
- 새 5개 검증은 쓰기·발송 도구의 노출/실행 차단, 대상 불일치와 취소, 일반 capability 동작 유지, 세션 cache 격리, 기존 Exa executor와 cache의 실제 연결을 확인한다. 모델의 문장 품질을 단어 매칭으로 검증하지 않는다.
- 변경한 TypeScript 7개 파일을 대상으로 한 compiler diagnostics는 0건이었다. 전체 repository typecheck·build 통과를 뜻하지 않는다.
- 신규 함수의 참조는 수동 CLI와 테스트뿐이다. 기존 activation·검색 예약·추천 Worker의 호출 경로를 추가하지 않았다.
- raw run 파일은 gitignored이며 디렉터리 0700, 파일 0600으로 보존한다. 생성된 preview·tool trace·completion·source snapshot·입력·hash·network 기록은 각 `runs/<run>/`에 있다. 이 문서에는 원본 모델 응답이나 개인 프로필을 복사하지 않았다.

## 다음 검토에서 풀어야 할 점

1. 기존 회사 기준을 그대로 유지하면서 추가 연구 제안을 별도 가설로 표현하는 품질. Brief 설명과 회사 메시지 모두에 같은 구분이 필요하다.
2. 다른 역할·과거 공고는 참고 자료라는 범위와 시점 표시. 웹 cache의 `truncated=false`는 provider가 원문 전체를 반환했다는 증명이 아니다. 이번 공식 About 본문도 15,000자 경계에서 끝났다.
3. 실제 회사 packet으로 회사 대화·이전 후보 검토와 공개 경력 자료를 함께 해석하는 품질. 현재는 운영 원문을 수집하지 않았다.
4. 공통 URL reader의 refresh/긴 본문 후속 조회, runtime에서 진행 중인 web 요청의 취소 전파. CLI는 fetch에 timeout을 전달하지만 새 함수의 기본 공통 web adapter 자체를 취소 가능하게 개편하지는 않았다.

이 검토를 통과하더라도 채용 시작 연결은 별도 요청 범위다. 이번 구현은 수동 초안 확인용으로 유지한다.
