# 먼저 말을 거는 인사의 배려와 맥락

2026-10-15 로컬 prompt 수정. 배포·운영 데이터 조회·외부 발송 없음.

공통 문체 원본 `uxWritingPrompt.ts`의 선제 연락 지침을 수정했다. 눈여겨본 상황, 먼저 챙긴 이유,
상대가 덜 수고할 수 있는 구체적인 도움을 연결하도록 했다. 짧은 결과 요약 때문에 이 맥락까지
생략하지 않는다. 확인된 이름과 대화에 맞는 웃음·느낌표는 자연스럽게 쓸 수 있지만 상대의 일정이나
미검토 이유를 단정하지 않는다. 스레드를 나누는 이유도 읽고 답하기 편하도록 배려한 맥락에서 전한다.

문체 지침은 이 원본에만 두고 `proactiveReview.ts`의 중복 인사 예문은 제거했다.
UX writing guide에 같은 일반 원칙을 기록했다. 고정 인사, 웃음 의무, 단어 판정이나 출력 교정 코드는 없다.

## 고정 입력 재실행

- 기존 v26/gold-v26 입력·정답을 유지했다.
- run: `20261015-proactive-warm-opening-r1`.
- canonical runner: `scripts/evalCompanyAgentCapabilities.ts --dataset=v26 --mode=full --model=gpt-6.1-sol --case=CSCQ2501-shortlist_then_contact,CSCQ2501-unchanged_silent --run=20261015-proactive-warm-opening-r1`.
- Sol/high 실제 모델, 합성 조회·부수효과, provider 외 네트워크 차단. source·prompt fingerprint와 전체 원문은 ignored owner-only run에 보존했다.
- 두 사례·세 턴 실행 완료. 전체 답변, 후보자 연락 본문, 도구 호출과 효과를 구현 담당 agent가 직접 검토했다.
- shortlist는 회사가 중요하게 본 경험을 받아서 먼저 비교한 이유와 검토 순서를 정하기 위한 도움을 연결했다. 바쁘거나 검토를 미뤘다고 단정하지 않았고, 명시적 승인 뒤 지정된 후보자에게 요청한 질문만 한 번 보냈다. 후속 답변에는 인사를 반복하지 않았다.
- 새 사실 없는 사례는 무응답·효과 없음. 선택한 기존 gold의 필수 의미·효과 2/2 통과.

이 작은 합성 재실행은 실제 회사 첫 연락의 호칭·여러 역할 스레드·친밀도 전체를 검증하지 않는다.
shortlist 사례는 이미 회사가 우선 검토를 요청한 맥락이며 실제 출력은 인사 없이 그 말을 이어받았다.
이를 SBVA 새 인사 원문이나 모든 첫 연락에서 동일한 온도가 재현된 증거로 제시하지 않는다.
독립 검토·실제 Slack 전달·전체 v26 gate는 제외했다. 관련 diff 공백 검사는 통과했다.

## 사용자 원문 예시 추가

후속 요청으로 사용자가 지정한 첫 연락 문장 전체를 공통 문체 prompt에 그대로 넣었다.
예시의 호칭·역할·수락/대기·상대 사정·수행 사실은 현재 맥락에 맞추는 참고 예시이며 고정 인사가 아니다.
같은 v26의 `CSCQ2501-shortlist_then_contact`만 새 run `20261015-proactive-warm-opening-r2`로
Sol/high 재실행했다. 두 턴 완료 후 원문·연락 본문·효과를 직접 검토했다. 예시의 투자팀·커뮤니케이션·
두 역할이나 상대가 바빠서 미검토했다는 사정을 복사하지 않았고, 실제 fixture의 API 경험에 근거한
검토 제안과 회사 승인 후 한 번의 연락을 유지했다. 선택 사례 필수 의미·효과는 통과했다.
완료 안내의 '발송 요청' 표현은 다소 시스템적이다. 이번 예시 추가가 모든 답변의 자연스러움을
해결했다거나 실제 첫 인사 전문을 검증했다고 주장하지 않는다. 이전 run은 보존했고 배포하지 않았다.
