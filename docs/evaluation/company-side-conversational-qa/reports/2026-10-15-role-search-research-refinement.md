# 수동 인재상 조사 후속 개선과 전달·Brief 계약

2026-10-15 로컬 후속 작업. [최초 구현·r3 검증](2026-10-15-role-search-research-preview.md)의 실패를 보존한 상태에서 개선했다. 제품 활성화·자동 저장·외부 발송·배포는 이번에도 하지 않았다.

## 바꾼 부분

변경 원본은 `src/lib/org/agent/roleSearchResearch.ts`의 조사 업무 지시다. company-side 기본 모델, 공통 authoring prompt, 권한 경계, 일반 대화의 prompt는 바꾸지 않았다. 새로운 판정 모델·별도 문구 작성기·정규식 출력 교정·조사 단계 상태 머신을 추가하지 않았다.

- **근거의 중심**: 일반 공고 요약보다 현재 회사 기준·이전 검토 이유와 관련 팀원의 실제 이전 경력을 조사한다. 역할 공고·제품 문서는 이를 보조한다. 링크가 없어도 모델이 회사·인물을 검색하고 공개 원문을 읽는다.
- **기준 보존**: 현재 필수·우대 자격 구절은 그대로 유지하고, 조사의 해석을 기존 조건 아래의 추가 의무로 붙이지 않는다. 강한 회사 배경 우대를 일반적인 실무 역량 중시로 약화하지 않는다. 필수가 아니라는 사실에서 가산점도 없다고 추론하지 않는다.
- **추가 제안**: 새 탐색 경로는 `Preferred criteria` 안의 별도 초기 탐색 제안으로 작성한다. 회사 확정 기준과 구분하며 그 경력이 없다는 이유로 기존 기준을 충족하는 후보를 탈락시키지 않는다. 이는 검토용 초안이다. 향후 가설의 실제 저장은 [설계 문서](../../../company/role-search-kickoff-implementation-plan-ko.md)의 공통 계약 정비가 남아 있다.
- **문서 전체 일관성**: 같은 기준·강도 보존을 Brief뿐 아니라 조사 설명·부모 메시지·답글에도 적용한다. 조회 실패는 현재 확인 한계이고 실제 경력·프로필의 부재를 뜻하지 않는다. 다른 직무·과거 공고·가상 역할의 범위도 구분한다.
- **검토 형태**: 조사 근거, 복사 가능한 Brief Markdown 블록, 채널의 부모 메시지와 스레드 설명 답글을 한 문서에서 구분한다. 이는 사람이 읽는 작성 계약이며 결과를 파싱해 저장·발송하는 로직은 없다.

## 현재와 향후 흐름

| 항목 | 현재 구현 | 자동 연결 때 필요한 동작 |
| --- | --- | --- |
| 시작 | 수동 CLI 호출 | 명확한 최초 채용 활성화에서 내구성 있는 회사 event를 enqueue |
| 조사 | 같은 company-side LLM의 일반 read·공개 웹 loop | 같은 경로에 실제 회사 맥락과 수신 범위 제공 |
| Brief | 로컬 문서 안의 초안 | 제한된 최초 위임·현재값 검증 아래 일반 편집 도구로 저장하고 read-back |
| 회사 설명 | 부모·답글의 초안 | 같은 LLM이 실제 저장본에 맞춰 최종 부모·답글을 작성 |
| 전달 | 없음 | 승인된 역할 채널에 기존 메시지 batch를 확정하고 부모 receipt 뒤 답글 전달 |
| 검색 | 이 기능에서 호출하지 않음 | 저장·필요 전달 사실을 확인한 뒤 기존 검색이 최신 Brief를 읽음 |

현재 구현에서 어떤 버튼을 눌러도 이 조사 기능이 자동 실행되거나 메시지가 발송되지 않는다. 수동 CLI의 내부 read는 입력 packet에 한정되고 운영 DB 조회가 아니다. 외부 호출은 모델과 Exa 공개 웹에 한정한다.

향후에도 조사 보고서 전체를 Slack에 복사하지 않는다. 부모는 Role과 인재상·탐색 방향이라는 주제, 답글은 기대 경험 수준과 가산 효과·근거·우선 경로를 전달한다. 기준 피드백은 같은 스레드에서 받는다. 초기 검색을 매번 회사의 추가 승인 대기로 만드는 설계는 아니지만, 현재의 일반 Brief 수정 확인 계약을 우회하는 자동 저장 권한은 아직 구현하지 않았다.

## 공통 전달 경로 재점검

기존 설계 문서의 일부 현재 상태 설명이 checkout과 달라 수정했다. 현재 `company_update`는 기존 Slack thread가 있으면 audience를 구성하고 메시지 batch 확정·복구·전달을 지원한다. 선택적 점검의 deadline 취소를 일반 회사 event에 적용하지 않는 분기도 이미 있다. 이 구현을 다시 만드는 것으로 계획하지 않는다.

남은 것은 thread가 없는 최초 Role 사건에 적절한 audience·원문/job 근거를 연결하는 일, Brief의 최초 위임과 충돌 보호, 첫 검색과의 실행 의존성이다. 팀원 진입 안내용 inline 멘션 부모 생성 경로를 킥오프가 구현됐다는 증거로 취급하지 않는다. 운영 DB·배포된 revision을 조회하지 않았으므로 이 내용은 로컬 코드 확인 범위다.

## 검증 계약

입력·gold는 기존 `research-preview-v1` 그대로이며 hash를 확인했다. 모델은 `google/gemini-3.8-flash`, OpenRouter, reasoning `medium`, temperature `0.5`를 유지했다. 합성 2건과 실제 공개 웹·가상 Role 1건이다. 같은 입력으로 여러 번 보완했으므로 blind 평가가 아니고, 실제 웹은 반환 시점에 따라 달라진다. source snapshot과 provider 기록은 run마다 보존했다.

의미 검토는 각 전체 원문과 도구 근거를 직접 대조한다. 코드 실행 성공과 품질 통과를 분리한다. 원본 출력·완료 호출·도구 trace·source snapshot·수동 review는 기존 ignored `runs/`에 owner-only로 두며 본 문서에는 raw 응답·개인 프로필을 복사하지 않는다.

최종 실행 **3/3 완료**, 기존 Brief 필수·우대 원문 보존과 부모·답글 분리는 **3/3 확인**, 문서 전체의 사전 의미 gate는 **0/3**이다. 부분 지표를 전체 품질 통과로 보고하지 않는다. 이전 r3의 1/3과 비교해 전체 gate가 개선됐다고 주장하지 않는다. 관측 가능한 개선은 Brief 원문 보존, 결과물 구분, 관련 인물의 실제 탐색이며, 조사 해석과 회사 설명의 사실성·강도 일관성은 여전히 부족하다.

r6 공개 URL 조회 3회도 같은 세션의 검색 cache를 읽었다. 이를 원문 재크롤링이나 최신 재직 확인으로 세지 않는다. 공개 프로필의 자기 서술과 provider 보강 정보가 섞일 수 있으며, 자료의 일부만 반환되는 한계도 유지된다. 실제 LinkedIn의 모든 페이지가 항상 조회된다는 보장은 없다.

같은 입력을 반복 보완한 9개 세션(r4/r5/r6 각 3개)을 운영 신뢰도나 독립 표본으로 해석하지 않는다. 이번 작업은 수동 조사 도구의 개선과 실패 확인이며, 자동 적용 품질 승인이 아니다. 모델을 바꿔 통과 결과를 얻거나 생성된 원문을 후처리해 숨기지 않았다.

## 코드 검증과 남은 범위

이번 수정 후 미리보기 경계 테스트 5/5가 통과했다. 새 semantic 문자열 검사를 만들지 않았다. 앞선 관련 테스트 25/25와 이번 5개 재검증을 새로운 30개 검사로 합산하지 않는다.

함수 참조는 수동 CLI와 테스트뿐이며 활성화·스케줄러·검색·발송 호출부를 추가하지 않았다. DB·Slack·메일·Worker 실행, 실제 회사 내부 read 권한, 새로운 자동 연결·동시 수정·전달 복구 E2E는 검증하지 않았다. 공통 URL refresh/후속 본문 조회와 기본 web adapter의 취소 전파 개선도 이번 수정 범위 밖이다.

## 회사 설명 말투의 소폭 보완 (r7)

사용자 요청에 따라 회사 메시지 작성 지시만 보완했다. 실제 읽은 역할 요구·이전 검토 이유·팀원 경력을 함께 짚고, 그 자료에서 기대 경험 수준과 우선 탐색 경로를 도출하는 짧은 헤드헌터 설명을 지향한다. 마지막에는 향후 탐색에서 기준 조정이 적합한 인재와의 연결 가능성을 높일 것으로 판단되면 근거와 조정 방향을 알리겠다는 한 문장을 자연스럽게 작성하도록 했다. 고정 문장 삽입·출력 후처리·기준 자동 변경은 없다.

동일 frozen v1 입력·gold·모델 설정으로 RSR01 한 건만 `20261015-role-research-r7-1`에서 실행했다(71.8초, 도구 8회, completion 8회). 원문과 실제 도구 결과를 직접 대조하여 기존 검토 이유와 확인한 팀원 경력을 연결한 설명, 기존 강한 배경 가산점, 조건부 조정 제안의 마무리를 확인했다. 이는 이번 표현 변경의 제한된 smoke이며 전체 3건 gate 재평가가 아니다. 문서 전체에는 조사 해석의 가산 대상 확대와 회사 답글의 가상 맥락 누락이 남아 RSR01 전체 의미 판정은 미통과로 기록했다. 앞선 r6 전체 gate 미통과와 자동 적용 보류는 유지한다. Brief 작성 계약·모델·도구 권한·실행 연결은 바꾸지 않았다.
