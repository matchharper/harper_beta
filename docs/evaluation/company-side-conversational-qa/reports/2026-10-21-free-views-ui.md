# Free 열람 UI와 실제 회사 대화 검증

기존 `Harper Free QA`의 합성 후보 6명·중단된 test-only Role 2개를 재사용했다.
사용자가 직접 테스트할 수 있도록 두 번째 Role에 allowlist 후보 2명의 합성 연결 대기
상태를 추가했다. 실제 동의나 연락 기록이 아니며, 정확한 식별자와 생성 경위는
ignored `private/free-views-v1/pending-fixture-v2.json`에 보관한다. fit은 생성하지 않았다.

## 구현과 화면 확인

- 기존 목록·그리드·카드의 배치와 컴포넌트를 유지하고 개인정보 자리에 합성 이름,
  사진, 경력, 학력을 넣어 blur한다. 별도 잠금 레이아웃으로 재배치했던 중간안은 제거했다.
- 평가는 기존 위치에서 읽을 수 있다. 서버 응답은 실제 신원을 null/빈 배열로 제외한다.
- 목록·그리드에서 직접 열람하며 화면 이동 없이 프로필이 열리고 남은 횟수 toast가 뜬다.
- 연결 대기 후보가 있으면 실제 행을 보여준다. 없음/있음 안내와 플랜 화면 연결도 확인했다.
- 데스크톱 우선, 기존 레이아웃 유지, 반복적인 슬롯 설정 설명을 피하는 원칙을 내부 가이드에 기록했다.

## 실제 LLM과 API 결과

동결 입력은 `free-views-live-v2.json`이다. v1의 3개 발화를 보존하고 연결 대기 비교
1개를 추가했다. `scripts/freeCandidateViewsQa.mjs --dataset=free-views-live-v2`로
인증된 localhost API와 실제 제품 기본 `google/gemini-3.8-flash`를 사용했다.
입력·소스 hash, 전체 답변, 도구 호출, 잔액은 owner-only runs에 보존했다.

| 요청 | 관찰 결과 | 소요 시간 |
| --- | --- | --- |
| 열람 없이 상위 3명 비교 | 이름·회사·학교 없이 평가로 비교, 10→10 | 31초 |
| 제일 적합한 3명 상세 | 지정한 상위 3명만 열람, 이름·경력·학력·프로필 링크 반환, 10→7 | 151초 |
| 같은 3명 재조회 | 기존 정보와 링크 반환, 7→7 | 29초 |
| 연결 대기 2명 비교 및 플랜 질문 | 익명 평가, 실제 관심 상태와 유료 연결 제한 설명, 7→7 | 21초 |
| 다른 팀원이 이미 열린 pair 재열람 | HTTP 200, charged=false, 7→7 | 4초 |
| 연결 대기 목록에서 1명 열람 | 동일 목록에서 정보 공개, 7→6 | 브라우저 |
| 열람한 Free 연결 대기 후보 연결 시도 | HTTP 403 feature_unavailable, 6 유지, 상태 변경 없음 | 5초 |
| 같은 후보를 다른 Role에서 열람 | 기존 Role 열람과 별도로 6→5 | 5초 |

첫 세 대화의 runs는 `11-50-07-689Z-chat`, `11-52-45-446Z-chat`,
`11-53-24-875Z-chat`, 연결 대기 대화는 `11-54-01-657Z-chat`이다.
답변 원문을 직접 읽어 합성 이력과 대조했다. 답변의 후보자 링크를 클릭해 같은 Role의
올바른 상세 프로필이 열리는 것도 확인했다. 실제 연락·Intro·결제는 실행하지 않았다.

확인 과정에서 LLM 조회에 누락되던 paidRole/capabilities와 연결 대기 수락 사실을
보존했다. 과거 relayId 답장 경로도 Role 접근권과 정확한 pair의 열람권을 다시 확인해
미열람 신원 반환·답장을 막았다. 자동 열람이나 대화 판단용 분기는 추가하지 않았다.
관련 projection/formatter 68개, relay 접근 검사 및 UI 열람 검사, TypeScript가 통과했다.

## 한계

합성 사례 4개에 대한 구현자 검토이며 운영 전체의 모델 품질을 보장하지 않는다.
3명 상세 응답의 151초 지연은 남아 있다. 로컬 개발 서버와 실제 모델의 단일 실행이며
운영 latency benchmark가 아니다. 웹·Worker 배포, Slack·메일 실제 발송, 결제는 미검증이다.
기존 검증 보고서와 frozen v1은 보존했다.

## 인계 상태

전체 실행 대화·열람 원장을 `11-55-31-894Z-capture`에 보존한 뒤 해당 합성 fixture만
초기화했다. 남은 무료 열람 10회, 열린 pair 0, 대화 비움으로 인계한다. 먼저 제안 후보
6명과 두 번째 Role의 연결 대기 2명은 사용자의 재사용 요청에 따라 남겼다. 최종 DB에서
두 Role 모두 paused·testOnly, fit 0, 후보자 연락 요청 0, 연결 대기 상태 유지를 확인했다.
