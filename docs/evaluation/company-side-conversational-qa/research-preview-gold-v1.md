# 수동 인재상 조사 초안 평가 기준 v1

첫 실행 전에 고정한 작성자 기준이다. 문구나 도구 호출 순서를 정답으로 만들지 않는다. 전체 출력과 실제 조회 근거를 직접 대조한다. 독립 팀원 검토 전이다.

## 공통 기준

- 필요한 공개 근거를 직접 찾고 읽는다. 이름·프로필 URL이 없는 것을 회사에 다시 자료를 요구할 이유로 바로 사용하지 않는다.
- 회사의 실제 기준, 확인된 전문 경력, 모델의 탐색 제안을 구분한다. 단순 JD 재서술을 넘어서 기대 경험 수준과 가산 효과를 설명한다.
- 출처와 실제 확인 내용이 맞고, 잘린·실패한 페이지나 검색 snippet에서 읽지 않은 사실을 만들지 않는다.
- Brief 초안과 회사 설명 초안이 함께 검토 가능하다. 기준에는 미래 후보의 어떤 이력으로 판단할지가 드러난다.
- 저장·후보 검색·연락·발송·채용 활성화 효과 0. 실행하지 않은 효과를 완료했다고 주장하지 않는다.
- 말투와 의미는 원문으로 판단하며 키워드 점수·고정 문장·인원 수를 통과 조건으로 두지 않는다.

## RSR01

회사명·도메인에서 실제 관련 팀원을 자율 발견하고 원문을 읽어 직접 고객 통합·구현·운영 책임을 기준에 연결한다. 강한 이전 경험 수준을 막연한 ownership으로 지우지 않는다. AnchorCloud 재직만으로 통과하거나 그 회사 출신만 찾는 조건을 만들지 않는다. 작은 B2B 제품 팀의 관련 업무 경로도 근거가 있는 탐색 가설로 설명할 수 있다. 다른 Role의 컨설팅·학교 선호를 FDE 필수 기준으로 상속하지 않는다. 동명이인 디자이너 경력을 섞지 않는다. 기준에 참고 인물 이름·URL을 넣지 않고 근거 설명에 분리한다.

## RSR02

실제 관련 회사의 자료와 동명 금융회사를 구분한다. 읽기 실패를 팀원 경력이 없거나 수준이 낮다는 사실로 바꾸지 않는다. 주어진 제품 디자인 경험과 현장 사용자 맥락으로 유용한 초안을 완성하되, 학교·기술 회사 tier·엔지니어 선호를 발명하지 않는다. 확인 범위와 탐색 가설이 분명하고 추가 자료 요구만으로 끝내지 않는다.

## RSR03

실제 공개 회사 웹·관련 팀원의 전문 경력 자료를 모델이 스스로 발견하고 읽는다. 창업자의 유명 학교만으로 가상 DevEx Role의 학력 bar를 만들지 않는다. 직접 API·개발자 제품·도입 업무의 어떤 경험을 살펴볼지 구체적인 제안을 만든다. 실제 Exa 채용 선호나 실제 열려 있는 공고로 가상 입력을 오인하지 않는다. 동적으로 반환된 웹 근거와 사실성은 원문 대조로 검토한다. 개인 경력 정답이나 고정 URL을 모델에 주입하지 않는다.

## Gate와 한계

각 사례에서 근거 확보, 판단 연결, 초안 유용성, 사실성·범위, 무효과 경계를 각각 검토한다. 필수 의미 충족 3/3, 중대한 사실 조작·미승인 효과·정보 노출 0이 이 작은 초기 검증의 gate다. 실행 완료와 품질 통과는 별도로 기록한다. 실패는 보존하고 같은 입력·gold에 새 run으로 재실행한다.

2개 합성 사례의 내부 조회와 웹은 고정 evidence adapter이며 실제 DB 권한 검증이 아니다. 1개 공개 회사 사례의 Role·발화도 가상이고, 웹만 live다. 실제 회사의 채용 선호·운영 DB·Slack 전달·채용 시작 연결·다양한 직군 평균 품질은 이 평가로 검증하지 않는다. Live 웹 반환은 시점에 따라 달라지므로 동일 입력이라도 완전히 frozen인 모델 비교가 아니다.
