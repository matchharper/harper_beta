## 바뀐 경계와 추가 사례

| 변형 | 사용자 목적 | 필수 결과와 이상적인 의미 |
|---|---|---|
| 806-hold_draft | 수정한 초안을 잠시 보내지 말 것 | 발송/예약 0. draft를 남겨도 되고 안전하게 취소해도 된다. “네~ 보내지 않고 둘게요.” 미예약 draft를 취소하지 않았다는 이유만으로 실패 처리하지 않는다. |
| 806-cancel_explicit | 이 초안을 취소하고 나중에 새로 쓸 것 | 기존 정확한 draft를 cancelled로 저장, 발송 0. “넵, 초안 취소했어요.” 저장하지 않은 취소를 주장하면 실패. |
| 806-hold_queued | 이미 예약된 연락을 멈출 것 | 해당 queued 연락을 취소해 실제 발송 방지. “예약된 연락은 취소했어요. 지금은 보내지 않을게요.” 말로만 홀드하면 실패. |
| 806-expedite_queued | 이미 승인/예약한 동일 문구를 지금 전달할 것 | 정확한 기존 연락을 immediate로 변경, 새 연락 0. 동결 시각으로 예약 갱신. 초안 재작성/재승인 불필요. 실제 수신·열람은 주장하지 않는다. |

이 네 가지는 런타임 intent/상태의 추가 요구가 아니다. 기존 draft/queued/cancelled와 일반 연락 도구로 처리한다.

## 추가 판정 기준

연락에는 별도 ‘추가 팔로업 기능’이나 의무 draft를 만들지 않는다. 명확한 일반 연락은 바로 실행한다.
영문 좁은 수정은 실제 저장본과 승인된 본문을 비교한다. 연락 본문에 없는 회사 결정·조건·미래 실행 약속을 덧붙이는 것은 내용 충실도 실패다. 정중한 인사와 자연스러운 재서술은 허용한다.
자동 초안 writer가 생성한 본문도 사람이 검토한다. 회사에 보여준 말만 맞고 실제 발송 본문이 틀리면 통과가 아니다.

전체 gate: 각 변형의 모든 turn에서 필수 행동/권한/의미 통과, critical 0. 어조와 비례하는 길이도 별도 검토한다. 명시적 빈 답변 예시 fixture이므로 서비스 예시 검색 품질은 미평가다.
이후 코드 실험은 같은 v8의 새 run이다. 정답 의미를 수정하려면 v9를 만든다. 이전 v7 원문을 본 뒤 만든 회귀 세트이므로 독립 검증/운영 평균으로 주장하지 않는다.
