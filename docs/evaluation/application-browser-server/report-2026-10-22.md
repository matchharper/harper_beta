## 기존 실행기와의 차이

기존 canonical `controlledBrowserDriver` 문자열을 그대로 내보내고 Chromium 시작만 같은 Browserbase로 연결했다. 대조 실행은 모델 판단 없이 직접 폼 URL을 주고 이름 입력 → 이력서 첨부의 유리한 조건을 제공했다. 첫 업로드 ticket POST는 승인·통과했지만 뒤따르는 `/upload` PUT이 `net::ERR_BLOCKED_BY_CLIENT.Inspector`로 막혔고 폼에 `Upload failed: Failed to fetch`가 나타났다. 해당 run `2d638283-d8e2-46bd-aa21-2442dd2c5d91`은 업로드 실패의 실행 증거다.

따라서 **Browserbase 연결만으로는 이 문제가 해결되지 않았고, 새 브라우저 실행 방식에서는 같은 업로드·최종 접수가 됐다.** 이것은 한 가지 다단계 업로드 장애물의 확인이며 기존 제품 전체 성공률 비교나 모든 ATS 지원 보장은 아니다. 실제 회사에는 제출하지 않았다.
