# 회사 수준·기대 기준 prompt 검토

## 변경과 이유

후보자 → 회사의 목표를 회사 자체에 만족하며 실제 기회를 진지하게 검토할 의향으로 정리했다. 후보자 기대 수준은 pedigree·직접 언급·현재 Brief와 실제 제공된 Memory 관련 근거로 추정하되 명시적 현재 선택이 추정보다 우선한다. 특정 회사 규모나 유형을 정답으로 삼지 않는다.

공통 근거 우선순위와 지표별 질문을 분리했다. 회사의 질, 회사 보상 여력과 실제 제시 보상, 후보자 만족과 직무 수행 능력, 회사 관심과 후보자 관심을 구별한다. 상호 적합도는 다른 답의 평균이 아니라 원래 근거에서 양쪽의 가치를 판단한다. 근거 충분성은 JD뿐 아니라 회사 수준·후보자 기대·관련 보상 근거를 포함한다.

v3 검토에서 좋은 회사에 대한 호감이 실제 기회의 필수조건 충돌을 충분히 낮추지 못한 출력을 발견했다. v4에서 후보자 관심의 판단 대상을 실제 기회 검토 의향으로 명확히 하고 양극 기준도 이에 맞췄다. 특정 사례 분기나 점수 후처리는 없다.

## 동결 평가와 결과

- 입력: 합성 `cases-v2.json` 8쌍. `gold-v2.json`의 순서 비교 8개와 정성 기준을 모든 호출 전에 작성했다. v1은 보존했다.
- 동일한 v2 입력으로 prompt v2/v3/v4를 실행했다. v4의 평가 summary 기록을 포함한 마지막 검증 run은 `runs/2026-10-13T12-16-25-990Z/`다. 실행 중 runner의 요약·재현 기록을 추가해 최종 runner도 동일 fixture로 확인했다. raw 출력과 각 버전의 실제 질문·hash는 ignored runs에 owner-only로 남겼다.
- 마지막 v4 run: 구조 유효 8/8, 사전 작성한 순서 비교 8/8 통과. 실제 비용 $0.001180914, 역할별 요청 왕복 391–640ms. 구조 테스트 7개 및 변경 모듈·runner lint 통과.
- 회사 수준만 바꾼 동일 후보·직무·회사 규모·보상의 비교에서 후보자 관심은 충분한 수준 근거 84%, 약한 수준 근거 18%, 수준 정보 부재 44%였다.
- 같은 좋은 회사의 규모만 바꾼 두 입력은 84%와 83%였다. 회사 규모만으로 회사 수준을 대체하지 않은 사례다.
- 좋은 회사에서도 공개 보상이 후보 선호보다 크게 낮으면 53%로 낮아졌다. 같은 약한 회사라도 후보자가 현재 안정성과 보상을 위해 그 타협을 명시적으로 선택하면 68%로 높아졌다.
- 필수조건 충돌 사례는 v3 후보자 관심 47%에서 v4 10%로 낮아졌다. 직무 수행 적합도는 유지됐다. 관련 직무 경험이 없는 사례의 회사 관심·직무 적합도는 매우 낮았다.

## 해석의 한계

합성 작성자의 의도와 순서를 확인한 작은 challenge이며 독립 human gold, 실제 사용자 반응률, 확률 calibration 검증이 아니다. 같은 데이터에서 prompt를 개선했으므로 holdout 결과로 해석하지 않는다.

마지막 v4에서 근거 충분성은 8개 모두 `partial`이었다. 회사 설명에 긍정적 근거가 있어도 이 항목이 보수적으로 반응한다. 충분/일부 부족 경계의 독립 검증이 남아 있으며, 8개 순서 비교 통과를 모든 항목의 완성도로 일반화하지 않는다.

웹은 Profile + 전체 Brief + 저장된 Behavior Context만 전달한다. Memory 원문이나 새 회사 조사·quality enrichment는 추가하지 않았다. 실제 회사 정보가 빈약하면 prompt만으로 그 회사의 실제 수준을 알아낼 수 없다. 이 변경은 로컬이며 배포하지 않았다.
