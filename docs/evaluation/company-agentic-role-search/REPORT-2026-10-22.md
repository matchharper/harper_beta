# 회사 대화 기반 Role 검색 — 전체 요청 구현·검증 보고

> 후속 정정: 아래 ‘구조 마무리’는 전체 요청 완료 판정으로 사용하지 않는다. 새 Top N 밖의 기존 미응답 후보가 남는 누락을 이후 확인해 수정했다. 현재 항목별 상태는 [2026-10-23 전체 감사](AUDIT-2026-10-23.md), 앞으로의 자연어 평가 범위는 [natural-v3](NATURAL-V3.md)를 따른다. 아래 수치와 원문은 당시 실행의 역사 기록이다.

최종 갱신: 2026-10-23. **요청한 기능 구조의 구현과 로컬 검증을 마무리했다.** 1·2차는 모두 Decisions API를 유지하며 일반 추론 fallback이나 사례별 판단 분기를 추가하지 않았다. 이번에는 평가의 완벽한 정답률보다 실행·저장·조회·복구 구조에 집중했다. 기존 전체 16개 평가와 UI 검증에 이어, 영향받는 기존 6개 대화를 같은 실제 데이터·초기 상태에서 다시 확인했다. 1·2차의 의미 판단 오류는 남아 있으며 별도 평가 과제로 기록한다. 필요한 운영 DB 구조는 앞서 적용했지만 **웹·Worker 코드는 미배포**다. 구현 완료와 운영 반영, 관찰한 행동과 전체 모델 정확도를 구분한다.

실제 유료 Slot 행이 없어서 사용자가 승인한 **기존 계약의 유료 권한 활성 Role**을 사용했다. 실제 후보 8,009명에서 당시 공유 가능한 모집단은 3,522명이었다. 가짜 후보·점수·과거 대화를 넣지 않았다. 운영에서 읽기 전용으로 캡처하고 실제 API 평가로 만든 `bootstrap-v3`를 동결했다. baseline은 1차 3,292명, 2차 2,946명, 새 추천 설명 8명이다. 각 사례와 각 후속 실험은 같은 baseline의 새 로컬 DB에서 시작한다. 원래 데이터·실패·출력은 ignored `private/`·`runs/`에 owner-only로 보존한다. 실험 간 상태는 초기화하지만 비교 로그를 삭제하지 않는다.

## 전체 요청 대조표

## 앞선 후속 개선 기록 — 조회 입력량과 질문 진단

사용자의 후속 요청에 따라 원래 입력·gold·초기 DB를 유지하고 개선을 계속했다. 당시에는 판단 오류가 남아 전체 완료 판정을 보류했다. 이후 사용자는 완벽한 평가보다 나머지 구조를 우선하도록 범위를 정리했다. 1·2차 runtime은 v40 Decisions를 유지한다. 회귀가 생긴 대안을 제품에 적용하거나 기존 실패를 지우지 않았다.

일반 후보 reader에 원문 상세 수준(`outline/full`)과 구획(`bio/experience/education/extras`) 선택을 추가했다. 특정 기준의 후보 목록에는 해당 기준과 전체 fit을 표시하고 다른 기준의 전체 조회 경로를 유지한다. 선택한 구획은 모든 행·본문을 보존하며, 필요한 구획·후보·호출 묶음은 원본 회사 LLM이 고른다. 현재 재직 여부를 종료일 미기록만으로 확정하지 않도록 원문 날짜의 의미도 알려준다.

## 발견한 문제와 현재 개선

v6에서는 도구 성공만으로는 잡히지 않는 세 문제를 실제 답변·입력 전문에서 확인했다. 후보의 선호를 배타 조건으로 읽는 1차/2차 오류, 요청한 저장 숫자를 답하지 않은 설명, 완료된 검색을 후속 대화에서 부정한 설명이다. 이전 평가 결과는 수정하지 않았다. 일반 평가 질문과 원문 전달, 점수 조회 계약, 요청과 실행의 연결 정보를 개선했다. 최신 병렬 도구 결과가 모델의 첫 읽기 전에 압축될 수 있었던 문제도 수정했다. 특정 인물·지역·문구에 대한 분기는 추가하지 않았다.

v7은 동일 baseline/gold에서 실행했고15개 대화와 실제팀부재1개를 모두 기록했다. 호스트 덮개 닫힘에 따른 절전과 DNS 연결 오류로 일부 사례가 첫 모델 호출 전에 중단됐다. 원문을 보존하고 같은 소스로 실패7개만 새 DB에서 재실행해 완료했다. 성공한 사례를 좋은 결과가 나올 때까지 반복 선택하지 않는다. 절전이 겹친 wall-clock을 제품 순수 지연으로 주장하지 않는다. 별도 작업의 타입 파일 수정은 drift flag를 남기되, JavaScript emit hash 동일 여부를 확인해 런타임 영향과 분리한다.

Hiring Brief 요약의 이전 네 실험에서는 부정 의미 누락, 무관한 언어, 과거 정책을 반대로 발명하는 오류가 있었다. 최소 입력은 유지하고 한 필드의 구조화 출력과 일반 문서변경 요약 계약을 개선했다. 마지막 v5의 실제7개 요약은 변경 의미·언어를 보존했다. 실패 문장을 정규식으로 삭제하거나 deterministic 문구로 교체하지 않았다.

API 계약을 대조한 당시 실험에서는 기존 developer 역할의 정책을 질문별 `instructions`로 옮겼고, 모든 입력 사실·질문·선택지를 유지했다. 진단 요청45건의 runtime 일치를 확인한 다음 v40 소스를 고정했다. **2026-10-23 다시 조회한 공식 문서는 developer/system도 지원한다.** 따라서 developer 입력이 현재 지원되지 않는다는 과거 설명을 정정한다. user 근거·질문별 정책 구조 자체는 지원되므로 현재 구현을 유지하며, 과거 의미 오류의 원인을 message role만으로 확정하지 않는다. 짧은 정책 대안은 명시 제한 누락이 더 많아 채택하지 않았다. [공식 Decisions 가이드](https://developers.openai.com/api/docs/guides/decisions#how-decisions-work).

필요한 원문과 올바른 API 형식이 있어도 의미 판정 오류가 남았다. 실제 한국 거주자를 회사 실무조건으로 제외하거나 후보자의 명시적 지역 제한을 놓친 사례가 있다. Decisions가 서술 이유를 반환하지 않으므로 내부 출처 우선순위 오독과 모델 판단 한계를 더 나눠 단정하지 않는다. 최종 선택이나3차 설명이 보완하더라도 앞 단계의 오판은 실패로 남긴다.

v8 뒤에는 두 가지 저장·표시 누락만 공통 경로에서 보완했다. 명시 ID 추천에서도 같은3차 호출이 공개 근거와 중요한 tradeoff를 한 문단으로 작성해 기존 평가 원장·review·presentation에 저장한다. 원래 ARS15를 같은 초기 DB와 입력으로 한 번 더 실행해 새3차2명·추천2명·통합설명2개를 확인했다. 기존 기준 점수12개는 그대로였고 Decisions1·2차는 호출하지 않았다. 이 실행은205.4초, 회사 Sol6회·Luna3차2회이며 v8 집계와 합산하지 않는다.

또한 전체 재평가에서1차만 새 평가한 기존 추천을 최종 모델이 유지하면, 그 카드도 새 기준으로 설명을 갱신하게 했다. 선정과 제외의 판단을 바꾸는 규칙이 아니라 이미 유지한 카드의 기준 버전을 맞추는 저장 계약이다. 새2차 점수가 없으면 현재 공개 근거·fitness만 작성하며 숫자·확률을 생성하거나 과거 값을 복사하지 않는다. 정기 Worker의 기존 출력 계약은 유지했다.

실제 누락 후보 1명을 같은 원문으로 보충 확인했다. 3차 1회, 81.1초로 현재 기준 6개의 설명과 통합 추천 근거를 생성했고 숫자 점수·라벨·확률은 만들지 않았다. 현재 한국 거주와 향후 해외 근무·비자 지원의 미확인을 구분했다. 이 보충은 공통 갱신 대상 선정과 실제 writer 입력·출력의 검증이며 DB 발행을 다시 실행하지 않았다. 원래 1차 오판은 그대로 실패로 남겼다.

ARS15 보충의 실제 새 카드에서는 저장한 추천 설명과 일반 도구 조회·상세 API·화면 문단이 모두 일치했다. 기존 기준 점수와 채팅은 유지됐고 설명 필드가 없는 기존 카드도 정상 표시됐다. 브라우저 전후 15개 표 중 14개는 완전히 같았으며, 나머지는 실제 방문한 두 프로필의 최초 열람 기록만 추가됐다. 임시 브라우저·서버·사본을 정리하고 원본 실험 자료를 보존했다.

## 적용 범위·관찰 한계

운영 DB에는 검색/Memory 구조 `20261022045532`, Hiring Brief 이력 `20261022123546`, 재고의 비교시점 provenance `20261022131045`를 적용했다. 서버 전용 권한·RLS와 실제 정의를 대조했다. 실험의 추천·Memory·대화 변경은 로컬 복제본에만 썼다. 웹·Worker 배포, 운영 서비스 재시작, 회사/후보자 연락은 하지 않았다. DB가 먼저 적용됐다는 사실만으로 기능 전체가 운영 중이라고 판단하지 않는다.

v8 전체 실행은 17분 2.6초였다. Sol 342회(회사 93·Worker 249), Luna 6,874회(1차 3,522·2차 3,312·3차 40)가 완료됐다. 연결 오류 2회·HTTP 503 32회는 재시도 후 복구됐고 별도로 보존했다. Sol 입력 12,634,260 tokens, Luna 입력 109,126,190 tokens이며 비용은 미보고다. retrieval 2회의 보고 부분 $0.00365965는 전체비용이 아니다. 별도 평가 전용 50명 실행은 94.2초, Sol 4회·Luna 62회이며 원래 16개와 합산하지 않는다. 작은 검증 테스트의 통과 개수도 LLM 성능점수와 합산하지 않는다. 변경 경로의 짧은 테스트는 통과했으며, 별도 동시 작업의 Ops `jobTitleSimilarityServer.test.ts`와 Career `OpportunitySwipeRow.test` 타입 오류2건 때문에 저장소 전체 타입검사 무오류라고 주장하지 않는다. 후속 capabilityLoop 검사에서도 연락 fixture 두 건은 workspace 조회 mock 부재로 실패했다. 이번에 바꾼 35회 도구 진행 후 정상 완료와 공개 설명 전달 검사는 통과했으며, 전체 테스트 통과로 확대하지 않는다.

평가 runner는 검색 요청 뒤 실제 Worker가 끝난 다음 다음 모델 발화를 진행한다. 따라서 전체 대화 시간에는 Worker 대기가 들어가고 운영 첫 접수응답 지연과 다르다. 로컬 인증은 실제 캡처 actor에 한정한 transport이며 운영 인증 E2E가 아니다. 최초 baseline의 기존시각/UTC 차이는 원문을 보존하고 새 clone만 UTC로 실행했다. 이전 source drift·절전·provider 실패도 각 run의 한계로 보존했다.
