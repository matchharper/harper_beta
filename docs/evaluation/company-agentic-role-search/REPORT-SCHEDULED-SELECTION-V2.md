# 정기 추천 선정 검증 — 2026-10-24

**기존 회사 LLM이 일반 Top 50 + 미소개 수락 후보에서 바로 선택하는 로컬 구현을 확인했다.** 회사 3곳의 저장된 실제 입력에서 각각 completion 1회, 상세 조회 0회였다. 운영 배포·DB 저장·Slack/메일 발송은 하지 않았다.

## 실제 모델 실행

[동결 계약](SCHEDULED-SELECTION-V2.md)에 따라 기존 회사 3곳의 Profile·Brief·Behavior와 1·2차 평가를 재사용했다. 기존 회사 loop의 `gpt-6.1-sol`을 호출했고, 추천 명령은 파일로만 받았다. 아래 인원은 **선택 명령의 인원**이며 저장·발송 완료 인원이 아니다.

| 동결 사례 | 일반 입력 / 해당 입력의 적격 인원 | 별도 수락 입력 | 회사 선추천 | talent-first | 연결 대기 선택 | 선정 시간 | completion / 상세 조회 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 회사 A | 44 / 44 | 0 | 1 | 0 | 0 | 16.688초 | 1 / 0 |
| 회사 B | 50 / 2,578 | 0 | 0 | 1 | 0 | 14.482초 | 1 / 0 |
| 회사 C | 6 / 6 | 10 | 1 | 1 | 8 | 18.290초 | 1 / 0 |

회사 C의 일반 후보 1명은 회사 선추천과 talent-first 양쪽에 선택됐다. 따라서 선택된 서로 다른 사람은 일반 1명 + 수락 8명 = 9명이다. 미선택 수락 후보 2명은 상태 변경 명령이 없다. 세 사례 모두 새 1·2차 평가와 별도 Worker 선정 LLM 호출은 0회다.

시간은 **2차 평가가 끝난 뒤의 회사 LLM 선정 단계**다. 검색·1·2차 평가·3차 설명 작성·메시지 작성·실제 전달 시간은 포함하지 않는다.

| 동결 사례 | 입력 토큰 | 출력 토큰 | 입력 중 cache read | 입력 중 cache creation |
| --- | ---: | ---: | ---: | ---: |
| 회사 A | 45,998 | 555 | 11,148 | 34,847 |
| 회사 B | 50,921 | 519 | 11,148 | 39,770 |
| 회사 C | 31,013 | 566 | 11,148 | 19,862 |

입력에는 후보 목록 외에 기존 회사 LLM의 공통 지침·도구·회사 문맥도 포함된다. 추가 원문 조회가 없어도 입력 자체는 3.1만~5.1만 토큰이었다. 금액은 청구 내역이나 적용 요율로 확인하지 않았으므로 제시하지 않는다.

첫 시도 3회에서 시스템 `scheduledSlot`의 원본 시각 표기를 발견해 공통 formatter를 적용했다. 같은 동결 입력으로 두 번째 시도 3회를 별도 저장했으며 위 표는 두 번째 시도다. 첫 시도의 입력·출력·usage도 보존했으므로 총 실제 provider 호출은 6회다. 원본은 gitignored `runs/compact-selection-v2-20261024/company-*/selection-run-{1,2}/`에 있고, 두 번째 시도는 호출 전 소스 hash도 보존한다. 개인정보 파일과 디렉터리는 0600/0700으로 확인했다.

## 무엇을 검증했는가

- 웹의 관련 테스트 8개 통과: 짧은 ID 변환, 허용 행동·상한, 일반 대화에 정기 전용 도구 비노출, 실제 공통 loop의 한 번 제출·즉시 종료, 상세 조회 없는 선택.
- Worker의 관련 테스트 52개 통과: 기존 수락 처리 포함. Top 50 밖 수락 전원, 점수 순위, 캐시 재사용, 정확한 선택만 발행, 입력 변경 시 재평가 없이 중단, 준비/발행 경로 분리를 확인했다.
- 준비 시 현재 호환 2차 평가와 수락 후보가 검색 결과 밖에 있어도 합쳐지는 경로를 가짜 DB adapter로 확인했다. 실제 운영 트랜잭션 테스트는 아니다.
- 전체 TypeScript 검사는 변경 범위 밖 오류 5건으로 통과하지 않았다. 해당 파일은 `OpportunitySwipeRow.test.tsx`, `candidateDigestEmail.ts`(2건), `jobTitleSimilarityServer.test.ts`, `slackCandidateWorkObject.server.ts`다. 이번 정기 선정 파일의 타입 오류는 보고되지 않았다.

## 선정 내용의 확인 범위

회사 A는 팀 리딩 기간이 미확인임을 남기고 회사 검토만 선택했다. 회사 B는 구체적인 개발·고객 조율 경력을 이유로 1명에게 역할 제안을 선택했다. 회사 C는 10명의 수락 후보 중 8명을 선택했다. 세 사례 모두 talent-first 상한을 채우려는 선택은 하지 않았다.

다만 회사 C의 전체 선정 이유에는 선택한 수락 후보 8명 모두에게 필수 학습·평가 경험 근거가 있다는 표현이 있다. 짧은 발췌와 일부 불명확한 기존 평가만으로 그 단정을 전원에 대해 확인하지는 못했다. 이 전체 reason은 개별 회사 소개나 후보자 메시지로 복사하지 않는다. 실제 소개 문장은 선택된 후보의 전체 원본을 사용하는 기존 3차·writer가 작성한다. 그 작성 결과와 사실 정확도는 이번 실행에서 재검증하지 않았다.

따라서 이번 결과로 확인한 것은 **추가 조회 없이 선택할 수 있는지, 누구를 어떤 행동으로 선택했는지, 호출 수와 시간, 재평가·별도 재선정이 없는지**다. 추천 정확도·응답률의 정답 집합은 없으며, 전체 추천 품질이나 실발송 성공을 통과로 판정하지 않는다.
