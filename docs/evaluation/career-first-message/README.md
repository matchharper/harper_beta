# 첫 메시지

2026-11-23. 가입 페이지(`/career/onboarding`)를 마친 사람이 Harper에게 아직 아무 말도 하지 않았을 때 Harper가 처음 건네는 말을 본다. 정본은 [좋은 기회를 어떻게 추천할까](../../career-good-opportunity-recommendation-ko.md) 3절이다.

## 무엇을 보나

가입 페이지는 이름, 원하는 근무 형태, 자료(선택), 프로필 공유 방식만 받는다. 그래서 첫 메시지는 추천이 아니라 관계의 시작이다. 사람이 실제 출력을 읽고 아래를 본다. 키워드나 길이로 채점하지 않는다.

| 기준 | 통과 | 실패 |
| --- | --- | --- |
| 자기소개 | Harper가 누구이고 이 사람에게 무엇을 해 줄지 짧게 말한다 | 소개 없이 질문부터 하거나, 기능 목록을 길게 늘어놓는다 |
| 이해 | 어느 회사에서 얼마나, 어떤 직함으로 무슨 일을 해 왔는지, 또는 그 사람에게 중요한 특별한 경험을 짚는다. 자료가 없으면 지어내지 않는다 | "프로필을 확인했어요" 같은 일반 문장, 자료에 없는 사실 |
| 상황 질문 | 왜 왔는지와 지금 상황을 묻고, 답에 따라 할 일이 달라지는 이유를 말한다. 답은 선택지 버튼으로도 고를 수 있다 | 묻지 않고 바로 추천한다. 선호를 한꺼번에 캐묻는다 |
| 공고로 온 사람 | 그 공고가 이 사람에게 무엇을 바꾸는지, 판단할 사실, 공고 카드, 회사에 추천할지 묻기 | 비슷한 곳을 찾아 주거나 팀과 바로 이야기하게 해 준다고 약속한다 |
| 자료 없이 온 사람 | 무슨 일을 하고 왜 왔는지를 통화나 한두 줄로 편하게 말하게 한다 | "전에 뭐 하셨어요?"만 남긴다 |
| 나중의 연락 | 첫 메시지에 답하지 않은 사람에게 메일을 보낸다면 다시 소개하고 상황을 묻는다. 찾은 것을 함께 줄 수는 있지만 질문을 대신하지 않는다 | 소개 없이 공고만 보낸다. 상황 질문이 빠진다 |

## 입력

- `cases-v1.json`: 가상 인물 다섯 명. 일반 가입 두 명(백엔드, 디자이너), 자료 없이 온 사람, Harper 연결 공고에서 온 사람, 첫 메시지에 답하지 않은 채 사흘 뒤 정기 점검을 맞는 사람이다.
- 프로필과 시장(회사·공고·웹 문서)은 [첫 추천 평가](../career-first-recommendation/README.md)의 v1을 그대로 쓴다. 그 평가의 온보딩 대화, Brief, Memory는 넣지 않는다. 가입 기록(`profile_submit`) 한 줄만 대화에 있다.

## 실행

harper_beta에서 실행한다.

```sh
NODE_PATH=./node_modules/next/dist/compiled NODE_OPTIONS=--conditions=react-server \
  pnpm exec tsx --tsconfig scripts/tsconfig.json scripts/evalCareerFirstMessage.ts --repeat 2 --label <이름>
```

- runner: [scripts/evalCareerFirstMessage.ts](../../../scripts/evalCareerFirstMessage.ts). `--only id,id`로 사람을 고르고, `--render-prompt <id>`는 모델을 부르지 않고 그 턴의 system 입력을 출력한다.
- 가입 직후 턴은 운영과 같은 prompt plan, preload 선택, 도구 schema, 채팅 기본 모델을 쓴다. 정기 점검은 운영처럼 scheduled 모델(Haiku)과 background preload를 쓴다.
- 도구 결과는 첫 추천 평가의 frozen 시장에서 만든다. 공고 상세(`get_role_context`), 예약 읽기, 메일 발송은 runner가 대신 답하고 보낸 메일을 기록한다. DB와 외부 실행은 없다.
- 결과는 `runs/<시각>-<이름>/review.md`에 남는다. git이 무시하는 로컬 폴더다.

## 한계

- 사용자가 답한 뒤의 대화(첫 추천)는 보지 않는다.
- 정기 점검에서 연락할지 말지는 Harper가 정한다. 조용히 넘어간 회차는 실패로 세지 않고 따로 적는다.
- 채팅 화면에서 가입 기록이 숨고, 첫 메시지가 오기 전까지 대기 표시가 보이는지는 이 평가로 볼 수 없다.

## 결과

- 2026-11-23 round1(가입 직후 4명 × 2회, 정기 점검 × 2회), round2-scheduled(정기 점검 문장을 고친 뒤 × 3회). 가입 직후 8회 모두 소개·이해·상황 질문(또는 공고에서 시작)이 들어갔다. 정기 점검은 round1에서 1회가 찾은 회사 이야기로 상황 질문을 대신했고, 문장을 고친 round2에서는 메일 2회 모두 상황을 물었고 1회는 연락하지 않았다.
