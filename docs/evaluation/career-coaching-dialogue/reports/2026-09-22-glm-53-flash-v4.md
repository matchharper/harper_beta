# GLM 5.3 Flash 코칭 대화 v4 검증

문서 기준: 2026-09-22

## 결론

`z-ai/glm-5.3-flash`를 `/career` 텍스트 채팅 기본 모델로 두고 검증했다. `high`는 frozen v4 14개에서 lifecycle 구조를 모두 지켰지만, 근거 없는 외부 사실과 긴 응답 시간 때문에 현재 상태로는 품질 release gate를 통과하지 못했다. `medium`은 더 빨랐지만 명시적 코칭 맥락 2개에서 activity를 만들지 않아 기본값으로 채택하지 않았다.

실제 SSE·DB 경로에서는 코드가 기대하는 coaching RPC와 현재 DB에 적용된 RPC 계약이 달라 모든 activity 생성이 실패했다. 일반 대화는 정상적으로 코칭 경계를 지켰지만, 코칭 카드와 지속 상태는 생기지 않았다. 적용 이력이 있는 migration 파일을 수정하는 대신 별도 보정 migration을 추가했다. 이 검증에서는 migration을 적용하거나 배포하지 않았다.

## 실행 범위

- 모델: `z-ai/glm-5.3-flash`
- reasoning 비교: `high`, `medium`
- frozen set: `cases-v4.json` / `gold-v4.json`, 14개
- 실제 경로: 로컬 `/api/talent/chat` SSE + 현재 연결 DB
- 실제 데이터: 전용 QA 계정의 합성 프로필과 매 실행마다 새로 만든 disposable conversation
- 초기화: 각 시나리오 뒤 message, coaching pointer, 새 Memory/Brief, disposable conversation 삭제
- 원상 복구: QA 계정의 onboarding·locale·profile 값 복구
- raw transcript와 tool output: gitignored `runs/` 아래 owner-only 파일

## frozen v4 결과

| 설정 | 구조 결과 | 관찰 |
| --- | ---: | --- |
| GLM 5.3 Flash high | 14/14 | 일반 대화 5종 activity 0, 명시적 start/suggest/end와 active 단발 질문 경계 통과 |
| GLM 5.3 Flash medium | 12/14 | 더 빨랐지만 해외 이직과 업무 흥미 저하의 명시적 코칭 탐색에서 lifecycle action 누락 |

`high` 첫 run에서 동일 lifecycle 호출 반복과 end reference 누락이 보였다. runner가 실제 SSE의 후속 tool 제한을 재현하도록 고쳤고, 서버는 모델이 현재 activity ID/revision을 빠뜨릴 때 trusted current activity에서 기계 참조만 보완하도록 고쳤다. 수정 뒤 `high`은 구조 오류 0건이었다.

구조 통과와 별개로 `high`의 human review는 release gate를 통과하지 못했다.

- 해외 이직 일반 대화와 코칭에서 검색 결과 없이 국가별 비자 난이도, 채용 접근성, 수요, 보상 차이를 단정했다.
- PM 전환 코칭에서 확인되지 않은 경로별 성공 가능성을 비교했다.
- 코칭 종료 뒤 실제 side effect 없이 다음에 공고를 준비해두겠다고 약속했다.
- 실제 DB 재검증에서는 GLM이 Memory에 사용자가 말하지 않은 날짜를 붙인 사례가 있었다.

이 문제들은 제공된 네 예시에 대한 분기가 아니라 사실성, tool 결과 준수, 실행 가능한 약속이라는 공통 기준의 실패다.

## 실제 SSE·DB 결과

일반 대화 5건을 서로 독립된 conversation에서 실행했다.

- PM 전환
- 연봉 인상
- 업무 흥미 저하
- 맥락 없는 공고 평가
- 예시에 없던 팀 리드 제안 판단

모두 coaching activity 0건이었다. 즉 커리어 주제나 감정 표현만으로 코칭을 시작하는 부작용은 재현되지 않았다.

명시적 코칭 버튼 진입 뒤 해외 이직, PM 전환, 연봉 인상, 업무 흥미 저하를 각각 별도 conversation에서 실행했다. 모델은 네 주제를 모두 이해하고 적절한 topic과 agenda를 만들거나 진단 질문으로 이어갔다. 하지만 activity는 모두 0건이었다. 서버 로그에서 현재 DB의 `mutate_talent_career_coaching_activity`가 예전 인자 계약으로 남아 있어 새 인자 계약을 찾지 못하는 것이 확인됐다.

수정 전에는 tool 실패 뒤에도 “코칭 시작”, “카드를 준비했다”라고 말하거나 내부 기술 문제를 사용자에게 노출했다. 수정 뒤에는 raw 오류를 모델에 넘기지 않고 activity가 적용되지 않았다는 user-safe 결과를 제공한다. PM 전환 시퀀스 재검증에서 거짓 카드·시작 주장은 사라졌고, 별도 activity를 열 수 없어 현재 채팅에서 이어간다고 정확히 안내했다.

## 응답 시간

실제 SSE 13턴의 서버 요청 완료 시간은 다음과 같았다.

| 지표 | 시간 |
| --- | ---: |
| 최소 | 19.8초 |
| 중앙값 | 44.9초 |
| 평균 | 41.2초 |
| p90 | 52.5초 |
| 최대 | 64.0초 |
| 일반 대화 평균 | 38.3초 |
| 명시적 코칭 흐름 평균 | 43.0초 |

텍스트는 SSE로 먼저 보일 수 있지만 tool 사용과 최종 답변 완료까지의 대기 시간이 길다. 별도 classifier나 코칭 감지를 위한 추가 모델 호출은 없으므로, 이 지연은 고정된 사전 판별 비용이 아니라 GLM high 생성과 tool loop에서 발생했다.

## 코드 보완

- `/career` 기본 텍스트 모델을 GLM 5.3 Flash high로 설정
- 실제 SSE와 동일한 후속 tool 범위를 evaluation runner에 적용
- 현재 activity의 ID/revision 누락 시 trusted DB state에서 기계 참조 보완
- activity mutation 실패를 user-safe 결과로 바꾸고 거짓 성공과 내부 오류 노출 방지
- 적용된 옛 RPC 계약을 새 계약으로 올리는 별도 corrective migration 추가

## 남은 release blocker

1. corrective migration을 승인된 환경에 적용한 뒤 카드 생성, suggested→active, active→ended, expiry, call rollback을 브라우저와 DB에서 다시 확인해야 한다.
2. GLM high의 외부 사실 단정과 unsupported promise가 사라질 때까지 동일 frozen set에서 human quality gate를 다시 통과해야 한다.
3. 평균 41.2초의 실제 응답 시간을 허용할지 결정하거나, GLM의 tool adherence를 유지하면서 더 빠른 설정을 찾아야 한다. 이번 `medium` 결과는 대체 설정으로 충분하지 않았다.
