### 오퍼 결정 행동 — PASS

## 첫 실행에서 수정한 문제

첫 v1 run은 대화의 반영·도전·질문 품질은 좋았지만 다음 문제로 NO-GO였다.

1. 음성 tool에 추천 묶음 개수와 외부 공고 수신 범위를 바꾸는 writer가 없어, 사용자를 텍스트 채팅으로 돌려보냈다.
2. 종료 지시가 “말을 먼저 한 뒤 tool”로 되어 Responses tool protocol과 충돌했고, 네 사례 모두 인사만 하고 실제 통화 종료를 요청하지 않았다.
3. 탐색 중인 같은 주제를 매 턴 저장하는 경향이 있었다.
4. 유용한 행동을 제안할 때 질문 여러 개를 묶는 순간이 있었다.

최종 구현에서는 기존 공통 `update_talent_profile`과 `update_setting`을 post-onboarding voice에도 열고, 같은 주제의 저장을 확정 시점에 모으도록 했다. 종료 계약은 provider가 말과 tool call을 결합하지 못하면 `end_call`을 우선하고 클라이언트 fallback이 짧게 인사하도록 실제 실행 구조와 맞췄다. 행동 제안은 한 대상·한 행동·한 사례 질문으로 압축하도록 했다.

## 남은 한계

- 이 평가는 합성 고정 발화 4개뿐이라 실제 사용자 분포의 성공률을 뜻하지 않는다.
- 일부 턴은 음성으로 들을 때 두세 문장으로 다소 길 수 있다. 현재는 이해 가능한 범위로 판정했지만 실제 통화의 끼어들기와 체감 길이는 E2E에서 봐야 한다.
- Memory/Brief tool은 메모리 stub이므로 실제 DB의 ref·동시 수정·권한 검증을 확인하지 않았다.
- `gpt-live-1`이 적절한 시점에 Terra로 위임하는지, 음성 인식·합성·지연·중단 처리는 평가 범위 밖이다.
- 한 번의 stochastic pass는 안정성을 증명하지 않는다. release 전 같은 frozen set 반복 실행과 실제 Live 통화 smoke가 필요하다.
