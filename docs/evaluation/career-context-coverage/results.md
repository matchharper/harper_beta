# Career 목록 완결성 표기 및 정기 실행 비교

로컬 코드에 목록 완결성 표시를 반영했다. **무작위 5건의 전후 재생에서 도구 호출은 0 → 0회, 감소는 0회였다.** 이미 완료된 정기 실행을 현재 데이터로 재생했기 때문에, 이번 표본으로 실제 정기 실행의 호출 절감 효과를 입증하거나 부정할 수 없다. 배포·운영 정기 실행 재등록·메시지 발송은 하지 않았다.

## 입력에 추가한 정보

별도의 행동 지침 대신 기존 목록 제목에 짧게 붙인다.

- `all 10`: 총 10개, 10개 표시, 목록 끝.
- `6 shown; more`: 6개 표시, 뒤에 더 있음.
- 추천 기회 `10/63`: 표시 개수/해당 조회 범위의 총 개수.
- 조회 실패는 `unavailable`, 끝을 확인할 수 없는 경우는 `N shown; rest unknown`. 실패를 전체 0개로 표시하지 않는다.

적용 범위:

| 데이터/context | 범위 |
| --- | --- |
| 할 일 | 기본 context와 `manage_action_items list` 결과 |
| 매칭·검색 실행 | 활성 매칭, 진행 중인 검색 각각 |
| 추천 기회 | 기존 기본 조회의 조건에 해당하는 기회; 추가된 예정 미팅 기회도 표시 개수에 포함 |
| 회사 연결·연락 | 상호 연결과 각 연결에 표시한 연락 |
| 정기 스케줄·회사 팔로우 | 별도로 보여 주는 discovery 스케줄을 중복 없이 포함 |
| 문서·프로필 버전·폼 | 문서 목록, 프로필 버전, 현재 대화/위임 작업의 미해결 폼 |
| 활동·발송 질문·기회 피드백 | 각각의 기존 조회 범위와 마지막 답변 이후 피드백 |
| Brief·Memory | 전체 Brief, 실제 선택·축약 여부를 반영한 Memory |
| 구조화 프로필 | 경력, 학력, 기타 이력, 이력서 링크, 제외 회사 |
| 위임 작업 | 현재 작업 외 다른 작업 목록 |
| 백그라운드 이메일 | 발송 완료 메일 이력 |
| 대화 이력 | 제공된 원문 메시지 범위, 이전 원문 존재 여부, rolling summary 이후 원문 범위 |

기존에 끝/개수 정보가 있던 예정 미팅, 일반 미완료 작업, 미게시 내부 제안 등의 표시는 유지했다. 표시 상한만큼 찼다고 곧바로 전체라고 하지 않도록 추가 한 행 또는 기존 count/cursor를 사용한다. 회사 연결은 상호 연결 판정 전 원본을 임의 개수에서 자르던 조회를 페이지 끝까지 읽도록 바꿨다.

## 실제 비교 결과

최근 7일 완료된 정기 실행에서 사용자별 최신 1건을 모은 뒤, 고정 seed로 순서를 섞어 5명을 선정했다. 동일한 현재 데이터와 모델(`claude-haiku-5-5`, adaptive thinking 기본값), 도구 구성으로 전후 각 5회 실행했다. 비교 기준은 과거 운영 배포본이 아니라 **이번 수정 직전의 작업 중 코드**다.

| 표본 | 변경 전 호출 | 최종 변경 후 호출 | 감소 | 입력 토큰 전 → 후 | 증가 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 0 | 0 | 0 | 36,393 → 36,506 | +113 |
| 2 | 0 | 0 | 0 | 34,950 → 35,060 | +110 |
| 3 | 0 | 0 | 0 | 41,596 → 41,712 | +116 |
| 4 | 0 | 0 | 0 | 44,090 → 44,198 | +108 |
| 5 | 0 | 0 | 0 | 36,326 → 36,445 | +119 |
| **합계** | **0** | **0** | **0** | **193,355 → 193,921** | **+566** |

평균 입력 증가는 **113.2토큰/실행, 0.29%**다. 캐시 생성·읽기 토큰까지 포함한 provider usage 기준이며, 비용이나 지연시간의 감소를 뜻하지 않는다. 5건 모두 provider 요청 1회로 종료했고 capability/guide 로더를 포함한 도구 호출, 업무 조회, 빈 조회, 모의 쓰기가 모두 0회였다.

초기 표기 버전도 같은 5건으로 실행했다(도구 0회, 입력 합계 194,539). 빈 회사 연결에 불필요한 긴 설명이 붙는 것을 제거하고 중복 안내를 줄인 최종 버전이 위 표다. 총 모델 생성은 baseline 5회 + 초기 변경 5회 + 최종 변경 5회이며, 결과를 골라 버리거나 같은 버전을 재시도하지 않았다. 이후 경계 수정은 5건의 최종 모델 입력을 변경하지 않았음을 확인했다.

## 해석과 검증

전체 응답을 검토했다. 각 모델은 이미 처리·발송된 추천과 현재 스케줄을 근거로 추가 실행 없이 종료했다. 실제 후보자에게 보낸 출력은 없다. **원래 실행 직전의 스냅샷이 아니고 baseline 자체가 0회였으므로, 이번 결과는 실제 새 정기 실행에서 얼마나 줄어드는지에 대한 답을 주지 못한다.** 이 제약을 숨긴 절감률은 계산하지 않는다.

관련 액션·context·프로필·Memory·활동·회사 연락 테스트와 목록 경계 테스트를 확인했다. 추가로 12개 최신 스케줄 밖의 별도 discovery 항목, 조회 실패, 필터링 후 끝을 알 수 없는 목록, 대화 요약/캐시 경로를 확인했다. 회사 연락 mock의 새 페이지 조회 지원과 스케줄 assertion의 구분자 오류를 고친 뒤 해당 실패 테스트는 통과했다. `git diff --check` 통과. 전체 TypeScript 검사는 이번 수정 대상 밖인 `src/lib/career/companyJobs.server.ts:167,173`의 기존 nullable 오류 2개로 통과하지 못했다.
