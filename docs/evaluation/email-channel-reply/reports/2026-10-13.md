# 이메일 답장 로컬 검증 — 2026-10-13

실제 Next 이메일 consumer, 공통 Career LLM·도구 실행기, 로컬 DB와 캡처 전송을 사용했다. 메인 모델은 웹 기본 설정 그대로 `claude-sonnet-5-5`이며 Anthropic API를 호출했다. 합성 입력 frozen v1의 12개 대화·13턴을 반복 실행하고 모든 답장 본문과 도구 결과를 읽었다. 외부 수신자에게 이메일을 보내거나 운영 DB를 수정하지 않았다.

## 발견한 문제와 수정

- 웹 공통 도구 결과의 장문 작성 지침 때문에 간단한 이메일도 설정 보고서가 됐다. 이메일 어댑터가 공통 작성 지침만 교체한다. 결과 데이터와 도메인별 동의·권한·후속 실행 규칙은 유지한다.
- 내부 공개 설정의 영문 표시명과 요청에 불필요한 프로필 질문이 답장에 나왔다. 이메일에 전달하는 설정 표시명을 의미로 설명하고 일반 후속 질문·이력서 요청 안내를 줄였다. 온보딩 체크리스트와 실제 역할 확인 질문은 유지한다. 생성된 문장을 키워드로 판정하거나 덮어쓰지 않는다.
- 첫 연결 의사에서 확인 질문만 하고 대기 사실을 저장하지 않으면 다음 동의에도 확인을 반복했다. 이메일 도구 설명에 첫 의사부터 공통 feedback 도구를 호출하도록 명시했다. 실제 첫 턴의 pending 기록과 다음 턴의 수락 실행을 확인했다.
- 회사의 응답 속도를 확인한 사실처럼 설명한 답장이 있었다. 확인된 연락 결과와 후보자에게 부탁하는 빠른 회신·인터뷰 참석을 구분하도록 이메일 지침을 수정하고 재실행했다.
- 링크가 없는 웹 이동 안내, 긴 로그인 URL 중복, plain text 표·목록의 줄바꿈 문제를 수정했다. 검증된 웹 진입 링크를 이메일 context에 추가하고 온보딩 링크에 읽기 쉬운 이름을 붙였다.
- 모바일 표의 단어가 글자 단위로 끊겼다. 셀 줄바꿈을 조정하고 독립 HTML에 UTF-8·viewport 선언을 추가했다.
- 웹 업로드만으로 자동 이메일 요약이 예약된 듯한 안내를 수정했다. 웹에서 할 수 있는 일과 다음 이메일 회신 또는 실제 예약된 작업을 구분한다.

## 마지막 결과

전체 실행 `runs/final-v8`과 첨부 누락 재실행 `runs/final-v9`를 기준으로 검토했다. 이전 실행은 원본을 덮어쓰지 않고 보존했다. raw 응답·프롬프트·스크린샷은 ignored `runs/`에만 있다.

검토한 최종 답장에는 raw ID·도구 오류 코드·앱 제어 payload·비공개 회사 기준 노출이 없었다. 짧은 회사 전달 요청은 짧게 답하고, 포지션 설명은 필요한 상세 내용을 유지한다. 이 결과는 작은 합성 challenge set의 Codex 검토이며 독립 사람 평가나 평균 정확도 수치가 아니다.

## 실행·렌더링 확인

- 이메일 단위/계약 테스트 43개, 웹 모델·도구 선택·대화 계약 테스트 17개 통과. Node 단독 웹 테스트에는 loopback dummy 환경과 `server-only` preload를 사용했다.
- TypeScript 검사와 격리 출력 디렉터리의 Next App API compile 성공. 전체 Pages 정적 생성이나 운영 배포 검증은 아니다.
- 웹 보호 대상 44개 파일의 SHA-256이 QA 시작 시점과 동일하며 공유 `chatTurn.ts`도 QA 중 변경되지 않았다.
- 저장된 실제 답장 13건을 새 렌더러로 replay했다. Playwright에서 390px 화면의 영문 표, 한글/중첩 목록, 이름이 붙은 긴 로그인 링크를 직접 확인했다. UTF-8이며 가로 스크롤이 없었다. 링크는 절대 URL이고 plain text 표는 한 행에 한 줄, bare URL은 중복되지 않는다.
- 테스트 계정·역할·추천·연락·온보딩·저장 파일은 정확한 fixture ID로 정리했다. 테스트용 역할의 fit 행은 생성되지 않았다. 초기 harness의 auth ID/relay cleanup 오류도 수정하고 기존 실행의 잔여 fixture를 정리했다.

## 남은 검증 범위

테스트용 일반 내부 역할은 기존 공통 수락 API의 안전 장치가 거부한다. 실제 LLM의 확인 순서와 실패 답장은 검증했고, 단위 테스트에서 동의·재실행 경계를 확인했지만 이 실행으로 일반 운영 역할의 수락 및 실제 회사 소개 완료를 입증하지는 않았다. 이를 통과시키려고 웹 수락 경계나 테스트 격리를 바꾸지 않았다.

운영 Vercel Queue·Resend 수신/DNS·실제 Gmail/Outlook 클라이언트는 이번 로컬 검증 대상이 아니다. CRM/일정/capture/referral 등 다른 이관 흐름의 실제 외부 전달도 이 12개 대화로 검증했다고 주장하지 않는다. 운영 배포·설정 변경·기존 worker 종료는 수행하지 않았다.
