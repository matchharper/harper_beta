## 추가 실행 경계 점검과 운영 DB 적용

후속 요청에 따라 재개 후 재종료, 발송 중 재개, 발송 직후 원본 검사의 자기 완료 인식, 사건 소유권 이전, 선정의 지연·수정·공개 회사명 차단, 기존 collector의 설정 검사, 자동 예약의 사용자 작성 근거를 추가 점검·수정했다. 취소된 팔로업의 사건 참조 보존과 재조정 실행의 scheduled 모델 유지도 검증했다. 새로운 모델 평가나 운영 후보자 연락을 수행했다는 뜻은 아니다.

영향받는 웹/DB 검사 묶음은 112 pass·0 fail·1 skip이다. 이후 이관 사례와 기존 RPC의 명시적 중지를 추가하고 재실행한 전체 예약 검사는 51 pass·0 fail·1 skip이며 일일 DB 21개를 포함한다. Worker handoff 16/16과 최종 전체 TypeScript 검사가 통과했다. skip은 실제 다중 연결 PostgreSQL이 필요한 동시 편집 검사다. PGlite 기능 검증을 실제 다중 연결 경쟁 검증으로 간주하지 않는다.

2026-11-05 01:49 KST에 운영 migration `career_daily_processing`(`20261104164906`)을 적용했다. 함수 14개의 본문·권한과 RLS/index/trigger를 확인했고 기존 예약 주기·다음 시각은 보존됐다. Stopped/외부 추천 off의 활성 자동 예약 2,876건이 일시 중지됐으며 해당 조건의 잔여 활성 예약은 0건이다. 미전달 선정 207건은 사건으로 저장했지만 새 일일 실행은 0건이다. 웹·Worker 코드는 미배포다. 상세 적용 범위와 한계는 [구현·적용 기록](../../career/daily-processing-ko.md)을 따른다.

후속 호환성 점검에서 기존 RPC의 명시적 중지에도 설정 중지 표식이 남는 실패를 재현했다. `write_career_schedule` 원본에서 표식을 제거하고 idempotent 재실행·다른 참조 보존·설정 변경 후 중지 유지를 확인했다. 01:56 KST에 `career_explicit_schedule_pause`(`20261104165630`)를 적용했고 함수 본문·권한을 검증했다. 기존 사용자 데이터를 일괄 변경하지 않았으며 두 적용 사이 해당 명시적 중지는 0건이다.
