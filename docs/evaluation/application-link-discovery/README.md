# Wanted → public application discovery

- Objective/unit: one fresh shared `runResolvedInspectionDebug` agent run from a frozen Wanted source and public employer/title facts. Find the same active job's accessible application form, fields and submission-access limitations. Not submission or a completeness benchmark.
- Input v1: `src/lib/ops/applicationDiscoveryCases.ts`. Three challenge cases selected read-only from active external company_roles on 2026-10-29. Only public employer/title/homepage/source URL are frozen; private IDs and candidate facts are excluded. Expected destinations in gold-v1.json were independently inspected before model execution, not supplied to the model.
- Input v2: three additional cases in the same preset module (`datasetVersion: v2`): DelightRoom Backend Engineer, Specter AI Engineer, mAy-I Field Engineer. Selected from active external Wanted rows read-only; independently opened the official application forms before execution. `gold-v2.json` is separate from unchanged v1. These cover Ninehire, a company-owned form, and Greeting. Run only this batch with `node --env-file=.env.local --import tsx scripts/evalApplicationLinkDiscovery.ts delightroom-backend specter-ai mayi-field`. Default runner selects all registered cases and records their dataset versions. No expected URL is passed into the agent.
- Canonical runner: `scripts/evalApplicationLinkDiscovery.ts`, imports actual production resolver, Exa search, Browser-use extraction and text projections. Ops preset uses identical source and path. Source IDs are null so neither path writes company_roles. No applications, uploads, login or candidate data.
- Model/config: gpt-6-luna medium Responses discovery, Exa auto/10 results, Browser-use V4 gpt-6-luna existing prompt/schema. Provider-default sampling, store:false for outer Responses; existing account provider retention unchanged. No explicit output token cap. Prompt budget each tool <=2 including failures; 240s overall product timeout, 180s per managed browser plus bounded cleanup.
- Run manifest: frozen input/gold hashes, source revision and source hashes, actual raw traces/result/error, elapsed and costs where available. Raw output stays ignored owner-only runs (0700/0600). Public form data only sent to configured OpenAI, Exa and Browser-use services, authorized by user live-test request on 2026-10-29.
- Metrics/gate: manually assess same employer+job, active application entry, final application URL, visible required information, observed access vs unknown, tool counts, latency and cleanup. Critical failure: wrong job, unsupported success claim, any applicant submission or production DB write. All three must reach a relevant public form with usable fields for this local challenge gate. Field count alone is not correctness. Preserve failed runs; a prompt change creates a new run against unchanged v1.
- Limitations: deliberately selected 3-case challenge, two employers, not representative accuracy. Public sites/search indices change; gold is as-of reference. Visible forms do not prove eventual submission or hidden-step completeness. Manual findings are not runtime keyword validators.

## 2026-10-29 local outcome

See [실행 결과와 수정 근거](report-2026-10-29.md). Initial run reached a usable form in 1/3 cases; after the general navigation/context correction, 3/3. Final actual Ops POST route runs confirmed 3/3, each one Exa call + one Browser-use extraction. The UI's Apply with Harper mode uses the same full-form agent; three presets live beside the URL input and never rewrite the original production role URL. Other diagnostic providers retain their existing readers and receive the same target-job context when discovery is enabled.
