# Apply with Harper의 OpenAI 실행기 전환 — 로컬 검증

2026-10-12 기준 `harper_beta`의 local main 코드에 적용했다. push, 배포, DB migration, 실제 회사 지원은 실행하지 않았다.

## 적용한 경로

Career Role의 **Apply with Harper → 채팅의 지원 준비 → 외부 사이트 입력·이력서 첨부·승인 후 제출** 경로다. 새 브라우저는 Agents API의 OpenAI-hosted 환경에서 실행한다. Harper 서버나 사용자 기기에 브라우저를 설치하거나 연결할 필요가 없다. 기존 Vercel 브라우저는 종료·정리만 지원한다.

이력서 선택·소유자와 파일 버전 확인, 추가 질문, 같은 페이지 재개, 명시적 제출 승인, 중복 방지를 유지했다. 기존 Memory·Brief·Profile 도구, Role 버튼의 채팅 연결, 대화 모델 설정과 `[llm-usage]` 로그도 유지했다. 일반 대화는 기존 기본 모델과 설정을 따르고, 지원 브라우저 판단 모델은 기존 Astra 설정을 따른다.

## 실행과 승인 경계

판단 모델은 별도 세션에서 제한된 입력 명령만 사용한다. 브라우저 파일·셸·승인 명령에 접근하지 못한다. 실행 환경은 고정 프로그램을 시작하며 모델 작업을 받지 않는다. 실제 API 조회로 실행 세션의 모델 turn이 0개임을 확인했다.

처음 여는 브라우저에는 사용자 인증·입력·파일이 없다. 폼을 불러오는 익명 요청은 허용한다. 사용자 답변이나 파일이 들어간 뒤에는 background 전송을 차단하고, foreground 전송은 실제 목적지·내용·파일 버전에 묶어 승인받는다. 읽기만 하는 화면 확인은 입력 동작으로 취급하지 않는다. Hosted 화면의 진단 목적지 `bzr.openai.com`도 차단한다.

실행 결과는 기존 비공개 저장소의 임시 객체로 연결한다. 객체마다 별도 업로드 권한과 AES-GCM 키를 사용한다. 관리자 키와 OpenAI 키는 실행 환경에 전달하지 않는다. 결과를 읽은 뒤 삭제하고 종료 시 환경과 남은 객체를 정리한다. 새 DB 테이블·bucket·서버 endpoint는 만들지 않았다. 파일 조각을 SHA-256으로 검사하며 기존 합계 10 MiB 제한을 유지한다.

## 한계

합성 접수와 공개 데모의 파일 선택은 실제 회사의 지원 접수·채용 결과와 다르다. 데모의 파일명 확인을 외부 서버의 첨부 수신으로 주장하지 않는다. 로그인·CAPTCHA, 입력 후 자동 저장, 여러 전송을 요구하는 사이트는 기존 승인 경계에 따라 제한되거나 추가 확인이 필요하다. 모든 ATS 지원이나 배포된 Harper의 변경을 의미하지 않는다.

Canonical runner는 `scripts/verifyAgentsHostedApplicationRuntime.ts`, frozen 계약은 runtime-v2다. 최초 모델 첨부 실험의 v1 입력·결과는 보존했다.
