# Agents API hosted resume attachment

## Objective and unit

Find a working resume-attachment path using only `/v1/agents` and OpenAI-hosted compute. No Responses API, Harper/Vercel browser VM, local browser, or user browser is used by the runner. One unit is a fresh session attaching one frozen synthetic PDF to one form. This is a capability experiment, not a production deployment or overall ATS compatibility benchmark.

2026-10-12: hosted Playwright path passed byte identity on both forms, with one server receipt on the owned form. Native Astra browser did not attach the file. [Observed report](reports/2026-10-12-hosted-upload.md). All sessions/environments were deleted and checked for 404. Model usage was unavailable; costs remain unknown.

## Frozen input and gold

`cases-v1.json` defines the Ashby public demo (attachment only) and an isolated synthetic form served inside the OpenAI sandbox (attachment plus submission receipt). `gold-v1.json` fixes byte identity, filenames and required evidence before execution. `manifest-v1.json` records fixture/source hashes. The PDF is the existing synthetic generator in `scripts/agents_api_application_probe.py`; no production person, company Role, or DB data enters this experiment. Public demo pages may change: each run records the observed URL, screenshot and limitations, and does not imply frozen third-party HTML.

## Canonical runner and contract

`scripts/agents_api_hosted_upload_probe.py` owns the client/API loop. `fixtures/hosted-files-v1.json` freezes reusable Playwright assets exported from the existing `applicationPlaywright.ts` implementation. The Assets run exclusively inside an `openai_hosted` environment. Native `computer_use` and sandbox-executed Playwright are separate methods; results must say which actually worked. The hosted method requires downloadable browser proof with file name, size and SHA-256. The owned fixture additionally requires a server-written receipt with the same bytes. Assistant prose alone is not success.

## Model, runs and metrics

Default model is `gpt-6-astra` (provider defaults for reasoning/sampling); explicit overrides are recorded. Deadline defaults to 420s including provisioning; API HTTP requests have bounded timeouts. Runs save request body without credentials, SSE events, session/items, artifacts and a reproducibility manifest under ignored owner-only `runs/`. Every new model or prompt uses a new run against the same cases/gold. Record actual aggregate usage and standard-rate partial token estimates; cache writes, context surcharges and container bills are separate/unknown.

Release gate for this experiment: downloaded byte-identity proof; for owned submission a real server receipt; no real employer submission; session cleanup verified. Native UI-only screenshots can establish visible selection but are weaker evidence than byte identity and cannot be reported as full gate success.

## Privacy and limits

External provider is `https://api.openai.com/v1/agents`; API key stays on the client and is never put in the sandbox, requests, manifests or logs. Only fabricated PDF/details and source assets are transmitted. Public Ashby demo receives only this synthetic file; never press its final Submit Application. Synthetic local server is reachable only inside the OpenAI environment and does not write Harper data. No production Supabase queries, company-side messages, migrations, push or deployment.

File selection, transport receipt and employer acceptance are different facts. Passing these two small forms is not proof that every ATS works. Login/CAPTCHA, production consent, user approval enforcement, large files and multi-file applications are outside this experiment.

## Local product runtime integration (runtime-v2)

`scripts/verifyAgentsHostedApplicationRuntime.ts` imports the current product runtime, driver, launcher and encrypted result transport. This is a deterministic integration test with **zero model turns**, separate from the model capability experiment above. `cases-v2.json` and `gold-v2.json` freeze the test inputs and gates; the original v1 assets and results remain unchanged. Each run records exact dirty-source SHA-256 values in its owner-only manifest.

The owned fixture wraps the same synthetic server in locally trusted HTTPS inside the OpenAI sandbox. Only this test launcher allows its loopback destination; product startup requires public HTTPS. Gate: the same form keeps entered data across separate requests; attachment bytes match; no receipt before approval; a forged request scope is refused; approval produces exactly one receipt; repeated approval cannot produce a second request; executor turn list is empty; session and environment return 404 after cleanup. The optional `--public-demo` case reads Ashby's public demo and selects the synthetic file without approving any third-party write or final submission. Visible filename is weaker evidence than server byte identity.

The result transport uses the existing private `talent-resumes` bucket under random `_application-browser/<uuid>` prefixes. Only encrypted synthetic command results are temporarily uploaded; no document rows, user records, Roles, messages, migrations or bucket settings are written. Each command has a distinct, non-overwriting signed upload grant and AES-GCM key; provider/admin keys never enter the sandbox. Command results are deleted after reading; remaining objects and the hosted environment are removed when stopping. No local/Harper/Vercel browser is started. These integration runs do not assess the conversational planner's judgment or all ATS protocols.

Local main integration and validation: [2026-10-12 report](reports/2026-10-12-local-runtime-integration.md). This feature change is not deployed.

## Product planner and full submission (product-submission-v5)

`cases-v5.json`, `gold-v5.json`, `manifest-v5.json` and `fixtures/receipt-server-v5.cjs` freeze one new synthetic ten-control form before model execution. The PDF is the wholly synthetic v1 fixture, not the PII-bearing Storage E2E file. Profile facts and two approved Korean answers are fixed; exact field/file identity is a structural transport gate, not a semantic writing classifier. Previous fixtures/gold remain unchanged.

Canonical runner: `TSX_TSCONFIG_PATH=scripts/tsconfig.json node --env-file=.env.local --import tsx scripts/evalApplicationBrowserSubmission.ts`. It imports the production `applicationBrowserAgent()` prompt/tools/configuration and the real hosted runtime/driver/result transport. The model has `environment:none`; the separate OpenAI-hosted executor runs zero model turns. The synthetic input mirrors the production task contract, including the initial snapshot, confirmed facts and approved materials. Only the reusable test launcher permits loopback HTTPS. Default planner is `gpt-6.1-sol`, explicit low effort, provider-default sampling/service tier, 420-second total deadline and no task retry. Model/prompt experiments reuse this frozen version in new runs.

The isolated test actor verifies the held POST destination, actual final-review values, absence of a receiver receipt and rejection of a forged scope, then explicitly approves that exact request. Gates require every approved field/answer, original PDF bytes/basename, one receiver receipt/POST attempt, observed receipt before a succeeded report, replay-safe approval, zero executor model turns, and independently verified 404 cleanup. Calls, snapshots, receiver receipt, usage, dirty-source/fixture/prompt hashes and model configuration are saved only under ignored owner-only `runs/`. Count/model-token estimates are diagnostic; hosted compute, cache-write accounting and missing usage remain separate. Manual trace review checks batch use, no unnecessary option enumeration/reinspection, unchanged approved writing and actual confirmation evidence.

This evaluates the product planner/tool/runtime boundary with a synthetic approval actor. It does not exercise the chat UI, durable SessionStore, document generation, writing review conversation, real ATS compatibility, login/CAPTCHA or actual employer delivery. Receiver attempt statistics are emitted independently; live environment file listing provides metadata, while receipt text provides the observed receiver counters. Local Chromium guard tests separately observe every received request and verify mid-batch interruption/duplicate approval. No production user, application, Role or message rows, settings, migration, push or deployment are written. Encrypted temporary results use the same isolated Storage prefixes/cleanup as runtime-v2; provider/admin credentials never enter the hosted executor.

PDF bytes, all supplied values and both approved Korean answers matched the receiver exactly. The test actor approval produced one receipt/POST attempt; repeated approval was handled by the existing executor receipt without replaying the click. All provider resources verified 404 cleanup. Session/turn token counters were unavailable; cost is unknown. Raw evidence: `runs/2026-10-13T04-06-21-656Z-product-submission-v5/`. ## Existing Storage PDF: storage-pdf-v1 and storage-live-v1

It must not be described as wholly invented or anonymized. Exact object metadata, original bytes, text review and authorization remain owner-only in ignored `private/storage-pdf-v1/` and `private/storage-live-v1/`.

`cases-storage-pdf-v1.json`, `gold-storage-pdf-v1.json` and `manifest-storage-pdf-v1.json` freeze the owned test URL, renamed attachment filename, original byte fingerprint and evidence gates before execution. The native attempt selected no file and produced no proof (60.94 seconds, partial token estimate USD 0.082766). The sandbox Playwright attempt selected the original PDF and the owned loopback receiver recorded exactly one matching file receipt (107.40 seconds, USD 0.076142). Browser file and server receipt name/size/SHA-256 all matched. No real company received these owned-test uploads. A preceding session-creation request was rejected for a setup-command type error in 0.22 seconds, before any session/model work; its evidence is retained, and it is not silently counted as a successful model attempt or retried model task.

`storage-live-v1` reuses the same unchanged E2E PDF and freezes the two real application destinations already reached in `native-korea-v1`; raw URLs are in `private/storage-live-v1/cases.json`. Public `gold-storage-live-v1.json` and `manifest-storage-live-v1.json` contain only de-identified identifiers, byte expectations, privacy boundaries and capture locators. Observed real-form results: one resume field displayed the uploaded filename after automatic processing settled (136.35 seconds, partial token estimate USD 0.111473); the site removed/reset the native file input, so browser File size/SHA-256 and a server receipt were unavailable. No challenge bypass, login, applicant answers, other documents, consent selection or employer application submission was performed. Canonical runner remains `scripts/agents_api_hosted_upload_probe.py`. Reproduce owned tests with `--dataset storage-pdf-v1 --method native --case owned_attachment --model gpt-6.1-sol` or `--dataset storage-pdf-v1 --method hosted --case owned_receipt --model gpt-6.1-sol`; the latter submits only the OpenAI-owned loopback test. ## Owned full application submission: v3

The user requested checking the complete path through PDF attachment, content writing and final submission. `cases-v3.json`, `gold-v3.json` and `manifest-v3.json` freeze a new owned form, synthetic candidate facts and structural/manual writing gates before execution. Earlier fixtures and labels remain unchanged. The original authorized Storage E2E PDF is reused byte-for-byte; it still contains real contact text and remains only inside OpenAI and its loopback receiver. All typed profile facts and written answers are synthetic. The form's consent is explicitly nonbinding synthetic processing, with no actual employer, legal agreement, email or Harper DB effect.

Canonical runner: `scripts/agents_api_hosted_upload_probe.py --dataset v3 --case owned_full_submission --method native` or `--method hosted`, with `--model gpt-6.1-sol --reasoning low`. Both use one fresh OpenAI-hosted session, the same profile/form/PDF, provider-default sampling/service tier, 420 seconds and no model task retries. Native computer use and the existing sandbox Playwright helper are separate capability runs. The latter performs browser DOM/control actions inside OpenAI; neither uses a local browser or Responses API. Only the exact owned loopback URL permits final submission. Real-form attachment-only cases keep their earlier boundary.

The new `fixtures/receipt-server-v3.cjs` receives multipart requests and records PDF name/size/SHA-256, applicant fields, two written answers, synthetic consent, POST attempts and accepted receipt count. A structural pass requires exactly one matching receipt, original bytes, supplied field identifiers/values and nonempty written fields. Writing relevance and factuality require manual semantic review; no keywords, length heuristic or deterministic prose rewriting score the model. Screenshots and actual browser tool commands are reviewed where available; model prose alone does not pass. Receipt files must not be edited by the agent. Raw request/event/item/receipt/content evidence stays in owner-only ignored `runs/`. Session and environment deletion must be verified independently. This tests an isolated owned form, not production ATS compatibility, login/CAPTCHA handling, actual employer delivery or hiring acceptance.

The first v3 hosted run passed the file/field/receipt transport gate, but its actual receipt screenshot showed garbled Korean because the owned receiver omitted its response charset. `cases-v4.json`, `gold-v4.json`, `manifest-v4.json` and `fixtures/receipt-server-v4.cjs` create a new frozen input version with UTF-8 response headers and wrapped receipt text. The applicant facts, original PDF and structural gates remain unchanged; v3 files/runs are preserved. Version v4 adds visual receipt encoding to manual review and runs only the hosted Playwright method with Sol low. This is a new fixture-version verification after a concrete test-page defect, not an automatic model retry or replacement of a random JD.
