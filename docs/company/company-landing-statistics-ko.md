# 회사 랜딩 통계

`/ko/company`, `/en/company`의 통계는 `/api/company/landing-stats`에서 같은 집계값을 읽는다. 고정 숫자나 개인별 데이터는 페이지에 넣지 않는다.

| 화면 지표 | 원본과 집계 기준 |
| --- | --- |
| Harper와 직접 이야기 나눈 인재 | 요청한 기준에 따라 `talent_users` 전체 행 수. 대화 여부와 탈퇴 여부로 필터링하지 않는다. 따라서 실제 대화 참여자 수와는 다르며, 화면의 보충 설명은 ‘전체 등록 인재 기준’이다. |
| 한 명과 주고받은 평균 메시지 | `talent_setting.is_onboarding_done = true`인 온보딩 완료자 중 채팅·음성에서 양쪽 발화가 모두 있는 인재만 집계한다. 해당 인재의 전체 `talent_messages` 기록에서 `chat`, `call_transcript`의 비어 있지 않은 user/assistant 메시지와 user의 `opportunity_feedback_note` 공고 피드백을 건당 1개씩 센다. 온보딩 중의 대화도 포함하며, 인재별 합계의 평균을 정수로 반올림한다. 미완료·완료 여부 없음·피드백만 남긴 계정은 분모에서 제외한다. 시스템 알림, 추천 알림, 이메일 등 다른 종류는 제외한다. 대상자가 없으면 평균은 null이다. |
| 인재와 포지션을 맞춰본 횟수 | `talent_external_fit`의 `(talent_id, role_id)`와 `talent_opportunity_fit`의 `(talent_id, opportunity_id)`를 합친 고유 조합 수. 각 테이블의 기존 unique index를 이용하며, 두 테이블에 함께 있으면 한 번만 센다. `company_roles.information.testOnly = true`인 내부 테스트 포지션은 제외한다. |

대화 시간은 메시지 사이의 대기 시간을 실제 대화 시간과 구분할 수 없어 사용하지 않는다. 매칭 지표는 추천·연결 성공 건수나 재평가를 포함한 총 실행 횟수가 아니라, 현재 저장된 평가 조합 수다. 원본 기록이 삭제되면 집계값도 줄어들 수 있다.

## 갱신과 실패 처리

- 전체 인재 수와 평균 메시지는 Next Data Cache에 24시간 보관한다. 매칭 횟수의 증가율을 계산할 실제 기준값도 이 집계에 포함한다.
- 매칭 횟수는 별도 집계로 5분마다 갱신한다. 이 쿼리는 메시지 테이블을 읽지 않는다. 모든 방문자와 언어가 캐시를 공유한다.
- 각 캐시의 유효 시간이 지난 뒤 첫 요청에서 백그라운드 갱신한다. 자정이나 정각에 실행하는 예약 작업은 아니다.
- 갱신 중에는 이전 값을 보여주고, 갱신 실패 시 기존 캐시를 유지한다. 처음부터 집계가 불가능하면 `—`를 표시하며 0이나 예시 숫자로 대체하지 않는다.
- 화면이 열려 있을 때 브라우저는 1분마다 API를 다시 확인한다. 브라우저/CDN의 HTTP 캐시는 30초이고, 백그라운드 갱신 동안 최대 30초의 이전 응답을 허용한다. 따라서 5분 갱신은 정확히 그 시각에 모든 화면에 반영된다는 뜻은 아니다.
- API는 집계 숫자 세 개, 일일 집계 시각, 매칭 집계 시각, 관측된 초당 증가율만 반환한다.
- 연결은 기존 Career 포지션 조회와 같은 서버 DB 환경변수를 사용한다. 로컬에서는 기존 `../worker.env`의 연결 설정을 읽을 수 있다. 운영에서는 서버 환경변수가 필요하다.
- 쿼리는 읽기 전용 트랜잭션, 30초 제한으로 실행한다. 새 테이블, DB 함수, migration, cron은 필요하지 않다.

## 매칭 횟수 애니메이션

- 두 집계가 1분 이상 떨어져 있으면 증가 속도는 `(최신 매칭 집계 - 일일 기준 집계) / 두 집계 사이의 초`로 구한다.
- 첫 요청이나 일일 캐시 갱신으로 비교 가능한 두 집계가 없을 때는 최근 7일의 평가 기록 수 / 7일의 초로 시작 속도를 추정한다. 테스트 포지션과 중복 조합, 미래 시각은 제외한다. `created_at`은 재평가에서도 바뀌므로 이는 최근 평가 활동에 근거한 임시 표시 속도이며, 신규 고유 조합의 정확한 증가율은 아니다. 다음 유효한 두 집계부터 실제 순증가율을 우선 사용한다. 최근 활동 자체가 없으면 0으로 유지한다.
- 최신 실제 수에 그 뒤의 경과 시간과 증가율을 곱해 더한다. 임의의 고정 증가량이나 무작위 가속은 없다. 이 움직임은 매초 DB에서 확인한 실시간 실측값이 아니라 증가 추세에 따른 추정이다.
- 공통 `LandingStats` 안에서 `RollingNumber`를 사용한다. 1초마다 목표값을 계산하고 바뀐 자릿수만 위로 굴려 전환한다. 회사 페이지와 홈 랜딩의 B그룹이 같은 집계·표시 컴포넌트를 사용하며, 페이지 전체를 프레임마다 다시 렌더링하지 않는다.
- 새 실제 집계가 오면 그 값을 기준으로 다시 맞춘다. 기록 삭제 등으로 실제 수가 줄어들었으면 감소도 반영하고 증가율은 0으로 둔다.
- 갱신 실패나 연결 중단 시 마지막 실제 집계 시각에서 최대 10분까지만 추정한 뒤 멈춘다. 숨겨진 탭에서는 화면 애니메이션을 중단한다.
- 애니메이션 감소 설정에서도 숫자는 갱신한다. 자릿수가 움직이는 전환 효과만 끈다.

## 확인

실제 집계 쿼리는 `src/lib/companyLandingStats.server.ts`에 있다.
`scripts/testCompanyLandingStats.mjs`는 로컬 PGlite에 합성 데이터만 만들고 같은 쿼리를 실행한다.
빈 데이터, 대화·음성·피드백 집계, 중복 및 테스트 포지션 제외, 일일/빈번 집계의 동일성, 실제 차이에 따른 증가율, 추정 상한, 시계 차이, 최초 캐시와 감소 보정, 구 API 응답 호환을 확인한다.

```sh
# PGlite가 별도 로컬 runtime에 설치됐다면 해당 dist/index.js 경로를 지정한다.
PGLITE_MODULE_PATH=/absolute/path/to/pglite/dist/index.js \
  node --import tsx scripts/testCompanyLandingStats.mjs
```
