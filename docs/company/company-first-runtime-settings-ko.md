# Company-first 검색 운영 설정

문서 기준: 2026-09-29. DB migration, Ops 화면과 Worker 설정 조회 코드를 운영에 반영했고 Company-first 실행기·예약 실행기를 활성화했다. 이 설정을 바꾸기 위해 재배포하거나 서비스를 재시작할 필요가 없다. 정기 검색은 `company_internal_roles.is_company_first_search = true`인 유효한 Role만 대상으로 한다. 직접 요청과 calibration 후 첫 검색은 별도 시작 조건을 유지한다.

## 변경 위치

Ops → 매칭 관리 → **검색 설정** (`/ops/company-first`). 로그인한 Harper 팀원이 조회하고 저장한다. 다른 팀원이 먼저 저장했다면 다시 불러온 뒤 수정해야 한다.

| 설정 | 기본값 | 변경 범위 |
| --- | --- | --- |
| 정기 검색 예약 | 켜짐 | 켜짐 / 꺼짐 |
| 실행 주기와 시간 | 매주 월요일 09:00 | 매일·매주·매월 또는 숫자 5개 필드 cron |
| 시간대 | Asia/Seoul | IANA 시간대 |
| 정기 검색 · Role당 최대 | 3명 | 1~50명 |
| 직접 요청 · Role당 최대 | 6명 | 1~50명 |
| 회사별 미처리 제안 한도 | 30명 | 1~500명 |

정기 인원 상한은 candidate-first와 company-first를 합친 수에 적용하며, calibration 전달 뒤 시작되는 검색에도 같다. 회사가 직접 요청한 검색은 company-first만 선택한다. 인원은 최대값이며 적합한 후보가 부족하면 더 적게 선택하거나 0명이 될 수 있다. 같은 후보자를 회사 안에서 중복 선택하지 않는다.

미처리 제안은 회사가 아직 판단하지 않은 `ready` 상태의 고유 후보자 수다. 회사가 Intro를 요청해 후보자 답변을 기다리는 상태는 여기에 포함하지 않는다. 한도를 낮춰도 기존 제안을 삭제하지 않으며, 미처리 수가 한도 아래로 내려올 때까지 새 검색을 시작하지 않는다.

## 적용 시점

- 예약 실행기는 매분 최신 설정을 읽는다. 정기 예약을 끄면 새로운 정기 검색 예약을 멈춘다. 이미 대기 중인 검색, 직접 요청한 검색, calibration 후 검색과 진행 중인 검색은 취소하지 않는다.
- 검색 실행기는 새 작업을 가져오기 직전에 설정을 읽고 그 작업 전체에서 같은 값을 사용한다. 진행 중인 작업의 인원 제한은 중간에 바뀌지 않는다.
- 직접 요청을 접수하는 DB 함수도 같은 미처리 한도를 읽는다. 최종 제안 저장 때는 기존 회사별 잠금 아래에서 실제 미처리 수를 다시 확인한다.
- 설정을 읽거나 검증하지 못하면 기본값으로 조용히 되돌리지 않고 새 작업 접수·예약을 보류한다.
- 사용한 설정은 기존 검색 실행 기록에 남는다. 설정은 기존 `worker_runtime_settings`의 `default` 행에 보관하며 다른 Worker 설정은 변경하지 않는다.

## 예약과 다른 검색의 관계

정기 예약은 해당 시간대의 현재 날짜 안에서 가장 최근의 실행 시각을 한 번 처리한다. 09:00에 실행기가 내려가 있었다면 같은 날 재개할 때 복구하지만, 전날이나 여러 번 놓친 예약을 한꺼번에 소급하지 않는다. 회사별 실행 시각의 기존 중복 방지 키를 유지한다. 예약을 과거 시간으로 바꾸면 변경한 날의 해당 시각이 즉시 처리될 수 있다.

회사에서 직접 새 검색을 요청하면 예약일까지 기다리지 않고 같은 검색 대기열에 넣는다. 새 Role calibration이 Slack에 처음 전달된 뒤 12시간 후의 검색도 유지한다. 이번 설정 화면의 실행 주기는 정기 예약에 적용되며, 이 12시간을 바꾸는 항목은 포함하지 않는다.

## 직접 지정 예시

| cron | Asia/Seoul 기준 실행 |
| --- | --- |
| `0 9 * * 1` | 매주 월요일 09:00 |
| `30 10 * * 1,3,5` | 매주 월·수·금요일 10:30 |
| `0 9 * * *` | 매일 09:00 |
| `0 */2 * * *` | 매일 두 시간마다 정각 |
| `0 9 1 * *` | 매월 1일 09:00 |

기존 후보자 공개 범위·동의·회사 차단·Role 상태·테스트 Role 제외와 전달 권한은 이 설정으로 변경하지 않는다. 검색 후보군의 전체 크기와 모델 병렬 실행 예산도 별도 기존 제한을 유지한다.
