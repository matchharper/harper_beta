# Company-first 검색 운영 설정

## 2026-10-08 로컬 구현 변경 — 미배포

아래 기존 설명의 정기 검색 통합 3명 상한은 새 로컬 구현에서 분리한다. 후보자 선추천은 역할당 한 번의 검색에서 최대 20명이며, 회사 선추천은 기존 Ops의 정기·직접 요청 한도를 각각 따른다(기본 3명·6명). 양측 추천은 양쪽 한도에 모두 포함한다. 우선 검토 요청의 별도 최대 3명 계약은 유지하며, 후보자 선추천으로 선정하면 전체 20명 한도에서도 차감한다. 20명은 선정 최대값이며 즉시 발송 인원이 아니다.

Rerank와 shortlist는 실제 전달을 확인한 추천의 14일 반응 집계·표본 수와 현재 진행 인원을 읽는다. 확인되지 않은 과거 반응은 미확인으로 표시하며 0% 수락률로 취급하지 않는다. 14일은 평가 관찰 기간이고 자동 dislike 정책은 바꾸지 않는다. 후보자에게만 먼저 추천한 대상에게는 criteria·회사 소개문을 작성하지 않는다. 이 변경은 운영 설정값이나 DB schema를 변경하지 않는다.

## 기존 운영 설정

문서 기준: 2026-10-09. 정기 검색 요일과 시각은 회사의 Role별 설정을 따른다. 2026-10-09부터 새 Role의 정기 검색은 기본적으로 켜지며, 기본 시각은 한국 시간 월·수·금 09:00이다. 기존 Role의 켜기·끄기 설정은 소급 변경하지 않는다. 직접 요청과 새 Role의 예시 프로필 첫 전달 12시간 뒤 검색은 정기 예약과 별도로 실행된다.

## 변경 위치

| 위치 | 설정 | 기본값 |
| --- | --- | --- |
| 회사 Workspace → Role → Settings | 해당 Role의 정기 검색 켜기, 요일, 시각 | 새 Role은 켜짐, 월·수·금 09:00 |
| Ops → 매칭 관리 → 검색 설정 (`/ops/company-first`) | 전체 정기 예약 켜기, 정기·직접 요청의 Role당 최대 인원, 회사별 미처리 제안 한도 | 켜짐, 3명, 6명, 30명 |

요일은 월요일부터 일요일 중 하나 이상, 시각은 00:00부터 23:00까지 한 시간 단위로 고른다. 모든 예약 시각은 `Asia/Seoul` 기준이다. 회사가 Role별 정기 검색을 꺼도 그 Role에 대한 명시적 직접 요청은 별도로 처리할 수 있다. 전체 정기 예약을 끄면 새 정기 검색만 멈추고 직접 요청과 예시 프로필 전달 후 첫 검색은 유지한다.

Ops의 인원 설정은 최대값이다. 정기 검색에서는 후보자 선제안과 회사 선검토를 합쳐 Role당 기본 최대 3명, 직접 요청에서는 회사 선검토를 Role당 기본 최대 6명까지 선택한다. 적합한 후보가 부족하면 더 적거나 0명일 수 있다. 회사 안에서 한 후보자를 중복 선택하지 않는다.

회사별 미처리 한도는 아직 회사가 결정하지 않은 회사 선검토 후보의 고유 인원이다. Intro를 요청해 후보자 답변을 기다리는 사람은 이 한도에 포함하지 않는다. 한도를 낮춰도 기존 제안을 삭제하지 않으며, 한도 아래로 내려갈 때까지 새 검색을 시작하지 않는다.

## 예약 실행과 적용 시점

- 예약 실행기는 매분 활성 Role의 요일·시각과 전체 예약 스위치를 읽는다. 같은 회사에서 같은 시각에 대상이 된 Role은 한 검색으로 묶고, 다른 시각의 Role은 별도 검색으로 예약한다. 예약된 검색에는 그 시점의 Role 범위를 보존한다.
- 해당 요일의 설정 시각을 놓쳤다면 같은 날 안에서 한 번 복구한다. 전날이나 더 오래된 예약을 한꺼번에 소급하지 않는다. 같은 회사·같은 예약 시각의 중복 등록은 막는다.
- Role의 요일·시각 변경과 전체 예약 스위치는 다음 분부터 적용된다. 이미 대기 중이거나 진행 중인 검색은 취소하지 않는다. 시간을 당일의 지난 시각으로 바꾸면 그날의 검색이 다음 확인 때 시작될 수 있다.
- 검색 실행기는 새 작업을 가져올 때 Ops의 인원·미처리 한도를 읽는다. 진행 중인 검색의 상한은 중간에 바뀌지 않는다. 설정을 읽거나 검증하지 못하면 조용히 기본값으로 돌아가지 않고 새 예약·작업 접수를 보류한다.
- 회사가 직접 요청한 검색은 정기 예약을 기다리지 않는다. 새 Role의 예시 프로필이 Slack에 처음 전달된 뒤 12시간 후에 시작하는 검색도 별도 시작 조건을 유지한다.

기존 공개 범위·동의·회사 차단·Role 상태·테스트 Role 제외·전달 권한은 이 설정으로 바뀌지 않는다. 예전 Ops 설정에 저장된 전역 cron과 시간대 값은 현재 Role별 정기 검색 시각을 결정하지 않는다.
