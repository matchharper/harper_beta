## 웹 연결

`/api/billing/promotion?token=...` → 서명 확인 → HttpOnly 쿠키 → `/org/slots?purchase=slot&interval=month&lang=ko` → 기존 로그인/가입 → 슬롯 구매 → 기존 Stripe Checkout.

- 링크는 양도 가능한 할인 초대다. 사용자 개인정보를 담지 않으며 Workspace 접근 권한이나 구매 권한을 부여하지 않는다. 기존 Owner/Admin 구매 권한을 그대로 검사한다.
- 서명은 기존 서버 전용 키와 별도 목적 문자열을 사용한다. 신규 환경변수·DB 변경이 필요 없다.
- 가격표와 결제는 같은 Stripe Price를 읽는다. 구매창에 표시한 단가를 서버에서 다시 확인해 할인 만료·쿠키 유실 시 일반 가격으로 조용히 결제되지 않게 한다.

## 발송 파일과 실행

비공개 원본·개인별 파일·미리보기·발송 영수증은 ignored `.local/launch-promotion-20261027/`에 보관하며 커밋하지 않는다. `prepared/manifest.json`이 파일 목록이다.

`scripts/prepareCompanyLaunchEmail.py`는 본문과 수신자를 치환하고 이미지 원본을 inline attachment로 바꾼다. 기본 발송은 없다. `scripts/sendPreparedCompanyEmail.mjs <manifest>` 역시 조회만 한다. `--test`는 테스트 3통만, `--send-customers`는 고객 발송이다. 고객 발송 옵션은 고객에게 보내라는 별도 명시적 요청 이후에만 실행한다. 동일 발송은 로컬 영수증과 Resend idempotency key로 중복을 방지한다. 영수증 파일을 지우고 재발송하지 않는다.

최초 테스트 메일은 로컬 웹을 사용하는 버튼으로 발송했다. 발송 당시 본문·미리보기·영수증은 `sent-test-original/`에 보존하며, 준비 폴더의 기존 영수증도 지우지 않는다. 이후 사용자가 실제와 같은 제목으로 다시 보내도록 요청해 `resend-original-subject-1114/`와 `send-optimizerai-original-subject-1114/`에 별도 발송본·영수증을 저장했다. 이 발송본의 마감은 당시 11월 14일이며, 이미 수신된 메일 본문은 바뀌지 않는다. 현재 `prepared/`의 41종은 11월 5일 마감으로 변경됐다. 제목·본문에 테스트 표기를 넣지 않으며 정식 `https://matchharper.com` 링크를 사용한다. 지정 주소·provider ID와 상태는 비공개 영수증에 보존한다.
