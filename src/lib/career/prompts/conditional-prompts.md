# Career Conditional Prompt Map

> 2026-10-31 일반 텍스트 채팅 프롬프트 정리 이후의 정본은 [mainPrompts.ts](./mainPrompts.ts)와 [현재 추가 입력 목록](./mainPrompts.md)이다. 아래에는 온보딩·통화와 이전 조립 구조를 포함한 기존 개요가 보존되어 있으므로, 일반 채팅의 현재 구성은 새 문서를 우선한다.

이 문서는 `/career`에서 조건에 따라 추가되는 prompt block과, "일반 채팅처럼 화면에 보이지만 별도 endpoint/action에서 LLM을 호출해 assistant message를 생성하는" 경로를 정리한다.

## Common Text Chat LLM Input

일반 `/api/talent/chat`과 `runCareerChatTurn` 계열 proactive reply는 대부분 같은 조립 함수를 쓴다.

- 조립 함수: `buildCareerConversationPromptPlan({ channel: "chat", ... })` in `src/lib/career/prompts/conversationPlan.ts`
- 실행 함수:
  - 일반 채팅 streaming: `/api/talent/chat` -> `runCareerChatAssistantStream`
  - proactive/non-streaming: `runCareerChatTurn` -> `runCareerChatAssistant`
- 공통 system block 순서:
  1. `chat_core`: `CAREER_CHAT_CORE_SYSTEM_PROMPT`
  2. mode guidance:
     - 온보딩 중: `CAREER_CORE_RESPONSE_GUIDANCE_PROMPT`
     - 온보딩 완료 후: `CAREER_DEFAULT_CONVERSATION_GUIDANCE_PROMPT`
  3. 온보딩 중이면 `onboarding_rules`: `CAREER_ONBOARDING_CONVERSATION_PROMPT`
  4. `profile_context`: talent profile, structured profile, recent recommended opportunities
  5. `tool_policy`: 노출 tool이 있을 때 `buildCareerToolPolicyPrompt` 결과
  6. `dynamic_state`: 현재 채널/시간, `conversationMode` 기반 high-priority runtime instruction, saved preferences/insights, pending feedback context, recent activity, opportunity status
- message input:
  - 최근 conversation message를 `fetchRecentMessagesWithSummary(... recentLimit: 16)` 또는 호출별 limit으로 가져온다.
  - `opportunity_feedback_note` message는 실제 유저 발화가 아니므로 `formatTalentMessageContentForLlmPrompt`가 아래 prefix를 붙인다.

```text
[System action log] This opportunity feedback note was generated by Harper after the user clicked a save/dislike control. It is not a user-authored chat message.
Action note: ...
```

## Default Tool Sets

`resolveCareerChatTools`가 최종 tool schema를 고른다.

온보딩 중 text chat 기본 tool:

- `update_language_setting`
- `web_search`
- `update_talent_profile`
- `open_url`
- `get_internal_roles`
- `internal_role_priority_review`

온보딩 완료 후 text chat 기본 tool:

- `update_language_setting`
- `web_search`
- `open_url`
- `recommend_job_postings`
- `get_internal_roles`
- `internal_role_priority_review`
- `read_recommended_opportunities`
- `get_role_context`
- `update_recommended_opportunity_feedback`
- `read_talent_activity_events`
- `update_setting`
- `update_talent_profile`
- `record_internal_fit_reevaluation_information` only when an active internal-fit hold question exists

`allowedToolNames: []`가 명시되면 tool schema는 빈 배열이다. 이 경우 LLM은 tool call을 할 수 없고, `tool_policy`도 사실상 들어가지 않는다.

## Chat-Like Separate LLM Calls

아래 경로들은 사용자가 직접 chat input에 메시지를 보낸 것은 아니지만, 결과가 assistant chat message처럼 표시된다.

| 상황 | 호출/파일 | Streaming | Runtime prompt | Tools | internal/external 차이 |
| --- | --- | --- | --- | --- | --- |
| Opportunity feedback follow-up | `/api/talent/opportunities/feedback-followup` -> `createTalentOpportunityFeedbackFollowUpReply` -> `runCareerChatTurn` | No | `buildCareerOpportunityFeedbackFollowUpTurnInstruction` + `pendingOpportunityFeedbackContext` | 일반 Career capability 전체 | 별도 모델/도구 제한 없이 저장된 internal/external 결정 사실을 같은 원본 agent가 판단 |
| Internal call request follow-up | `/api/talent/opportunities/internal-call-request-followup` -> `createInternalOpportunityCallRequestFollowUp` | No | 동일 feedback event의 호환 adapter | 일반 Career capability 전체 | 신규 UI는 호출하지 않음. 기존 client의 재호출도 같은 reply ID로 중복 방지 |
| Company watchlist follow follow-up | `/api/talent/company-watchlist/follow-followup` -> `createTalentCompanyFollowFollowUpReply` -> `runCareerChatTurn` | No | `buildCompanyFollowUpInstruction` | `[]` | No |
| Gmail career history import completion | Gmail career-history queue -> `createGmailCareerHistoryFollowUpReply` -> `runCareerChatTurn` | No | `buildGmailCareerHistoryFollowUpInstruction` with the saved high-confidence application records | `[]` | No |
| Session start greeting/re-engagement | `/api/talent/session`, `/api/talent/session/reengagement` -> `runCareerChatTurn` | Dedicated endpoint streams text; session GET is non-streaming | `buildCareerSessionStartTurnInstruction` | Shared Career capability runtime | Explicit app-return event after history; no persisted user speech |
| Voice call wrap-up | `/api/talent/chat/call-wrapup` -> `runCareerChatTurn` | No | 일반 call: `buildCareerCallWrapupTurnInstruction`; internal opportunity call: `buildInternalOpportunityCallWrapupInstruction` | `update_setting`, `update_talent_profile` | Prompt differs for internal opportunity call. Tool allowlist is the same. |
| Onboarding completion wrap-up card | `createOnboardingCompletionMessages` / `regenerateOnboardingCompletionMessages` -> `generateOnboardingCompletionWrapupContent` | No | `buildWrapupInstruction` as `runtimeInstruction` | `update_setting`, `update_talent_profile` | No |
| Onboarding continuation | direct web reply queue → `processCareerBackgroundRun` → `runCareerChatTurn` | Yes | `buildOnboardingCompletionHandoffInstruction` | Normal Career tools | Current `/jobs` entry and conversation facts guide the next action; the server saves the original final response in chat. No Python handoff or Behavior preparation. |

Not separate chat-like LLM calls:

- `Conversation Starter`: normal `/api/talent/chat` request with `conversationMode: "career_coaching"`, `conversationMode: "match_quality"`, or `conversationMode: "career_check_in"`. It can stream through the normal chat SSE path. Stale `preference_update` call requests are normalized to `career_coaching` during the transition.
- `Post-onboarding conversation guide`: a shared block in `buildCareerConversationPromptPlan`, not a separate LLM call or turn-specific scenario prompt. The completion handoff applies it immediately, and later chat/voice turns use recent history to continue without a fixed turn counter.
  - 여기서 post-onboarding은 온보딩 종료 후 첫 opportunity run 완료 전까지를 뜻한다. 이 기간에는 이미 진행 중인 초기 run과 중복되지 않도록 `recommend_job_postings` 호출을 가능한 피한다.
- Internal opportunity call-request decision: separate JSON LLM, but it does not directly write the first chat reply. The visible call-request message is currently a deterministic template after the decision.

## Opportunity Feedback Follow-Up

2026-10-30 로컬 구현 기준. 배포 여부와는 별개다.

저장된 수락·거절 버튼 → `createTalentOpportunityFeedbackFollowUpReply` → 일반 `runCareerChatTurn`을 사용한다. internal/external/목록 소진 trigger는 사건 출처이며 각각의 답변 workflow가 아니다. 일반 Career 모델·context·capability loader·handbook·전체 도구를 사용하고 별도 feedback 모델 설정은 없다.

- 원본 DB 결정·사용자 이유·정확한 추천/Role·수락 자료·현재 progress를 전용 텍스트로 제공한다. 모델용 시각은 공통 formatter를 거친다.
- 이미 실행된 버튼 결정은 재실행하지 않는다. 질문, form, profile/document, 검색, 후속 일정, 짧은 응답 또는 무응답은 원본 모델이 판단한다. 목록이 비었다고 새 추천을 강제하지 않는다.
- 같은 추천의 같은 저장 결정 시각은 같은 reply ID를 사용한다. 체크포인트와 비동기 child 작업도 이 ID와 원래 context로 재개한다. 늦은 사용자 메시지는 자동 답변의 표시를 억제하고, 완료된 무응답도 재실행하지 않는다.
- 별도 통화 판단 LLM과 고정 통화 제안은 UI 경로에서 제거했다. `internal-call-request-followup`은 이전 client를 위한 동일 event adapter다. 기존에 이미 만든 통화의 답변/조회 기능은 보존한다.
- 회사 요청 Intro 수락/거절도 같은 event 경로에 들어간다. 일반 internal 소개의 지연 전달과 Intro 요청의 실제 전달 결과를 구분하며 회사 열람이나 답변을 추정하지 않는다.

동작 정본은 `historyActionReply.ts`, `opportunityFeedbackEvent.ts`, `lifecyclePrompts.ts`, `chatTurn.ts`다. 입력·실모델·DB 검증은 `docs/evaluation/career-agentic-runtime/`에 기록한다.

## Other Runtime Prompt Details

### Company Watchlist Follow Follow-Up

Prompt builder: `buildCompanyFollowUpInstruction`

```text
## Company follow proactive assistant turn
The user followed company "{companyName}" from Career Watchlist. They did not send a new chat message.
Short description: ...
Location: ...
Specialities: ...

Write the next assistant message in {outputLanguage}.
Do not mention triggers, timers, events, logs, systems, or implementation details.
Do not open with a long explanation of Watchlist mechanics.
Keep it to 1-2 natural sentences.
Acknowledge the saved interest and say Harper will remember this direction when tracking relevant company changes or future matching.
Ask no question unless one very specific missing preference would materially improve future matching.
```

Tools: `[]`.

### Session Start Re-Engagement

Prompt builder: `buildCareerSessionStartTurnInstruction`

Current local contract (2026-11-04):

- 사용자가 새 메시지 없이 다시 방문했다는 사실과, 자연스러운 인사로 새 대화를 여는 목적을 마지막 앱 사건 입력에 제공한다. 준비된 추천 사실은 runtime context에 유지한다.
- 일반 Career 역할·대화 context를 재사용한다. 최근 대화, 최근 재접속 이력, 현재 pending action을 제공하며 주제별 제안 목록이나 연속 주제 금지 규칙은 넣지 않는다.
- `runCareerChatTurn`은 실제 대화 역할·순서를 보존하고 그 뒤에 재접속 사건을 provider `user` 역할로 전달한다. 사건에는 앱 입력이며 사용자 발화·새 동의가 아님을 표시한다. 대화 DB에 사용자 메시지를 만들지 않고, 시스템 context에 같은 지침을 중복하지 않는다. 이전 assistant 답변을 prefill로 전달하지 않는 입력 계약이다.
- pending action은 현재 `selectCareerReengagementPromptActions`가 반환하는 항목을 제공한다. actionKey를 정확히 사용하는 UI 실행 계약은 유지하며, 다룰 주제와 설명은 원본 LLM이 판단한다.
- 시각은 공통 formatter로 변환한다. 쓸 메시지가 없으면 `__NO_SESSION_GREETING__`을 반환할 수 있다.
- 온보딩 이후에는 `reengagementOpportunities.ts`가 최근 검색한 활성 매칭의 미추천·유효 공고 상위 10개를 준비한다. 최신 공고별 평가, 매칭 기준, 공고 공개 정보, 목록 revision과 마지막 시도·완료·진행 중 실행을 제공한다. 10개는 초기 context page이며 추천 개수를 제한하지 않는다.
- 활성 매칭 검색이 없으면 기존 `talent_external_fit`의 상위 후보와 평가 시점을 제공한다. 이 과거 cache에는 현재 추천 executor가 요구하는 평가 참조가 없으므로 선택 공고를 기존 `search_opportunities`로 평가해 반영한다. DB 이관·자동 전체 재검색은 없다.
- 공통 Career runtime에서 `opportunities` capability와 `opportunity_search` guide를 첫 provider 호출에 미리 제공한다. 다른 기능은 기존 loader를 유지하며 권한 경계는 같다. 후처리 인사 템플릿은 없다.

### Call Wrap-Up

Prompt builders:

- General call: `buildCareerCallWrapupTurnInstruction`
- Internal opportunity call: `buildInternalOpportunityCallWrapupInstruction`

Tools:

- `update_setting`
- `update_talent_profile`
- `update_setting` is for clear subscription-scope actions only: `stop_external`, `stop_all`, or `resume`.
- Recommendation batch-size changes go through `update_talent_profile.recommendationBatchSize`.

Internal opportunity call wrap-up prompt specifically says:

```text
## Internal opportunity call wrap-up
The user just ended a voice call for an accepted internal opportunity.
- companyName: ...
- roleTitle: ...
- callDuration: ...
- callLengthAssessment: ...

Tool instruction:
- If the user disclosed clear profile facts, role-specific achievements, constraints, preferences, or resume/CV positioning context, call update_talent_profile before writing the wrap-up.
- Do not call search, recommendation, company research, or activity-reading tools.

Response instruction:
- Write one short natural {outputLanguage} follow-up message for the chat after the call ends.
- Say the connection is continuing.
- If the call was substantial, say Harper will reflect the shared details when presenting them to the company.
- If the call was brief/incomplete, tell them they can continue by selecting Call from the + button in the chat when convenient.
- No heading, no bullets, 1-3 sentences.
```

### Onboarding Completion

Wrap-up card prompt: `buildWrapupInstruction`

- The card body is generated by LLM.
- It may call `update_setting` for clear subscription-scope actions (`stop_external`, `stop_all`, `resume`) and `update_talent_profile` for profile/memory or recommendation batch-size changes.
- Generic stop/unsubscribe wording should ask for clarification instead of calling `update_setting`.
- It must output only the markdown card body without the `Call Wrap-up` title.

Continuation prompt: `buildOnboardingCompletionHandoffInstruction`

- The completion transaction admits the existing durable Career run directly to the web reply queue, without Python handoff or initial Behavior Context preparation.
- After the completion response, the original Career executor uses the normal chat prompt and general tools. The server saves its final response to the same chat through the existing idempotent delivery executor; the model need not call a delivery tool. The tool-less next-steps writer is no longer called.
- The model uses the actual request and entry opportunity to choose an action or useful question. There is no fixed sequence of onboarding follow-up questions.
- The first selection should be generous when useful options exist, with one role per company. This is model guidance, not a count validator.
- Internal Role evaluation remains an independent Worker task and is not a prerequisite for starting the continuation.
- The `/jobs` source comes from the current conversation's `official_jobs_signup_intent` activity. Its stored slug resolves current company/role facts and, when available, an active non-test internal role ID. Older intent events without a slug may recover it from the latest preceding apply click.
- A priority-review reply retains the company and role labels from that exact conversation-bound slug. Another public job mapped to the same internal role cannot replace the candidate-facing labels.
- When Gmail is disconnected and recruiting history is the chosen topic, the assistant may append one validated `/career/profile?profileSection=links` action. Connected users are not asked to reconnect, and Gmail-derived Career Memories are not described as live inbox access.
