# Ops UI Instructions

- `/ops`는 내부 사용자가 빠르게 조작하고 결과를 확인하는 밀도 높은 도구다.
- 제목 위에 `Debugging` 같은 decorative eyebrow를 넣지 않는다.
- 제목, 필드, 버튼, 결과를 다시 설명하는 안내 문구·helper text·긴 empty state를 넣지 않는다.
- 화면에는 조작에 필요한 label, 실제 값과 상태, action만 우선 남긴다.
- 부가적인 기술 설명이 꼭 필요하면 본문을 늘리지 말고 접근 가능한 tooltip에 넣는다. 필요하지 않으면 생략한다.
- 오류, 되돌릴 수 없는 작업, 외부 전송처럼 판단에 꼭 필요한 경고는 짧고 구체적으로 유지한다.

## PR 작성 기준

- Harper 저장소의 PR을 작성하거나 수정하기 전에 [harper_incidents](https://github.com/matchharper/harper_incidents)의 최신 README를 직접 열어 읽고, 그 기준을 참고해 PR 내용을 작성한다.
- README는 변경될 수 있으므로 PR 작업마다 원본을 다시 확인한다. 내용을 이 파일에 복사하거나 고정된 요약으로 대신하지 않는다.
