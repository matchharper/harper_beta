# Documents <!-- id: documents -->

처음 사용한다면 **Harper 소개 → 시작하기 → 회사와 팀 → 역할 등록** 순서로 읽어 보세요. 이미 채용 중이라면 검색 설정, 후보자 연결, 소통과 전형 가이드부터 확인해도 좋습니다.

## Harper 소개 <!-- id: harper-introduction -->

Harper는 회사와 함께 채용을 진행하는 파트너입니다. 찾는 사람과 팀의 상황을 알려 주면 역할과 기준을 정리하고, 후보자 탐색·검토·연락·일정 조율을 돕습니다. 회사는 누구에게 제안하고 누구와 연결할지 결정합니다.

### 두 가지 소개 방식 <!-- id: harper-introduction-two-introduction-paths -->

| 구분 | 먼저 제안 가능한 후보 | 연결 대기 |
| --- | --- | --- |
| 후보자 의사 | 이 Role을 아직 수락하지 않았습니다. 이전 Harper 추천이나 거절 이력이 있을 수 있습니다 | 회사와 역할에 대한 설명을 듣고 대화해 볼 의사를 밝힌 후보자입니다 |
| 회사의 결정 | **Intro 요청**으로 먼저 제안하거나 **Pass**로 제외합니다 | **Connect**로 연결하거나 **Reject**로 이번 Role의 진행을 끝냅니다 |
| 수락 후 | 후보자가 수락하면 미리 선택한 팀원과 소개 이메일로 연결합니다. 회사의 추가 승인은 필요하지 않습니다 | 회사가 연결을 수락하면 선택한 방식으로 연결합니다 |
| 이용 범위 | Free의 공용 Intro로도 Intro를 요청할 수 있습니다 | 슬롯이 배정된 Role 또는 해당 기능이 포함된 기존 계약에서 이용합니다 |

추천은 단순히 검색 조건에 맞는 사람의 목록이 아닙니다. 그렇다고 **먼저 제안 가능한 후보**에 보인다는 이유로 후보자의 관심이나 지원 의사를 확정할 수는 없습니다.

### 연결 대기의 뜻 <!-- id: harper-introduction-what-ready-to-connect-means -->

Harper가 후보자에게 역할을 소개하고, 프로필만으로 역할을 판단하는 데 중요한 정보가 부족하면 필요한 내용을 확인합니다. 실제로 이 회사와 대화해 보고 싶다는 의사가 확인되고 소개가 준비·전달되면 **연결 대기** 상태로 회사에 소개합니다. 후보자의 수락만으로 회사에 소개가 이미 전달됐다고 판단하지 않습니다.

```callout
회사가 검토할 차례입니다

연결 대기 후보자는 회사의 결정을 기다립니다. 후보자는 이미 동의했습니다. 이 회사와 대화해도 좋다고 답한 상태이므로 회사가 추천 이유와 자료를 읽고 연결 여부를 결정하면 됩니다.
```

### Intro Requested의 뜻 <!-- id: harper-introduction-what-intro-requested-means -->

회사가 **Intro 요청**을 확정한 후보는 **Intro Requested**로 이동합니다. 카드는 **제안 준비 중 → 후보자 답변 대기 → 후보자 수락 · 연결 준비 중**을 구분해 표시합니다. 답변이 없으면 수락도 거절도 아닙니다.

제안이 실제로 전달된 뒤에는 Harper를 통해 추가 질문이나 정보를 전달할 수 있습니다. 후보자가 수락하기 전에는 면접 조율이나 일반 Pipeline 이동을 진행하지 않습니다.

## 시작하기 <!-- id: getting-started -->

**회사 정보, 함께 채용할 팀원, Slack 채널, 찾는 역할**을 준비하세요. 완성된 채용 공고는 없어도 됩니다.

### Workspace에 들어오기 <!-- id: getting-started-joining-a-workspace -->

현재 새 회사가 직접 Workspace를 만드는 가입은 일시 중단되어 있습니다. 초대받았다면 초대한 이메일로 로그인해 초대를 수락하세요. 회사에 Workspace가 있다면 Owner에게 초대를 요청합니다. 같은 회사 이메일로 로그인한다고 자동으로 팀원이 되지는 않습니다.

새 회사의 도입은 회사 페이지의 상담 요청 또는 문의하기를 통해 Harper 팀과 상의할 수 있습니다.

### 처음 설정할 것 <!-- id: getting-started-initial-setup -->

1. [회사 정보](#org-company)에서 현재 소개와 Pitch를 확인합니다.
2. 후보자를 검토하고 소개 이메일을 받을 사람을 [팀원으로 초대](#org-members)합니다. 팀원 관리는 Owner가 맡습니다.
3. [Integrations](#org-slack)에서 Slack을 연결하고 알림 채널을 준비합니다.
4. [New role](#org-newRole)에서 맡길 일, 필요한 경험과 근무 조건을 정리합니다.
5. 등록한 Role의 Settings에서 **추천 후보 검색**, 요일·시각, 담당자와 알림 채널을 확인합니다.

### 등록한 다음 <!-- id: getting-started-after-registration -->

화면을 계속 열어둘 필요는 없습니다. 먼저 제안 가능한 후보에서 연락해 볼 사람을 고르고, 이용 가능한 Role에 연결 대기가 도착하면 회사가 연결 여부를 결정합니다. Slack과 [Inbox](#org-inbox)에서도 회사에 공유된 후보자를 확인할 수 있습니다.

역할 등록은 후보자가 이미 발견되거나 연락이 완료됐다는 뜻은 아닙니다. 적합한 후보가 부족하면 결과가 적거나 없을 수 있습니다.

```action
첫 역할 등록하기
org:newRole
```

## 회사와 팀 관리 <!-- id: company-and-team -->

회사 전체의 소개는 [회사 정보](#org-company)에서, 특정 Role의 채용 기준은 역할 화면에서 관리합니다.

### Pitch와 Context for Harper <!-- id: company-and-team-pitch-and-context-for-harper -->

**Pitch**에는 무엇을 만드는 회사인지, 어떤 성과·문화·혜택 때문에 합류할 만한지 구체적인 근거를 적습니다. 일반적인 칭찬보다 실제 제품, 팀의 방식과 혜택 조건이 도움이 됩니다.

**Context for Harper**에는 계속 참고할 회사·역할 배경을 둡니다. 특정 Role의 필수·선호 기준은 Hiring Brief에, 후보자 한 명의 진행 상황은 그 후보자의 기록에 남깁니다. 한 후보자의 상황을 회사 전체의 기준으로 바꾸지 않습니다.

Harper에게 저장된 회사 정보나 맥락을 읽어 달라고 요청할 수 있습니다. Hiring Brief와 기억을 바꿀 때는 제안된 수정 내용을 확인한 뒤 반영합니다.

### 팀원 권한 <!-- id: company-and-team-team-member-permissions -->

| 권한 | 할 수 있는 일 |
| --- | --- |
| Owner | 팀원 초대·제거·권한 변경, Workspace 관리, 제공되는 결제 관리 |
| Admin | 후보자·Role·회사 정보·Integrations 관리, 연결 결정 |
| Viewer | 회사와 후보자 정보 검토 |

Slack에서도 연결된 팀원의 권한을 따릅니다. 채널에 참여했다는 이유만으로 변경 권한이 생기지는 않습니다.

### 응답 언어 <!-- id: company-and-team-response-language -->

웹에서 선택한 한국어·영어는 팀원별 설정으로 저장되며 Slack의 개인 대화에도 기본으로 사용됩니다. 이번 답변의 언어를 직접 요청할 수도 있습니다. Workspace 전체 공지와 정기 소개는 회사 Headquarters가 한국이면 한국어, 그 외에는 영어를 사용합니다.

응답 언어를 바꿔도 Role 문서와 후보자에게 보낼 연락을 자동으로 번역하지는 않습니다.

## Slack에서 사용하기 <!-- id: slack -->

Slack에서 Harper에게 역할 작성, 후보자 검토, 새 검색, 연락과 일정 조율을 요청할 수 있습니다. 연동과 개인 일정 같은 설정은 웹에서 준비합니다.

### 연결 방법 <!-- id: slack-connecting-slack -->

1. [Organization의 Integrations](#org-slack)에서 회사 Slack을 연결합니다. 설치 승인이 필요하면 Slack 관리자에게 요청합니다.
2. 실제 채용에 참여하는 팀원이 있는 알림 채널을 선택합니다.
3. Role Settings에서 해당 역할이 사용할 채널과 담당자를 확인합니다.

비공개 채널은 Harper를 먼저 초대한 뒤 추가합니다.

```example
채널에서 입력

/invite @Harper
```

```callout
채널 선택

후보자 정보가 전달되므로 실제 채용에 참여하는 팀원만 있는 채널을 권합니다. 역할마다 담당 팀이 다르면 여러 채널을 연결할 수 있습니다.
```

### 대화를 이어가기 <!-- id: slack-continuing-a-conversation -->

새 요청에는 **@Harper**를 붙입니다. 후보자 알림 아래 답글로 물으면 해당 후보자와 역할의 맥락에서 이어갈 수 있습니다. 여러 후보자나 역할이 섞였다면 이름을 함께 적으세요.

```example
Slack 요청 예시

@Harper 이 역할에 먼저 Intro를 요청할 만한 후보자를 찾아줘.
@Harper 백엔드 역할의 최근 검색 이력을 알려줘.
@Harper 이 후보자에게 최근 경력이 포함된 이력서를 요청해줘.
```

```action
Slack 연결하기
org:slack
```

## 역할 등록하기 <!-- id: create-a-role -->

공고 링크·파일을 주거나 채용 배경과 찾는 사람을 몇 문장으로 설명하면 됩니다. 웹에서는 **New role**, Slack에서는 Harper에게 새 역할 작성을 요청하세요.

### 어떤 정보를 알려주면 되나요? <!-- id: create-a-role-what-to-share -->

- **회사와 팀:** 이번 채용이 필요한 이유와 팀 상황
- **맡길 일:** 풀 문제, 책임 범위와 기대 결과
- **경험:** 필수·선호 경험과 진행하기 어려운 조건
- **근무 조건:** 지역·출근 방식, 고용 형태, 보상 범위, 비자·언어와 합류 시점

```quote
입력 예시

“첫 데이터 엔지니어를 찾고 있어. 데이터 파이프라인 구축을 주도한 경험과 Python·SQL이 필요해. 서울 하이브리드이고, 좋은 후보자에게는 보상을 유연하게 논의할 수 있어.”
```

확정되지 않은 조건은 열린 내용으로 알려 주세요. **필수**와 **있으면 좋은 조건**을 구분하면 Harper가 기준을 더 정확하게 정리할 수 있습니다.

### Description과 Hiring Brief <!-- id: create-a-role-description-and-hiring-brief -->

**Description**은 후보자에게 설명할 업무·팀·근무 조건입니다. **Hiring Brief**는 회사가 인터뷰할 사람을 판단하는 내부 기준입니다. 새 역할의 기본 작성물은 이 두 문서이며, **Evaluation Criteria**는 별도 평가 기준이 필요한 경우 정리합니다.

한 문서를 수정했다고 다른 문서를 모두 자동으로 다시 쓰지는 않습니다. 후보자가 알아야 할 사실과 내부 기준이 달라졌다면 필요한 범위를 함께 확인하세요.

### 예시 프로필과 참고 인물 <!-- id: create-a-role-example-profiles-and-reference-people -->

원하는 수준을 설명하기 어렵다면 참고 인물의 **LinkedIn·GitHub·소개 자료**와 중요한 강점을 알려 주세요. Harper는 그 사람을 곧바로 후보자로 판단하지 않고 수준과 강점을 역할 기준에 반영합니다.

Harper가 준비한 예시 프로필에는 좋은 점과 아쉬운 점의 이유를 남깁니다. 예시는 채용 기준을 맞추기 위한 자료이며 실제 후보자에게 연락했다는 뜻은 아닙니다. 평가 이유가 없으면 새로운 필수 조건을 추정하지 않습니다.

### 등록 전과 수정 후 <!-- id: create-a-role-before-registering-and-after-editing -->

등록 전에는 공개 설명, 필수·선호 기준, 주 담당자와 Slack 알림 채널을 확인하세요. 이후 역할 대화에 무엇이 달라졌는지와 이유를 말하면 수정안을 검토할 수 있습니다.

```example
역할 대화 예시

핀테크 경험은 이제 필수가 아니라 선호야. Hiring Brief 수정안을 보여줘.
이 예시 프로필은 직접 제품을 출시한 범위가 좋아. 같은 수준의 책임을 중요하게 봐줘.
```

이미 소개된 후보자는 이전 기준으로 검토됐을 수 있습니다. 기준을 크게 바꿨다면 기존 후보자도 새 기준으로 다시 확인하세요.

```action
새 역할 등록하기
org:newRole
```

## 후보자 검색 관리 <!-- id: candidate-search -->

정기 검색 설정, 지금 새 후보를 찾는 요청, 기존 후보 조회는 서로 다른 일입니다.

### 정기 검색 설정 <!-- id: candidate-search-recurring-search-settings -->

Role Settings의 **추천 후보 검색**에서 켜기·끄기와 검색 요일·시각을 정합니다. 새 Role은 기본으로 켜져 있고, 한국 시간 월·수·금 오전 9시를 사용합니다. 기존 Role은 저장된 설정을 따릅니다.

이 설정은 회사가 먼저 검토할 후보의 정기 검색을 관리합니다. 꺼도 직접 검색 요청은 가능하며, 슬롯이나 기존 계약에서 허용되는 후보자 선추천을 모두 끄지는 않습니다. 설정을 바꿔도 이미 시작한 검색과 전달된 제안이 취소되지는 않습니다.

### Run Search <!-- id: candidate-search-run-search -->

역할 대화의 **Run Search**를 사용하거나 Harper에게 현재 저장된 Hiring Brief로 새 후보를 찾아 달라고 요청하세요. 정기 예약을 기다리지 않고 회사가 먼저 Intro를 요청할 만한 후보를 탐색합니다.

검색 요청만으로 후보자에게 회사 제안을 보내지는 않습니다. 회사가 결과를 검토하고 **Intro 요청**을 확정한 뒤 실제 연락이 시작됩니다. 적합한 후보가 없다면 결과가 0명일 수 있습니다.

### 검색 이력과 한도 <!-- id: candidate-search-search-history-and-limits -->

Harper에게 최근 검색이 언제 있었고 몇 명을 검토했는지 물어보세요. 더 오래된 기록도 요청할 수 있습니다. 선정 집계는 실제 발송·열람·수락 인원이 아니며 기록이 없는 수치는 0으로 단정하지 않습니다.

해당 역할의 검토 한도에 도달하면 새 후보자에게 먼저 추천하는 일부 탐색이 제한됩니다. 기존 연결 대기 후보자를 결정해 대기가 줄면 제한이 풀릴 수 있습니다. 먼저 제안 가능한 후보 검색까지 모두 중단되는 것은 아닙니다.

## 추천 검토하기 <!-- id: review-recommendations -->

먼저 제안 가능한 후보는 회사의 제안 여부를, 연결 대기는 회사의 연결 여부를 결정하는 목록입니다. 현재 상태와 후보자의 확인된 의사를 함께 읽으세요.

### 프로필에서 볼 것 <!-- id: review-recommendations-what-to-review -->

- **TL;DR:** 확인된 경력, 실제 기여와 책임 범위의 짧은 요약
- **Harper Note:** 공유 가능한 다음 업무·책임·근무 조건·합류 시점의 맥락
- **적합성과 기준별 평가:** 저장된 Role 기준과 맞는 경험, 아직 확인할 부분
- **자료와 기록:** 현재 회사에 공유된 이력서, 연락과 진행 내역

평가는 검토를 돕는 근거이며 지원·수락이나 채용 성공을 보장하지 않습니다. 회사 이름보다 실제로 맡았던 문제와 책임을 보고, 없는 정보는 확인할 질문으로 남기세요.

### 공개 범위와 추가 확인 <!-- id: review-recommendations-sharing-scope-and-additional-questions -->

먼저 제안 가능한 후보와 수락 전 Intro Requested에서는 제한된 프로필만 볼 수 있습니다. 추가 연락이 가능해도 비공개 이력서나 연락처가 자동으로 공개되지는 않습니다. 현재·희망 보상 수치와 다른 회사와의 대화 내역도 공개하지 않습니다.

결정에 중요한 정보가 빠졌다면 [Harper에게 후보자 확인](#ask-harper)을 요청하세요. 연결 대기 후보자는 회사의 답을 기다립니다. 팀 안에서 검토 담당자와 최종 결정자를 정해 두면 좋습니다.

```action
후보자 확인하기
org:inbox
```

## 제안과 연결 결정 <!-- id: accept-or-decline -->

**Intro 요청**, **Pass**, **Connect**, **Reject**는 후보자에게 미치는 효과가 다릅니다.

### Intro 요청과 Pass <!-- id: accept-or-decline-intro-request-and-pass -->

Intro 요청에는 **만나보고 싶은 이유**와 **수락 후 소개 이메일을 받을 팀원**이 필요합니다. 최종 내용을 확인해 요청을 확정하면 Harper가 회사와 역할을 소개합니다. 후보자가 수락하면 소개 이메일로 연결하며 회사의 추가 연결 승인을 기다리지 않습니다. 별도 전형 단계 설정은 필수가 아닙니다.

Pass는 제안을 제외하는 결정입니다. 후보자에게 연락하거나 알림을 보내지 않습니다.

### 연결 대기의 Connect <!-- id: accept-or-decline-connect-in-ready-to-connect -->

기본 방식인 **Email intro**는 후보자에게 소개 이메일을 보내고 선택한 팀원을 CC에 넣습니다. 팀원이 목록에 없다면 Owner가 먼저 [초대](#org-members)해야 합니다. 이메일을 받은 팀원은 전체 답장으로 인사하고 다음 순서를 안내하세요.

**Direct contact**를 선택하면 소개 이메일은 발송되지 않고 회사가 직접 첫 연락과 일정 조율을 진행합니다. 연결 수락만으로 인터뷰 일정이 확정되지는 않습니다.

### 연결 대기의 Reject <!-- id: accept-or-decline-reject-in-ready-to-connect -->

Reject는 보류가 아니라 이번 Role의 진행을 끝내는 결정입니다. 소개 이메일은 발송되지 않고 종료 결정이 후보자에게 표시되고 Harper가 이를 안내합니다. 이미 후보자에게 보이거나 전달된 안내는 회수할 수 없습니다.

정보가 부족하면 거절하기 전에 [질문이나 자료 요청](#ask-harper)을 맡길 수 있습니다.

```callout
판단 이유

Connection note와 Reject reason은 선택 사항이며 후보자에게 그대로 보내지지 않습니다. 다음 추천에 참고할 수 있도록 실제 판단 이유를 남겨 주세요.
```

## 후보자와의 소통 <!-- id: ask-harper -->

연결 대기에서 결정하기 전이나 연결 후 진행 중에 질문·자료 요청·정보 전달을 `/org` 대화와 Slack에서 맡길 수 있습니다. Intro Requested도 제안이 전달되어 후보자 답변을 기다리는 중이면 추가 연락이 가능합니다.

### 요청할 내용 <!-- id: ask-harper-what-to-request -->

**누구에게, 어느 Role의 어떤 판단을 위해 무엇을 확인할지** 알려 주세요. 경력의 실제 범위, 근무 가능 여부, 최신 이력서 등을 요청할 수 있습니다. 보상처럼 후보자가 공유 범위를 정해야 하는 정보는 새로 허락된 답변을 받아야 합니다.

```example
연락 요청 예시

이 후보자가 결제 장애 대응을 직접 주도했는지, 당시 책임 범위를 물어봐줘.
이미 보낸 제안에 서울 주 2회 근무 조건도 전달해줘.
최근 경력이 포함된 이력서를 받을 수 있는지 물어봐줘.
```

### 바로 전달하는 연락과 검토용 초안 <!-- id: ask-harper-direct-messages-and-reviewed-drafts -->

대상과 목적·내용이 명확한 일상적인 연락은 바로 전달할 수 있습니다. 첫 연락이나 회사의 인상·제안 내용이 중요한 순간에는 초안을 먼저 확인합니다. 초안을 만들거나 수정한 것만으로 발송되지는 않습니다.

표시된 최종 문구를 확인해 발송을 승인하면 일반적으로 짧은 대기 시간 뒤 전달합니다. **지금 보내 달라는 명확한 요청**은 즉시 전달할 수 있습니다. 대기 중인 연락은 취소 가능한 상태에서만 취소할 수 있으며 이미 전달된 연락은 회수되지 않습니다.

### 답변과 후속 연락 <!-- id: ask-harper-replies-and-follow-ups -->

답변이 오면 요청을 시작한 `/org` 대화나 Slack 스레드에서 알려줍니다. 후보자는 답변·자료 공유 범위를 직접 정하며 응답하지 않거나 거절할 수도 있습니다.

답변이나 자료 제출을 요청했고 요청이 여전히 유효하면 최초 전달 후 최소 3일 뒤 후속 확인 이메일을 한 번 보낼 수 있습니다. 단순 정보 전달이 모두 후속 확인 대상이 되는 것은 아닙니다. 추가 연락을 요청할 때는 최근 연락 내역도 함께 확인합니다.

추가 연락은 후보자의 수락·연결이나 회사의 채용 결정을 대신하지 않습니다.

## Pipeline과 일정 관리 <!-- id: pipeline -->

연결이 완료된 후보자는 **Pipeline**에서 첫 대화부터 최종 결정까지 관리합니다.

### 진행 상태와 연락 <!-- id: pipeline-process-records-and-correspondence -->

전형에 맞는 단계를 구성하고 실제 진행에 맞춰 후보자를 이동합니다. 메모에는 확인한 사실, 남은 질문과 다음 담당자를 적으세요. Pipeline의 단계만 옮겨서는 일정 요청이 발송되지 않으며 후보자에게 이메일이나 Harper 메시지도 가지 않습니다.

다음 전형 안내가 필요하면 Harper에게 연락을 요청하거나 회사가 직접 전달합니다. 기존 미팅의 확인과 새 일정 요청의 전달 여부도 따로 확인해야 합니다.

### 면접 일정 조율하기 <!-- id: pipeline-coordinating-interviews -->

일정 담당자가 [Settings의 일정 저장](#org-calendar)에서 Google Calendar를 연결하고 가능한 시간을 설정합니다. Harper는 이미 바쁜 시간을 제외한 선택지를 후보자에게 보내고, 후보자가 시간을 고르면 Calendar 초대와 Google Meet 링크를 함께 전달합니다.

대상 후보자, Role과 대화 목적을 알려 주세요. 후보자가 아직 회사의 제안을 수락하지 않았다면 먼저 수락이 필요합니다. 가능 시간을 설정했다고 기존 일정이 자동으로 바뀌지는 않습니다.

### Role 중단과 종료 <!-- id: pipeline-pausing-and-ending-a-role -->

**중단**은 새 추천을 잠시 멈추며 기존 후보자는 계속 검토할 수 있습니다. **종료**는 새 추천을 멈추고 Role을 끝냅니다. 종료와 동시에 모든 안내가 발송되는 것은 아니지만 유예 기간 뒤 수락 후 진행 중인 후보자에게 종료를 안내하고 진행을 끝냅니다. 최종 오퍼 단계는 이 자동 종료에서 제외합니다.

후보자 한 명의 진행 종료와 Role 전체의 종료는 별개입니다. 이미 발송된 이메일은 없어지지 않으므로 대화 중이거나 일정이 잡혔다면 회사 담당자도 직접 안내하세요.

```action
전체 Pipeline 열기
org:pipeline
```

## 슬롯과 Intro <!-- id: slots-and-credits -->

Intro는 소개 요청이나 연결 수락에 사용하는 단위입니다. `Intro 요청`은 행동 이름이며, 남은 Intro는 완료된 소개 건수가 아니라 앞으로 사용할 수 있는 수량입니다.

Role 수, 유료 기능 이용 범위, Intro 잔액은 서로 다른 기준입니다. 회사의 기존 계약이 있다면 합의한 조건을 따릅니다.

### 표준 이용 범위 <!-- id: slots-and-credits-standard-access -->

| 구분 | Role 수 | Intro와 기능 |
| --- | --- | --- |
| Free | 무제한 | 모든 Role이 함께 쓰는 월 10 공용 Intro |
| 슬롯 | Role 수는 계속 무제한 | 배정한 Role에 유료 기능과 월 50 Intro 추가. 공용 10 Intro는 별도로 유지 |
| Enterprise·기존 계약 | 합의한 조건 | 회사별 계약을 확인 |

연결 대기는 해당 Role의 슬롯 또는 기존 계약의 권한이 필요합니다. 공용 Intro가 남아 있다고 연결 대기가 열리지는 않습니다. Free와 표준 슬롯 구독에는 채용 성공보수가 없습니다.

### 차감과 갱신 <!-- id: slots-and-credits-spending-and-renewal -->

표준 요금에서는 **Intro 요청 확정**과 **연결 대기의 Connect**에 각각 1 Intro를 사용합니다. Role의 슬롯 Intro를 먼저 쓰고 부족하면 공용 Intro를 사용합니다. 다른 Role의 슬롯 Intro를 가져오지는 않습니다.

Intro는 월 단위로 갱신되며 남은 Intro는 이월되지 않습니다. 연간 결제도 Intro 갱신은 월 단위입니다. Intro 소진이 Role 생성과 채용 시작 자체를 막지는 않습니다.

### 배정과 이용 종료 <!-- id: slots-and-credits-assignment-and-access-expiry -->

슬롯 만료는 Role을 자동 중단하지 않습니다. 해당 슬롯의 유료 기능은 종료되지만 Role은 Free 기능과 공용 Intro 범위에서 계속 진행할 수 있습니다. 슬롯을 다른 Role에 배정할 때는 기존 Role의 이용 범위도 확인하세요.

```callout
현재 결제 이용 범위

새 회사의 직접 가입과 일반 회사의 셀프서비스 결제는 일시 중단되어 있습니다. Slots·Billing 메뉴가 제공되는 Workspace에서는 배정·구독·결제 내역을 확인할 수 있습니다. 메뉴가 없거나 현재 계약이 궁금하면 문의하기로 Harper 팀에 확인하세요. 공개 상품 설명만으로 회사의 실제 계약이나 잔액을 판단하지 않습니다.
```

## 외부 공고와 회사명 공개 <!-- id: public-job-visibility -->

Role Settings에서 **외부 공고 노출**과 **회사명 공개 여부**를 관리합니다. 후보자에게 설명할 Description도 함께 확인하세요.

### 외부 공고 노출 <!-- id: public-job-visibility-external-job-visibility -->

설정을 켜면 Harper가 LinkedIn 등 외부에 역할을 소개할 수 있습니다. 설정을 켰다는 사실만으로 공고가 바로 게시됐다고 판단하지 않습니다. 꺼도 내부 Role을 삭제하거나 채용을 중단하는 것은 아닙니다.

### 회사명 비공개 <!-- id: public-job-visibility-hiding-the-company-name -->

회사명을 비공개로 설정할 수 있습니다. 공개 Description에 회사가 드러나는 표현이 있으면 내용도 함께 검토하세요.

```callout
이미 게시된 공고

회사명 공개 여부나 외부 노출 설정을 바꿔도 기존 외부 공고가 자동으로 모두 수정되지는 않습니다. 이미 게시된 공고의 변경이 필요하면 Harper 팀에 대상 공고를 알려 주세요.
```
