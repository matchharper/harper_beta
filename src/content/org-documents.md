# Documents   <!-- id: documents -->

Harper를 처음 사용한다면 **Harper 소개 → 시작하기 → Slack → 역할 등록** 순서로 읽어 보세요.

## Harper 소개 <!-- id: harper-introduction -->

Harper는 검색 조건에 맞는 이력서를 많이 모아 보내는 서비스가 아닙니다. 채용을 잘 아는 동료에게 설명하듯 현재 팀의 상황과 찾는 사람을 알려 주고, 추천이 왔을 때 만나볼지 결정하면 됩니다.
후보자를 찾고, 부족한 정보를 확인하고, 연결을 위한 연락을 준비하는 중간 과정은 Harper가 함께 맡습니다.

### Harper가 후보자를 소개하는 방식

Harper는 크게 두가지 방식으로 인재와 회사를 연결합니다.

1. `연결 대기` : 후보자에게 먼저 역할을 추천하고 실제로 이 회사와 대화해 보고 싶다는 의사를 확인한 사람들입니다. **실제로 대화를 시작할 준비가 된 후보자를 신중하게 소개하는 방식**입니다. 연결 대기에 후보자가 도착했다면 처음부터 회사를 설명하고 관심을 묻는 단계는 이미 지나 있습니다. 회사는 검색 결과를 일일이 거르는 대신, 추천 이유와 자료를 읽고 실제로 만나볼 사람을 결정하는 데 집중할 수 있습니다.

2. `먼저 제안 가능한 후보` : 회사에게 먼저 후보자를 추천합니다. 회사는 원하는 후보자를 선택해 Harper를 통해 intro 요청을 보낼 수 있습니다. 조금 **더 다양하고 많은 후보자를 소개합니다.** 후보자가 수락시 바로 연결해드립니다.

### 피드백이 다음 제안을 바꿉니다

추천을 수락했거나 거절했다면, 가능할 때 판단 이유를 한두 문장 남겨 주세요. 예를 들어 "이력은 좋지만 연차가 부족해요"처럼 적으면 됩니다. Harper가 회사의 기준을 더 정확히 이해하고 다음 탐색과 제안에 반영할 수 있습니다. 거절 이유는 후보자에게 전달되지 않습니다.

### 자세한 설명

| 구분 | 먼저 제안 가능한 후보 | 연결 대기 |
| --- | --- | --- |
| 후보자에게 역할을 추천했나요? | 아직 추천하지 않았습니다 | 이미 추천했고 후보자가 수락했습니다 |
| 회사는 무엇을 결정하나요? | 먼저 제안할지, 제안하지 않을지 선택합니다 | 인터뷰 등 다음 과정을 시작하도록 연결할지 결정합니다 |
| 다음에는 어떻게 되나요? | Intro를 요청하면 Harper가 대신 후보자에게 회사를 소개하고 만나볼지 물어봅니다. | 회사가 연결을 수락하면 소개 이메일로 연결합니다 |

### 먼저 제안 가능한 후보의 뜻

**먼저 제안 가능한 후보**는 Harper가 회사에 먼저 연락해볼 수 있게 추천하는 후보입니다. 해당 역할에 대한 후보자의 관심은 아직 확인되지 않았습니다.

**Request Intro**를 Harper가 대신 후보자에게 회사를 소개하고 만나볼지 물어봅니다. 후보자가 수락하면 바로 이메일을 통해 연결합니다. **Pass**를 선택하면 제외합니다.

제안을 요청한 후보는 **Intro Requested**로 이동합니다. 이 단계의 후보자에게는 추가 질문이나 인터뷰 요청을 할 수 없습니다.
### 연결 대기의 뜻

**연결 대기**는 후보자가 회사와 역할을 듣고 대화할 의사를 밝힌 상태입니다. 후보자는 회사의 결정을 기다립니다. 회사는 추천 이유와 자료를 검토한 뒤 **Connect**로 연결하거나 **Reject**로 이번 역할의 진행을 끝냅니다. 중요한 정보가 빠졌다면 결정 전에 Harper에게 확인을 요청할 수 있습니다.

```callout
회사가 검토할 차례입니다

Reject는 보류가 아닙니다. 회사가 더 진행하지 않기로 했다는 결정이 후보자에게 안내되며, 이미 전달된 안내는 회수할 수 없습니다.
```

## 시작하기 <!-- id: getting-started -->

처음에는 **회사 정보, 함께 결정할 팀원, Slack 채널, 찾는 역할**을 준비하세요. 완성된 채용 공고는 없어도 됩니다.

### 처음 설정할 것

1. **회사 정보 확인.** [회사 정보](#org-company)에 후보자에게 설명할 팀의 현황과 일하는 방식을 적습니다.
2. **팀원 초대.** 후보자를 검토하고 소개 이메일을 받을 사람을 [팀원으로 초대](#org-members)합니다.
3. **Slack 연결.** [Slack](#org-slack)에서 알림을 받을 채널을 선택합니다. 실제 채용에 참여하는 팀원이 있는 채널을 고르세요.
4. **역할 등록.** [첫 역할을 등록](#org-newRole)하며 맡길 일, 필수 경험과 근무 조건을 알려줍니다.

### 역할을 등록한 다음

역할 등록 후 Harper가 후보자를 찾기 시작합니다. **먼저 제안 가능한 후보**는 역할 화면에서 검토해 Intro를 요청할 수 있습니다. 후보자가 먼저 역할을 수락하고 Harper가 소개를 준비해 전달한 **연결 대기** 후보자는 Slack과 [Inbox](#org-inbox)에서 확인하고 연결 여부를 결정하세요.

```action
첫 역할 등록하기
org:newRole
```

## Slack에서 사용하기 <!-- id: slack -->

Slack에서 Harper의 모든 기능을 사용할 수 있습니다.

### 연결 방법

1. [Organization의 Integrations](#org-slack)으로 이동합니다.
2. **회사 Slack 선택.** Slack 연결을 누르고 회사에서 사용하는 Slack을 선택합니다. 설치 승인이 필요하면 Slack 관리자에게 요청합니다.
3. **알림 채널 추가.** 후보자를 실제로 검토하고 결정할 사람들이 있는 채널을 고릅니다.
- **비공개 채널의 경우** 아래 명령으로 Harper를 먼저 초대한 뒤 채널을 추가합니다.

```example
채널에서 입력

/invite @Harper
```

```callout
채널 선택

역할마다 담당 팀이 다르면 여러 채널을 연결할 수 있습니다. 후보자 개인 정보가 올라오므로 **실제 채용에 참여하는 사람만 있는 채널**을 권합니다.
```

### 후보자가 도착하면

**연결 수락** 또는 **연결 거절**을 선택합니다. 연결 거절은 임시 보류가 아니며 후보자에게 회사의 종료 결정이 안내됩니다. 자세한 차이는 [연결 수락과 연결 거절](#accept-or-decline)에 정리했습니다.

### Slack에서 검토를 이어가기

새 질문이나 요청에는 **@Harper**를 붙입니다. 후보자 알림 아래에서는 답글로 이어서 물어보면 해당 후보자와 역할의 맥락을 함께 볼 수 있습니다. 여러 역할이나 후보자가 섞여 있다면 대상의 이름을 함께 적어 주세요. 역할의 우선순위가 바뀌었거나 비교 기준을 다시 잡고 싶을 때도, Harper에게 채용 동료에게 이야기하듯 알려 주면 됩니다.

```example
Slack 요청 예시

@Harper 지금 먼저 봐야 할 후보자가 누구야?
@Harper 백엔드 역할의 연결 대기 후보자를 비교해줘.
@Harper 이 역할은 시스템 설계 경험을 더 중요하게 봐줘.
```

```callout
후보자에게 질문하거나 자료를 요청할 때

후보자에게 처음 연락하거나 중요한 제안을 할 때는 Harper가 보낼 초안을 먼저 보여줍니다. 회사가 확인하고 보내 달라고 답하면 전달합니다. 일상적인 확인이나 후속 연락은 바로 전달될 수 있습니다.
```

```action
Slack 연결하기
org:slack
```

## 역할 등록하기 <!-- id: create-a-role -->

공고 링크·파일을 주거나, 채용 배경과 찾는 사람을 몇 문장으로 설명하면 됩니다. 완성된 JD가 없어도 역할을 만들 수 있습니다.

### 공고가 있을 때와 없을 때

- **공고가 있다면** 링크나 파일을 전달하고, 공고에 없는 실제 우선순위나 제약을 덧붙여 주세요.
- **공고가 없다면** 왜 뽑는지, 어떤 일을 맡길지, 어떤 경험이 필요한지 말해 주세요. 확정되지 않은 조건은 그대로 알려주면 됩니다.

### 무엇을 알려주면 되나요?

처음부터 모든 조건을 채울 필요는 없습니다. 다음 네 가지를 아는 범위에서 알려 주세요.

```quote
입력 예시

“시리즈 A B2B SaaS 팀의 첫 데이터 엔지니어를 찾고 있어. 데이터 파이프라인 구축을 주도할 4년 이상 경력자가 필요하고 Python·SQL은 필수야. 서울 하이브리드이고, 보상은 8천만~1억 원 범위에서 좋은 후보자에게 유연하게 열어둘 수 있어.”
```

기술 이름이나 연차뿐 아니라 **그 경험이 필요한 이유와 맡길 일**을 설명해 주세요.

- **회사와 팀.** 팀의 상황과 이번 채용이 필요한 이유
- **맡길 일.** 입사 후 풀 문제, 책임 범위와 기대 결과
- **경험.** 필수 경험과 선호 경험, 진행하기 어려운 조건
- **근무 조건.** 지역·출근 방식, 고용 형태, 보상 범위, 비자·언어와 채용 일정

원하는 수준을 설명하기 어렵다면 참고할 사람의 LinkedIn·GitHub·소개 자료와 **어떤 점을 기준으로 삼을지** 알려 주세요. Harper는 그 사람을 곧바로 후보자로 판단하지 않습니다.

```callout
필수와 선호를 나누세요

**“있으면 좋다”**와 **“없으면 진행하기 어렵다”**를 구분해 주세요. 빠진 내용은 Harper가 이어서 묻습니다.
```

### Harper가 정리하는 내용

- **후보자에게 보여줄 역할 설명:** 맡길 일, 회사·팀 정보와 근무 조건
- **Harper가 매칭에 사용할 기준:** 필수·선호 경험, 진행하기 어려운 조건과 확인이 필요한 부분

후보자가 기회를 판단하는 데 필요한 업무와 근무 조건은 역할 설명에 정확히 담아야 합니다. 내부 판단 기준과 다른 내용이 있다면 등록 전에 바로잡아 주세요.

```callout
Harper가 다시 묻는 경우

빠진 조건이 있거나 공고와 대화 내용이 다르면 다시 확인합니다. 예를 들어 원격 근무와 주 2회 출근 중 현재 기준이 무엇인지 묻습니다.
```

### 등록하기 전에 확인할 것

- **역할 설명.** 후보자에게 보여도 되는 이름과 내용인지 확인합니다.
- **우선순위.** 필수 조건과 선호 조건이 구분되어 있는지 봅니다.
- **담당자.** 후보자를 검토하고 소개 메일을 받을 팀원을 정합니다.
- **알림.** 새 후보자 알림을 받을 Slack 채널을 선택합니다.

### 등록한 뒤 기준을 바꾸려면

역할 대화에 **무엇이 달라졌는지와 그 이유**를 말해 주세요. 우선순위, 경력, 보상, 근무 방식도 바꿀 수 있습니다.

```example
역할 대화 예시

시니어보다 직접 만드는 사람을 우선해줘.
핀테크 경험은 이제 필수가 아니야.
```

```callout
기준을 크게 바꿨다면

이미 연결 대기에 있는 후보자는 이전 기준으로 소개됐을 수 있습니다. 새 기준에서도 만나볼 사람인지 다시 확인하세요.
```

회사 전반의 내용은 [회사 정보](#org-company)에서, 특정 역할의 기준은 역할 대화에서 바꿉니다. 새 추천을 잠시 멈추려면 **중단**, 채용을 끝내려면 **종료**를 선택하세요. 중단해도 이미 검토 중인 후보자는 남습니다. 종료 전에는 Inbox와 Pipeline의 진행도 정리해 주세요.

```action
새 역할 등록하기
org:newRole
```

## 추천 검토하기 <!-- id: review-recommendations -->

연결 대기에는 Harper가 회사와 역할을 설명하고 대화 의사를 확인한 후보자가 들어옵니다. 후보자는 회사의 결정을 기다리므로, 추천 이유와 자료를 검토한 뒤 **연결 수락 또는 연결 거절**로 답해 주세요.

### 프로필에서 볼 것

- **추천 이유.** 역할과 이어지는 경험과 그 근거
- **실제로 맡았던 일.** 문제의 범위, 본인의 책임과 결과
- **확인되지 않은 내용.** 다음 대화에서 확인할 부분
- **이력서와 진행 기록.** 최근 경력과 지금까지 공유된 자료

회사 이름이나 기술 이름보다 **어떤 문제를 맡았고 어디까지 책임졌는지**를 보세요. 분명하지 않은 내용은 사실로 단정하지 말고 확인할 질문으로 남깁니다.

### 결정 전에 더 확인하고 싶다면

결정에 필요한 정보가 빠졌다면 [Harper를 통해 질문하거나 자료를 요청](#ask-harper)하세요.

```example
Slack 요청 예시

@Harper 이 후보자가 결제 장애 대응을 직접 주도했는지, 당시 맡은 범위를 물어봐줘.
@Harper 최근 경력이 포함된 이력서를 받을 수 있는지 물어봐줘.
```

### 결정이 오래 미뤄지지 않도록

팀 안에서 검토할 사람과 최종 결정할 사람을 정해 두세요. 모든 역할의 대기 항목은 [Inbox](#org-inbox)에서 볼 수 있습니다. 수락하거나 거절한 이유를 짧게 남기면 다음 추천에 반영할 수 있습니다.

```callout
연결 대기가 검토 한도에 도달하면
```

## 추천 결정하기 <!-- id: accept-or-decline -->

**연결 수락(Connect)**은 후보자와 직접 대화를 시작할 때, **연결 거절(Reject)**은 이번 역할에서 더 진행하지 않을 때 선택합니다.

### 선택하기 전에

- **만나볼 근거.** 대화로 확인할 가치가 있는 강점이 있는지 봅니다.
- **첫 담당자.** Email intro를 선택한다면 첫 인사와 일정 조율을 맡을 팀원을 정합니다.
- **판단 이유.** Connection note와 거절 이유는 선택 사항이며 후보자에게 그대로 전달되지 않습니다. 다음 추천에 참고할 기준을 짧게 남겨 주세요.

### 연결 수락

기본 방식인 **Email intro**에서는 소개 이메일을 받을 팀원을 선택합니다. 목록에 없다면 먼저 [팀원으로 초대](#org-members)하세요. 대상과 방식을 확인하면 Harper가 후보자에게 이메일을 보내고 선택한 팀원을 참조에 넣습니다. 팀원은 전체 답장으로 첫 인사와 다음 순서를 안내하세요. 연결 수락만으로 인터뷰 일정이 확정되지는 않습니다.

**Direct contact**를 선택하면 소개 이메일은 발송되지 않습니다. 회사가 후보자에게 직접 첫 연락과 일정 조율을 진행해야 합니다.

### 연결 거절

- 이번 역할의 검토와 연결이 끝납니다. 소개 이메일은 발송되지 않습니다.
- 후보자에게 회사의 종료 결정이 안내됩니다. 이미 전달된 안내는 상태를 다시 열어도 회수할 수 없습니다.
- 정보가 부족하다면 거절 전에 [Harper에게 질문이나 자료 요청](#ask-harper)을 맡길 수 있습니다.

```callout
연결 거절 이유

Reject reason은 선택 사항이며 후보자에게 그대로 보내지지 않습니다. **“이번에는 결제 경험을 우선함”**처럼 실제 판단 기준을 남겨 주세요.
```

### 연결한 뒤 진행을 끝낼 때

연결 후 진행을 종료하면 Harper가 후보자에게 안내합니다. 이미 발송된 이메일이나 연락은 없어지지 않습니다. 대화 중이거나 일정이 잡혔다면 회사 담당자도 후보자에게 직접 알려 주세요. [Pipeline](#org-pipeline)도 최종 결과에 맞게 정리합니다.

```action
후보자 검토하기
org:inbox
```

## 후보자와의 소통 <!-- id: ask-harper -->

연결 여부를 결정하기 전이나 연결 후 채용을 진행하는 동안, 필요한 질문과 자료 요청을 `/org` 대화나 Slack에서 Harper에게 맡길 수 있습니다.

**누구에게, 어떤 역할의 어느 판단을 위해 무엇을 확인할지** 알려 주세요. Harper가 그 맥락을 담아 후보자에게 연락하고, 답변이 오면 요청을 시작한 대화에서 알려줍니다.

### 어떤 내용을 확인할 수 있나요?

- **경험의 실제 범위.** 프로젝트에서 직접 맡은 일과 책임
- **역할의 필수 조건.** 기술·도메인·근무 방식에 관한 최신 경험이나 의사
- **최신 자료.** 최근 경력이 포함된 이력서 등 판단에 필요한 자료
- **후보자가 정할 정보.** 보상처럼 후보자의 허락과 공유 범위 확인이 필요한 내용

현재 결정에 필요한 내용부터 구체적으로 물어보세요.

```example
Slack 요청 예시

@Harper 이 후보자가 결제 장애 대응을 직접 주도했는지, 당시 맡은 범위를 물어봐줘. 연결을 수락하기 전에 책임 범위를 확인하고 싶어.
@Harper 서울 주 2회 근무가 가능한지 확인해줘. 이 역할의 필수 조건이야.
@Harper 최근 경력이 포함된 이력서를 받을 수 있는지 물어봐줘.
```

### 후보자에게 전달할 때

Harper는 연락의 성격에 따라 바로 전달하거나 회사가 검토할 초안을 먼저 보여줍니다. 후보자에게 **처음 연락하거나 중요한 제안을 하는 경우**에는 초안을 확인하고 보내 달라고 명시적으로 답해 주세요. 일상적인 확인과 후속 연락은 바로 전달될 수 있습니다.

### 답변이 오면

후보자가 답하면 요청을 시작한 `/org` 대화나 Slack 스레드에서 알려줍니다. 확인된 내용과 아직 모르는 부분을 구분해 연결 여부나 다음 진행을 결정하세요.

후보자는 답변과 공유 범위를 직접 정하며, 답하기 어렵다고 하거나 응답하지 않을 수도 있습니다. 답변이 없고 요청이 여전히 유효하면 최초 전달 후 최소 3일 뒤 Harper가 후속 확인 이메일을 한 번 보냅니다. 그 뒤에도 답변이 없다면 기다릴지 현재 자료로 결정할지 팀에서 정하세요.

## Pipeline 관리하기 <!-- id: pipeline -->

연결을 수락한 후보자는 **Pipeline**에서 첫 대화부터 최종 결정까지 관리합니다.

### Pipeline에 들어오는 시점

**Inbox**에서는 회사 결정을 기다리는 후보자를, **Pipeline**에서는 연결 수락 후 진행 중인 후보자를 봅니다. Email intro를 선택했다면 소개 이메일에서 첫 인사와 일정을 조율하고, Direct contact를 선택했다면 회사가 직접 연락합니다.

### 후보자 진행 상태 관리하기

- **단계 준비.** 전화 대화, 인터뷰, 과제 등 회사 전형에 맞게 구성합니다.
- **단계 이동.** 실제 진행 단계에 맞춰 옮깁니다. 단계 이동만으로 후보자에게 연락이 발송되지는 않습니다.
- **메모.** 확인한 사실, 남은 질문, 다음 담당자와 할 일을 남깁니다.
- **마무리.** 진행을 끝내면 결과에 맞게 종료하고, 별도 연락이 필요한 경우 후보자에게도 안내합니다.

### 면접 일정 조율하기

일정 담당자가 Google Calendar를 연결하고 가능한 시간을 설정하면, Harper가 바쁜 시간을 제외한 선택지를 후보자에게 보냅니다. 후보자가 시간을 고르면 회사 참석자와 후보자의 Calendar에 일정을 만들고 Google Meet 링크를 전달합니다. **단계 이동만으로 일정 요청이 발송되지는 않으므로** 일정 조율도 함께 요청해 주세요.

### 여러 역할을 함께 볼 때

[전체 Pipeline](#org-pipeline)에서는 모든 역할의 후보자를 함께 보거나 역할별로 좁혀볼 수 있습니다. 오래 머문 후보자부터 **다음 담당자와 예정된 일정**을 확인하세요.

```action
Pipeline 열기
org:pipeline
```
