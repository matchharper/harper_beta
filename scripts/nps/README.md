# 국민연금 가입 사업장 조회

국민연금공단이 공공데이터포털에 공개하는 사업장별 가입 현황을 조회하는 스크립트다. 제품 코드가 이 API를 직접 부르지는 않는다. 대신 추천이 많이 된 회사의 결과를 `sync.ts`로 미리 `company_datas`에 저장해 두면, 회사 정보를 읽는 기존 경로(LLM 입력, 채팅 회사 카드)가 그대로 읽는다.

- Open API: [국민연금공단_국민연금 가입 사업장 내역](https://www.data.go.kr/data/3046071/openapi.do) — 무료, 이용허락범위 제한 없음
- 월간 CSV: [같은 이름의 파일데이터](https://www.data.go.kr/data/15083277/fileData.do) — 공개 대상 사업장 전체가 매달 한 파일로 올라온다

## 준비

1. 팀 계정으로 data.go.kr에 로그인하고 Open API 페이지에서 **활용신청**을 누른다.
2. 마이페이지의 개발계정 상세에서 일반 인증키를 복사한다. Encoding 키와 Decoding 키 중 무엇을 넣어도 된다.
3. `harper_beta/.env.local`에 넣는다.

```
DATA_GO_KR_SERVICE_KEY=발급받은_키
```

승인 직후에는 키가 게이트웨이에 퍼지기까지 시간이 걸려 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 날 수 있다. 하루 호출 한도는 마이페이지에서 확인한다.

## 사용법

`harper_beta`에서 실행한다.

```bash
# 회사의 최근 12개월 가입자수·입사·퇴사·고지금액을 달별 표로 본다. --json이면 응답 그대로 출력한다.
node --env-file=.env.local --import tsx scripts/nps/cli.ts history "채널코퍼레이션"

# 사업장 검색 결과만 본다. 사업자등록번호 앞 6자리(--biz)와 시도 코드(--sido)로 좁힐 수 있다.
node --env-file=.env.local --import tsx scripts/nps/cli.ts search "채널코퍼레이션" --biz 144812

# seq 하나의 상세를 본다.
node --env-file=.env.local --import tsx scripts/nps/cli.ts detail 6719039
```

다른 스크립트에서는 `scripts/nps/client.ts`의 `readNpsWorkplaceHistory`, `searchNpsWorkplaces`, `readNpsWorkplaceDetail`, `readNpsWorkplaceMonth`를 가져다 쓴다.

### API가 실제로 동작하는 방식 (2026-11-23 확인)

- **seq는 달마다 다르다.** 사업장명으로 검색하면 같은 사업장이 최근 12개월 동안 달마다 한 줄씩, 각기 다른 seq로 나온다. 그 이전 달은 API로 볼 수 없다. 더 긴 추이는 월간 CSV를 모아야 한다.
- **기간별 현황은 그 달의 seq와 그 달(dataCrtYm)을 함께 넣어야 값이 나온다.** 다른 달을 넣으면 빈 결과가 온다. `history`는 검색된 줄마다 상세와 그 달 현황을 읽는다. 회사 하나에 1 + 12 × 2번쯤 호출한다.
- **결과가 없으면** 빈 객체 하나(`{}`)가 온다. 클라이언트는 이를 빈 목록으로 돌려준다.
- **키가 등록되지 않았으면** HTTP 403과 `OpenAPI_ServiceResponse.cmmMsgHeader`(`SERVICE_KEY_IS_NOT_REGISTERED_ERROR`, 사유 코드 30)가 온다.
- **업종은 비어 있을 수 있다.** 채널코퍼레이션은 업종명이 `BIZ_NO미존재사업장`, 업종코드가 `999999`로 나왔다.
- 브랜드명(예: 채널톡)으로는 찾을 수 없다. 법인 등기상의 이름으로 검색한다.

응답 필드:

| 오퍼레이션 | 필드 |
| --- | --- |
| 사업장 정보조회 `getBassInfoSearchV2` | `seq`, `dataCrtYm` 자료생성년월, `wkplNm` 사업장명, `bzowrRgstNo` 사업자등록번호(앞 6자리만, 나머지 `****`), `wkplRoadNmDtlAddr` 도로명 주소(번지 없이), `ldongAddrMgplDgCd`·`ldongAddrMgplSgguCd`·`ldongAddrMgplSgguEmdCd` 법정동 코드, `wkplJnngStcd` 가입상태(1 등록, 2 탈퇴), `wkplStylDvcd` 형태(1 법인, 2 개인) |
| 상세 정보조회 `getDetailInfoSearchV2` | 위 항목에 더해 `jnngpCnt` 가입자수, `crrmmNtcAmt` 당월고지금액(원), `adptDt` 적용일자, `scsnDt` 탈퇴일자(탈퇴 전이면 `00010101`), `wkplIntpCd` 업종코드, `vldtVlKrnNm` 업종명 |
| 기간별 현황 정보조회 `getPdAcctoSttusInfoSearchV2` | `nwAcqzrCnt` 신규취득자수, `lssJnngpCnt` 상실가입자수 |

## 회사 자료로 미리 저장하기 (`sync.ts`)

추천이 많이 된 회사의 국민연금 기록을 회사 자료(`company_datas`)에 label `국민연금 가입 현황`으로 한 행씩 저장한다. 중간 결과는 `output/nps/`(git 제외)에 남고, 단계마다 이어서 다시 돌릴 수 있다.

```bash
node --env-file=.env.local --import tsx scripts/nps/sync.ts select --limit 1600   # 추천받은 사람 수가 많은 회사
node --env-file=.env.local --import tsx scripts/nps/sync.ts pending --size 100   # 아직 매칭 안 한 회사를 판단할 묶음으로 나눔
node --env-file=.env.local --import tsx scripts/nps/sync.ts lookup "비바리퍼블리카" "토스"   # 이름별 사업장 검색 결과
node --env-file=.env.local --import tsx scripts/nps/sync.ts import output/nps/decisions/*.json   # 판단 결과 합치기
node --env-file=.env.local --import tsx scripts/nps/sync.ts biznum                # 못 찾은 회사 홈페이지에서 사업자등록번호 모으기
node --env-file=.env.local --import tsx scripts/nps/sync.ts fetch --limit 1000    # 매칭된 사업장의 12개월 기록
node --env-file=.env.local --import tsx scripts/nps/sync.ts write --limit 1000    # company_datas에 저장 (--dry-run이면 출력만)
node --env-file=.env.local --import tsx scripts/nps/sync.ts refresh --older-than-days 25 --limit 1000  # 매달 갱신
```

- **고르는 회사**: 추천(`talent_opportunity_recommendation`)을 받은 사람 수가 많은 순서다. 고객(`is_internal`) workspace는 뺀다. 회사 자료가 생기면 이름으로 찾을 수 있게 되기 때문이다.
- **매칭**: 회사와 국민연금 사업장을 잇는 판단은 사람이나 Claude Code 세션이 한다. 스크립트는 LLM API를 부르지 않는다. `pending`이 판단할 회사를 묶음 파일로 나누면, 판단하는 쪽이 회사 이름·홈페이지·개요를 보고 국민연금에 등록됐을 법한 법인명(예: 토스 → 비바리퍼블리카)으로 `lookup`을 돌려 이 회사의 사업장을 고른다. 결과는 `[{id, searched, status: matched|none|not_korean, workplaces: [{wkplNm, bzowrRgstNo, address}], reason}]` 파일로 쓰고 `import`로 합친다. `import`는 고른 사업장이 검색 결과에 실제로 있는지 확인한다. 해외 회사는 한국 법인(예: 구글코리아 유한회사)을 고른다. 확신이 없으면 고르지 않는다. 2026-11-23 첫 적재에서는 앞 1,019곳을 Anthropic API로, 나머지를 Claude Code 세션이 직접 판단했다.
- **저장 형식**: 사업장마다 `사업장: 이름 · 사업자등록번호 · 주소 · …` 한 줄과 월별 표(가입자수, 입사, 퇴사, 당월고지금액), 그리고 데이터의 뜻을 설명하는 한 문단이다. 채팅 회사 카드의 탭과 LLM이 같은 글을 읽는다. `refresh`는 이 `사업장:` 줄을 읽어 같은 사업장을 다시 찾는다.
- **출처**: 받은 응답 그대로를 공개 출처(`documents`, `career_public_observations`, provider `data_go_kr_nps`)로 남기고 회사 자료가 그것을 가리킨다. 출처 URL과 본문에 서비스키는 넣지 않는다.
- **사업자등록번호로 다시 찾기**: API는 사업자등록번호 10자리로는 찾지 못하고 앞 6자리만 받는다. 앞 6자리는 세무서와 법인 구분이라 여러 회사가 같이 쓰므로(예: 144812로만 찾으면 1,978줄) 이름 일부와 함께 넣는다. `lookup "채널#144812"`처럼 쓰면 거의 한 곳으로 좁혀진다. 번호는 회사 홈페이지 하단(`biznum`), 개인정보처리방침, 채용·기업정보 사이트에서 구한다.
- **첫 적재 결과(2026-11-23~24)**: 1,600곳 중 867곳 매칭, 한국 법인 없음 695곳, 못 찾음 38곳. 이름으로 찾지 못한 167곳은 사업자등록번호나 한국 법인명을 찾아 다시 판단했다. 88곳을 새로 매칭했고 40곳은 한국 법인이 없었다. 11/23에는 국민연금 API 하루 호출 한도에 걸려 757곳만 저장했고, 11/24에 나머지 109곳을 받아 저장했다. 보류했던 Ascend Inc.는 `어쎈드 주식회사(Ascend Inc.)`로 찾아 추가했고, Ericsson의 한국 법인 에릭슨엘지는 어느 표기로도 검색되지 않아 못 찾음으로 남겼다. 매칭된 867곳 모두 `company_datas`에 한 행씩 있다.
- **갱신**: 국민연금 자료는 매달 한 번 바뀐다. `refresh`는 확인한 지 25일이 지난 행을 다시 읽어 새 달을 반영한다. 회사 하나에 25번쯤 호출하므로 하루 호출 한도를 넘으면 멈추고, 다음 날 같은 명령으로 이어 간다.

## 데이터에 있는 것

CSV 열 기준이다. API 응답에도 같은 내용이 영문 필드로 나온다.

| 항목 | 쓸 수 있는 곳 |
| --- | --- |
| 가입자수 | 현재 인원. 그 달에 보험료가 고지된 인원이다 |
| 신규취득자수 | 그 달 입사 인원 |
| 상실가입자수 | 그 달 퇴사 인원 |
| 당월고지금액 | 평균 연봉 추정 (아래 절) |
| 사업장업종코드·업종코드명 | 업종 |
| 도로명·지번 주소, 법정동 코드 | 근무지, 같은 이름의 회사 구별 |
| 적용일자 | 국민연금이 처음 적용된 날. 첫 직원을 고용한 시점에 가깝다 (채널코퍼레이션 2014-01-14) |
| 재등록일자, 탈퇴일자, 사업장가입상태코드(1 등록, 2 탈퇴) | 폐업·이전·합병 신호 |
| 사업장형태구분코드(1 법인, 2 개인) | 법인 여부 |
| 자료생성년월 | 기준 달 |

이 값들을 여러 달 모으면 다음을 계산할 수 있다.

- **성장률**: 1년 전 대비 가입자수 증감
- **채용 강도**: 최근 3~6개월 신규취득자수 ÷ 가입자수. 공고 없이도 사람을 뽑고 있는지 보여 주는 채용 신호다
- **퇴사율**: 12개월 상실가입자수 합 ÷ 12개월 평균 가입자수
- **조직 규모 변화의 방향**: 입사와 퇴사가 모두 많은지(회전이 큼), 입사만 많은지(성장), 퇴사만 많은지(축소)
- **지점 수**: 같은 회사가 지점별로 등록했다면 사업장 수와 지역 분포

## 평균 연봉 추정

당월고지금액은 사업장 전체의 월 보험료(회사 부담분과 직원 부담분의 합)다. 보험료는 기준소득월액에 보험료율을 곱해 정하므로 거꾸로 풀 수 있다.

```
1인당 기준소득월액 ≈ 당월고지금액 ÷ 가입자수 ÷ 보험료율
추정 평균 연봉     ≈ 1인당 기준소득월액 × 12
```

보험료율은 2025년까지 9%, 2026년 9.5%이고 2027년부터 해마다 0.5%p씩 올라 13%까지 간다. 계산하는 달의 보험료율을 써야 한다.

예: 채널코퍼레이션의 2026년 9월 당월고지금액은 130,160,860원, 가입자수는 277명이다. 130,160,860 ÷ 277 ÷ 0.095 ≈ 495만 원/월, 연 약 5,940만 원이다.

보험료율이 바뀌는 1월과 상한이 바뀌는 7월에는 고지금액이 계단처럼 뛴다. 추이를 볼 때는 그 달의 보험료율로 나눈 값을 비교한다.

이 값은 실제 평균 연봉보다 낮게 나오기 쉽다.

- **상한이 있다.** 기준소득월액 상한은 2025.7~2026.6에 637만 원, 2026.7~2027.6에 659만 원이다. 연봉 약 7,900만 원 이상은 모두 상한으로 계산되어, 고연봉자가 많은 회사일수록 더 낮게 나온다.
- **1년쯤 늦다.** 직장가입자의 기준소득월액은 보통 전년도 소득으로 정하고 매년 7월에 바꾼다. 올해 연봉 인상은 다음 해에 반영된다.
- **비과세 소득은 빠진다.** 식대 같은 비과세 수당은 들어가지 않는다.
- **평균이다.** 대표와 임원, 신입이 모두 섞인다. 직무별 연봉은 알 수 없다.

그래서 회사끼리 비교하거나 같은 회사의 추이를 볼 때 쓰고, 특정 직무의 연봉으로 말하지 않는 편이 맞다.

## 해석할 때 주의할 점

- **작은 회사는 빠진다.** 가입자 3인 이상 법인과 10인 이상 개인사업장만 공개된다.
- **같은 회사인지 확인해야 한다.** 사업자등록번호는 앞 6자리로만 조회할 수 있어 이름이 같은 다른 회사가 섞인다. 사업장명, 주소, 업종을 함께 본다. 지점별로 등록된 회사는 사업장을 합쳐야 한다.
- **입사·퇴사와 정확히 같지 않다.** 신규취득자수에는 납부재개가, 상실가입자수에는 납부예외가 들어간다. 휴직과 복직이 퇴사와 입사처럼 잡힐 수 있다. 같은 회사 안에서 사업장을 옮긴 사람도 한쪽에서는 상실, 다른 쪽에서는 취득으로 잡힐 수 있다.
- **반영이 늦다.** 자격 변동은 다음 달 15일까지 반영되고, 공개 자료는 전월 기준이다. 1일이 아닌 날 입사해 그 달에 고지되지 않은 사람은 다음 달 신규취득자로 잡힌다. 그래서 가입자수 증감과 '신규취득 − 상실'이 딱 맞지 않을 수 있다.
- **실제 인원보다 적다.** 만 60세 이상, 일부 단시간·일용 근로자처럼 국민연금 사업장 가입 대상이 아닌 사람은 빠진다.
